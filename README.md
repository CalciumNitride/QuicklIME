# QuicklIME

Windows 用の自作日本語IME。通常のローマ字入力をベースに、変換の工夫による高速入力を目指す。

## 構成

| ディレクトリ | 内容 |
|---|---|
| `tsf/` | TSF テキストサービス (C++ / in-proc COM DLL)。フェーズ1で作成 |
| `engine/` | 変換エンジン (Rust / 常駐別プロセス) |
| `llm/` | LLM による候補の並べ替えの子プロセス (Rust / llama.cpp。エンジンが起動する) |
| `models/` | LLM のモデル (git管理外。`scripts/fetch-models.ps1` で取得) |
| `data/` | 設定ファイルのプリセット (AZIK 風ローマ字テーブルなど) |
| `docs/` | ドキュメント。全体の構成は [docs/architecture.md](docs/architecture.md)、機能ごとの設計書は [設計書の索引](docs/design/README.md)、未着手の項目と既知の問題は [docs/roadmap.md](docs/roadmap.md)、TSF-エンジン間プロトコルは [docs/protocol.md](docs/protocol.md) |
| `references/` | 参考用の外部リポジトリ (git管理外)。CorvusSKK、SampleIME |
| `scripts/` | 開発用スクリプト (`dev-deploy.ps1`: デバッグ反映、`cleanup-old-binaries.ps1`: 旧DLL/exeの掃除、`fetch-models.ps1`: LLM のモデルの取得、`build-llm.ps1`: LLM の子プロセスのビルド) |

## 開発環境

- Visual Studio 2022 (C++ によるデスクトップ開発ワークロード、Windows SDK 含む)
- Rust (stable-x86_64-pc-windows-msvc)
- Windows 11
- LLM の子プロセス (`llm/`) のビルドのみ: LLVM (`C:\Program Files\LLVM`)、Vulkan SDK
  (既定は `C:\VulkanSDK\1.4.363.0`)

## ビルド

- エンジン: `cd engine && cargo build`
  (quicklime-engine.exe 本体に加え、`src/bin/` の quicklime-config.exe /
  quicklime-regword.exe も一緒にビルドされる)
- エンジンのテスト: `cd engine && cargo test`
- エンジン単体の動作確認 (起動中のエンジンに接続して CONVERT/CONVSEG を試す):
  `cargo run --example query -- <読み> [<読み>...]`
- TSF層 (VS付属のCMakeを使用、64bit):
  ```
  cmake -S tsf -B tsf/build -G "Visual Studio 17 2022" -A x64
  cmake --build tsf/build --config Debug
  ```
  成果物: `tsf/build/Debug/QuicklIME.dll`
- LLM の子プロセス: `scripts\fetch-models.ps1` でモデルを `models\` に取得し (サイズと
  SHA-256 を確かめる)、`scripts\build-llm.ps1` で CPU 版 `quicklime-llm.exe` と Vulkan 版
  `quicklime-llm-vulkan.exe` を release ビルドする (成果物は `llm\target\release\`)。
  llama.cpp のビルドに要る環境変数 (LIBCLANG_PATH、CMake・Ninja、VULKAN_SDK、vcvars64) と、
  長いパスを避ける `subst` はスクリプトの中で設定する。エンジンの通常のビルドには要らない
- LLM の並べ替えの計測 (エンジンを隔離して起動し、llm_cases.tsv の左文脈で RERANK を送る):
  `cargo run --release --example nbest_eval -- --cases examples/data/llm_cases.tsv --llm cpu`
  (`--llm vulkan` で Vulkan 版)

## インストーラでの導入

`installer\build.ps1` を実行すると `installer\output\quicklime-<版>-setup.exe` が生成される
(前提: Inno Setup 6 = `winget install -e --id JRSoftware.InnoSetup`、references/mozc の辞書と
単漢字辞書 (`git -C references/mozc sparse-checkout add src/data/single_kanji` で取得)、
`scripts\fetch-ut-dict.ps1` で生成した UT 辞書 (`references\mozcdic-ut\dictionary_ut.txt`)、
`scripts\build-llm.ps1` でビルドした LLM の exe、`scripts\fetch-models.ps1` で取得したモデル)。

- 配置先は `%ProgramFiles%\QuicklIME\` (64bit DLL + エンジン・設定・単語登録の exe +
  辞書 `dict\`)。32bit アプリ用の DLL は `x86\` に入り、両方が IME として登録される
- 初回インストールは再起動不要。更新時は DLL がロード中のため再起動を求められることがある
- アンインストールしてもユーザデータ (`%APPDATA%\QuicklIME\` の設定・ユーザ辞書・学習) は残る
- 同梱辞書は Mozc (BSD ライセンス) のもの。ライセンス文書 LICENSE-mozc.txt を同梱している。
  単漢字辞書 (`dict\single_kanji.tsv`) も Mozc の `src/data/single_kanji/` のもので、候補リストの
  辞書候補の後ろに単漢字を足すのに使う
- UT 辞書 (`dict\dictionary_ut.txt`) は、Mozc 向けの追加辞書 mozc-ut (utuhiro78 氏) のうち
  SudachiDict (一般語。Apache License 2.0、一部 UniDic 由来で BSD ライセンス)・日本郵便の
  郵便番号データ (地名。日本郵便は著作権を主張しない)・人名 (Apache License 2.0) から、Mozc 辞書と
  重複する語などを除いて生成したもの。`scripts\fetch-ut-dict.ps1` が元データをリビジョン固定で
  `references\mozcdic-ut\` に取得し (サイズと SHA-256 を確かめる)、`engine/examples/build_ut_dict.rs`
  で生成する。元データの説明と SudachiDict の LEGAL・LICENSE-2.0.txt の全文をまとめた
  LICENSE-mozcdic-ut.txt を同梱している
- モードレス入力の英単語辞書 (`dict\english-words.txt`) は SCOWL (English Speller Database、
  https://github.com/en-wl/wordlist) から生成したもの。著作権表示と許諾文 LICENSE-SCOWL.txt を
  同梱している。生成の手順と条件はファイル先頭のコメントにある。固有名詞・技術用語の
  `dict\english-names.txt` は自作
- LLM の子プロセス (quicklime-llm.exe・quicklime-llm-vulkan.exe) と、モデル (`models\` に
  zenz-v3.2-xsmall と zenz-v3.2-small) を同梱する。ライセンス文書 LICENSE-llama.cpp.txt (MIT)・
  LICENSE-zenz.txt (Apache License 2.0) を同梱している。LLM の子プロセスは VC++ ランタイムを
  動的にリンクするため、再頒布可能な DLL (msvcp140・vcruntime140・vcruntime140_1・vcomp140) を
  exe と同じディレクトリに置く (ビルド環境の Visual Studio の `VC\Redist\MSVC\<版>\x64` から取る)

登録後、Win+Space で「QuicklIME」を選択して使用する。

## 開発版 DLL の切替とインストール版の更新

`scripts\dev-deploy.ps1` でビルドから反映までをまとめて実行できる。

| コマンド | 動作 |
|---|---|
| `scripts\dev-deploy.ps1` | エンジンのみ反映 (release ビルド → 常用の Program Files へコピー) |
| `scripts\dev-deploy.ps1 -Dll` | エンジン反映に加え、TSF DLL を Debug ビルドして開発版へ切替 (要管理者権限) |
| `scripts\dev-deploy.ps1 -Dll -Install` | エンジン反映に加え、TSF DLL を Release ビルドして常用インストール版へ直接反映 (管理者権限・再起動とも不要) |
| `scripts\dev-deploy.ps1 -Restore` | DLL を開発版からインストール版へ戻す (要管理者権限) |

DLL の反映方法は用途で使い分ける。

- **`-Dll`** (開発版切替): `tsf\build\Debug\QuicklIME.dll` に regsvr32 で排他的に切り替える。
  常用インストール版には触れない。確認が終わったら `-Restore` で必ず戻すこと
- **`-Dll -Install`** (インストール版更新): 常用インストール版の DLL 自体を新しいビルドに
  差し替える。ロード中の DLL を `.old-<日時>` にリネーム退避してから同じパスに新 DLL を
  コピーするので、レジストリ再登録も PC 再起動も不要 (インストーラでの更新は
  ロード中だと `restartreplace` により再起動待ちになる)。32bit 版 (`x86\QuicklIME.dll`) も
  同じ手順で更新する (ビルドツリーは `tsf\build32`。未構成なら自動で生成する)

手動で行う場合 (開発版切替):

```
regsvr32 tsf\build\Debug\QuicklIME.dll      # 登録
regsvr32 /u tsf\build\Debug\QuicklIME.dll   # 解除
```

インストール版と開発版は同じ CLSID を共有し、後から regsvr32 (または再インストール) した
方に登録が切り替わる。開発を終えて常用へ戻すときは、インストーラを再実行するか
`regsvr32 "%ProgramFiles%\QuicklIME\QuicklIME.dll"` で戻す。

## ローマ字テーブルのカスタマイズ

`%APPDATA%\QuicklIME\romaji.tsv` (UTF-8) を置くと、既定のローマ字テーブルへ
追加・上書きされる。書式は 1行1エントリ「ローマ字<TAB>かな」。`#` 始まりの行は
コメント、かな欄が空の行は既定エントリの削除。反映は各アプリの再起動後。

AZIK 風拡張 (撥音拡張「かん」=kz、二重母音拡張「こう」=kp など) のプリセットを
[data/romaji-azik.tsv](data/romaji-azik.tsv) に用意している (インストール版では
`%ProgramFiles%\QuicklIME\presets\` にも同梱)。使う場合はこれを
`%APPDATA%\QuicklIME\romaji.tsv` へコピーする。

```powershell
# PowerShell の場合 (%APPDATA% は展開されないので $env:APPDATA を使う)
copy data\romaji-azik.tsv $env:APPDATA\QuicklIME\romaji.tsv
```

## 辞書インポート

他の IME からエクスポートしたユーザ辞書や、それらの形式で配布されている辞書
(ニコニコ大百科 IME 辞書・pixiv 辞書など) を取り込める。

使い方: 単語登録ツール (quicklime-regword.exe、Ctrl+F7) の「インポート...」ボタンで
ファイルを選ぶ。取り込んだ件数 (取り込み / 重複 / 未対応の品詞 / 不正な行) が表示され、
起動中のエンジンには即時反映される (エンジン未起動なら次回起動時に反映)。

| 形式 | 判別 | 備考 |
|---|---|---|
| MS-IME | 先頭行が `!Microsoft IME Dictionary Tool` | `!` 始まりの行はヘッダ |
| ATOK | 先頭行が `!!ATOK_TANGO_TEXT_HEADER_1` | `!` 始まりの行はヘッダ。品詞末尾の `$` `*` は無視 |
| Mozc / Google 日本語入力 | 上記以外 | `#` 始まりの行はコメント |

- 各行は `読み<TAB>語句<TAB>品詞[<TAB>...]`。文字コードは UTF-16 (BOM 付き)・UTF-8
  (BOM の有無を問わない)・Shift_JIS を自動判別する
- 読みのカタカナはひらがなに直す
- 取り込むのは名詞系と短縮よみのみ。品詞は次のように対応づけ、それ以外 (動詞・形容詞・
  副詞・数・サジェストのみ など) は「未対応の品詞」として読み飛ばす

  | 元の品詞 | 取り込み後 |
  |---|---|
  | 人名, 固有人他, 固有人名(姓名) | 人名 |
  | 姓, 固有人姓 | 姓 |
  | 名, 固有人名 | 名 |
  | 地名, 固有地名, 地名その他 | 地名 |
  | 組織, 固有組織, 社名 | 組織 |
  | 固有名詞, 固有一般, 固有商品, 物品, その他「固有」で始まる・「固有名詞」を含む品詞 | 固有名詞 |
  | 短縮よみ, 短縮読み, 顔文字, 記号 | 短縮よみ |
  | 上記以外で「名詞」を含む品詞 (普通名詞, さ変名詞, 名詞サ変, 形動名詞, 副詞的名詞 など) | 名詞 |

- ファイル内の重複 (読み・語句・取り込み後の品詞が同じ) と、ユーザ辞書 (userdict.tsv)・
  他のインポート済み辞書に既にある (読み, 語句) は「重複」として読み飛ばす
- 取り込んだ辞書は `%APPDATA%\QuicklIME\imported\<元ファイル名から拡張子を除いた名前>.tsv`
  に 1 辞書 1 ファイルで保存される (書式は `読み<TAB>表記<TAB>品詞`、UTF-8)。
  同じ名前のファイルを取り込み直すと上書きする (配布辞書の更新用)。
  取り込める語が無かった場合はファイルを作らない
- 辞書を外すにはそのファイルを削除する。反映はエンジンの再起動時、または
  単語登録ツールでの次回のインポート時
- インポートした語は変換 (文中を含む)・予測・F5 のユーザ辞書変換に出る。
  変換候補での優先度は手動登録より低く、一般的な名詞と同程度。予測では手動登録・
  確定履歴より後に、同梱辞書の語とコスト順に混ざって出る。
  手動登録と同じ (読み, 表記) の語は手動登録側が優先される
- 保存先ディレクトリは環境変数 `QUICKLIME_IMPORT_DIR` で変更できる
  (エンジン・単語登録ツール共通。動作検証時の隔離用)

## 入力方式

打鍵した文字は、未確定文字列 (下線付きの composition) を使わずに文書へ直接入る。
IME は自分が入れた文字列とその読み (run) を覚えておき、変換は変換キーで後から行う
(後置変換)。かなは完成した時点で文書に追記し、未完成のローマ字 (`k`、`ky` など) は
文書に入れずにキャレット付近の小窓に出す。未確定文字列の挙動が不安定な Web フォーム
(文字数固定・自動で次欄へ移動する欄など) でも、ターミナルなどの文書を読み戻せない
アプリでも同じ方式で動く。

キー操作 (IME オン時。変換キー・無変換キー・F4〜F10 などは既定の割当で、
下記「キー割当」で変えられる):

- 英字・記号・数字: run を始める / 読みに追加し、かなが完成したら文書に追記する
  (下線は付かない)。Backspace は、未完成のローマ字があればそれを削り、無ければ文書の
  末尾の1文字を消して読みからも削る (空になれば run 終了)
- 変換キー: run 中は変換開始 (run が無いときは下記「後置再変換」)。候補選択中は次候補
  (Shift+変換キー で前候補)。
  候補は入力中のかな全体を1単位にした変換結果 (区切りの違う「今日は医者に行った」
  「今日歯医者に行った」などが並ぶ) で、縦の候補ウィンドウから1つ選ぶ。英字を含む入力は
  全体を1語として変換する (打鍵したローマ字の apple / Apple / APPLE も選べる。固有名詞・
  技術用語は大文字小文字を直した表記が先頭に入り、github / ぎてゅb から GitHub を選べる)。
  変換中 (候補選択中) だけは run を未確定文字列 (composition) に切り替え、下線と
  変換対象の強調を表示する。候補選択中は Space で次候補、Shift+Space で前候補、
  ↑↓・数字 1〜9・F4〜F10 (入力全体にかかる) も使える。run 中の F4〜F10 も
  同様に未確定文字列に切り替えて働く。未確定文字列にできない文書では、変換対象を
  選択状態にして強調する (どちらの文書でもキーの挙動は同じ)
- 変換の範囲の伸縮: 候補選択中の ← で範囲の先頭を1文字左へ広げ、→ で1文字縮める (範囲の
  右端はキャレットに固定)。範囲を変えると、その読みで変換をやり直す (F6〜F10 で文字種を
  変えている間は同じ文字種変換をやり直し、F4・F5 の後は通常の変換に戻る)。縮めて外したかなは
  かなのまま文書に残り、学習しない。縮めて外した文字は ← で打鍵ごと元に戻せる。それより左へ
  広げられるのは範囲の直前がひらがなか ー のときで、範囲は 127 文字まで。縮めるのは2文字以上のとき。広げられない・縮められないときは何もしない。
  追記のみの文書 (下記「読める文書と追記のみの文書」) では、外したかなは文書に戻さず
  未確定文字列の先頭に下線付きで残り、確定するとそのかなと選んだ候補がまとめて入る
  (広げられるのは外したかなを戻すところまで。変換を取り消すと run 全体のかなに戻る)。
  英字を含む入力 (英単語の打鍵・末尾の未完成のローマ字など) の変換キーでの変換・`segment_ui` 1・
  まだ読めるかどうかを判定していない文書では範囲を伸縮せず、←→ は下記のとおり確定してアプリへ
  渡す (`segment_ui` 1 では文節の移動)。英字を含む入力でも F6〜F10 の間は伸縮できる
  (`kyouhawant` → F10 → → を4回 → `きょうは` + `want`)
- 文節単位の変換: 設定 `segment_ui` (設定ツールの「文節単位で変換する」、既定 0) を 1 にすると、
  候補選択を文節ごとに行う。候補選択中の ←→ で文節の移動、Shift+←→ で文節の伸縮、
  PgUp/PgDn で先頭 / 末尾の文節へ移動し、候補は現在の文節のものになる
- 候補選択中の Enter: 確定してから Enter をアプリへ渡す (1打で確定と改行・送信)。
  Esc・Backspace: 変換前のかなに戻し、下線の無い run に戻る。英字などの印字キー:
  確定して新しい run を始める。Tab: 変換を取り消して候補バーの先頭を選ぶ。
  Home・End・Delete (`segment_ui` 0 では Shift+←→・PgUp/PgDn と、範囲を伸縮しないときの
  ←→ も): 確定してからアプリへ渡す。確定してキャレットを動かすには、確定キーか Enter で
  確定してから動かす
- 確定キー (無変換キー): run 中はかなのまま run を終える (候補バーの候補は採用しない。
  末尾の未完成のローマ字は Enter で終えたときと同じく文書に残る)。候補選択中は確定、バーで候補を選んでいるときはその候補を採用する。
  キーはアプリへ渡さない (改行は入らない)
- 後置再変換: run が無いときに変換キーを押すと、次の文字列を読みとして候補選択に入る
  (F6〜F10 も同じ文字列を対象に働く。F4・F5 は run が無いときは働かない)
  - 選択があれば選択した文字列。ひらがな・カタカナ・ー だけで 127 文字までのときに限る
    (漢字を含む選択では何も起きない)
  - 選択が無ければ、キャレット直前が IME の入れた文字列の記憶 (下記) で終わり、最新の記憶が
    ひらがな・ー だけでなければ、その1件 (1回で採用・確定した単位)。漢字を含む部分も読みを
    打ち直さずに直せる。候補の先頭は記憶の表記 (変換キーを押しただけでは文書は変わらない) で、
    2回目の変換キーから次の候補へ進む。F6〜F10 は記憶した打鍵から変換する
  - それ以外は、キャレット直前のひらがな・ー の連続 (127 文字まで。カタカナ・漢字・英数字・
    記号・空白・改行で止める)。Enter・確定キーで run を終えた後や、キャレットを動かした後に
    残ったかなもそのまま変換できる
  - 選択が無いときは読める文書だけで働く。前文脈は、範囲の直前が記憶ならその最後の文節、
    そうでなければ範囲の直前が直前の確定の表記で終わるときだけ直前の確定を使う
  - 範囲の伸縮は記憶にまたがって行える。→ で外した読みはかなのまま残り、← で範囲の直前の
    記憶に入ると、その最後の文節を (範囲に入らなかった部分も含めて) かなに書き直して広げる。
    確定すると範囲が新しい1件の記憶になり、かなに書き直した部分はかなの1件として残る。
    記憶から始めた変換を取り消す (Esc・Backspace・Tab) と、かなに書き直した部分も含めて
    変換前の表記に戻る
  - 対象が無いとき (キャレット直前がかなでも記憶でもない、読めない文書) は変換キーをアプリへ渡す
  - 記憶: 読める文書で、run が文書に残した出力 (候補バーの採用・候補選択の確定・かなのままの
    run の終了) を1件ずつ、表記・文節ごとの読み・打鍵とともにメモリ上だけで覚える (新しいものから
    読みの合計 127 文字まで)。使うときにキャレット直前の文書と末尾から照合し、一致する分だけを
    使う (Space で入れたスペース・アプリへ渡した改行など、IME を通らない文字や編集が入ると
    そこで途切れる)。フォーカス移動・IME オフで捨てる。追記のみの文書では記憶せず、確定アンドゥ
    だけが働く
- 候補バー: 入力中はキャレット行の下に変換結果と予測候補を横一列に出す (下記「候補バー」)
- 次の語の予測: 確定キーで run を終えた直後は、読みを打つ前に、直前に確定した語の後に
  確定したことのある語を候補バーに出す (下記「次の語の予測」)
- Space: スペース (設定 `space` に従う)。run 中は run を終えてからスペースを入れる
  (バーで候補を選んでいるときは採用してからスペースを入れる)
- Enter・Esc・矢印・Tab・Home/End・PgUp/PgDn (候補選択・バー選択以外): run をかなのまま
  終える (Esc 以外はアプリに渡す。Esc は文字を消さず run を忘れるだけ)。未完成のローマ字は
  そのまま文書に残る。候補バーが出ている間の Tab・↑↓ はバーの選択に使う
- Ctrl+Backspace (確定アンドゥ): run 終了後に、直前の run を読みのかなに戻して再開する
  (変換結果もかなに戻る)
- Ctrl+J (改行キー): Enter で送信するチャットアプリなどで、アプリへ Shift+Enter を送って
  改行を入れる。run 中・候補選択中・バー選択中は Enter と同じく確定 (バー選択中は選んでいる
  候補の採用) してから送る。働くのは設定 `newline_apps` に exe 名がある対象アプリだけで、
  既定は `Discord.exe,slack.exe,ms-teams.exe,Teams.exe,LINE.exe` (カンマ区切り、大文字小文字は
  区別しない。空にすると対象なし)。対象外のアプリでは Ctrl+J は割当なしと同じくアプリへ渡る。
  対象アプリは設定ツールの「アプリ」タブ (下記「アプリごとの設定」) で切り替えられる
- run の終了時・候補バーの採用時は学習 (候補選択の文節ごと・採用した候補) と文脈の更新を行う。
  2文節以上の変換結果を確定・採用したときは読み全体の表記も学習し、次に同じ読みを打つと
  その表記が変換候補の先頭に来る (予測候補にも出る)
- フォーカス移動・IME オフ・キャレット移動でも run は終わる (未完成のローマ字は捨てる)

### アプリごとの設定

設定ツールの「アプリ」タブには、アプリ (exe 名) ごとの設定を1つの一覧にまとめている。
列は「exe 名」「改行キー」(`✓` なら有効)「起動時の IME」(`自動` / `オン` / `オフ`)
「学習」(学習しないアプリは `しない`)。

- 一覧で選んだアプリの設定は、下の編集欄で変える: チェックボックス「改行キー (Ctrl+J など) で
  Shift+Enter を送る」、コンボ「起動時の IME」、チェックボックス「このアプリでは学習しない」。
  変えるとすぐ一覧に反映する。何も選んでいないときは編集欄は無効
- [実行中のアプリから追加...] (見えているウィンドウを持つアプリから選ぶ) か [ファイルから追加...]
  (exe ファイルを選ぶ) で足したアプリは「改行キーなし・自動・学習する」から始まる。一覧にある exe
  (大文字小文字は区別しない) は重ねて足さず、その行を選ぶ
- [削除] はそのアプリの設定をすべて外す。[既定に戻す] は改行キーの既定の5アプリ
  (改行キーあり・自動・学習する) だけの一覧に戻す。変更は [保存] で書き、[キャンセル] では書かない
- config.tsv では機能ごとのキーに分けて書く: 改行キーは `newline_apps` (上記 Ctrl+J)、起動時の
  IME は `ime_start_apps`、学習の停止は `no_learning_apps`。どの設定も既定
  (改行キーなし・自動・学習する) のアプリはどのキーにも書かれないので、開き直すと一覧から消える

起動時の IME の状態 (`ime_start_apps`): アプリの起動時に IME をオンで始めるかオフで始めるかを
アプリごとに決める。値は `exe名:on` / `exe名:off` のカンマ区切り (例:
`Notepad.exe:on,WindowsTerminal.exe:off`。exe 名と `on` / `off` は大文字小文字を区別しない)。
既定は空。

- 一覧に無いアプリは「自動」: IME のオン/オフをアプリやシステムに任せる (状態が未設定のときだけ
  オンにする)
- 適用するのはプロセスで最初に文書へフォーカスしたときの1回だけ。同じプロセスで開いた
  新しいウィンドウ・別の IME から QuicklIME へ戻したときには適用せず、アプリの中で切り替えた
  オン/オフを上書きしない。設定の変更は、次に起動したアプリから効く
- `on` / `off` 以外の項目・exe 名が空の項目は無視する。同じ exe 名が重なれば最初の項目を使う

学習の停止 (`no_learning_apps`): 指定したアプリでは、確定・採用の結果を学習に記録しない。
値は exe 名のカンマ区切り (例: `WindowsTerminal.exe,wezterm-gui.exe`。大文字小文字は区別しない)。
既定は空 (どのアプリでも学習する)。

- 止めるのは記録だけで、既存の学習データは対象アプリでも候補の並びに使う
- 単語登録ツールでの登録は止めない。直前に確定した文節 (前文脈) は対象アプリでも後続語予測と
  文脈補正に使う
- 設定の変更は、TSF 層の設定の再読込で開いているアプリにも効く

### 候補バー

入力中は、キャレット行のすぐ下 (入らなければ上) に候補を横一列に出す。文書の文字列は
候補を採用したときだけ書き換わり、選んでいる間や採用せずに run を終えたときは
かなのまま変わらない。

- 候補は次の順に最大9件並び、各候補の前に番号 1〜9 が付く。表記が同じ候補は前のものだけ残す
  - 英字候補: モードレス入力で、今 run を終えたら英字になる形 (下記「モードレス入力」。
    `min_suggest_chars` によらず出る)。英字区間の入力中は、代わりに英単語の大文字小文字を
    直した形 (`きょうはGitHub`) が出る
  - 全体変換: 入力中のかな全体の変換結果の上位 (最大3件。かなと同じ表記は出さない)
  - 予測候補: 入力中のかなで始まる語・確定履歴
  - 先頭文節: 変換結果の上位から集めた第1文節 (区切りや表記の違うものを最大3件。2文節以上の
    変換結果から取る)。末尾に「…」が付く
- 未完成のローマ字 (小窓に出ている `k` など) は候補の対象外。確定済みのかなが
  `min_suggest_chars` 文字以上のときに出す。候補選択中・モードレスの英字モード中 (日本語の
  部分を残して英単語の部分だけが英字になった run では、日本語の部分に対して出す)・
  エンジン未接続のときは出さない
- バーの横位置は run で最初に出した位置に固定する。画面の作業領域の右端に収まらない
  後ろの候補は出さない (選択もできない)
- 選択: Tab / ↓ で右へ、Shift+Tab / ↑ で左へ (未選択から Tab で先頭、先頭で Shift+Tab で
  未選択に戻る)。数字 1〜9 で番号の候補を選ぶ。Esc で選択解除。選んでも文書は変わらない
- 採用:

  | 操作 | 未選択 | 選択中 |
  |---|---|---|
  | 確定キー (無変換キー) | かなのまま run を終える | 選んでいる候補を採用する |
  | Enter | かなのまま run を終えて Enter を渡す | 採用して run を終え、Enter を渡す |
  | 印字キー | (打鍵を続ける) | 採用し、その打鍵から続ける |
  | Space | かなのまま run を終えてスペース | 採用して run を終え、スペース |

- 全体変換・予測候補を採用すると、入力中のかな全体が候補に置き換わる。先頭文節を
  採用すると、その文節の読みの部分だけが置き換わり、残りのかなは入力中のまま続く
  (確定キーで採用したときも続く)。バーは採用した文節を前の文脈にして作り直される
- 採用した部分は以後 IME が書き換えない。確定アンドゥ (Ctrl+Backspace) は run を終えた
  後にだけ働き、最後に採用した部分 (または終えたときのかな) を読みに戻す
- 設定: `candidate_bar` (設定ツールの「候補バーを表示する」、既定 1)。0 にするとバーを
  出さず、run 中の Tab・↑↓ はアプリへ渡る (run を終える)。`min_suggest_chars` (設定ツールの「サジェスト開始文字数」、1〜5、既定 2) で
  バーを出す文字数を変えられる。`suggest` (「入力中にサジェストを表示する」) を 0 にすると
  予測候補だけが出なくなる (全体変換・先頭文節は出る)
- 見た目: `panel_theme` (設定ツールの「候補の見た目」、既定 `capsule`)。組み込みの
  `capsule` (カプセル (横一列))・`capsule-column` (カプセル (縦積み))・`ghost` (ゴースト) から選ぶか、
  テーマフォルダ `%APPDATA%\QuicklIME\themes\` に置いたテーマファイル (`<名前>.tsv`) を選ぶ。
  テーマファイルの書き方は [docs/theme.md](docs/theme.md)
- 表示位置: `candidate_position` (設定ツールの「候補の表示位置」、`caret` / `center`、既定
  `caret`)。`center` にすると、候補バー (次の語の予測を含む) をキャレットのあるモニタの作業領域の
  中央に、幅を固定して出す (幅に収まらない後ろの候補は出さず、選択もできない)。変換キーの
  候補一覧もこの設定に従い、`center` では候補バーと同じ上端から下へ伸ばして出す。未完成ローマ字の
  小窓はキャレットの位置のまま
- 入力行: `panel_input` (設定ツールの「入力中の読みも候補と同じ場所に表示する」、既定 0)。
  1 にすると、候補バーの上に入力中のかな (下線付き) と未完成ローマ字を出し、未完成ローマ字の
  小窓は出さない。候補が無くても入力中は入力行だけを出す。次の語の予測では直前の確定の末尾を
  出す。変換キーの候補選択中は、変換中の文を文節ごとに区切り、選択中の文節を強調して出す。
  `candidate_bar` が 0 のときは出さない
- ぼかし: `panel_blur` (設定ツールの「候補の背景をぼかす」、既定 0)。1 にすると、候補バーと
  変換キーの候補一覧のパネルと未完成ローマ字のカプセルの背景が、後ろが透けるぼかし (アクリル) になる。角丸は
  Windows が描く小さい角丸になる。Windows の透明効果がオフのときや、機能が使えない環境
  (Windows 10 など) では通常の描画で出る
- 予測候補は、直前に確定した語 (前文脈) に続けて確定したことのある語を、短縮よみの次
  (ユーザ登録の名詞・確定履歴より前) に上げて出す

### 次の語の予測

確定キーで run を終えた直後は、読みを打つ前に「直前に確定した語の後に確定したことのある語」を
候補バーに出す (前文脈付きの学習を、記録が新しい順に引く)。

- 出すとき: 確定キーで run を終えたとき (候補バーの採用・候補選択の確定・かなのままの
  いずれも)、候補バーの採用で残りのかなが無くなって run が終わったとき、次の語の予測を
  確定キーで採用したとき (続けてその次の語を出す)
- 出さないとき: Space・Enter・アプリへ渡すキーで run を終えたとき、前文脈が無いとき、
  候補が無いとき、エンジン未接続のとき、`candidate_bar` か `next_word` が 0 のとき
- 位置と見た目は候補バーと同じ。文書は採用するまで変わらない
- 消えるとき: 選んでいない状態で選択以外のキーを押したとき (そのキーは今どおり働く。
  ↓・Tab などもアプリへ渡る)、キャレットの移動・クリック・フォーカス移動・IME オフ
- 選択: Ctrl+↓ (`key.next_word_next`) で先頭、Ctrl+↑ (`key.next_word_prev`) で末尾を選ぶ
  (予測が出ていないときはアプリへ渡る)。選んだ後は候補バーと同じく Tab / ↓・Shift+Tab / ↑・
  数字 1〜9 で選択を動かし (先頭で Shift+Tab / ↑ を押すと未選択に戻る)、Ctrl+↓ / Ctrl+↑ も使える
- 採用 (選択中):

  | 操作 | 動作 |
  |---|---|
  | 確定キー (無変換キー) | 候補をキャレット位置に入れ、続けて次の語の予測を出す |
  | Enter | 候補を入れてから Enter を渡す |
  | Space | 候補を入れてからスペースを入れる |
  | 印字キー | 候補を入れてから、その打鍵で入力を始める |
  | Esc | 選択を外して予測を消す |
  | 変換キーなど他のキー | 予測を消し、入力なしのときと同じく処理する |

- 候補は既存の文字列を書き換えずに追記で入る。採用した語は学習し、次の前文脈になる。
  確定アンドゥ (Ctrl+Backspace) で読みのかなに戻せ、読める文書では後置再変換の記憶にもなる
- 設定: `next_word` (設定ツールの「確定の後に次の語を予測する」、既定 1)。0 にすると出さない
  (入力中の予測候補の前文脈による順位付けは `next_word` によらず働く)。`suggest` が 0 のときも出ない

### AI による候補の並べ替え

設定 `llm` (設定ツールの「AI で候補を並べ替える」、既定 0) を 1 にすると、候補バーと変換キーの
候補 (入力全体の変換結果) を、かな漢字変換モデル (zenz) で文脈に合う順に並べ替える。

- 候補バーは、まず統計変換の並びで出し、並べ替えの結果が出たら (多くは数十 ms 以内) 作り直す。
  打鍵は待たない。バーの候補を選んでいる間・候補選択中は並びを変えない
- 変換キーを押した時点で並べ替えの結果が出ていれば、縦の候補リストもその並びになる
- 文脈は入力を始めた位置より前の、同じ行の文字列 (読める文書は文書から読み、ターミナルなどの
  追記のみの文書は IME が入れた文字列を覚えて使う。Enter・キャレット移動・フォーカス移動などで
  捨てる)。文脈はメモリ上だけで使い、ログやファイルには書かない
- 並べ替えるのは変換結果の上位 10 件。読み全体を学習した表記・学習で表記が変わった変換結果・
  ユーザ辞書の語を含む候補・英字を含む候補は位置を動かさない
- `llm_backend` (設定ツールの「AI の実行環境」) で、`cpu` (既定。zenz-v3.2-xsmall) か
  `vulkan` (GPU。zenz-v3.2-small) を選ぶ。Vulkan 版が動かない環境では CPU 版で動く
- 推論はエンジンが起動する別プロセス (quicklime-llm.exe / quicklime-llm-vulkan.exe) で行う。
  子プロセスは起動時にモデルの読み込みと試しの推論を済ませ、それまでは統計変換の並びで動く。
  応答が 2 秒を超えた依頼は統計変換の並びのままにする (子プロセスは止めずに応答を待ち、その間の
  依頼も統計変換の並びにする)。60 秒応答しない・終了したときは 10 秒後に起動し直し、続けて3回
  失敗したら設定を保存し直す (読み直す) まで使わない。その間も統計変換だけで入力できる
- エンジンは子プロセスの exe を自分と同じディレクトリ → 開発レイアウトの `llm\target\release\`、
  モデルを環境変数 `QUICKLIME_LLM_MODEL_DIR` → 自分と同じディレクトリの `models\` → 開発レイアウトの
  リポジトリ直下の `models\` の順で探す

### キー割当

機能ごとのキー割当は、設定ツールの「キー割当」(機能の一覧から「編集」) か config.tsv で
変えられる。1つの機能に複数のキーを割り当てられ、状態ごとに割当を上書きできる。

| 機能 | 設定キー | 働く状態 | 既定 |
|---|---|---|---|
| 変換 | `key.convert` | 全状態 | `Convert` |
| 次候補 | `key.next_candidate` | 候補選択中 | `Space` |
| 前候補 | `key.prev_candidate` | 候補選択中 | `Shift+Space` |
| 確定 | `key.commit_run` | run 中・候補選択中・サジェスト選択中 | `NonConvert` |
| 記号・日付変換 | `key.convert_symbol` | 同上 | `F4` |
| ユーザ語変換 | `key.convert_user` | 同上 | `F5` |
| ひらがな変換 | `key.to_hiragana` | 全状態 | `F6` |
| カタカナ変換 | `key.to_katakana` | 同上 | `F7` |
| 半角カタカナ変換 | `key.to_half_katakana` | 同上 | `F8` |
| 全角英字変換 | `key.to_full_ascii` | 同上 | `F9` |
| 半角英字変換 | `key.to_half_ascii` | 同上 | `F10` |
| 確定アンドゥ | `key.undo_commit` | 入力なし | `Ctrl+Backspace` |
| 単語登録 | `key.register_word` | 入力なし | `Ctrl+F7` |
| 設定を開く | `key.open_config` | 入力なし | `Ctrl+F12` |
| 改行 | `key.insert_newline` | 全状態 | `Ctrl+J` |
| 次の語の予測: 次 | `key.next_word_next` | 入力なし・サジェスト選択中 | `Ctrl+Down` |
| 次の語の予測: 前 | `key.next_word_prev` | 同上 | `Ctrl+Up` |

- 状態: 入力なし (`idle`、run が無い)、run 中 (`run`)、候補選択中 (`candidate`)、
  サジェスト選択中 (`suggest`、候補バーまたは次の語の予測で候補を選んでいる)
- 次の語の予測の2機能は、次の語の予測が出ているときだけ打鍵を食べる (出ていなければ、
  run 中のバー選択でもアプリへ渡す)
- 書式: `key.<機能>\t<キー>[,<キー>...]` が基本の割当、`key.<機能>@<状態>\t<キー>[,...]` が
  状態別の上書き (その機能が働く状態にだけ書ける。上書きした状態では基本の割当を使わない)。
  値 `none` は割当なし。例: `key.convert\tConvert,Ctrl+Space`、
  `key.commit_run@candidate\tCtrl+Enter`
- キーの表記: 修飾キー `Ctrl+`・`Shift+` を前置し、キー名を続ける。キー名は
  `A`〜`Z`・`0`〜`9`・`F1`〜`F24`・`Space`・`Enter`・`Esc`・`Tab`・`Backspace`・`Delete`・
  `Insert`・`Home`・`End`・`PageUp`・`PageDown`・`Up`・`Down`・`Left`・`Right`・
  `Convert` (変換)・`NonConvert` (無変換)・`Kana` (カタカナ/ひらがな)、それ以外は
  `VK_xx` (16進2桁の仮想キーコード)
- 割り当てられないキー: Enter・Esc・Tab・Backspace・Delete・矢印・Home・End・PgUp・PgDn の
  無修飾と Shift 併用、Ctrl+M・Ctrl+H、英字・数字・記号・テンキーの無修飾と Shift 併用、
  IME の切替キー (半角/全角など)、修飾キー単体、Alt 併用 (アプリによっては IME に
  届かないため)、Win キー併用。Ctrl 併用のコア操作 (Ctrl+Enter など) と Space・変換・
  無変換・ファンクションキーは割り当てられる。
  config.tsv に書かれた読めない値・割り当てられないキーは無視する (1つも残らなければ既定のまま)
- 同じ状態で同じキーが複数の機能に割り当てられているときは、状態別の上書きを優先し、
  それでも重なれば上の表の順で先の機能が働く (設定ツールは重なりを保存しない)
- 変換に割り当てたキーは、Shift を足した打鍵にも一致する (候補選択中は前候補)。
  Shift を足した打鍵に別の機能を割り当てていれば、そちらが働く
- 入力なしの状態では、機能を実行できないとき (変換・F6〜F10: 後置再変換の対象 (選択か
  キャレット直前の記憶・かな) が無い、確定アンドゥ: 直前の確定が無い) は打鍵をアプリへ渡す
- 改行は、対象アプリ (`newline_apps`) でだけ働く。対象外のアプリでは状態によらず割当なしと
  同じ扱いになる
- 割当に一致しない打鍵は本来の処理に進む。たとえば候補選択中の Space の割当を外すと
  (`key.next_candidate@candidate\tnone`)、Space は確定してスペースを入れる

### 読める文書と追記のみの文書

IME は文書ごとに、自分が入れた文字列を読み戻せるかを run の2文字目以降の追記で確かめ、
次のどちらかとして扱う。

- 読める文書 (メモ帳・Word・Chrome など): 追記の前に run の文字列を照合し、キャレットが
  動いていれば run を捨てる。英字への切り替え・候補バーの採用は文書の文字列の
  置き換えで行う
- 追記のみの文書 (WezTerm などの CUAS 経由のアプリ): 照合せずに追記する。変換・英字への
  切り替え・候補バーの採用・確定アンドゥは、Backspace の擬似打鍵で run の文字列を
  消してから行う (押している修飾キーはその間だけ離して押し直す)。候補選択中の変換の範囲の
  伸縮は未確定文字列の中だけで行い、擬似打鍵は使わない (縮めて外したかなは未確定文字列の
  先頭に残り、確定時に候補と一緒に入る。確定アンドゥでは外したかなを含めた run 全体の読みに戻る)

追記のみの文書では文書を読み戻せない代わりに、キャレットが動きうる操作で run を終え、
確定アンドゥの記憶も捨てる: アプリに渡したキー (Enter・矢印・Ctrl 併用など)、
マウスのボタン・ホイール (実際にキャレットが動いたかは問わない)、フォーカス移動。
このため確定アンドゥは、Space・確定キーなどで run を終えた直後に使える (Enter はアプリに
渡すキーなので、Enter で確定した直後には使えない)。
どのキーで run を終えても、モードレス入力の run を終えたら成り立つ判定 (ルール3・6・7、下記) で
書き換えることはしない (候補バーの英字候補で選ぶ)。

### パネル保持入力 (input_buffer)

設定 `input_buffer` (`document` / `panel`、既定 `document`) を `panel` にすると (設定ツールの
「入力」タブの「入力中の読みを文書に書かず、候補パネルだけに表示する」)、入力中の読みを文書に
書かずに候補パネルの入力行だけに出し、採用・確定したときに初めてキャレット位置へ挿入する
(選択があれば置き換える)。打鍵ごとに文書が変わらないので、逐次検索する欄や文字数カウンタが
途中のかなに反応せず、アプリの元に戻す履歴にもかなが1文字ずつ積まれない。方式は run を始めた
時点の設定で決まり、run の途中で設定を変えてもその run が終わるまでは変わらない。

上記の入力方式と違うところ:

- 入力行は `panel_input`・テーマ・`candidate_bar` の設定によらず出す (`candidate_bar` 0 では
  入力行だけのパネル)。未完成のローマ字も入力行に出し、キャレット付近の小窓は出さない
- Backspace: 読みの末尾 (未完成のローマ字があればそれ) を削る。空になると run を終え、
  次の Backspace はアプリへ渡る
- Esc: run を捨てる (文書には何も入らない)。バーの選択中は選択の解除
- Space: 読み + スペースを挿入する (バー選択中は選んでいる候補 + スペース)
- 確定キー: 見えているとおりの読み (未完成のローマ字を含む) を挿入する。バー選択中は選んでいる
  候補を挿入し、先頭文節なら残りの読みで run を続ける
- Enter・矢印・Tab (バーが無いとき)・Home/End/Delete・PgUp/PgDn・Ctrl/Alt 併用: 読み (Enter の
  バー選択中は選んでいる候補) を挿入してからアプリへ渡す。読めると判定されていない文書では、
  キーをいったん止めて挿入の後に送り直す (Alt 併用は送り直さずに、挿入の後にそのまま渡す)
- 候補バーの採用: 採用した候補だけを挿入する (文書の文字列の置き換えも擬似打鍵も使わない)
- 変換キー・F4〜F10: キャレット位置に未確定文字列を出して候補選択に入り、確定すると文書に入る。
  取り消す (Esc・Backspace・Tab) と未確定文字列が消えて、読みが入力行に戻る。変換の範囲の伸縮は
  未確定文字列の中だけで行い、広げられるのは縮めて外したかなを戻すところまで。未確定文字列を
  出せない文書では変換できず、読みは入力行に残る
- 後置再変換 (run が無いときの変換キー・F6〜F10): 対象は上記と同じ。取り消すと元の文字列は
  文書に戻らず、その読みが入力行の run になる
- 確定アンドゥ: 直前に挿入した文字列を文書から消し、読みを入力行の run に戻す (読める文書では
  キャレット直前と照合して消し、それ以外は Backspace の擬似打鍵で消す)
- IME オフ: 読み (未完成のローマ字を含む) を挿入して run を終える。フォーカス移動: run を捨てる
  (元の文書には何も入らない)。マウスのクリック・キャレットの移動: run を続け、挿入するときの
  キャレット位置に入る
- 読める文書かどうかは、IME が直前に挿入した文字列を、次の run の始め・run が無いときの
  変換キーと F6〜F10・確定アンドゥの時点で読み戻して判定する。一致しなければ追記のみの文書とは
  せずに未判定のまま残し、追記のみの文書と同じく扱う (次に挿入したときにまた判定する)。
  後置再変換に使う記憶は未判定の文書でも覚え、読める文書と判定された後に照合して使う

## モードレス入力 (modeless)

設定 `modeless` (設定ツールの「モードレス入力」、既定 OFF) を ON にすると、英語の打鍵を
IME が自動で見分けてアルファベットのまま入れる。半角/全角キーで IME をオフにせずに
日本語と英語を混ぜて打てる (IME のオン/オフ自体はそのまま残る)。

判定が成立すると、run のうち英単語の部分だけを英字モードへ移す (英字区間)。英字区間に
入る部分の打鍵列をそのまま文字として並べ直し、それより前の日本語の部分 (日本語区間) は
そのまま残す (`kyouhagithu` → `きょうはgithu`、`apple` → `あっp` → `appl`)。

打鍵中の判定 (成立した時点で切り替える):

- ルール1: ローマ字として成立しない英小文字が現れた (英語特有の子音連続。`apple` の `pl`、`str`)
- ルール2: 促音の直後に小書き母音が来た (`hello` の `へっ` + `ぉ`)
- ルール4: `c` の直後に母音が来る綴り (`ca` `ci` `cu` `ce` `co`。`ch` は対象外) を含み、
  run の打鍵列が5文字以上になった。ローマ字テーブルに c 行のかな (`ca` = か など) を足して
  いるときだけ働く
- ルール5: `tha` `thu` `the` `tho` が完成した (`github` `the` `method`。外来語で使う
  `thi` は対象外)

ルール1・2 は英語でしかありえない綴りなので、英単語辞書に無い語でも英字にする (根拠の強い判定)。
ルール4・5 はローマ字として読める綴りなので、英単語辞書に一致したときだけ英字にする
(根拠の弱い判定)。一致しなければ日本語のまま入力を続け、その綴りを含む間は打鍵ごとに調べ直す。

既定のローマ字テーブルには c 行が無いので、`c` + 母音で始まる未変換ローマ字 (`ca` など。
`ch` のち行は除く) はルール1 に当たる。ただし、英単語の始まりを辞書で決められる長さになるまで
文書に入れずに小窓に保留し、4文字になった時点 (3文字で英単語に完全一致すればその時点) で
判定する。`kyouhacamera` は `kyouhaca` の間は文書が `きょうは`・小窓が `ca` で、`cam` が
英単語に一致して `きょうはcam` になる。4文字で一致しなければルール1 どおり run 全体を英字に
する (`kaicaku` → `kaicaku`)。保留中に run を終えると、小窓の文字はそのまま文書に入る。

ルール1 が成立しても英単語辞書に一致しないときは、未変換ローマ字が4文字になるまで英字にせず、
文書に入れずに小窓に保留する (英単語の3文字目までに読めない綴りが出る `python` の `pyt` で、
run 全体が英字になるのを避けるため)。保留中は打鍵ごとに辞書と照合し直し、一致すればその位置から
英字にする (`kyouhapyt` は文書が `きょうは`・小窓が `pyt`、`pyth` で `きょうはpyth`)。4文字で
一致しなければ run 全体を英字にする (`korehaxyzw` → `korehaxyzw`)。保留中に run を終えると、
小窓の文字はそのまま文書に入る (`kaisyast` → Space → `かいしゃst`)。

自動判定で英字になった後、判定のきっかけになった打鍵まで Backspace で消すと、判定前の日本語の
状態に戻る (`kyouhagithu` → Backspace → `きょうはぎ` + 小窓 `th`、`korehaxyzw` → Backspace →
`これは` + 小窓 `xyz`)。Shift+英字で入った英字区間は対象外。

run を終えたら成り立つ判定 (英字候補):

run を終えるときに英字へ書き換えることはせず、どのキーで終えても見えているとおりに確定する
(`kyouhawant` → Space → `きょうはわんt`)。代わりに、今 run を終えたら次の判定で英字になる形を、
打鍵中に候補バーの先頭に英字候補として出す (`min_suggest_chars` によらず出す)。Tab などで選んで
Space で採用すると英字と半角スペース、確定キー・Enter で採用すると英字で run を終え、
印字キーで採用すると英字区間に打鍵を続ける。候補バーが無効 (`candidate_bar 0`) のときは出ない。

- ルール3: 未変換ローマ字として `n` 以外の英小文字が1文字残っていて、その位置で英単語辞書と
  完全一致する (`kyouhawant` → 英字候補 `きょうはwant`)。辞書に一致しない語 (`watasihant`) は
  候補に出ない (F10 で直す)
- ルール6: 直前に確定した文字列の末尾 (スペースを除く) が ASCII 英字で、run 全体が
  ローマ字として読め、その打鍵列が英単語辞書の語と完全一致する (英文の途中の `pen`)。
  数字の後は英語の文脈にしない (`2026 nen` の `nen` は `ねん`)。英単語辞書に無い語は英字に
  しない (`Apple kensaku` の `kensaku` は `けんさく`)。助詞などと同じ形の語 (`no` `to` `ga`
  `wo` `ni` `de` `ha` `wa` `mo` `he` `ya` `ka` `yo` `ne`) は対象外 (`GitHub no` → `GitHub の`)。
  英文中の短い語も拾うので、下の長さの制限は当てない (`this is a pen.` の `is` `a`)。
  ただし1文字の語は `a` と `i` だけを英字にする (`Apple u` の `u` は `う`)
- ルール7: run の打鍵列の全体、または末尾 (5文字以上) が、ローマ字として読めるが日本語に
  ならず、日本語を打つ場面がほぼない英単語の一覧 (数十語。`remote` `feature` など) の語と
  一致する (`korehafeature` → `これはfeature`)

英字候補に出ない語を英字にしたいときは、確定前に F10 で英字にする (F10 の後の ←→ で英字にする
範囲を調整できる。`kyouhawant` → F10 → → を4回 → `きょうは` + `want`)。

英単語の始まり (英字区間の開始位置) は判定の種類で決まる:

- ルール7、Shift+英字: 一致した語・その打鍵の位置から
- ルール6: run 全体
- それ以外: エンジンの英単語辞書 (`english-words.txt`・`english-names.txt` と、ユーザ辞書の
  表記が英字だけの語) で、かなの区切りの前から順に「そこから後ろの打鍵列」が英単語に一致する
  最初の位置から。打鍵中の判定は前方一致、run を終えたら成り立つ判定は完全一致で調べる。
  一致とみなすのは、完全一致なら3文字以上、完全一致でない前方一致なら4文字以上のときだけ
  (ルール6 を除く)。
  どこでも一致しないときと、エンジンに接続していないときは、ルール1 は保留 (未変換ローマ字が
  4文字になったら run 全体を英字)、ルール2 は run 全体を英字にし、ルール3 は英字候補を出さず、
  根拠の弱い判定 (ルール4・5) は英字にしない

区間の境目が外れたときは、F10 (半角英字) / F6 (ひらがな) などで run 全体を直せる。

Backspace で英字区間を全部消せば解除され、日本語区間の末尾から日本語の入力を続けられる。

英字混じりの文 (英字区間を閉じて日本語に戻る):

- 英字区間で英字を打つたびに、英字区間の文字列 + 打った文字が英単語辞書のどの語の前方一致にも
  ならなくなったら、英字区間の先頭部分のうち英単語に完全一致する部分 (3文字以上) で英字区間を閉じ、
  残りと打った文字をローマ字で打ち直す。残りがローマ字として読めないときは閉じない
  (`kyouhagithubdesagyousuru` → `きょうはgithubでさぎょうする`、`pythonwotukau` → `pythonをつかう`)
- 閉じられる切れ目が複数あるときは、残りが子音で始まるものを優先し、その中で最も長いもので閉じる
  (Shift+`M` `akeru` → `Makeる`。`Maker` の間は英単語の前方一致なので英字のまま)
- 英単語の前方一致の間 (`apples`) と、英単語に一致する先頭部分が無い語 (`xyzwdesu`) は英字のまま。
  エンジンに接続していないときも閉じない
- 1つの run に英字区間が複数あってよい (`きょうはgithubでpythonをつかう`)
- Backspace で閉じた英字区間の直後まで消すと、その英字区間に戻る (`githubd` → Backspace → `s` で `githubs`)
- 英字区間と日本語区間の両方がある run の変換キーは、英字の部分を英単語1語のまま日本語の部分だけを
  変換する (`今日はgithubで作業する`)。この run では生ローマ字の候補は出さない
  (run 全体を英字にするときは F10)

英単語の大文字小文字の補正 (`github` → `GitHub`):

- 自動では書き換えず、候補として出す。正しい表記は、英単語辞書の固有名詞・技術用語
  (`english-names.txt`) とユーザ辞書の英字の語 (大文字を含む登録の表記。英単語辞書より優先) から引く。
  一般語 (`apple`、`may`) は補正しない
- 変換キー: 補正した表記の候補が上位、打ったとおりの候補がその下に出る
  (`kyouhagithubdesagyousuru` → `今日はGitHubで作業する`、`今日はgithubで作業する`)。
  打ったとおりの候補を選んで確定すれば、学習で次からそちらが上位になる
- 候補バー: 英字区間の入力中、英字区間を補正した形をバーの先頭に出す (`kyouhagithub` →
  `きょうはGitHub`)。採用の操作は英字候補と同じで、採用後も英字区間は続く
  (Tab → Space で `きょうはGitHub `、Tab → `s` で `きょうはGitHubs`)

日本語区間がある run (区間分割した run) の候補バー:

- 日本語区間が `min_suggest_chars` 文字以上なら出す。候補は日本語区間に対する全体変換と
  先頭文節で、予測候補は出さない。全体変換は英字区間を付けて表示する (`今日はgithub`)
- 採用すると日本語区間だけを置き換え、英字区間は run として続く
- 確定キー・Space・Enter では自動で採用しない (`kyouhagithub` → 確定キー → `きょうはgithub`)

`modeless` が ON のときの英字モード中 (自動判定・Shift+英字のどちらで入った場合も) のキー:

- Space: 設定 `space` が全角でも半角スペースを入れて run を終える。候補選択中は
  次候補ではなく、確定して半角スペースを入れる
- 変換キー: 候補選択に入る (run 全体が英字なら生ローマ字候補で `apple` / `Apple` / `APPLE` を選べる。
  `github` は `GitHub` が先頭)
- 記号は半角、Enter はアプリへ渡して run 終了

`modeless` が OFF のときは、Shift+英字で入った英字モードも従来どおり (Space は
設定 `space` の幅のスペース)。区間分割の扱い (Backspace での解除・候補バー・採用・確定キー) も
しない。

`modeless` が ON のとき、run が無いときの Space は、直前に確定した
文字列が ASCII 英数字だけなら半角、それ以外は設定 `space` に従う。

自動では判定しないもの (日本語を優先する):

- ローマ字として成立する英単語のうち、ルール6・7 に当たらないもの (`sake`、`name`、
  `date`、日本語の後の `pen` など)。
  変換キーの生ローマ字候補か、Shift+頭文字での英字モードで入れる
- 大文字始まり (Shift+英字で明示的に英字モードに入るため判定は不要)

打ち途中の日本語を確定したときは誤判定しうる (`かk` を Space で終えると `kak`)。

## 注意

IME の DLL は全アプリケーションのプロセスにロードされる。開発版の動作確認は
テスト用アプリで行い、Microsoft IME へいつでも切り替えられる状態を維持すること。
