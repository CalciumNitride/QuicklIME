# QuicklIME

Windows 用の自作日本語IME。通常のローマ字入力をベースに、変換の工夫による高速入力を目指す。

## 構成

| ディレクトリ | 内容 |
|---|---|
| `tsf/` | TSF テキストサービス (C++ / in-proc COM DLL)。フェーズ1で作成 |
| `engine/` | 変換エンジン (Rust / 常駐別プロセス) |
| `llm/` | LLM による候補の並べ替えの子プロセス (Rust / llama.cpp。エンジンが起動する) |
| `models/` | LLM のモデル (git管理外。`scripts/fetch-models.ps1` で取得) |
| `data/` | 設定ファイルのプリセット (AZIK 風ローマ字テーブルなど) |
| `docs/` | ドキュメント。開発計画は [docs/roadmap.md](docs/roadmap.md)、TSF-エンジン間プロトコルは [docs/protocol.md](docs/protocol.md) |
| `references/` | 参考用の外部リポジトリ (git管理外)。CorvusSKK、SampleIME |
| `scripts/` | 開発用スクリプト (`dev-deploy.ps1`: デバッグ反映、`cleanup-old-binaries.ps1`: 旧DLL/exeの掃除、`fetch-models.ps1`: LLM のモデルの取得、`build-llm.ps1`: LLM の子プロセスのビルド) |

## 開発環境

- Visual Studio 2022 (C++ によるデスクトップ開発ワークロード、Windows SDK 含む)
- Rust (stable-x86_64-pc-windows-msvc)
- Windows 11
- LLM の子プロセス (`llm/`) のビルドのみ: LLVM (`C:\Program Files\LLVM`)、Vulkan SDK
  (既定は `C:\VulkanSDK\1.4.363.0`)

## ビルド

- エンジン: `cd engine && cargo build`
  (quicklime-engine.exe 本体に加え、`src/bin/` の quicklime-config.exe /
  quicklime-regword.exe も一緒にビルドされる)
- エンジンのテスト: `cd engine && cargo test`
- エンジン単体の動作確認 (起動中のエンジンに接続して CONVERT/CONVSEG を試す):
  `cargo run --example query -- <読み> [<読み>...]`
- TSF層 (VS付属のCMakeを使用、64bit):
  ```
  cmake -S tsf -B tsf/build -G "Visual Studio 17 2022" -A x64
  cmake --build tsf/build --config Debug
  ```
  成果物: `tsf/build/Debug/QuicklIME.dll`
- LLM の子プロセス: `scripts\fetch-models.ps1` でモデルを `models\` に取得し (サイズと
  SHA-256 を確かめる)、`scripts\build-llm.ps1` で CPU 版 `quicklime-llm.exe` と Vulkan 版
  `quicklime-llm-vulkan.exe` を release ビルドする (成果物は `llm\target\release\`)。
  llama.cpp のビルドに要る環境変数 (LIBCLANG_PATH、CMake・Ninja、VULKAN_SDK、vcvars64) と、
  長いパスを避ける `subst` はスクリプトの中で設定する。エンジンの通常のビルドには要らない
- LLM の並べ替えの計測 (エンジンを隔離して起動し、llm_cases.tsv の左文脈で RERANK を送る):
  `cargo run --release --example nbest_eval -- --cases examples/data/llm_cases.tsv --llm cpu`
  (`--llm vulkan` で Vulkan 版)

## インストーラでの導入

`installer\build.ps1` を実行すると `installer\output\quicklime-<版>-setup.exe` が生成される
(前提: Inno Setup 6 = `winget install -e --id JRSoftware.InnoSetup`、references/mozc の辞書、
`scripts\build-llm.ps1` でビルドした LLM の exe、`scripts\fetch-models.ps1` で取得したモデル)。

- 配置先は `%ProgramFiles%\QuicklIME\` (64bit DLL + エンジン・設定・単語登録の exe +
  辞書 `dict\`)。32bit アプリ用の DLL は `x86\` に入り、両方が IME として登録される
- 初回インストールは再起動不要。更新時は DLL がロード中のため再起動を求められることがある
- アンインストールしてもユーザデータ (`%APPDATA%\QuicklIME\` の設定・ユーザ辞書・学習) は残る
- 同梱辞書は Mozc (BSD ライセンス) のもの。ライセンス文書 LICENSE-mozc.txt を同梱している
- LLM の子プロセス (quicklime-llm.exe・quicklime-llm-vulkan.exe) と、モデル (`models\` に
  zenz-v3.2-xsmall と zenz-v3.2-small) を同梱する。ライセンス文書 LICENSE-llama.cpp.txt (MIT)・
  LICENSE-zenz.txt (Apache License 2.0) を同梱している。LLM の子プロセスは VC++ ランタイムを
  動的にリンクするため、再頒布可能な DLL (msvcp140・vcruntime140・vcruntime140_1・vcomp140) を
  exe と同じディレクトリに置く (ビルド環境の Visual Studio の `VC\Redist\MSVC\<版>\x64` から取る)

登録後、Win+Space で「QuicklIME」を選択して使用する。

## 開発版 DLL の切替とインストール版の更新

`scripts\dev-deploy.ps1` でビルドから反映までをまとめて実行できる。

| コマンド | 動作 |
|---|---|
| `scripts\dev-deploy.ps1` | エンジンのみ反映 (release ビルド → 常用の Program Files へコピー) |
| `scripts\dev-deploy.ps1 -Dll` | エンジン反映に加え、TSF DLL を Debug ビルドして開発版へ切替 (要管理者権限) |
| `scripts\dev-deploy.ps1 -Dll -Install` | エンジン反映に加え、TSF DLL を Release ビルドして常用インストール版へ直接反映 (管理者権限・再起動とも不要) |
| `scripts\dev-deploy.ps1 -Restore` | DLL を開発版からインストール版へ戻す (要管理者権限) |

DLL の反映方法は用途で使い分ける。

- **`-Dll`** (開発版切替): `tsf\build\Debug\QuicklIME.dll` に regsvr32 で排他的に切り替える。
  常用インストール版には触れない。確認が終わったら `-Restore` で必ず戻すこと
- **`-Dll -Install`** (インストール版更新): 常用インストール版の DLL 自体を新しいビルドに
  差し替える。ロード中の DLL を `.old-<日時>` にリネーム退避してから同じパスに新 DLL を
  コピーするので、レジストリ再登録も PC 再起動も不要 (インストーラでの更新は
  ロード中だと `restartreplace` により再起動待ちになる)。32bit 版 (`x86\QuicklIME.dll`) も
  同じ手順で更新する (ビルドツリーは `tsf\build32`。未構成なら自動で生成する)

手動で行う場合 (開発版切替):

```
regsvr32 tsf\build\Debug\QuicklIME.dll      # 登録
regsvr32 /u tsf\build\Debug\QuicklIME.dll   # 解除
```

インストール版と開発版は同じ CLSID を共有し、後から regsvr32 (または再インストール) した
方に登録が切り替わる。開発を終えて常用へ戻すときは、インストーラを再実行するか
`regsvr32 "%ProgramFiles%\QuicklIME\QuicklIME.dll"` で戻す。

## ローマ字テーブルのカスタマイズ

`%APPDATA%\QuicklIME\romaji.tsv` (UTF-8) を置くと、既定のローマ字テーブルへ
追加・上書きされる。書式は 1行1エントリ「ローマ字<TAB>かな」。`#` 始まりの行は
コメント、かな欄が空の行は既定エントリの削除。反映は各アプリの再起動後。

AZIK 風拡張 (撥音拡張「かん」=kz、二重母音拡張「こう」=kp など) のプリセットを
[data/romaji-azik.tsv](data/romaji-azik.tsv) に用意している (インストール版では
`%ProgramFiles%\QuicklIME\presets\` にも同梱)。使う場合はこれを
`%APPDATA%\QuicklIME\romaji.tsv` へコピーする。

```powershell
# PowerShell の場合 (%APPDATA% は展開されないので $env:APPDATA を使う)
copy data\romaji-azik.tsv $env:APPDATA\QuicklIME\romaji.tsv
```

## 辞書インポート

他の IME からエクスポートしたユーザ辞書や、それらの形式で配布されている辞書
(ニコニコ大百科 IME 辞書・pixiv 辞書など) を取り込める。

使い方: 単語登録ツール (quicklime-regword.exe、Ctrl+F7) の「インポート...」ボタンで
ファイルを選ぶ。取り込んだ件数 (取り込み / 重複 / 未対応の品詞 / 不正な行) が表示され、
起動中のエンジンには即時反映される (エンジン未起動なら次回起動時に反映)。

| 形式 | 判別 | 備考 |
|---|---|---|
| MS-IME | 先頭行が `!Microsoft IME Dictionary Tool` | `!` 始まりの行はヘッダ |
| ATOK | 先頭行が `!!ATOK_TANGO_TEXT_HEADER_1` | `!` 始まりの行はヘッダ。品詞末尾の `$` `*` は無視 |
| Mozc / Google 日本語入力 | 上記以外 | `#` 始まりの行はコメント |

- 各行は `読み<TAB>語句<TAB>品詞[<TAB>...]`。文字コードは UTF-16 (BOM 付き)・UTF-8
  (BOM の有無を問わない)・Shift_JIS を自動判別する
- 読みのカタカナはひらがなに直す
- 取り込むのは名詞系と短縮よみのみ。品詞は次のように対応づけ、それ以外 (動詞・形容詞・
  副詞・数・サジェストのみ など) は「未対応の品詞」として読み飛ばす

  | 元の品詞 | 取り込み後 |
  |---|---|
  | 人名, 固有人他, 固有人名(姓名) | 人名 |
  | 姓, 固有人姓 | 姓 |
  | 名, 固有人名 | 名 |
  | 地名, 固有地名, 地名その他 | 地名 |
  | 組織, 固有組織, 社名 | 組織 |
  | 固有名詞, 固有一般, 固有商品, 物品, その他「固有」で始まる・「固有名詞」を含む品詞 | 固有名詞 |
  | 短縮よみ, 短縮読み, 顔文字, 記号 | 短縮よみ |
  | 上記以外で「名詞」を含む品詞 (普通名詞, さ変名詞, 名詞サ変, 形動名詞, 副詞的名詞 など) | 名詞 |

- ファイル内の重複 (読み・語句・取り込み後の品詞が同じ) と、ユーザ辞書 (userdict.tsv)・
  他のインポート済み辞書に既にある (読み, 語句) は「重複」として読み飛ばす
- 取り込んだ辞書は `%APPDATA%\QuicklIME\imported\<元ファイル名から拡張子を除いた名前>.tsv`
  に 1 辞書 1 ファイルで保存される (書式は `読み<TAB>表記<TAB>品詞`、UTF-8)。
  同じ名前のファイルを取り込み直すと上書きする (配布辞書の更新用)。
  取り込める語が無かった場合はファイルを作らない
- 辞書を外すにはそのファイルを削除する。反映はエンジンの再起動時、または
  単語登録ツールでの次回のインポート時
- インポートした語は変換 (文中を含む)・予測・F5 のユーザ辞書変換に出る。
  変換候補での優先度は手動登録より低く、一般的な名詞と同程度。予測では手動登録・
  確定履歴より後に、同梱辞書の語とコスト順に混ざって出る。
  手動登録と同じ (読み, 表記) の語は手動登録側が優先される
- 保存先ディレクトリは環境変数 `QUICKLIME_IMPORT_DIR` で変更できる
  (エンジン・単語登録ツール共通。動作検証時の隔離用)

## 入力方式

打鍵した文字は、未確定文字列 (下線付きの composition) を使わずに文書へ直接入る。
IME は自分が入れた文字列とその読み (run) を覚えておき、変換は変換キーで後から行う
(後置変換)。かなは完成した時点で文書に追記し、未完成のローマ字 (`k`、`ky` など) は
文書に入れずにキャレット付近の小窓に出す。未確定文字列の挙動が不安定な Web フォーム
(文字数固定・自動で次欄へ移動する欄など) でも、ターミナルなどの文書を読み戻せない
アプリでも同じ方式で動く。

キー操作 (IME オン時。変換キー・無変換キー・F4〜F10 などは既定の割当で、
下記「キー割当」で変えられる):

- 英字・記号・数字: run を始める / 読みに追加し、かなが完成したら文書に追記する
  (下線は付かない)。Backspace は、未完成のローマ字があればそれを削り、無ければ文書の
  末尾の1文字を消して読みからも削る (空になれば run 終了)
- 変換キー: run 中は変換開始。候補選択中は次候補 (Shift+変換キー で前候補)。
  候補は入力中のかな全体を1単位にした変換結果 (区切りの違う「今日は医者に行った」
  「今日歯医者に行った」などが並ぶ) で、縦の候補ウィンドウから1つ選ぶ。英字を含む入力は
  全体を1語として変換する (打鍵したローマ字の apple / Apple / APPLE も選べる)。
  変換中 (候補選択中) だけは run を未確定文字列 (composition) に切り替え、下線と
  変換対象の強調を表示する。候補選択中は Space で次候補、Shift+Space で前候補、
  ↑↓・数字 1〜9・F4〜F10 (入力全体にかかる) も使える。run 中の F4〜F10 も
  同様に未確定文字列に切り替えて働く。未確定文字列にできない文書では、変換対象を
  選択状態にして強調する (どちらの文書でもキーの挙動は同じ)
- 文節単位の変換: 設定 `segment_ui` (設定ツールの「文節単位で変換する」、既定 0) を 1 にすると、
  候補選択を文節ごとに行う。候補選択中の ←→ で文節の移動、Shift+←→ で文節の伸縮、
  PgUp/PgDn で先頭 / 末尾の文節へ移動し、候補は現在の文節のものになる
- 候補選択中の Enter: 確定してから Enter をアプリへ渡す (1打で確定と改行・送信)。
  Esc・Backspace: 変換前のかなに戻し、下線の無い run に戻る。英字などの印字キー:
  確定して新しい run を始める。Tab: 変換を取り消して候補バーの先頭を選ぶ。
  Home・End・Delete (`segment_ui` 0 では ←→・Shift+←→・PgUp/PgDn も): 確定してから
  アプリへ渡す
- 確定キー (無変換キー): run 中は候補バーの全体変換 (1件目) を採用して run を終える。全体変換が
  無いときはかなのまま run を終える (末尾の未完成のローマ字は Enter で終えたときと同じく
  文書に残る)。候補選択中は確定、バーで候補を選んでいるときはその候補を採用する。
  キーはアプリへ渡さない (改行は入らない)
- 後置再変換: run が無いときに、ひらがな・カタカナ・ー だけの文字列を選択して変換キーを
  押すと、それを読みとして候補選択に入る (漢字を含む選択では何も起きない)
- 候補バー: 入力中はキャレット行の下に変換結果と予測候補を横一列に出す (下記「候補バー」)
- Space: スペース (設定 `space` に従う)。run 中は run を終えてからスペースを入れる
  (バーで候補を選んでいるときは採用してからスペースを入れる)
- Enter・Esc・矢印・Tab・Home/End・PgUp/PgDn (候補選択・バー選択以外): run をかなのまま
  終える (Esc 以外はアプリに渡す。Esc は文字を消さず run を忘れるだけ)。未完成のローマ字は
  そのまま文書に残る。候補バーが出ている間の Tab・↑↓ はバーの選択に使う
- Ctrl+Backspace (確定アンドゥ): run 終了後に、直前の run を読みのかなに戻して再開する
  (変換結果もかなに戻る)
- run の終了時・候補バーの採用時は学習 (候補選択の文節ごと・採用した候補) と文脈の更新を行う。
  2文節以上の変換結果を確定・採用したときは読み全体の表記も学習し、次に同じ読みを打つと
  その表記が変換候補の先頭に来る (予測候補にも出る)
- フォーカス移動・IME オフ・キャレット移動でも run は終わる (未完成のローマ字は捨てる)

### 候補バー

入力中は、キャレット行のすぐ下 (入らなければ上) に候補を横一列に出す。文書の文字列は
候補を採用したときだけ書き換わり、選んでいる間や採用せずに run を終えたときは
かなのまま変わらない。

- 候補は次の順に最大9件並び、各候補の前に番号 1〜9 が付く。表記が同じ候補は前のものだけ残す
  - 全体変換: 入力中のかな全体の変換結果の上位 (最大3件。かなと同じ表記は出さない)
  - 予測候補: 入力中のかなで始まる語・確定履歴
  - 先頭文節: 変換結果の上位から集めた第1文節 (区切りや表記の違うものを最大3件。2文節以上の
    変換結果から取る)。末尾に「…」が付く
- 未完成のローマ字 (小窓に出ている `k` など) は候補の対象外。確定済みのかなが
  `min_suggest_chars` 文字以上のときに出す。候補選択中・モードレスの英字モード中・
  エンジン未接続のときは出さない
- バーの横位置は run で最初に出した位置に固定する。画面の作業領域の右端に収まらない
  後ろの候補は出さない (選択もできない)
- 選択: Tab / ↓ で右へ、Shift+Tab / ↑ で左へ (未選択から Tab で先頭、先頭で Shift+Tab で
  未選択に戻る)。数字 1〜9 で番号の候補を選ぶ。Esc で選択解除。選んでも文書は変わらない
- 採用:

  | 操作 | 未選択 | 選択中 |
  |---|---|---|
  | 確定キー (無変換キー) | 全体変換を採用して run を終える | 選んでいる候補を採用する |
  | Enter | かなのまま run を終えて Enter を渡す | 採用して run を終え、Enter を渡す |
  | 印字キー | (打鍵を続ける) | 採用し、その打鍵から続ける |
  | Space | かなのまま run を終えてスペース | 採用して run を終え、スペース |

- 全体変換・予測候補を採用すると、入力中のかな全体が候補に置き換わる。先頭文節を
  採用すると、その文節の読みの部分だけが置き換わり、残りのかなは入力中のまま続く
  (確定キーで採用したときも続く)。バーは採用した文節を前の文脈にして作り直される
- 採用した部分は以後 IME が書き換えない。確定アンドゥ (Ctrl+Backspace) は run を終えた
  後にだけ働き、最後に採用した部分 (または終えたときのかな) を読みに戻す
- 設定: `candidate_bar` (設定ツールの「候補バーを表示する」、既定 1)。0 にするとバーを
  出さず、run 中の Tab・↑↓ はアプリへ渡り (run を終える)、確定キーはかなのまま run を
  終える。`min_suggest_chars` (設定ツールの「サジェスト開始文字数」、1〜5、既定 2) で
  バーを出す文字数を変えられる。`suggest` (「入力中にサジェストを表示する」) を 0 にすると
  予測候補だけが出なくなる (全体変換・先頭文節は出る)

### AI による候補の並べ替え

設定 `llm` (設定ツールの「AI で候補を並べ替える」、既定 0) を 1 にすると、候補バーと変換キーの
候補 (入力全体の変換結果) を、かな漢字変換モデル (zenz) で文脈に合う順に並べ替える。

- 候補バーは、まず統計変換の並びで出し、並べ替えの結果が出たら (多くは数十 ms 以内) 作り直す。
  打鍵は待たない。バーの候補を選んでいる間・候補選択中は並びを変えない
- 変換キーを押した時点で並べ替えの結果が出ていれば、縦の候補リストもその並びになる
- 文脈は入力を始めた位置より前の、同じ行の文字列 (読める文書は文書から読み、ターミナルなどの
  追記のみの文書は IME が入れた文字列を覚えて使う。Enter・キャレット移動・フォーカス移動などで
  捨てる)。文脈はメモリ上だけで使い、ログやファイルには書かない
- 並べ替えるのは変換結果の上位 10 件。読み全体を学習した表記・学習で表記が変わった変換結果・
  ユーザ辞書の語を含む候補・英字を含む候補は位置を動かさない
- `llm_backend` (設定ツールの「AI の実行環境」) で、`cpu` (既定。zenz-v3.2-xsmall) か
  `vulkan` (GPU。zenz-v3.2-small) を選ぶ。Vulkan 版が動かない環境では CPU 版で動く
- 推論はエンジンが起動する別プロセス (quicklime-llm.exe / quicklime-llm-vulkan.exe) で行う。
  子プロセスは起動時にモデルの読み込みと試しの推論を済ませ、それまでは統計変換の並びで動く。
  応答が 2 秒を超えた依頼は統計変換の並びのままにする (子プロセスは止めずに応答を待ち、その間の
  依頼も統計変換の並びにする)。60 秒応答しない・終了したときは 10 秒後に起動し直し、続けて3回
  失敗したら設定を保存し直す (読み直す) まで使わない。その間も統計変換だけで入力できる
- エンジンは子プロセスの exe を自分と同じディレクトリ → 開発レイアウトの `llm\target\release\`、
  モデルを環境変数 `QUICKLIME_LLM_MODEL_DIR` → 自分と同じディレクトリの `models\` → 開発レイアウトの
  リポジトリ直下の `models\` の順で探す

### キー割当

機能ごとのキー割当は、設定ツールの「キー割当」(機能の一覧から「編集」) か config.tsv で
変えられる。1つの機能に複数のキーを割り当てられ、状態ごとに割当を上書きできる。

| 機能 | 設定キー | 働く状態 | 既定 |
|---|---|---|---|
| 変換 | `key.convert` | 全状態 | `Convert` |
| 次候補 | `key.next_candidate` | 候補選択中 | `Space` |
| 前候補 | `key.prev_candidate` | 候補選択中 | `Shift+Space` |
| 確定 | `key.commit_run` | run 中・候補選択中・サジェスト選択中 | `NonConvert` |
| 記号・日付変換 | `key.convert_symbol` | 同上 | `F4` |
| ユーザ語変換 | `key.convert_user` | 同上 | `F5` |
| ひらがな変換 | `key.to_hiragana` | 同上 | `F6` |
| カタカナ変換 | `key.to_katakana` | 同上 | `F7` |
| 半角カタカナ変換 | `key.to_half_katakana` | 同上 | `F8` |
| 全角英字変換 | `key.to_full_ascii` | 同上 | `F9` |
| 半角英字変換 | `key.to_half_ascii` | 同上 | `F10` |
| 確定アンドゥ | `key.undo_commit` | 入力なし | `Ctrl+Backspace` |
| 単語登録 | `key.register_word` | 入力なし | `Ctrl+F7` |
| 設定を開く | `key.open_config` | 入力なし | `Ctrl+F12` |

- 状態: 入力なし (`idle`、run が無い)、run 中 (`run`)、候補選択中 (`candidate`)、
  サジェスト選択中 (`suggest`、候補バーで候補を選んでいる)
- 書式: `key.<機能>\t<キー>[,<キー>...]` が基本の割当、`key.<機能>@<状態>\t<キー>[,...]` が
  状態別の上書き (その機能が働く状態にだけ書ける。上書きした状態では基本の割当を使わない)。
  値 `none` は割当なし。例: `key.convert\tConvert,Ctrl+Space`、
  `key.commit_run@candidate\tCtrl+Enter`
- キーの表記: 修飾キー `Ctrl+`・`Shift+` を前置し、キー名を続ける。キー名は
  `A`〜`Z`・`0`〜`9`・`F1`〜`F24`・`Space`・`Enter`・`Esc`・`Tab`・`Backspace`・`Delete`・
  `Insert`・`Home`・`End`・`PageUp`・`PageDown`・`Up`・`Down`・`Left`・`Right`・
  `Convert` (変換)・`NonConvert` (無変換)・`Kana` (カタカナ/ひらがな)、それ以外は
  `VK_xx` (16進2桁の仮想キーコード)
- 割り当てられないキー: Enter・Esc・Tab・Backspace・Delete・矢印・Home・End・PgUp・PgDn の
  無修飾と Shift 併用、Ctrl+M・Ctrl+H、英字・数字・記号・テンキーの無修飾と Shift 併用、
  IME の切替キー (半角/全角など)、修飾キー単体、Alt 併用 (アプリによっては IME に
  届かないため)、Win キー併用。Ctrl 併用のコア操作 (Ctrl+Enter など) と Space・変換・
  無変換・ファンクションキーは割り当てられる。
  config.tsv に書かれた読めない値・割り当てられないキーは無視する (1つも残らなければ既定のまま)
- 同じ状態で同じキーが複数の機能に割り当てられているときは、状態別の上書きを優先し、
  それでも重なれば上の表の順で先の機能が働く (設定ツールは重なりを保存しない)
- 変換に割り当てたキーは、Shift を足した打鍵にも一致する (候補選択中は前候補)。
  Shift を足した打鍵に別の機能を割り当てていれば、そちらが働く
- 入力なしの状態では、機能を実行できないとき (変換: 後置再変換できる選択が無い、
  確定アンドゥ: 直前の確定が無い) は打鍵をアプリへ渡す
- 割当に一致しない打鍵は本来の処理に進む。たとえば候補選択中の Space の割当を外すと
  (`key.next_candidate@candidate\tnone`)、Space は確定してスペースを入れる

### 読める文書と追記のみの文書

IME は文書ごとに、自分が入れた文字列を読み戻せるかを run の2文字目以降の追記で確かめ、
次のどちらかとして扱う。

- 読める文書 (メモ帳・Word・Chrome など): 追記の前に run の文字列を照合し、キャレットが
  動いていれば run を捨てる。英字への切り替え・候補バーの採用は文書の文字列の
  置き換えで行う
- 追記のみの文書 (WezTerm などの CUAS 経由のアプリ): 照合せずに追記する。変換・英字への
  切り替え・候補バーの採用・確定アンドゥは、Backspace の擬似打鍵で run の文字列を
  消してから行う (押している修飾キーはその間だけ離して押し直す)

追記のみの文書では文書を読み戻せない代わりに、キャレットが動きうる操作で run を終え、
確定アンドゥの記憶も捨てる: アプリに渡したキー (Enter・矢印・Ctrl 併用など)、
マウスのボタン・ホイール (実際にキャレットが動いたかは問わない)、フォーカス移動。
このため確定アンドゥは、Space・確定キーなどで run を終えた直後に使える (Enter はアプリに
渡すキーなので、Enter で確定した直後には使えない)。
アプリに渡すキーで run を終えるときは、モードレス入力の判定ルール3 (下記) は働かない。

## モードレス入力 (modeless)

設定 `modeless` (設定ツールの「モードレス入力」、既定 OFF) を ON にすると、英語の打鍵を
IME が自動で見分けてアルファベットのまま入れる。半角/全角キーで IME をオフにせずに
日本語と英語を混ぜて打てる (IME のオン/オフ自体はそのまま残る)。

判定は打鍵ごとに行い、次のいずれかが成立した時点でその run を英字モードへ
移す。移るときはそれまでの打鍵列をそのまま文字として並べ直す (`あっp` → `appl`)。

- ローマ字として成立しない英小文字が現れた (英語特有の子音連続。`apple` の `pl`、`str`、`th`)
- 促音の直後に小書き母音が来た (`hello` の `へっ` + `ぉ`)
- 無変換のまま Space で終えるとき (読める文書では Enter・矢印・確定キーなどで終えるときも)、
  未変換ローマ字として `n` 以外の英小文字が1文字残っている (`わんt` を Space で終えると
  `want`)。この判定は表示も英字へ直せる場面だけで働き、フォーカス移動・IME オフでの
  終了では `わんt` のまま確定される

英字モードに入った run は日本語には戻らない。Backspace で全部消せば解除され、
次の入力は日本語から始まる。

`modeless` が ON のときの英字モード中 (自動判定・Shift+英字のどちらで入った場合も) のキー:

- Space: 設定 `space` が全角でも半角スペースを入れて run を終える。候補選択中は
  次候補ではなく、確定して半角スペースを入れる
- 変換キー: 候補選択に入る (生ローマ字候補で `apple` / `Apple` / `APPLE` を選べる)
- 記号は半角、Enter はアプリへ渡して run 終了

`modeless` が OFF のときは、Shift+英字で入った英字モードも従来どおり (Space は
設定 `space` の幅のスペース)。

`modeless` が ON のとき、run が無いときの Space は、直前に確定した
文字列が ASCII 英数字だけなら半角、それ以外は設定 `space` に従う。

自動では判定しないもの (日本語を優先する):

- ローマ字として成立する英単語 (`sake`、`name`、`date`、`pen` など)。
  変換キーの生ローマ字候補か、Shift+頭文字での英字モードで入れる
- 大文字始まり (Shift+英字で明示的に英字モードに入るため判定は不要)

打ち途中の日本語を確定したときは誤判定しうる (`かk` を Space で終えると `kak`)。

## 注意

IME の DLL は全アプリケーションのプロセスにロードされる。開発版の動作確認は
テスト用アプリで行い、Microsoft IME へいつでも切り替えられる状態を維持すること。
