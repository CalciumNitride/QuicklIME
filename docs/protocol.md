# TSF層 - エンジン間プロトコル

作成日: 2026-07-13 (フェーズ3)

## トランスポート

- named pipe: `\\.\pipe\quicklime-engine`
- エンジン (quicklime-engine.exe) がサーバ、各アプリにロードされた TSF DLL がクライアント
- 接続は複数同時に成立する (アプリごとに1本)
- TSF 側はエンジンに接続できない場合、フォールバック (ひらがな1候補のみ) で動作を継続する

## メッセージ形式

- 1リクエスト = 1行 (LF 終端)、UTF-8、フィールドはタブ区切り
- 1リクエストに対して必ず1行のレスポンスを返す

### CONVERT: かなを全文一括の変換候補リストへ

```
要求:   CONVERT\t<かな>\n
成功:   OK\t<候補1>\t<候補2>\t...\n
失敗:   ERR\t<メッセージ>\n
```

候補の並び: [Viterbi による文変換] → [短縮よみ (ユーザ辞書、読み完全一致)] →
[読み全体の辞書完全一致 (コスト順)] → カタカナ → ひらがな。
短縮よみは手動登録 → インポート辞書の順。辞書完全一致にはシステム辞書・ユーザ登録の
名詞系・インポート辞書の名詞系がコスト順で混ざる (以下の変換系コマンドも同じ)。

### CONVSEG: かなを文節列へ (フェーズ4-3)

```
要求:   CONVSEG\t<かな>\n
成功:   OK\t<文節1>\t<文節2>\t...\n
失敗:   ERR\t<メッセージ>\n

文節 = <読み>\x1f<候補1>\x1f<候補2>...  (\x1f = ASCII Unit Separator)
```

- 文節は Viterbi 最小コスト経路を品詞で区切ったもの (付属語は前の自立語に付く)
- 各文節の候補は [経路上の表記] → [短縮よみ (ユーザ辞書、文節読み完全一致)] →
  [文節読みの辞書候補 (コスト順)] → カタカナ → ひらがな
- 学習済みの表記がある文節では、その表記が候補の先頭に移動する (短縮よみより優先)

### CONVCTX: 前文脈付きの文節変換 (文脈補正)

```
要求:   CONVCTX\t<文脈読み>\x1f<文脈表記>\t<かな>[\t<文節長カンマ区切り>]\n
成功:   OK\t<文節1>\t<文節2>\t...\n   (CONVSEG と同一形式)
失敗:   ERR\t<メッセージ>\n
```

- 前文脈 = 直前に確定した文節の (読み, 表記)。TSF 層が確定時に覚えておき、
  続けて変換するときに送る
- エンジンは前文脈から直前語の文脈ID (right_id) を復元し、Viterbi の文頭の
  連接コストに使う (確定をまたいでも「を」の後に名詞が出やすい、など)。
  復元できない前文脈は無視され、CONVSEG と同じ結果になる
- 文脈読み・文脈表記のどちらかが空の場合も前文脈なしとして扱う (CONVSEG と同じ)
- 文脈読み・文脈表記は末尾 64 文字に切り詰めて解釈する
- 文節長フィールドの意味は CONVSEG と同じ

### CONVNBEST: 入力全体の候補 (N-best)

```
要求:   CONVNBEST\t<文脈読み>\x1f<文脈表記>\t<かな>\n   (前文脈なしは文脈フィールドを空にする)
成功:   OK\t<候補1>\t<候補2>\t...\n
失敗:   ERR\t<メッセージ>\n   (かなの欠落時のみ)

候補 = <読み>\x1f<表記>\x1e<読み>\x1f<表記>...  (文節ごと。\x1e = ASCII Record Separator)
```

- かな全体を1単位とした候補を返す。候補の表記は文節の表記を連結したもので、
  TSF 層は文節の (読み, 表記) を確定時の学習に使う
- 候補の並び (表記が同じ候補は先勝ちで除く):
  1. 読み全体の学習表記 (読み全体の1文節)
  2. 文節ごとの学習を当てた 1-best (CONVCTX の各文節の先頭候補の連結。文節は CONVCTX と同じ)
  3. N-best の残り (経路のコスト順。文節は経路を CONVSEG と同じ規則で区切ったもの)
  4. 短縮よみ・読み全体の辞書完全一致 (CONVERT と同じ並び。最大 24 件。読み全体の1文節)
  5. 記号・カタカナ・ひらがな (読み全体の1文節)
- N-best は、前向きの Viterbi の後に文末から A* 探索して経路をコスト順に取り出す
  (ラティス・連接コスト・文節境界ペナルティ・境界学習は CONVSEG と同じ。文節ごとの学習は当てない)。
  コストが 1-best + 5000 を超えるか、取り出した部分経路が 3000 に達したら探索を打ち切る。
  表記の連結が同じ経路は1件にまとめ、1-best に無い文節 (開始位置・読み・表記) の
  (開始位置, 読み) の並びが同じ候補は、(1-best に無い単語の数, コスト) の順に並べ直して
  4件までにする (分類どうしの並びはコスト順のまま)。N-best は最大10件
- 前文脈の扱い (空なら無し、末尾 64 文字に切り詰める、文頭の文脈IDの復元) は CONVCTX と同じ
- 旧エンジン (CONVNBEST 未対応) は「不明なコマンド」を返す。TSF 層はそのとき CONVCTX /
  CONVSEG の各文節の先頭候補を連結した1件で代用する

### CONVSYM: 特殊変換の候補取得 (F4 用)

```
要求:   CONVSYM\t<かな>\n
成功:   OK\t<候補1>\t<候補2>\t...\n   (該当なしなら OK のみ)
失敗:   ERR\t<メッセージ>\n
```

- 読みに対応する記号辞書 (symbol.tsv) のエントリ (記載順) と、
  日付・時刻の動的候補をこの順で返す
- 日付・時刻の動的候補: 読みが「きょう」「あした (あす)」「あさって」「きのう」
  「おととい」「ことし」「らいねん」「きょねん」「いま」のとき、エンジンの
  現在日時から作った表記 (2026/07/15、7月15日(水)、令和8年7月15日、14:30 など)
- 通常語・カタカナ・ひらがな候補は含めない
- 該当する候補が無い読みはエラーにせず、候補ゼロの OK を返す

### CONVUSER: ユーザ辞書変換の候補取得 (F5 用)

```
要求:   CONVUSER\t<かな>\n
成功:   OK\t<候補1>\t<候補2>\t...\n   (該当なしなら OK のみ)
失敗:   ERR\t<メッセージ>\n
```

- 読みに完全一致するユーザ登録語 (短縮よみ → 名詞系 → インポート辞書の名詞系) の表記のみを返す。
  短縮よみは手動登録 → インポート辞書の順。手動登録と同じ表記は1回だけ
- 通常語・記号・カタカナ・ひらがな候補は含めない
- 該当する候補が無い読みはエラーにせず、候補ゼロの OK を返す

### PREDICT: 予測入力の候補取得 (フェーズ4-11)

```
要求:   PREDICT\t<かな>\n
成功:   OK\t<読み>\x1f<表記>\t<読み>\x1f<表記>...\n   (候補なしは OK のみ)
失敗:   ERR\t<メッセージ>\n   (かなの欠落時のみ)
```

- 読みが <かな> で始まる候補を、ユーザ辞書 (短縮よみ → 名詞系、記載順) →
  確定履歴 (新しい順) → システム辞書とインポート辞書の名詞系 (両者を混ぜてコスト順。
  同コストはシステム辞書が先) の順で最大8件 (設定
  max_predictions で 1-8 に変更可) 返す。
  表記の重複は先勝ちで除き、表記が入力かなそのままの候補は除外する
- 完全一致で最大数に満たない場合、読み3文字以上ならタイプミス補正の曖昧一致
  (1かな置換・隣接かな入れ替え・1かな脱落/余分。先頭かなは対象外) の候補を
  コスト順で末尾に補充する (フェーズ4-15。設定 typo_correction で無効化可)
- 各候補は「読み\x1f表記」のペア。読みは入力の接頭辞ではなく候補の完全な読みで、
  TSF 層が採用時の LEARN にそのまま使う
- かなが2文字 (設定 min_suggest_chars で 1-5 に変更可) 未満・該当なし・
  サジェスト無効 (設定 suggest=0) はエラーにせず、候補ゼロの OK を返す

### LEARN: 確定結果の学習 (フェーズ4-4)

```
要求:   LEARN\t<読み>\x1f<表記>\t<読み>\x1f<表記>...\n
成功:   OK\n
失敗:   ERR\t<メッセージ>\n
```

- TSF 層が変換確定時に、文節ごとの (読み, 選択した表記) を送る
- エンジンは「読み → 最後に確定した表記」として記録し、
  %APPDATA%\QuicklIME\learning.tsv に追記保存する (QUICKLIME_LEARN_FILE で上書き可)
- 例外: 日付・時刻の動的候補と一致する表記は記録しない
  (時間が経つと古くなり、翌日以降も昨日の日付が先頭に来てしまうため)
- 学習が無効 (設定 learning=0) のときは記録せず OK を返す
  (既存の学習データは引き続き候補順の調整に使う)

### LEARN2: 前文脈付きの学習 (文脈学習)

```
要求:   LEARN2\t<読み>\x1f<表記>\x1f<文脈表記>\t...\n   (文脈表記は空でもよい)
成功:   OK\n
失敗:   ERR\t<メッセージ>\n
```

- LEARN の拡張。各文節の第3フィールドに「直前文節の表記」を付ける
  (先頭文節は直前に確定した文節の表記、2文節目以降は1つ前の文節で選んだ表記)
- エンジンは従来の「読み → 表記」に加えて「(文脈表記, 読み) → 表記」を記録し、
  %APPDATA%\QuicklIME\learning_context.tsv (文脈\t読み\t表記) に追記保存する。
  文脈表記はキー化の際に末尾 16 文字へ切り詰める
- CONVCTX / CONVSEG の候補順では、前文脈に一致する文脈学習が
  文脈なしの学習よりさらに優先される (文脈一致学習 > 文脈なし学習 > 経路表記 > ...)
- 文脈表記が空の文節は LEARN と同じ扱い (文脈なし学習のみ記録)
- 2文節以上を確定・採用したとき、TSF 層は文節ごとの組に加えて「読み全体 → 表記の連結」を
  文脈表記を空にして同じ要求に入れる。CONVNBEST の先頭 (読み全体の学習表記) に使われ、
  確定履歴として PREDICT の前方一致にも出る
- 日付・時刻の動的候補の除外、学習無効 (learning=0) の挙動は LEARN と同じ

### LEARNSEG: 文節境界の学習

```
要求:   LEARNSEG\t<読み>\t<読み>...\n
成功:   OK\n
失敗:   ERR\t<メッセージ>\n
```

- TSF 層が文節伸縮 (Shift+←→) で区切りの位置を動かしたまま確定したときだけ、
  確定した全文節の読みを送る。既定の分割のまま確定したものは送らない
  (人が直していない区切りまで境界として強化してしまうため)。
  区切りの位置は動かさずに1文節を割った・複数文節をまとめただけのときは、
  区切り直しではなく複合語の入力とみなして LEARNWORD を送る
- エンジンは受け取った読みを文節境界として記録し、
  %APPDATA%\QuicklIME\learning_boundary.tsv (1行1読み) に追記保存する
  (QUICKLIME_LEARN_FILE で学習ファイルを差し替えたときは同じディレクトリに対で作られる)
- 2文字未満の読みは記録しない (1文字の付属語を境界にすると、どこでも切れる方向に効くため)
- CONVSEG / CONVCTX の文節分割では、学習済み境界と一致する区間について Viterbi の
  文節境界ペナルティを開始位置で下げ、区間の内部で上げる。部分一致で効くため、
  読み全体を毎打鍵で変換し直すライブ変換でも入力途中から分割が安定する
- 文節長を指定した変換 (CONVSEG の文節長フィールド) では境界学習を使わない
  (指定された区切りを動かしてはいけないため)
- 学習が無効 (設定 learning=0) のときは記録せず OK を返す

### LEARNWORD: 分割して確定した複合語の学習

```
要求:   LEARNWORD\t<読み>\x1f<表記>\t...\n
成功:   OK\n
失敗:   ERR\t<メッセージ>\n
```

- 入力したい語が候補に無く、文節伸縮で割って (まとめて) 入力したときに、
  TSF 層がその範囲の連結した読みと表記を送る
  (伸縮の前後で区切りの位置が動いていないときだけ。動いていれば LEARNSEG)
- エンジンは名詞相当の1語として記録し、
  %APPDATA%\QuicklIME\learning_word.tsv (読み\t表記) へ追記保存する
  (QUICKLIME_LEARN_FILE で学習ファイルを差し替えたときは同じディレクトリに対で作られる)。
  手動登録 (userdict.tsv) とは別ファイルにして、誤学習だけを捨てられるようにしている
- 記録した語は Viterbi のラティスにノードとして載るが、単語コストは手動登録より
  ずっと高い。辞書語の組み合わせで経路が作れる読み (「けいしょうか」= 継承+化) は
  そのままにし、未知語まじりの経路しか無い読み (「まいぐらふぃ」) だけ1文節にまとまる。
  前者をはじめから1語に置き換えると、先頭語を入れ替えた候補 (継承化・敬称化…) が
  候補リストから消えてしまうため
- 同時に LEARN と同じ「読み → 表記」も記録する。候補の並びはこちらが受け持つ
- 同じ読みの古い学習は置き換える (追記ログの後の行が勝つ)
- 2文字未満の読みと、表記が読みのままの語は記録しない
- 日付・時刻の動的候補の除外、学習無効 (learning=0) の振る舞いは LEARN と同じ

### ADDWORD: ユーザ辞書への単語登録 (単語登録ツール用)

```
要求:   ADDWORD\t<読み>\t<表記>\t<品詞>\n
成功:   OK\n
失敗:   ERR\t<メッセージ>\n   (引数不足・未対応の品詞・登録済み)
```

- ユーザ辞書ファイル (userdict.tsv) へ「読み\t表記\t品詞」を追記し、
  メモリへも即時反映する (エンジンの再起動なしで変換・予測に効く)
- 品詞は「短縮よみ」と名詞系 (名詞/固有名詞/人名/姓/名/地名/組織) に対応する。
  名詞系は id.def から文脈IDを解決し、Viterbi のラティスに通常語として載る
- 同じ (読み, 表記) の登録済みエントリがあればエラーを返す

### RELOADUSER: ユーザ辞書の再読込

```
要求:   RELOADUSER\n
成功:   OK\n
```

- userdict.tsv と、インポート辞書 (%APPDATA%\QuicklIME\imported\*.tsv。
  QUICKLIME_IMPORT_DIR で上書き可) をすべて読み直す
  (手動編集・単語登録ツールでのインポート・インポート辞書ファイルの削除を、
  エンジンの再起動なしで反映する用)

### RELOADCONFIG: 設定ファイルの再読込 (設定ツール用)

```
要求:   RELOADCONFIG\n
成功:   OK\n
```

- config.tsv (%APPDATA%\QuicklIME\config.tsv、QUICKLIME_CONFIG_FILE で上書き可)
  を読み直し、エンジン側の設定 (learning・suggest・typo_correction・
  max_predictions・min_suggest_chars) を即時反映する
- ファイルが無い・不正な行がある場合も既定値で動作を続け、OK を返す
- TSF 層向けのキー (space, punctuation, candidate_font, key.* など) は
  エンジンでは無視される (TSF 層が同じファイルを自前で読む)

## 設計メモ

- タブと改行はかな文字列に現れないため、エスケープは不要
- TSF 側の読み取りは同期・ブロッキング (フェーズ5でタイムアウトを検討)
- プロトコルの拡張はコマンド (先頭フィールド) の追加で行う
