# モードレス入力と英字

設定 `modeless` で、IME をオンにしたまま英語の打鍵を自動で見分けて英字のまま入れる入力の仕様。英字区間、
自動英字判定と英単語の始まりの決め方、英単語辞書、英字区間を閉じて日本語に戻る動作、Backspace で判定の前に戻る動作、
候補バーの英字候補、英字混じりの読みの変換、英単語の大文字小文字の補正を扱う。

- 利用者向けの操作の説明は [モードレス入力](../user/modeless.md) にある
- ASCIISTART・ASCIIWORD・ASCIIFORM の形式は [docs/protocol.md](../protocol.md)。本書は TSF 層がいつ何を送り、
  結果をどう使うかを書く
- run と読みの持ち方・Shift+英字の英字モード・スペースの幅は入力方式の側 ([input.md](input.md)「印字キー」
  「run の終わり方」)、キーの状態別の働きは [keys.md](keys.md)
- 候補バーの並び・表示の条件・採用の操作と結果は [suggest.md](suggest.md)「候補バーの候補」「表示の条件」「採用」。
  本書は英字候補の作り方を書く
- 英字を含む読みの変換キーの候補 (1 文節の固定・生ローマ字の候補・範囲の伸縮) は [conversion.md](conversion.md)
  「入力全体の候補選択 (`segment_ui` 0)」「生ローマ字の候補」「英字を含む読み」、英字の連続の語のラティスは
  [engine.md](engine.md)「ラティスの語」
- 英字を含む読みの学習は [learning.md](learning.md)「学習しない確定」
- 実装は tsf/src/romaji.cpp (`RomajiComposer`。英字区間・自動英字判定・英字区間を閉じる・Backspace)、
  tsf/src/english_words.h (ルール 7 の語リスト)、tsf/src/text_service.cpp (`ResolveAsciiRequest`・`CloseAsciiSection`・
  `BuildAsciiCandidate`・`BuildAsciiFormCandidate`・`BuildConversionSegments`)、tsf/src/text_service_direct.cpp
  (`PushDirectKey`・`AdoptAsciiCandidate`)、engine/src/english.rs (英単語辞書と照合)、engine/src/userdict.rs
  (ユーザ辞書の英字の語と表記)、engine/src/main.rs (ASCIISTART・ASCIIWORD・ASCIIFORM の受付)、
  data/english-words.txt・data/english-names.txt (英単語辞書)

## 有効と無効

- 設定 `modeless` (既定 0) は TSF 層だけが読む。設定を読み直すたびと打鍵ごとに `RomajiComposer` へ渡す
  (設定を読み直す通知が来ないホストでも設定どおりに判定するため)
- 無効のときは、自動英字判定・英字区間を閉じる動作・英字候補 (補正の候補を含む)・Backspace での英字区間の解除と
  判定の前への復元・英字混じりの run の変換・英字モード中の半角スペースのどれも働かない。Shift+英字の英字モードは
  run が終わるまで続く (Backspace で英字区間が空になっても抜けない)
- `modeless` によらず働くもの: エンジンが英字の連続を 1 語にする変換と、正しい大文字小文字の表記の候補
  (下記「大文字小文字の補正」)、英字モード中の印字キーの入り方 (下記「英字区間」)
- IME のオン/オフ (半角/全角キー・言語バー) はそのまま使える。モードレス入力はオン/オフを使わなくて済む機能で、
  パスワード欄やターミナルなどで IME を完全に止める手段は要るため

## 英字区間

- 読み (`RomajiComposer`) の確定済みのかなの一部を英字区間にする。英字区間の文字は ASCII の 1 文字をかな 1 字とし、
  打鍵もその 1 文字にする。どの英字区間にも入らない部分が日本語区間
- 開いている英字区間は 1 つまでで、run の末尾にある。英字モードは開いている英字区間がある状態をいう。開始位置が 0 なら
  run 全体が英字
- 英字区間を閉じると (下記「英字区間を閉じる」) 閉じた英字区間になり、後ろに日本語区間が続く。閉じた英字区間は
  1 つの run に複数あってよい (`きょうは|github|で|python|をつかう`)。最後に閉じた英字区間の終わりを閉じた位置といい、
  新しい英字区間と自動英字判定はそれより後ろだけを対象にする
- 区間分割した run は、開いている英字区間の前に日本語区間がある run (開始位置が 0 でない)。英字混じりの run は、
  英字区間 (開いている・閉じたもの) と日本語区間の両方がある run
- 英字区間に入るもの
  - Shift+英字: その打鍵の位置から英字区間を開く。打った文字から英字と分かるため。未完成のローマ字は先に、`n` は「ん」、
    それ以外はそのまま日本語区間に入れる
  - 自動英字判定による切り替え: 判定で決めた位置から後ろの打鍵 (未完成のローマ字を含む) を 1 文字ずつ英字区間に
    置き直す。位置より前の日本語区間はそのまま。2 文字以上のかなのまとまり (`kyo` → きょ) の途中の位置は、まとまりの
    先頭まで戻す (まとまりの打鍵は先頭のかなが持つため)
  - 英字モード中の印字キー: 英字 (Shift の大文字を含む) はそのまま、記号キーは打鍵文字 (`-` `,` `/` など半角)、
    数字キー・テンキーは設定 `digits` に従った文字を入れる。ローマ字には変換しない
- 英字区間の切り替え・閉じる・戻すは、読み (composition か入力行) を書き換えるだけで、文書には触れない
  ([input.md](input.md)「原則」)
- 読みの表示・確定の文字列・打鍵の列は、英字区間をそのまま英字として含む。F6〜F10 は run 全体の打鍵とかなから作るので、
  英字区間の境界が外れたときは F10 / F6 で run 全体を直せる ([conversion.md](conversion.md)「ファンクションキー変換 (F3〜F10)」
  「英字を含む読み」)

## 自動英字判定

`modeless` が有効で英字モードでないときに、閉じた位置より後ろの打鍵に当てる。

| 判定 | 成り立つとき | 判定する時点 | 根拠 |
|---|---|---|---|
| ルール 1 | 未完成のローマ字がテーブルのどの項目の先頭にもならず、促音 (同じ子音の連続) にも「ん」にもならない (`apple` の `pl`、`str`) | 打鍵中 | 強い |
| ルール 2 | 促音「っ」の直後に小書きの母音 (ぁぃぅぇぉ) 1 字のかなが来る (`hello` の「へっ」+「ぉ」) | 打鍵中 | 強い |
| ルール 3 | 未完成のローマ字が `n` 以外の英字 1 字 (`want` の `t`) | run の終わり | 強い |
| ルール 4 | 打鍵に `c` + 母音 (`ch` は除く) があり、打鍵が 5 文字以上。ローマ字テーブルに c 行 (`ca` など) があるときだけ | 打鍵中 | 弱い |
| ルール 5 | 打鍵に `th` + 母音 (`thi` は除く) がある (`github`・`the`・`method`) | 打鍵中 | 弱い |
| ルール 6 | 直前の確定の末尾が英字で、run の打鍵が英単語辞書の語と完全一致する | run の終わり | 下記「直前の確定が英字のとき (ルール 6)」 |
| ルール 7 | run の打鍵の全体か末尾が語リストの語と一致する | run の終わり | 下記「語リスト (ルール 7)」 |

- 根拠の強い判定 (ルール 1〜3) はローマ字として読めない打鍵なので、英単語辞書に無い語 (固有名詞・略語など) でも英字にする。
  根拠の弱い判定 (ルール 4・5) はローマ字として読める綴りなので、英単語辞書で英単語と確かめられたときだけ英字にする
- ルール 4: 日本語を打つときは k や s を使うため、c 行の綴りを英語の根拠にする。打鍵の短い語は誤判定を避けるため対象外。
  既定のテーブルには c 行が無く、`c` + 母音はルール 1 の側で扱う (下記「未完成のローマ字の保留」)
- ルール 5: `thi` (てぃ) はパーティーなどの外来語で日本語でも使うため除く
- run の終わりに成り立つ判定 (ルール 3・6・7) では読みを書き換えず、候補バーの英字候補にする (下記「英字候補」)。
  語を打ち終えたかは run の終わりでしか分からない (`わんt` の `t` は次に母音が来れば「た」になる) が、run を終える
  時点で書き換えると、見えている文字列と違う形で確定するため。どのキーで run を終えても見えているとおりに入る
  ([suggest.md](suggest.md)「採用せずに run を終えたとき」)
- 判定しないもの: ローマ字として読める英単語 (`sake`・`name`・`date` など)。日本語を優先し、Shift の頭文字・F10・
  生ローマ字の候補・英字候補で英字にする
- 採らなかった案: ぢ・づの綴り (`di` `du`) を英語の根拠にする。`tuduku` (続く)・`tidimu` (縮む) のように日本語の打鍵で
  普通に使うため

### 打鍵中の判定

- ルール 1・2・4・5 は英字の打鍵のたびに判定し、成り立てば英単語辞書で境界を決めて (下記「境界の決め方」)、その場で
  英字区間に切り替える
- ルール 2・4・5 は、判定のきっかけの打鍵をかなにする前に判定する。ルール 4・5 で英字にしなかったときは、そこからかなへの
  変換を続ける
- ルール 4・5 は、英単語辞書に一致せず英字にしなかった後も、run がその綴りを含む間は打鍵ごとに問い合わせ直す
  (問い合わせは c 行・`th` + 母音の綴りを含む run に限られる)

### 未完成のローマ字の保留

- 既定のテーブルで `c` + 母音で始まる未完成のローマ字は、4 文字になるまでかなに変換せず、未完成のローマ字のまま持つ
  (`kyouhaca` は「きょうは」+ `ca`)。3 文字になったら英単語辞書に問い合わせ、一致すればその境界から英字にする
  (`kyouhacam` → `きょうはcam`)。4 文字になったらルール 1 として判定する (`kaicaku` は `caku` で一致せず run 全体が英字)
  - `ca` の 2 文字では英単語の始まりを決められず、すぐにルール 1 で判定すると run 全体を英字にしてしまうため
  - `ch` で始まる未完成のローマ字 (ち行) は対象外
- ルール 1 が成り立ったときに未完成のローマ字が 4 文字未満なら、英単語辞書に一致しない間は英字にせず、未完成のローマ字の
  まま持つ。打鍵ごとに問い合わせ直し、一致すればその境界から英字にする (`kyouhapyt` は「きょうは」+ `pyt`、`pyth` で
  `きょうはpyth`)。4 文字になっても一致しなければ、根拠の強い判定どおり英字にする (`korehaxyzw` → `korehaxyzw`)
  - 英単語の 3 文字目までにローマ字として読めない綴りが出る語 (`python` の `pyt`) で、打鍵が短すぎて境界を決められず、
    run 全体 (閉じた英字区間があればその後ろ全体) が英字になるのを避けるため
- 4 文字は、英単語辞書の完全一致でない前方一致の最小の長さ (下記「境界の決め方」)
- 保留中に run を終えたときは、見えているとおり未完成のローマ字のまま入れる。保留中の打鍵をそこで判定しない
  (見えている文字と確定する文字を食い違わせないため)

### 境界の決め方

- 判定が成り立ったら、閉じた位置より後ろの打鍵を、かなのまとまり (打鍵を持つかな。「きょ」は 1 つ) ごとの要素と、
  最後の要素の未完成のローマ字に分けて ASCIISTART で問い合わせる
- エンジンは先頭の要素から順に、その要素から後ろの打鍵を英単語辞書と照合し、最初に一致した要素の位置を返す。最も前の
  境目を採るのは、後ろの短い打鍵 (`th` など) ほど偶然に一致しやすいため
- 打鍵中の判定は英単語を打っている途中なので前方一致 (完全一致を含む)、run の終わりの判定は打ち終えた語なので完全一致で
  照合する

| 判定 | 照合 | 一致したとき | 一致しなかったとき |
|---|---|---|---|
| ルール 1 (未完成のローマ字が 4 文字以上)・ルール 2 | 前方一致 | その境界から英字 | run 全体 (閉じた位置から後ろ) を英字 |
| ルール 1 の保留・`c` の保留 | 前方一致 | その境界から英字 | 保留を続ける |
| ルール 4・5 | 前方一致 | その境界から英字 | 英字にしない |
| ルール 3 | 完全一致 | その境界から英字 (英字候補) | 英字候補を出さない (下記「英字候補」) |
| ルール 6 | 長さの制限の無い完全一致 | 先頭から一致したときだけ run 全体を英字 (英字候補) | 英字にしない |
| ルール 7 | 問い合わせない (語リストで境界が決まる) | | |

- 長さの制限: 完全一致は後ろの打鍵が 3 文字以上、完全一致でない前方一致は 4 文字以上のときだけ一致とする。先頭の要素にも
  当てる。1〜3 文字の打鍵はほぼ必ず何かの英単語の頭になり、日本語の末尾に英字が少しだけ付く結果 (`かいしゃst`) になるため
  - `kyou|ha|gi|thu` → `githu` が前方一致 → `きょうは` + `githu` (`hagithu` は一致しない)
  - `ko|re|ha|a|っ|pl` → `appl` が前方一致 → `これは` + `appl`
  - `wo|rl` → 先頭から `worl` (world) が一致 → run 全体が英字
  - ルール 3 の `kyou|ha|wa|n|t` → `want` が完全一致 → `きょうは` + `want`
  - `ka|i|sya|st` → `st` は 2 文字で一致にならず、未完成のローマ字が 4 文字未満なので保留
- エンジンに接続できないときは一致なしとして扱う (下記「エンジンへの問い合わせ」)
- 採らなかった案: CONVNBEST の 1 位の候補の文節区切りから境界を推測する。1 文字の助詞が単独の文節になる
  (`world` → `をrld`)、英単語由来のかなが細かく分かれる (`今日は|技|テュ`) など、日本語の文節区切りでは英単語の始まりを
  決められなかった

### 直前の確定が英字のとき (ルール 6)

- 直前の確定は、確定アンドゥの記憶 ([input.md](input.md)「確定アンドゥ」) の文字列。末尾 (半角スペースを除く) が ASCII 英字の
  ときに当てる。数字は英語の文脈にしない (`2026 nen` の `nen` は日本語のまま)
- 対象は、run の打鍵が英小文字だけで、未完成のローマ字が無いか `n` だけの run。英字区間 (開いている・閉じたもの) のある
  run には当てない (run 全体が対象の判定のため)
- 英単語辞書に無い語は、文脈だけでは英字にしない (`kensaku` など、ローマ字として読める日本語を守るため)
- 助詞などと同じ形の語は対象外: `no` `to` `ga` `wo` `ni` `de` `ha` `wa` `mo` `he` `ya` `ka` `yo` `ne` (`GitHub no` は「の」)
- 英文中の短い語 (`is` `an`) を拾うため、長さの制限を外して照合する。1 文字の語は `a` と `i` だけを、エンジンに問い合わせずに
  英字にする (それ以外の 1 文字を送ると `u` `o` まで英字になる)

### 語リスト (ルール 7)

- 語リストは、ローマ字として読めるが日本語にならず、日本語を打つ場面がほぼない英単語 (tsf/src/english_words.h。語の
  選び方はファイルの先頭のコメント)。辞書を引かずに TSF 層だけで判定できる
- 対象はルール 6 と同じく、打鍵 (閉じた位置より後ろ) が英小文字だけで、未完成のローマ字が無いか `n` だけの run。
  ルール 6 より先に見る
- 打鍵の全体が一致すれば閉じた位置から英字にし、末尾 (かなのまとまりの境目から始まる部分) が一致すればその語の頭から英字に
  する (`korehafeature` → `これはfeature`)。境目は前から順に見る
- 末尾の一致は 5 文字以上の語に限る。日本語の末尾が偶然短い英単語の綴りになる誤判定を避けるため
- Meltype の語の表は GPL-3.0 のため使わない

## 英単語辞書

- エンジンが起動時に読む。TSF の DLL は全アプリのプロセスにロードされるため、数万語の辞書は持たせない
- 中身
  - data/english-words.txt: 一般語。SCOWL から生成した語を小文字にしたもの (生成の条件と手順はファイルの先頭のコメント)
  - data/english-names.txt: SCOWL に無い固有名詞・技術用語。正しい表記で書き、表記が小文字だけでない語は大文字小文字の補正に
    使う (下記「大文字小文字の補正」)
  - ユーザ辞書 (userdict.tsv) の短縮よみ・名詞系の語のうち、表記が ASCII 英字だけのもの。登録 (ADDWORD) と RELOADUSER で
    更新する。インポート辞書の語は含まない
- UTF-8 として読めない行は、その行だけを読み飛ばして続きを読み、ファイルごとに行数をログに出す
- 照合は、小文字にした語の整列済みの配列の二分探索 (前方一致・完全一致)。語数が数万なので fst は使わない。打鍵の英大文字は
  小文字にして照合する
- 置き場所は、exe と同じディレクトリの `dict\` に english-words.txt があればそこ (インストール先)、無ければリポジトリの
  `data/` (開発時)。`QUICKLIME_DICT_DIR` は見ない。インストーラは 2 つのファイルを `dict\` に置き、SCOWL の許諾文
  `LICENSE-SCOWL.txt` をインストール先に置く (installer/build.ps1)
- english-words.txt と english-names.txt が無いときは英単語辞書なしで動く。ASCIISTART はユーザ辞書の英字の語だけで照合し、
  ASCIIWORD は前方一致ありを返す (何も一致しないと英字区間を誤って閉じるため)

## 英字区間を閉じる

`modeless` が有効な英字モード中に英字を打ったとき、英単語が終わって日本語が続いたと分かれば英字区間を閉じて日本語に戻る
(`kyouhagithubdesagyousuru` → `きょうはgithubでさぎょうする`)。

- 英小文字のキー (Shift なし) を打つたびに、開いている英字区間の文字列 S と打った文字 c を足した S + c で ASCIIWORD を
  問い合わせる。S + c に英字以外 (記号・数字) があれば問い合わせない
- S + c が英単語辞書のどの語の前方一致 (完全一致を含む) にもならないとき、次を満たす切れ目 k を探す
  - S の先頭 k 文字 (3 文字以上) が英単語辞書の語と完全一致する
  - 残りの S[k..] + c を自動英字判定を止めたローマ字の照合に流すと、英字の残らないかなとして読める (末尾の未完成の
    ローマ字は残ってよい)
- 切れ目が複数あれば、残りが子音 (a i u e o 以外) で始まるもののうち最長のものを採り、子音で始まるものが無ければ最長のものを
  採る。英単語に続く日本語はほとんどが子音で始まり (を・で・の・が・は・する・に)、母音 1 文字から始まることはまれなため
  - `make` + `r` は `maker` が前方一致なので英字のまま。続く `u` で `makeru` が前方一致でなくなり、残りが子音で始まる
    `make` で閉じて `ru` → 「る」
  - `carpet` + `w` は `carpet` で閉じる (`car` では閉じない)。`apple` + `a` は子音で始まる切れ目が無いので `apple` で閉じて「あ」
- 切れ目が見つかれば先頭 k 文字で英字区間を閉じ、残りを自動英字判定を止めてローマ字として打ち直してから、c だけを通常の
  打鍵と同じく判定に通す。見つからなければ c を英字区間に足す (辞書に無い語・閉じられる切れ目の無い語)
- S + c が前方一致になる間は閉じない (`apples` は英字のまま)
- 記号キー・数字・Space・確定キー・Shift+英字では閉じない
- 閉じた位置より前は自動英字判定の対象外。ASCIISTART の要素、ルール 4 の打鍵の長さと綴り、ルール 5 の綴り、ルール 7 の照合は
  閉じた位置より後ろの打鍵で数え、ルール 6 は閉じた英字区間のある run に当てない。閉じた `github` の `thu` で、閉じた後の
  打鍵ごとにルール 5 の問い合わせが出続けないようにするため
- エンジンに接続できないときは閉じない
- 採らなかった案: 閉じる専用のキーを設ける。英字混じりの文を打つたびにキーを挟む必要があり、切替を意識しないという
  モードレス入力の目的に合わない

## Backspace

Backspace の 1 回分の削り方は [input.md](input.md)「読みの編集」。`modeless` が有効なときは次も行う。

- 英字区間が空になったら英字モードを抜け、日本語区間の末尾から入力を続ける
- 閉じた位置まで消した (閉じた位置より後ろのかなと未完成のローマ字が空になった) ら、最後に閉じた英字区間を開き直す。閉じた
  位置は 1 つ前の閉じた英字区間の終わりに戻る (`githubd` → Backspace → `s` で `githubs`)
- 自動英字判定で英字に切り替えるたびに、切り替える直前の読みの状態 (かな・打鍵・未完成のローマ字・英字区間・閉じた英字区間) と
  そのときの打鍵の数を積む。英字候補の採用で切り替えたときも積む。Shift+英字で入った英字区間と、英字区間を閉じる操作は積まない
- Backspace の後の打鍵の数が最後に積んだ記録より少なくなったら、記録の状態に戻してから 1 回分を削り、記録を取り除く。記録の
  状態の未完成のローマ字の末尾は判定のきっかけの打鍵なので、判定の前の日本語に戻る
  - `kyouhagithu` (`u` で `きょうはgithu`) → Backspace → `きょうはぎ` + `th`
  - `korehaxyzw` (4 文字で一致せず run 全体が英字) → Backspace → `これは` + `xyz` (保留中)
  - `kyouhagithubde` → Backspace 3 回 → `きょうはgithub` (英字区間を開き直す) → `きょうはgithu` (`b` は判定のきっかけで
    ないので英字のまま) → `きょうはぎ` + `th`
- 削った後は、残った未完成のローマ字に打鍵中の判定をやり直す (保留に入る・抜ける、英字にする)
- 積んだ記録は、候補バーの採用で run の先頭を外したとき、範囲の伸縮で先頭にかなを足したとき、run を終えたときに捨てる
  (位置がずれて戻せないため)。範囲の伸縮で積む読みの状態は記録ごと戻る ([conversion.md](conversion.md)「外した文字の打鍵の復元」)

## 英字候補

候補バーの先頭に出す英字の形の候補 ([suggest.md](suggest.md)「候補バーの候補」)。作り方は 2 つあり、1 件だけ出す
(英字モード中は前者を作らないので両方は並ばない)。

| 候補 | 出すとき | 候補の形 |
|---|---|---|
| run の終わりの判定の候補 | 英字モードでない run で、読みの複製に run の終わりの判定 (ルール 3・6・7) を当てると英字になる | 複製の確定の文字列 (`きょうはwant`・`pen`・`remote`・`これはfeature`) |
| 大文字小文字の補正の候補 | 英字モード中で、開いている英字区間 (英字だけのもの) に正しい表記がある | 英字区間を正しい表記に置き換えた run (`きょうはGitHub`・`GitHub`) |

- 候補は打鍵ごとにバーを作り直すときに読みの複製から作り、読み自体は変えない
- ルール 3 は英単語辞書と完全一致したときだけ候補にする。一致しないときの扱いは run 全体 (閉じた位置から後ろ) を英字にする
  ことになり、日本語の打ち途中で子音を 1 つ打つたびにその候補が出てしまうため (`watasihant` のような語は F10 で直す)
- 補正の候補の正しい表記は ASCIIFORM で問い合わせる。最後に問い合わせた文字列と応答を覚え、同じ文字列では問い合わせ直さない
  (未接続・エラーは覚えない)
- 英字候補は `min_suggest_chars` によらず出し、`candidate_bar` 0 では出ない。並び・表示の条件は
  [suggest.md](suggest.md)「候補バーの候補」「表示の条件」
- 採用は、読みを候補を作った複製に置き換える。採用した部分は開いている英字区間になり、印字キーで採用すれば英字区間に打鍵を
  続け、それ以外のキーでは run を終える。Space で終えるときのスペースは半角 ([suggest.md](suggest.md)「採用の操作」「採用の結果」)
- バーを作った後に読みが変わっていたら、採用せずに選択を外す
- 採用では学習を送らない。run を終えたときに、英字を含む読みとして 読み = 表記 で学習する
  ([learning.md](learning.md)「学習しない確定」)。英字候補の学習の削除は何もしない ([keys.md](keys.md)「機能」)

## 英字混じりの読みの変換

- `modeless` が有効で英字混じりの run は、変換キーで英字を含む読みでも 1 文節に固定せず、英字を含まない run と同じ経路で
  変換する ([conversion.md](conversion.md)「入力全体の候補選択 (`segment_ui` 0)」「文節 UI (`segment_ui` 1)」)。生ローマ字の
  候補は入れない (run 全体を英字にするなら F10)
- エンジンは英字の連続を 1 語として扱い、途中で割らない ([engine.md](engine.md)「ラティスの語」)。そのため日本語の部分だけが
  変換される (`きょうはgithubでさぎょうする` → `今日はgithubで作業する`)
- それ以外 (`modeless` が無効、run 全体が英字、ローマ字に変換されないまま入った英字だけを含む読み) は、全体を 1 文節に固定して
  生ローマ字の候補を入れる ([conversion.md](conversion.md)「生ローマ字の候補」)
- 範囲の伸縮は、英字を含む読みの通常の変換ではしない ([conversion.md](conversion.md)「英字を含む読み」)
- 候補バーの読みは、区間分割した run では開いている英字区間の前まで、それ以外では確定済みのかな全体。閉じた英字区間は日本語区間の
  一部として読みに入り、英字のまま変換される。閉じた英字区間だけを含む run は区間分割した run にしない
  ([suggest.md](suggest.md)「候補バーの候補」)
- 英字を含む候補は LLM の並べ替えから外す ([engine.md](engine.md)「保護の印」)
- 変換して確定したときは、英字を含む読みでも文節ごとの通常の学習を送る ([conversion.md](conversion.md)「学習」)。変換せずに
  run を終えたときは 読み = 表記 で学習する。未完成のローマ字が残る run の例外は [learning.md](learning.md)「学習しない確定」

## 大文字小文字の補正

英単語の正しい大文字小文字の表記 (`github` → `GitHub`) を候補として出す。打った文字列を自動では書き換えない。

- 正しい表記の出どころ
  - ユーザ辞書の英字の語 (英単語辞書に入る語) のうち、表記が小文字だけでないもの。登録した表記を正しい表記にする。同じ小文字の形で
    表記の異なる登録が複数あれば、先のもの。小文字だけの登録は読みから引くためのものとみなし、表記にしない (english-names.txt の
    表記を打ち消さない)
  - english-names.txt の語のうち、表記が小文字だけでないもの (`GitHub`・`iPhone`・`macOS`)。小文字で書いた語 (`localhost` など)
    は補正しない。ユーザ辞書に同じ小文字の形があればユーザ辞書を優先する
  - english-words.txt (SCOWL) の語は使わない。`may` / `May`、`bill` / `Bill` のように小文字のほうが正しい場合があるため
  - 表記が ASCII 英字だけで書けない語 (`Next.js`・`VS Code`) は補正しない
- 効く所

| 所 | 効き方 | `modeless` |
|---|---|---|
| 変換 (エンジン) | 英字の連続に正しい表記があれば、正しい表記の語を打ったとおりの語より安く足す ([engine.md](engine.md)「ラティスの語」)。変換キーの候補と候補バーの全体変換で、補正した候補が上に、打ったとおりの候補がその下に出る | よらない |
| 生ローマ字の候補 | 打鍵が英字だけなら ASCIIFORM を問い合わせ、表記があれば変種の先頭に入れる ([conversion.md](conversion.md)「生ローマ字の候補」) | よらない |
| 候補バー | 開いている英字区間の補正の候補 (上記「英字候補」) | 有効のときだけ |

- 打ったとおりの候補を選んで確定すれば、学習で次からそちらが上に来る
- 採らなかった案: ASCIIWORD の応答に表記を足す。TSF 層の解析が余分なフィールドを不正とみなすため、TSF 層が古いままエンジンだけを
  新しくすると英字区間を閉じる判定が働かなくなる

## 英字モード中のスペース

- `modeless` が有効なときの英字モード中は、Space で入れるスペースを設定 `space` によらず半角にする。英文の語の区切りのため。
  run を Space で終えるとき ([input.md](input.md)「run の終わり方」)、候補バーの採用 (英字候補の採用を含む。
  [suggest.md](suggest.md)「採用の操作」)、候補選択中 (割当によらず確定して半角スペースを入れる。[keys.md](keys.md)「割当の照合」)
  が対象
- run が無いときの Space も、直前の確定 (確定アンドゥの記憶) が ASCII 英数字だけなら半角にする ([input.md](input.md)「印字キー」)。
  英字モードの run を Space で終えた直後も英文の途中のため
- `modeless` が無効なら、Shift+英字の英字モード中も設定 `space` に従う

## エンジンへの問い合わせ

- ASCIISTART・ASCIIWORD・ASCIIFORM は打鍵ごとに呼ぶので、接続を待たない。パイプを開けなければエンジンを起動だけして、その打鍵では
  失敗として扱う (打鍵を止めないため)
- 失敗 (未接続・エラー・コマンドを知らない古いエンジン) のときの扱い
  - ASCIISTART: 一致なし。根拠の強い判定は run 全体 (閉じた位置から後ろ) を英字にし、根拠の弱い判定は英字にせず、保留は続け、
    ルール 3・6 の英字候補は出ない
  - ASCIIWORD: 英字区間を閉じない
  - ASCIIFORM: 候補バーの補正の候補と、生ローマ字の候補の補正した表記を出さない
- エンジンに接続できないときに英字候補になりうるのは、辞書を引かないルール 7 と、1 文字の語 (`a` `i`) のルール 6 だけ

## 設定

値の書式と設定ツールでの名前は [設定一覧](../user/settings.md)。

| 設定 | 既定 | 読む側 | 本書での働き |
|---|---|---|---|
| `modeless` | 0 | TSF 層 | 1 でモードレス入力 (自動英字判定・英字区間を閉じる・英字候補など) を使う |
| `candidate_bar` | 1 | TSF 層 | 0 で英字候補を出さない |
