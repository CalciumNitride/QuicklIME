# 表示

IME が画面に出すものの仕様。画面の部品の呼び名、入力パネル (候補バー・変換の候補一覧・入力行) の描き方と
表示位置、テーマ、ぼかし、キャレットの印、入力モードの一時表示、タスクバーの入力モードのアイコンと言語バー、
文書の composition の表示属性、設定ツールに渡す入力パネルの見本の描画を扱う。

- 利用者向けの説明は [候補バーと表示](../user/candidate-bar.md) と [入力パネルのテーマ](../user/theme.md) にある。
  テーマのキー・値・範囲・既定値の一覧は [入力パネルのテーマ](../user/theme.md) に置き、本書では重複させない
- 候補バーに並べる候補・並び・選択・採用・ページの区切りは [suggest.md](suggest.md)、変換の候補一覧の候補と
  候補選択の操作は [conversion.md](conversion.md)、入力中の読みを出す場所 (`input_buffer`) は
  [input.md](input.md)「入力中の読みの表示 (`input_buffer`)」、キーの働きの一覧は [keys.md](keys.md)
- 設定ツールの「見た目」ページ (テーマ・フォントの選択肢) と見本の表示は [tools.md](tools.md)「入力パネルのテーマとフォント」
  「入力パネルの見本」
- 実装は tsf/src/suggest_panel.cpp (入力パネルの描画と位置)、tsf/src/panel_theme.cpp (テーマの読み込み)、
  tsf/src/caret_marker.cpp (三角)、tsf/src/mode_popup.cpp (入力モードの一時表示)、tsf/src/lang_bar.cpp と
  tsf/src/icon_font.cpp (入力モードのアイコン)、tsf/src/display_attribute.cpp (表示属性)、tsf/src/preview.cpp
  (見本)、tsf/src/text_service.cpp と tsf/src/text_service_direct.cpp (位置の基準・出すとき・消すとき)

## 画面の部品の呼び名

画面に出る文言 (設定ツール・README・docs/user/) と docs・コードコメントでは、次の呼び名を使う。

| 呼び名 | 指すもの |
|---|---|
| 入力パネル | 入力中に出るパネル (ウィンドウ) 全体。入力行と候補を含む。テーマ (`panel_theme`) が見た目を決める対象 |
| 候補バー | 入力中に入力パネルに並ぶ候補 (変換結果・予測など) と、その機能。パネルそのものの名前には使わない |
| 変換の候補一覧 | 変換キーで入力パネルに出す、現在の文節の候補の縦の一覧 |

- 「候補パネル」「サジェストパネル」「候補ウィンドウ」は使わない。パネルは入力行も出すので、「候補」と呼ぶと
  指すものが文書ごとに揺れるため
- 識別子・ファイル名・設定キー (`SuggestPanel`、`candidate-bar.md`、`panel_theme` など) は変えない。
  コード上の名前を画面の文言に流用しない

## 入力パネル

候補バー (run の候補と後続語の予測)・変換の候補一覧・入力行を、1 つのパネル (`SuggestPanel`) で出す。

### ウィンドウと描画

- ウィンドウは `WS_POPUP` に `WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_LAYERED`。
  クリックされてもフォーカスを奪わない (`WM_MOUSEACTIVATE` に `MA_NOACTIVATE`)。マウスの操作は扱わない
- 文書のルートウィンドウ (求め方は下記「入力位置がウィンドウの外を指すとき」と同じ) をオーナーにして作る。取れなければ
  オーナー無し。ぼかしで描くときも同じ
  - オーナー付きのウィンドウはオーナーのすぐ上に同じ重なり順の層で置かれる。オーナー無しでは `WS_EX_TOPMOST` でも
    デスクトップの層に置かれ、スタートメニューの検索欄のような immersive の層のアプリでは後ろに隠れるため
  - 出すときに求めたオーナーが、ウィンドウを作ったときのオーナーと違えば作り直す (作ったウィンドウを使い回すため)
  - オーナーを閉じると、パネルも OS がオーナーと一緒に破棄する (入力先のウィンドウを閉じたら残さないため)。そのときは
    隠したのと同じ状態にし、次に出すときに作り直す
  - オーナーを最小化するとパネルも隠れる。オーナーより下には回らない
- 32bpp の DIB に Direct2D (`ID2D1DCRenderTarget`、premultiplied alpha) で描き、`UpdateLayeredWindow`
  (`ULW_ALPHA`) で画素ごとの不透明度つきで出す。ぼかしで描くときは別の方式 (下記「ぼかし」)
- 描画先は software で作る。hardware はホストのプロセス (ゲームなど) に D3D のデバイスを作るため
- 文字のアンチエイリアスはグレースケール。透過する背景の上では ClearType の色付きの縁が浮くため
- D2D の factory はパネルごとに single-threaded で作る。TextService はスレッドごとに 1 つで、パネルも同じ
  スレッドからしか触らないため
- DPI は 96 に固定し、DIP を px として扱う (DPI による拡大はしない)。寸法は設定 `candidate_font_size`
  (以下 f) に比例させる (テーマの寸法のキーは f に対する比率)
- フォントは設定 `candidate_font` (GDI の面名) を次の順に DirectWrite のフォントへ解決する
  (tsf/src/suggest_panel.cpp `ResolveFont`)。GDI は太さや幅の違うフォントを別の面名 (`Yu Gothic UI Semibold`・
  `Noto Sans JP Thin` など) で列挙するが、DirectWrite ではそれらが 1 つのファミリの中の太さ・幅の違いになるため
  1. システムのフォントコレクションの `FindFamilyName` で見つかれば、そのファミリを標準の太さ・幅・斜体なしで使う
  2. 見つからなければ、`EnumFontFamiliesExW` にその面名を指定して (`DEFAULT_CHARSET`) `LOGFONTW` を得る (斜体でない
     ものを優先し、なければ最初のもの)。それを `IDWriteGdiInterop::CreateFontFromLOGFONT` に渡して得たフォントの
     ファミリ名 (en-us があればそれ、なければ先頭) と太さ・幅・斜体を使う
  3. どちらでも得られなければ Yu Gothic UI を標準の太さで使う
  - 書式 (候補・入力行・番号・ラベル・タグ) はすべて解決したファミリ名と太さ・幅・斜体で作る。選択中の候補の太字の
    書式だけは太さを Bold に固定する (幅と斜体は解決したもの)
  - 面名だけを入れた `LOGFONTW` (太さは標準) は渡さない。`Noto Sans JP Thin` などが「太さ 700 + 太字の合成」の
    別のフォントに解決されるため、列挙で得たそのフォント自身の太さ入りの `LOGFONTW` を渡す
- 影はパネルの外側に余白 (影の広がり + 下へのずらしの切り上げ) を取り、少しずつ広げた角丸矩形を外側から
  `shadow_steps` 枚重ねて近似する。1 枚の不透明度は、全部が重なるパネルの縁で `shadow` の不透明度になるように
  決める。`ID2D1DCRenderTarget` ではブラーのエフェクトが使えないため
- 位置の計算は影を除いたパネルの矩形で行い、ウィンドウの矩形は影・尻尾の余白を含む
- 表示・再描画のたびに、位置の基準・位置・大きさ・候補の数・方式 (layered かぼかし) とウィンドウの状態を
  診断ログに出す

### 中身と大きさ

パネルの中は上から入力行・区切り線・候補・位置の表示の順に並ぶ (キャレット行の上に反転して出すときは逆。
下記「キャレット行の上に出すときの反転」)。

| 部品 | 出すとき |
|---|---|
| 入力行 | 入力行を出す設定のとき (下記「入力行」) |
| 区切り線 | 入力行があるとき (縦積みと変換の候補一覧は候補もあるとき)。`style ghost` では線を引かず間だけ取る (枠を持たないため) |
| 候補 | テーマの `layout` で横一列 (`row`) か縦積み (`column`)。変換の候補一覧は `layout` によらず縦積み |
| 位置の表示 (`12/24`) | 候補が複数ページになるとき。横一列はチップの列の右に並べ、縦積みは最後の行の下に置く (`align center` では中央)。副次色・`label_text_size` の文字 |

- 横一列のパネルの高さは、入力行の有無だけで決まる (候補が無くてもチップの列の高さを取る)。打鍵で候補の数が
  変わっても入力行の位置を上下させないため
- 縦積みのパネルの高さは出している行の数で決まる。候補が無ければ入力行だけの高さ
- 角丸の半径は `panel_radius` × f とパネルの高さの半分の小さいほう
- 幅は表示位置で決まる (下記「表示位置」)。候補 1 件の高さ (`chip_height` × f) の 2 倍より狭くしない

### 入力行

入力行を出すのは次のとき (tsf/src/text_service.cpp `PanelInputActive`)。

- パネル保持入力 (`input_buffer panel`) の run。設定によらず出す (出さないと読みがどこにも見えないため)
- 設定 `candidate_bar` 1 で、設定 `panel_input` 1 かテーマの `input_row always`

| 状態 | 入力行に出すもの |
|---|---|
| run 中 | 確定済みのかなを文字の色とアクセント色の下線 (`underline_px`) で、続けて未完成のローマ字を副次色と点線の下線で出し、末尾にアクセント色のキャレット (`caret_width_px`) を置く |
| 変換の取消の直後 (run に戻る前の composition) | composition の文字列を確定済みのかなと同じく出す |
| 後続語の予測の表示中 | 直前に確定した表記の末尾 8 文字 (サロゲートペアは 1 文字) を副次色で出し (切り詰めたら先頭に「…」)、続けて `next_word` 色の「次の語」のラベル (`label_text_size`) |
| 候補選択中 | 下記「変換の候補一覧」 |

- キャレットは点滅させない (打鍵ごとの再描画のほかに描き直さない)
- 入力行は入力行の幅で切る。`align center` では、ゴーストまで含めた幅で中央に置く
- `style ghost` では、入力行の文字を `ghost_text_size` で描き (行の高さも同じ比で伸ばす)、キャレット (後続語の
  予測ではラベル) の後ろに「→ 候補」の形で、選んでいる候補 (選んでいなければ先頭の候補) を文字の色・
  `ghost_opacity` の不透明度で出す。幅はいちばん長い候補が入る分を取る (選択で幅を変えないため)

### 候補の描き方

| 部品 | 描き方 |
|---|---|
| 候補の背景 | 横一列の `chip_shape pill` / `rounded` では未選択の候補も `chip` 色の背景を持つ。縦積みでは未選択の行は背景を持たない。`underline` は背景を持たない |
| 選択中の強調 | `selection fill`: アクセント色で塗り、文字と番号を `selected_text` に。`soft`: アクセント色を不透明度 0.16 で敷き、文字と番号をアクセント色に。`text`: 文字だけをアクセント色の太字に。`underline` の `fill` / `soft` は文字を変えず、文字の下にアクセント色の下線を引く |
| 番号 | ページ内の 1〜9。`badge_shape circle` / `square` は線 (`line_width_px`) の形の中に、`plain` は数字だけ、`none` は出さない。色は副次色 (選択中の `fill` / `soft` は上の強調に従う) |
| 候補の文字列 | 収まらなければ末尾を「…」で切る。`selection text` では、選択で幅が変わらないよう太字の幅も見込んで幅を決める |
| 縁 | 横一列の `pill` / `rounded` で、後続語の予測の候補に `next_word` 色、補正の候補 (全体変換の補正・ずれを使った予測) に `typo` 色の縁を内側に付ける |
| 種類のタグ | 縦積みで `kind_tag on` のとき、行の右端に「英字」「変換」「補正」「予測」「文節」「次の語」を、テーマの `tag_*` の文字の色と、その色を不透明度 0.16 で敷いた背景で出す |
| 採用範囲の外 | 採用範囲を縮めた全体変換 ([suggest.md](suggest.md)「採用範囲の縮め」) は、範囲の外の文節を文字の色の不透明度 0.5 で描き、種類のタグを「文節」にする。1 つの文字列として描いた位置のまま範囲の外だけを切り分けて薄くする (分けて描くと、収まらないときの「…」の位置が変わるため) |

- 縦積みの行の幅は、`align left` では行どうしでそろえ、`align center` では行ごとの幅で中央に置く
- `text_shadow on` では、文字の下に、文字と反対の明るさ (ダークでは黒、ライトでは白) の同じ文字を不透明度 0.35 で
  1px ずらして描く。下の背景の明暗によらず読めるようにするため
- `style ghost` はパネルの背景・縁・影の代わりに、ウィンドウ (外側の余白を含む) に内接する楕円の放射状の
  にじみを描く。中心から半径の 45% までは `scrim` の濃さのまま、そこから外周で透明になる。文字の載る内側は
  濃さを保ち、ウィンドウの端で切れて見えないようにするため。にじみのためにパネルの外側に f × 1.5 の余白を取る

### 変換の候補一覧

変換キー・F4〜F10 の候補選択の候補を、候補バーと同じパネルで出す (`ShowConversion`)。テーマの値 (色・形・
寸法・`style`・`align` など) とぼかしは候補バーと同じものを使う。

- テーマの `layout` によらず縦積みにする (候補の数が多く、ページ送りがあるため)。1 行の描き方は `layout column` と同じ
- 種類のタグは補正の候補にだけ出し、`kind_tag` によらない。ほかの候補はほぼすべて同じ種類で、補正の候補は縦に
  積むと縁では目立たず、ほかに見分ける方法が無いため
- 1 ページは最大 9 件で、作業領域 (キャレットの下に出すときは出す側の空き) に 9 行が収まらなければ収まる行数に
  する。選んでいる候補を含むページを出し、番号はページ内で 1 から振る。複数ページなら位置の表示を出す
- 入力行には文書の composition と同じ内容を出す
  - 範囲を縮めて外したかな: 副次色・点線の下線
  - 変換結果は文節ごとに区切り、現在文節はアクセント色を不透明度 0.16 で敷いてアクセント色の下線 (`underline_px`)、
    ほかの文節は文字の色と副次色の細い下線 (`line_width_px`) にする。文節の境目では下線を 2px 空ける。
    `segment_ui` 0 では全体が現在文節
  - キャレットとゴーストは出さない
  - 現在文節が入力行の幅に収まらなければ、現在文節が見えるよう左を「…」で切る
- 採らなかった案: 変換の候補一覧を別のウィンドウで描く。描画が 2 つになり、テーマの項目を足すたびに両方を
  直すことになるため

### 出すとき・消すとき

- 候補バーを出す条件・作り直し・消す条件は [suggest.md](suggest.md)「表示の条件」「後続語の予測」
- 入力行を出す run の間は、候補が無くても入力行だけのパネルを出す。候補が無くなったときはウィンドウを作り直さず、
  入力行だけのパネルに描き直す
- 候補選択に入ったら候補バーの表示を変換の候補一覧に切り替え、LLM の並べ替えの結果の問い合わせを止める
  (パネルが共用なので、並べ替えの結果で候補一覧を上書きさせないため)
- F6〜F10 で候補一覧を閉じている間は、入力行を出す設定なら入力行だけのパネルを出し、そうでなければパネルを隠す
- キャレットの下に出す設定で、候補バーと入力行だけのパネルの位置の基準 (下記「位置の基準」) が取れないときは、パネルを出さない
- テーマを読み直したとき、表示中のパネルは色だけが変わったなら描き直し、並べ方・形・寸法が変わったなら隠す
  (今のレイアウトは前の見た目で組んであるため)

## 表示位置

設定 `candidate_position` で、入力パネルをキャレットの下 (`caret`、既定) か画面中央 (`center`) に出す。

### 位置の基準

| 表示 | 基準の矩形 (取れた最初のもの) |
|---|---|
| 候補バー・入力行だけのパネル・入力モードの一時表示 (`CaretRect`) | run の composition の矩形 (composition 入力の run) → 選択範囲の矩形 → システムキャレット (`GetGUIThreadInfo`) |
| 変換の候補一覧 (`CandidateAnchor`) | composition の矩形 (候補選択中) → 選択範囲の矩形 (run 中) → システムキャレット → マウスカーソルの位置 |
| キャレットの印 | 下記「キャレットの印」 |

- 候補バーの横の位置は、run で最初にバーを出した時点の基準の左端に固定する ([suggest.md](suggest.md)「表示の条件」)。
  変換の候補一覧の左端は基準の矩形の左端

### 入力位置がウィンドウの外を指すとき

TSF が入力欄と無関係な位置を返すアプリ (マビノギで、モニタの隅に丸めた値が返る) でも、見える場所に出すための規則
(tsf/src/text_service_direct.cpp `FallbackIfOutsideWindow`)。

- 基準の矩形の左上の点が文書のルートウィンドウ (`GetWindowRect`) の中に無ければ、ルートウィンドウの中央の点
  (幅・高さ 0) に置き換える。幅・高さ 0 の矩形も来るため、矩形の重なりではなく点で判定する
- 文書のウィンドウは `ITfContext::GetActiveView` → `GetWnd` のルート (`GA_ROOT`)。得られなければ (CUAS 経由など)
  入力を受けているスレッドのフォーカス (無ければアクティブ) のウィンドウのルート。どちらも無ければ判定しない
- 候補バー・変換の候補一覧・入力モードの一時表示の基準 (取れた矩形すべて) と、キャレットの印の composition の
  末尾の矩形に当てる。置き換えたときは元の矩形・ウィンドウの矩形・代わりの位置を診断ログに出す
- 入力パネルは代わりの位置を基準に出す。キャレットの印と入力モードの一時表示は出さない (代わりの位置は
  キャレットの位置ではなく、印や状態が無関係な場所を指すため)
- 採らなかった案
  - マウスカーソルの近くに出す: マビノギではマウスをキャラクターの操作に使い、入力欄と無関係な位置になりやすい
  - 固定の位置を設定で指定させる: 求められていない
  - 候補をアプリに渡して描かせる (`ITfCandidateListUIElement`): QuicklIME の入力パネルを使い続けるため

### キャレットの下 (`caret`)

- 基準の矩形の下端から間 (2px。三角の印を出すときは三角の高さを足す。吹き出しの尻尾を付けるときは尻尾の高さ) を
  空けて下に出す。左端は上記「位置の基準」の x
- 横一列: 作業領域の下端からはみ出すなら、基準の矩形の上端の上に出す (間は 2px か尻尾の高さ)。パネルの高さは
  候補の数で変わらないので、上下は打鍵で変わらない
  - 幅は候補の列 (位置の表示を含む) と入力行の広いほう。作業領域の右端で切るが、候補の列は切らない
  - 1 ページの候補は、左端から作業領域の右端までに収まるだけ (ページの区切りは [suggest.md](suggest.md)「ページ送り」)。
    1 件だけで幅を超えるページは、その候補が収まるところまで左へ寄せる
- 縦積み (候補バーの `layout column` と変換の候補一覧): 下記「キャレット行の上に出すときの反転」で上下を決める。
  幅はいちばん広い行・入力行・位置の表示に合わせ、作業領域の幅を超えない。収まらない行は末尾を「…」で切る
- 変換の候補一覧は、作業領域の右端からはみ出せば左へずらし、左端・上端からはみ出せば端に合わせる

### キャレット行の上に出すときの反転

縦に並ぶ入力パネル (縦積みの候補バー・後続語の予測と、変換の候補一覧) をキャレットの下に出すときの規則。
同じ行で入力している間、入力行と各候補の位置を動かさないため。

- 上下は出しうる最大の高さで決める。最大の高さは、作業領域の高さに収まる行数 (最大 9) の候補と位置の表示の行を
  出したときの高さ (位置の表示の行は、ページが分かれるかによらず含める)。入力行の有無はそのときの入力行の設定に従う
  - 下の空き (基準の矩形の下端 + 間から作業領域の下端まで) に収まれば下、収まらなければ、上の空き (作業領域の上端から
    基準の矩形の上端 − 間まで) に収まるか上の空きのほうが大きければ上、それ以外は下
  - 1 ページの行数は、出す側の空きに収まる行数 (最大 9)
  - どちらの側にも 1 行も入らなければ、作業領域の高さで行数を決め、下に出してはみ出すなら上に出す (変換の候補一覧は
    それでもはみ出せば作業領域の下端に寄せる)
- 今の候補の数で決めると、候補が少ない間は下に出て、増えると上へ飛ぶため。候補バーと変換の候補一覧で同じ式にし、
  候補選択に入っても出す側を変えない
- 上に出すときは、パネルの下端を基準の矩形の上端 − 間に揃え、中の並びを上下に反転する。キャレット側 (下) から
  入力行・区切り線・候補 1, 2, 3…・位置の表示。番号は候補の順 (1 番目がキャレット側)。伸び縮みするのはパネルの上端だけ
- 上下の判定と 1 ページの行数は、候補を組み直すとき (`Show`・`ShowConversion`) に決め、選択の移動とページの切り替えでは
  変えない
- 反転しているパネルでは、↑ / ↓ を見た目の向きに合わせる (tsf/src/text_service.cpp `ArrowOrder`)。↑ が順番での次、
  ↓ が前。候補バーの選択、変換の候補一覧の ↑ / ↓、↑ / ↓ に割り当てた `NextWordNext`・`NextWordPrev` (既定の Ctrl+↑ は
  反転中は次) に効く。未選択からの最初の一打の扱い・端での循環・ページの切り替えは、入れ替えた後の順番での次 / 前に
  対して反転していないときと同じ。Tab・Space・変換キーなど向きを持たないキーは入れ替えない
- 横一列と画面中央 (`center`) は反転しない
- 採らなかった案
  - 上に出すときに上端を最大の高さで固定し、下へ伸ばす: 候補が少ないとき、パネルとキャレット行の間が最大で 9 行分空き、
    入力した文字が挿入先から遠くに出る
  - 上下の判定だけを直す: 上に出したときに候補の数で上下に動くのが残る

### 画面中央 (`center`)

- 基準の矩形を含むモニタ (`MonitorFromRect`、`MONITOR_DEFAULTTONEAREST`) の作業領域の中央に出す。基準の矩形が
  取れなくても出し、そのときは前景ウィンドウのモニタ (前景ウィンドウが無ければプライマリモニタ) を使う
- 幅は `center_width` × f と、作業領域の幅 × `center_width_ratio` の小さいほうで固定する。入力行と候補は左詰め
  (`align` に従う) で、打鍵ごとに候補の位置が左右へ動かないようにする。1 件で幅を超える候補は幅に収めて「…」で切る
- 横一列: パネルの高さは候補の数によらないので、作業領域の縦の中央に置けば入力行と候補は動かない
- 縦積みの候補バー: 出せる最大の行数のとき (複数ページなら位置の表示の行を含む) の高さで上端を決めて固定し、下へ伸び
  縮みさせる
- 変換の候補一覧: 上端を、同じ設定・同じテーマで候補バーを出したときの上端にそろえて下へ伸ばす (候補選択に入っても
  入力行が動かないため)。作業領域の下端を超えるときは収まるところまで上へずらす
- 候補の視線の行き先を一か所に固定し、アプリごとのキャレット位置の取り方の違いにも左右されないようにするための設定

## テーマ

入力パネルの見た目 (色・形・寸法・並べ方) はテーマで決める。キーの一覧と組み込みテーマの値は
[入力パネルのテーマ](../user/theme.md)。

### 方式

- 見た目は値 (数値・色・選択肢) を書いたテーマファイルで決める
- 採らなかった案: スクリプト (Lua・JavaScript など) を DLL に組み込み、描画や配置を書けるようにする。IME の DLL は
  全アプリ (ゲームを含む) に読み込まれ打鍵ごとに描くので、スクリプトの不具合や重い処理が全アプリの入力を止め、遅延に
  なる。任意のコードが全プロセスで動くことにもなる。値の指定でも、色・形・大きさを変える目的は満たせる

### テーマの選び方

設定 `panel_theme` (既定 `capsule`) のテーマを次の順で探す (tsf/src/panel_theme.cpp `PanelThemeLoader`)。

1. テーマフォルダの `<テーマ名>.tsv`。テーマフォルダは `QUICKLIME_THEME_DIR`、無ければ `%APPDATA%\QuicklIME\themes`
2. 同名の組み込みテーマ
3. どちらも無ければ組み込みの `capsule` (診断ログに出す)

- 組み込みと同じ名前のファイルを置くと、ファイルが勝つ (組み込みのテーマを全体的に手直しするため)
- AppContainer で動くアプリ (スタートメニューの検索欄など) でも読めるよう、エンジンが起動時にテーマフォルダへ中身に継承する
  読み取りの ACE を足す ([tools.md](tools.md)「AppContainer のアプリから読むための権限」)
- `\ / : * ? " < > |` を含む名前・`.`・`..` はファイルとして探さず、`capsule` を使う (フォルダの外を指させないため)

### テーマファイルの読み込み

書式は [入力パネルのテーマ](../user/theme.md)「テーマファイルの書式」。

- 重ねる順は、すべてのキーの既定値 (`capsule` と同じ見た目) → `base` の組み込みテーマ → ファイル自身の行。
  ファイルの中は、`light.` / `dark.` の付かない行を先に、今の配色に合う接頭辞の行を後に重ねる (書いた順によらず
  接頭辞の付いた行が勝つ)。同じ順位の中では後の行が勝つ
- `base` は何行目に書いても先に重ねる。`base` に書けるのは組み込みテーマだけ (循環を避けるため)。組み込みに無い
  名前は `capsule` にして診断ログに出す
- 不明なキー・読めない値・色以外のキーに付けた `light.` / `dark.` は、その行だけ無視して診断ログに出す。数値は範囲に
  丸め、丸めたことを診断ログに出す
- `border`・`shadow`・`caret_marker` は形と色の両方のキー。値が `#` で始まれば色、それ以外は形として読む
- 色の `caret_marker` を書かなかったテーマでは、重ね終えた `accent` (ライト・ダークそれぞれ) を三角の色にする。
  `accent` だけを変えたテーマでも三角の色が追従するようにするため
- `blur on` と `caret_marker pointer` が両方あるテーマでは、読み込んだときに診断ログに 1 行出す (下記「ぼかし」)
- 配色は Windows のアプリモード (`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` の
  `AppsUseLightTheme`。値が無ければライト) で選び、ライト・ダークを解決した 1 組 (`PanelTheme`) にする

### 組み込みテーマ

| 名前 | 内容 |
|---|---|
| `capsule` | 背景・縁・影のあるパネルに、両端が半円の候補を横一列に並べる。すべてのキーの既定値そのもの |
| `capsule-column` | `capsule` の配色で候補を縦に積み、行に種類のタグを付ける |
| `capsule-blur` | `capsule` の背景をぼかしにする |
| `ghost` | 枠を持たず、大きな文字で入力行とゴーストを出し、その下に番号つきの候補を並べる。入力行は設定によらず出す |

- 組み込みテーマは、テーマファイルと同じ形式の文字列として DLL に持ち、同じ読み込み処理で解釈する (形式と実装を
  一致させるため)
- 既定の配色はロゴの色 (スレート #2D3437・ミント #7DC7B0・オフホワイト #FAFBF7) から取る
  - ダークの `selected_text` はスレートにする。ミントは明るく、白い文字ではコントラストが足りない
  - ライトの `accent` は暗いティール (#2A7D66) にする。ミントのままでは白い背景の上で下線・キャレットが見えにくい
  - `next_word` はアンバー系にし、アクセントのミントと区別する

### 読み直し

- 設定の読み直しの機会 (フォーカスの移動と IME のオン/オフの切替。[tools.md](tools.md)「読み込みと反映」) に、
  選んでいるテーマファイルの有無と更新時刻を確かめる。設定ファイルが変わったとき、テーマ名・
  テーマファイルの有無・更新時刻が変わったときだけ読み直す。打鍵ごとには読まない
- アプリモード (ライト / ダーク) も、テーマを読み直すときにだけ読む
- 読み直したら、入力パネルにフォント・テーマ・ぼかしの有無を渡す (上記「出すとき・消すとき」)

## ぼかし

テーマの `blur on` で、入力パネルの背景をアクリル (背景のぼかし) にする。組み込みでは `capsule-blur`。

- ぼかしで描くときは layered window を使わず、通常の `WS_POPUP` (`WS_EX_TOPMOST | WS_EX_NOACTIVATE |
  WS_EX_TOOLWINDOW`) に `SetWindowCompositionAttribute` (user32 の非公開 API) で `ACCENT_ENABLE_ACRYLICBLURBEHIND` を当て、
  上に重ねる色を `blur_tint` にする。角丸は `DwmSetWindowAttribute` の `DWMWA_WINDOW_CORNER_PREFERENCE`
  (`DWMWCP_ROUND`) に任せる
- 中身は `ID2D1HwndRenderTarget` (software、premultiplied alpha、DPI 96) で透明の上に描く。背景・外周の縁・影は
  描かず (DWM が描く)、影の余白も取らない (ウィンドウの矩形 = パネルの矩形)
- ちらつかないよう、`WM_ERASEBKGND` では背景を消さず、位置・大きさを変えたら `WM_PAINT` を待たずにその場で描く
- 次のときは layered window の描画に戻し、理由を診断ログに出す
  - Windows の透明効果がオフ (`EnableTransparency` が 0。オフだとアクリルがぼかさず単色になる)。次にウィンドウを
    作るときに確かめ直す
  - `SetWindowCompositionAttribute` が無いか失敗した、`DWMWA_WINDOW_CORNER_PREFERENCE` の指定が失敗した (Windows 10
    など)、描画先を作れない。このパネルでは以後ぼかしを試さない (テーマのぼかしを切ってから入れ直すまで)
- ぼかしの有無が変わったら、表示中のパネルを隠し、次の表示から新しい方式でウィンドウを作る (作り方が違うため)
- 角丸は DWM の小さい角丸 (約 8px) になり、`panel_radius` やカプセルの半円にはならない
- ぼかしで描くパネルには吹き出しの尻尾を描けない (DWM の角丸ウィンドウの外に描けない)。`blur on` と
  `caret_marker pointer` が同じテーマにあるときはぼかしを優先し、尻尾は出さない (三角にも代えない)。layered window に
  戻ったときは尻尾を出す
- ぼかすかどうかは設定ではなくテーマのキーで決める。吹き出しとの組み合わせをテーマの中で完結させ、テーマで選んだ
  吹き出しが設定次第で消えないようにするため
- ぼかしで描くときは `style ghost` のにじみも描かない。組み込みの `ghost` は `blur off`
- 採らなかった案: `SetWindowRgn` で大きな角丸に切る。縁がギザギザになり、DWM の角丸と影も効かなくなる

## キャレットの印

入力中・候補選択中・後続語の予測の表示中に、文書のキャレットの位置をテーマの `caret_marker` の印で示す。
パネル保持入力では文書のキャレットがアプリの細い線だけになり、`caret` の候補バーも左端を run の先頭に固定するので、
打鍵が進むとキャレットがパネルの左端から離れるため。

### 出す期間と位置

- 出す期間: run 中・候補選択中 (composition がある間)・後続語の予測の表示中。それ以外 (run の終了・採用・確定・取消、
  フォーカス移動、IME オフ、キー入力が無効な文書) では消す
- 位置: composition があれば (composition 入力の run・候補選択中) composition の末尾 (空の範囲) の矩形、取れなければ
  composition の矩形の右端。折り返した composition では全体の矩形の右端がキャレットの位置にならないため、末尾の空の範囲を
  先に使う。composition が無ければ (パネル保持入力の run・後続語の予測) 上記「位置の基準」の候補バーと同じ矩形
- 矩形が取れないとき・代わりの位置に置き換えたときは出さない (上記「入力位置がウィンドウの外を指すとき」)
- 位置は打鍵ごと・入力パネルを出し直すごとに取り直す。スクロールとウィンドウの移動は追わない (入力パネルと同じ)
- 点滅させない

### 三角 (`triangle`)

- キャレットの矩形の下端に、先端を上に向けた正三角形 (高さ `triangle_size` × f、色 `caret_marker`) を出す。先端の x は
  キャレットの矩形の左端、先端の y は矩形の下端
- 入力パネルとは別の小さな layered window (`WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_LAYERED |
  WS_EX_TRANSPARENT`) で出す。パネルの有無・表示位置・`style`・ぼかしによらず出す。クリックは下のアプリへ通す
- 入力パネルと同じく、文書のルートウィンドウをオーナーにして作る (上記「入力パネル」「ウィンドウと描画」)。オーナーが
  変われば作り直し、オーナーと一緒に OS が破棄したときは次に出すときに作り直す
- `caret` で入力パネルをキャレット行の下に出すときは、三角の高さの分だけパネルを下げて重ねない

### 吹き出しの尻尾 (`pointer`)

- 入力パネル (候補バーと変換の候補一覧) の、キャレット行に向いた辺に二等辺三角形の尻尾 (高さ `pointer_size` × f、
  底辺は高さの 2 倍) を付ける。パネルがキャレット行の下なら上辺に上向き、上なら下辺に下向き
- 尻尾の塗りは `background`、縁は `border` (`border on` のとき) で、パネルと 1 つの輪郭にして描く。縁は尻尾の底辺の
  部分で切れ、影も尻尾ごと落とす (別々に塗ると重なりで濃くなるため)
- パネルは尻尾の高さの分だけキャレット行から離す (尻尾の先端がキャレット行に届く)
- 尻尾の先端の x はキャレットの矩形の左端。角丸にかからない範囲 (左右端から角丸の半径 + 尻尾の高さの内側) に止める
- 尻尾を付けるときは、パネルの左端を通常の位置から「角丸の半径 (切り上げ) + 尻尾の高さ」だけ左へずらす。ずらさないと
  尻尾が角丸を避けて右へ押し出され、打ち始めのキャレットを指せないため。打ち始めは尻尾がキャレットの真下に来て、
  打鍵が進むと尻尾だけが右へ動く。ずらした結果が作業領域からはみ出すときは作業領域に収め、尻尾は右へ押し出されてよい
- 描けないときは何も出さない (三角に代えない。テーマで選んだ見た目と違うものを出さないため)。描けないのは
  `center`・`style ghost` (付ける枠が無い)・ぼかしで描くとき・パネルを出していないとき・作業領域に収めたパネルが
  キャレット行に重なったとき (指す向きが決まらない)

## 入力モードの一時表示

IME のオン/オフの切替時と、別の入力欄へのフォーカス移動時に、キャレットの近くに「あ」(オン) / 「A」(オフ) を約 1 秒出す
(設定 `mode_popup`)。オン/オフはタスクバーのアイコンでしか分からず、視線のあるキャレットの近くでは打つまで分からない
ため。

### 出すとき

- IME のオン/オフが変わったとき (`GUID_COMPARTMENT_KEYBOARD_OPENCLOSE` の変化。キーでの切替もアイコンのクリックも含む)
  - プロセスで最初の文書フォーカスの処理 (起動時の IME の状態の適用。[input.md](input.md)「起動時の IME の状態」) より前の
    変化では出さない。適用前の状態を一瞬出してから切り替わって見えるため。適用したときは適用後の状態を出す
- 別の文書にフォーカスが移ったとき (アプリの切替を含む)。同じ文書への `OnSetFocus` では出さない (ダイアログの開閉などで
  戻るたびに出ると目障りなため)
- 出さないとき: 設定 `mode_popup` 0、入力欄でないとき (下記「入力モードのアイコン」の × の条件)、基準の矩形
  (`CaretRect`) が取れないとき・代わりの位置に置き換えたとき。フォーカス移動の直後にアプリがまだキャレットを置いて
  いなければ、待たずに出さない
- 表示中に出し直したときは、新しい字で描き直して 1 秒を数え直す
- QuicklIME の入力モードはオンとオフの 2 つなので、モードの変化はオン/オフの切替と同じ

### 見た目と位置

- 角丸の正方形に 1 字を出す。一辺は 96dpi で 28px を、キャレットのあるモニタの DPI (`GetDpiForMonitor`。使えなければ画面の
  DC の DPI) で拡大する
- 色は今のテーマの解決後の値 (背景 `background`、縁 `border` (`border on` のとき)、文字 `text`)。角丸の半径は
  `panel_radius` × f を一辺の半分までで使う。ぼかしと影は使わない
- 字は入力モードのアイコンと同じフォント (下記) で、「あ」の字形の外接矩形の長辺が一辺の 45% になる大きさにし、「A」も
  同じ大きさで描く。字ごとに外接矩形で上下左右の中央に置き、原点を整数 px に丸める
- 入力パネル・キャレットの印とは別の小さな layered window (`WS_EX_TRANSPARENT` を含む) で出し、フォーカスを奪わず、
  クリックは下のアプリへ通す
- 入力パネルと同じく、文書のルートウィンドウをオーナーにして作る (上記「入力パネル」「ウィンドウと描画」)。オーナーが
  変われば作り直す
- 位置: 左端を基準の矩形の左端、上端を矩形の下端に置く。作業領域の下端からはみ出すときは矩形の上端の上に出す。左右は
  作業領域に収める

### 消すとき

- 出してから 1 秒で消す (フェードしない)
- 1 秒を待たずに消す: キー入力 (`OnTestKeyDown`・`OnKeyDown`・preserved key。食べるキーもアプリへ渡すキーも)、
  フォーカス移動 (移った先で出すなら出し直す)、入力パネル・キャレットの三角を出したとき、テキストサービスの終了
- オーナーを閉じたときは OS がオーナーと一緒に破棄する。次に出すときに作り直す

### 採らなかった案

- IME オンの間、キャレットの近くに印を出し続ける: 入力していない間はキャレットの移動 (クリック・スクロール) を知る手段が
  無く、印が違う場所に残る。常に出ていると目障りでもある
- 切替時の大きな表示と常時の小さな印の併用: 上と同じ理由
- キャレットが取れないときにウィンドウ中央や画面中央に出す: 視線から離れた場所に出ても気づきにくく、状態と無関係な
  場所に出すほうが紛らわしい

## 入力モードのアイコン

タスクバーの入力インジケータ (`GUID_LBI_INPUTMODE`) に出すアイコン (tsf/src/lang_bar.cpp `CreateModeIcon`)。

| 状態 | 字 |
|---|---|
| 入力欄でない | 「×」(U+00D7)。オン/オフより優先する |
| IME オン | 「あ」 |
| IME オフ | 「A」 |

- 入力欄でないのは、フォーカスに document manager・context が無いか、context の `GUID_COMPARTMENT_KEYBOARD_DISABLED` か
  `GUID_COMPARTMENT_EMPTYCONTEXT` が立っているとき (`TextService::IsKeyboardDisabled`。CorvusSKK と同じ判定)。入力欄で
  ない所で `EMPTYCONTEXT` を立てないアプリでは「×」にならない
- アイコンはフォーカスの移動 (`ITfThreadMgrEventSink::OnSetFocus`) と IME のオン/オフの切替で作り直す。フォーカスを
  移さずに context の `KEYBOARD_DISABLED` だけが変わったときは作り直さない
- 背景は透明で、字だけを描く。字の色はタスクバーのテーマ (`Personalize` の `SystemUsesLightTheme`。1 ならライトで黒、
  それ以外・値が無ければダークで白)。アイコンを作るたびに読む。Windows のテーマを切り替えても、次に作り直すまでは
  古い色のまま (即時に追従するには設定変更の通知を受ける隠しウィンドウが要り、それに見合わないため)
- 一辺は `MulDiv(16, LOGPIXELSY, 96)` px (画面の DC の DPI)。「あ」の字形の外接矩形の長辺が一辺 − 2px になる大きさを
  求め、「A」「×」も同じ大きさで描く。「×」は小さく見えるが、状態の違いが分かれば十分なので拡大しない
- 字ごとに字形の外接矩形 (`GetDesignGlyphMetrics`) をアイコンの上下左右の中央に置き、原点を整数 px に丸める (線を
  ぼかさないため)
- アンチエイリアスはグレースケール。アイコンは描いた後に別の背景へ合成されるため
- D2D (`ID2D1DCRenderTarget`、software) で 32bpp の DIB に描き、文字色の単色で straight alpha (RGB = 文字色、A = 被覆率)
  に直して `CreateIconIndirect` に渡す。mask は 0 で埋めた 1bpp のビットマップ (32bpp の alpha があれば使われないが、
  未初期化の内容は渡さない)

### フォント

- M PLUS Rounded 1c Regular (SIL Open Font License 1.1) を「あ」「A」「×」の 3 字にサブセット化し
  (tsf/src/Font/MPLUSRounded1c-Regular-icon.ttf、scripts/subset-icon-font.py で再生成)、DLL のリソース (`RCDATA`) に入れる。
  入力モードの一時表示も同じフォントを使う
  - 元のフォントは約 3.4MB あり、DLL は全プロセスにロードされるため、使う字以外は持たない
  - サブセットは生成物としてコミットする。ビルドに Python や元のフォントを要らないようにするため
  - 別ファイルにせずリソースに入れる。DLL からの探索とインストーラの管理が増えるため
  - 太さは Regular。タスクバーの時計 (Segoe UI Regular) と線の太さがそろい、なじむため
  - 同梱できる (アプリへの埋め込みが許諾されている) フォントから選ぶ
- リソースのメモリを返す `IDWriteFontFileLoader` / `IDWriteFontFileStream` を自前で持ち、フォントコレクションは作らずに
  font face を作る。対応 OS の下限 (Windows 10 1607) に `CreateInMemoryFontFileLoader` (1703 以降) が無いため
- DirectWrite の factory は `DWRITE_FACTORY_TYPE_ISOLATED` にする。自前の loader を登録するので、プロセスで共有の factory を
  汚さないため
- リソースのフォントを読めなければ、システムの Yu Gothic UI で同じ描き方をする
- OFL の本文と著作権表示は tsf/src/Font/LICENSE-MPLUSRounded1c.txt に置き、インストール先に同梱する

### 採らなかった案

- フォントを画像 (.ico) に描き出して同梱する: DPI ごとの大きさをそろえる必要があり、テーマの色も画像ごとに要る。
  実行時に描けば、どの DPI でも鮮明で色も選べる
- 「×」を線で描く・拡大する: 違いが分かれば十分なので、フォントの字をそのまま使う
- 入力欄でないときに `TF_LBI_STATUS_DISABLED` を返す (CorvusSKK の方式): 右クリックのメニューも使えなくなる

## 言語バー

- タスクバーの入力インジケータに項目 (`TF_LBI_STYLE_BTN_BUTTON | TF_LBI_STYLE_SHOWNINTRAY`) を出す
- 左クリックで IME のオン/オフを切り替える。「×」の間は何もしない (切り替えてもアイコンが「×」のままで、状態が見えない
  まま変わるため)
- 右クリックで「設定...」「単語登録...」のメニューを出し、設定ツール・単語登録ツールを起動する (CorvusSKK と同じ方式)。
  「×」の間も使える (デスクトップなどからも設定を開けるようにするため)
- `GetStatus` は常に 0 を返す

## 文書の composition の表示属性

文書の composition に付ける表示属性 (tsf/src/display_attribute.cpp)。色は指定せず (`TF_CT_NONE`)、下線の形だけを決める。

| 属性 | 下線 | 付けるところ |
|---|---|---|
| 入力中 (`TF_ATTR_INPUT`) | 点線 | run の読み、候補選択中の現在文節以外と、範囲を縮めて外したかな |
| 変換対象の文節 (`TF_ATTR_TARGET_CONVERTED`) | 実線の太線 | 候補選択中の現在文節 (`segment_ui` 0 では範囲の変換結果全体) |

## 入力パネルの見本の描画

設定ツールの「見た目」ページの見本のために、DLL は入力パネルを画像に描く関数 `QuicklimePanelPreview` を公開する
(tsf/src/preview.cpp、tsf/src/exports.def)。設定ツールでの読み込みと表示は [tools.md](tools.md)
「入力パネルの見本」。

- 入力パネルの描画 (`SuggestPanel`) をウィンドウを作らずにそのまま使い、layered window に出すのと同じ画像 (影・にじみの
  余白を含む) を、上から下へ並ぶ BGRA (premultiplied alpha) の画素で返す
- 引数はテーマ名 (`panel_theme` の値)・フォント名・フォントの大きさ (px)・見本の種類 (0: 入力パネル、1: 変換の候補一覧)。
  画素のバッファは呼び出し側が渡し、足りなければ必要な大きさ (幅・高さ) を返して `ERROR_INSUFFICIENT_BUFFER` で失敗する。
  あわせて、解決したテーマがダークか・ぼかしが on かを返す
- テーマは呼ぶたびに TSF 層と同じ規則 (上記「テーマの選び方」) で読み直し、パネルを作って捨てる (状態を持たない)。
  ダーク / ライトは今のアプリモード
- 見本の内容は固定

| 見本 | 入力行 | 候補 | 選択 |
|---|---|---|---|
| 入力パネル | `きょうは` | 今日は (変換)、京は (変換)、今日はいい天気 (予測)、教派 (変換)、kyouha (英字) | 2 番目 |
| 変換の候補一覧 | 変換中: 文節 `今日は` `いい` `天気`、現在文節は 1 番目 | 今日は、京は、教派、強は、きょうは | 2 番目 |

- 入力行は、テーマが `input_row setting` でも出す (見本では設定 `panel_input` を見ない)
- 位置はキャレットの下 (`caret`) の規則で、プライマリモニタの作業領域の左上をキャレットとして組む (下に収まるので
  縦積みでも反転しない)。キャレットの印 (尻尾・三角) は描かない
- ぼかしは DWM の効果なので再現せず、ぼかしの無い描画で描く
- 採らなかった案: 設定ツールの側で入力パネルの見た目を作り直す。テーマのキーが多く、描画を二重に実装するとすぐに
  実物とずれる

## 設定

値の書式と設定ツールでの名前は [設定一覧](../user/settings.md)。どれも TSF 層が読む。

| 設定 | 既定 | 本書での働き |
|---|---|---|
| `candidate_position` | `caret` | 入力パネルの表示位置 (`caret` / `center`)。ほかの値は無視する |
| `panel_input` | 0 | 1 で入力パネルに入力行を出す (`candidate_bar` 1 のとき。パネル保持入力の run は設定によらず出す) |
| `panel_theme` | `capsule` | テーマ名。空の値は無視する |
| `candidate_font` | `Yu Gothic UI` | 入力パネルのフォント (31 文字まで)。見つからなければ Yu Gothic UI |
| `candidate_font_size` | 18 | 入力パネルの寸法の基準 f (px。10〜40 に丸める)。入力モードの一時表示の角丸にも使う |
| `mode_popup` | 1 | 0 で入力モードの一時表示を出さない |
| `candidate_bar` | 1 | 0 で候補バーと入力行 (パネル保持入力の run を除く) を出さない。変換の候補一覧は出す |
