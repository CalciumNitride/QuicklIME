# 候補バーと予測

入力中に入力パネルへ並べる候補バーと、読みなしの後続語の予測の仕様。候補バーの候補と並び (SUGGEST)、
打鍵のファジィ照合、選択と採用、採用範囲の縮め、ページ送り、LLM の並べ替えの結果の反映、後続語の予測と
文節の連なりの統計を扱う。

- 利用者向けの操作の説明は [候補バーと表示](../user/candidate-bar.md) にある
- 入力パネルの見た目・表示位置・テーマ・キャレットの印は表示の側で、今は設計書にある
  ([suggest-panel.md](../design/suggest-panel.md)・[panel-theme.md](../design/panel-theme.md)・
  [panel-above-caret.md](../design/panel-above-caret.md)・[caret-marker.md](../design/caret-marker.md))
- 英字候補と英字区間の大文字小文字の補正の候補の作り方はモードレス入力の側
  ([modeless-commit-candidate.md](../design/modeless-commit-candidate.md)・[english-case.md](../design/english-case.md)・
  [mixed-conversion.md](../design/mixed-conversion.md))
- 全体変換の候補 (CONVNBEST の N-best と並び・補正の候補・LLM の並べ替えと生成) はエンジンの側
  ([nbest.md](../design/nbest.md)・[typo-conversion.md](../design/typo-conversion.md)・
  [unified-suggest.md](../design/unified-suggest.md) の D・[llm-rerank.md](../design/llm-rerank.md)・
  [llm-generate.md](../design/llm-generate.md))
- 学習の割引の式と学習の削除は学習の側 ([learning-score.md](../design/learning-score.md)・
  [forget-learning.md](../design/forget-learning.md))
- キーの状態別の表は今は [keymap.md](../design/keymap.md) にある。本書は機能の中で候補バーのキーの挙動を書く
- SUGGEST・PREDICT・NEXTWORD の形式は [docs/protocol.md](../protocol.md)
- 実装は tsf/src/text_service.cpp (バーの組み立て・選択・並べ替えの反映)、tsf/src/text_service_direct.cpp
  (キーの判定・採用・採用範囲の縮め・後続語の予測)、tsf/src/suggest_panel.cpp (ページ送り)、
  engine/src/suggest.rs (SUGGEST の並び)、engine/src/predict.rs (予測・PREDICT・NEXTWORD)、
  engine/src/typo.rs (ずれのモデル)、engine/src/dict.rs (fst の照合)

## 候補バーの候補

run の確定済みかなを読みにした候補を、入力中に入力パネルへ並べる。文書は採用したときだけ書き換える。

| 種類 | 内容 | 作る側 |
|---|---|---|
| 英字候補 | モードレス入力で、今 run を終えたら英字になる形か、開いている英字区間の大文字小文字を補正した形。最大 1 件 | TSF 層 |
| 全体変換 | 読み全体の変換 (補正の候補を含む)。最大 3 件 | SUGGEST の `whole`・`typo` |
| 予測候補 | 打鍵と照合した予測 (ずれを使ったものを含む) | SUGGEST の `predict`・`predict_typo` |

- 並びは英字候補を先頭に、続けて SUGGEST が返した順。TSF 層は並べ替えない
- 英字候補と表記が同じ候補は除く (全体変換と予測の表記の重複はエンジンが除く)
- 英字候補を足して合計が `max_predictions` を超えるときは、エンジンの並びの最後の 1 件を落とす。最後の 1 件が
  全体変換の先頭 (SUGGEST が 9 番目に入れたもの) なら、その 1 つ前を落とす (全体変換の先頭を 2 ページ目に送らないため)
- 区間分割した run (日本語区間の後ろに開いている英字区間が続く run) は、日本語区間を読みにして全体変換だけを出す。
  読みの後ろに英単語が続き、読みを延ばす予測は合わないため。全体変換は英字区間を付けて見せる (`今日はgithub`)
  - 閉じた英字区間だけを含む run は区間分割した run にしない (予測も出す)

### 件数

- `max_predictions` (9 / 18 / 27 / 36、既定 9) は候補バーの合計の上限。ページの件数 (9) の倍数にして、候補が
  十分にあれば最後のページも 9 件で埋まるようにする
- 9 の倍数でない値は 9 の倍数へ切り上げ、範囲外は 9〜36 に丸める (8 → 9、10 → 18、100 → 36)。エンジン
  (engine/src/config.rs)・TSF 層 (tsf/src/config.cpp)・設定ツール (engine/gui/src/config.rs) で同じ規則にする
- エンジンは SUGGEST・PREDICT・NEXTWORD を `max_predictions` 件まで返す
- 採らなかった案: 予測候補の件数だけを 9 の倍数にする。英字候補・全体変換が加わるので合計がそろわず、最後の
  ページが半端になる

### 表示の条件

- run の確定済みかなが `min_suggest_chars` (1〜5、既定 2) 文字以上のときに出す。未完成のローマ字は採用の
  対象外なので数えない。英字候補は文字数によらず出す (`pen` は「ぺん」、`want` は「わんt」で 2 文字)
- 出さないとき
  - 候補選択中 (変換の候補一覧を出している)
  - 設定 `candidate_bar` 0
  - モードレスの英字モード中 (英字区間の大文字小文字の補正の候補だけを出す。区間分割した run は日本語区間に出す)
  - 候補が 1 件も無いとき
- 打鍵ごとに作り直し、作り直すと選択は外れる。エンジンへの問い合わせは接続を待たない。未接続ならエンジンを
  起動だけして、その打鍵では候補なしとして扱う (打鍵を止めないため)
- 横の位置は、run で最初にバーを出した時点のキャレットの x に固定する (打鍵ごとに左右へ動かさない)。採用範囲を
  縮めた採用で run の先頭が変わったときは、次に出す時点の位置で取り直す
- `candidate_bar` 0 では、バーを出さず打鍵ごとの問い合わせもしない。英字候補と後続語の予測も出ない。run 中の
  Tab・↑ / ↓ は他の編集キーと同じく run を終えてアプリへ渡す
- 設定 `suggest` 0 では予測を出さず、全体変換だけを出す (エンジンが予測を入れない)

### 採用せずに run を終えたとき

- run を終えるキー (確定キー・Space・Enter・矢印・キャレット移動・フォーカス移動など) で、選んでいない候補を
  自動で採用しない。かなのまま (未完成のローマ字も見えているとおりに) 文書に残す
- 確定キーも、候補を選んでいなければ全体変換もモードレスの run 終了時の英字判定も当てず、見えているとおりに
  run を終える。Enter で送信するアプリで、見えている文字と送られる文字を食い違わせないため
- 採らなかった案: 先頭の候補を選んだ状態でバーを出す。未選択の確定キーは打ったとおりに終える規則が崩れ、
  かなのままを望む読みほど推測と食い違うため

## SUGGEST の並び

エンジンは全体変換と予測を 1 つの点数 s (小さいほど上) で並べて返す (engine/src/suggest.rs)。雑に打っても
「打つ → 並びから選ぶ」で入力できるよう、予測を全体変換と同じ並びで比べる。

- 採らなかった案: TSF 層で並べ替える。候補のコストが TSF 層に届かず、届けるにはプロトコルでコストを渡すことになり、
  点数の規則がエンジンと TSF 層に分かれるため

### 全体変換の枠

- CONVNBEST と同じ並び (打鍵による補正の候補を含む。並びはエンジンの側) の先頭から、表記が読みのかなと
  同じ候補を除いて最大 3 件 (`MAX_WHOLES`)
- 書き換えの候補 (表記をひらがなに直すと読みと同じになる候補。「ヨロシクオネガイシマス」「オヤスミなさい」の
  ように、かなの種類だけが違うもの) は 1 件まで
  - 表記がかなと同じ候補を除いた上位 3 件の中に書き換えの候補があれば、その最初の 1 件を取り、取った全体変換の
    最後に置く。残りの枠は書き換えでない候補から並びの順に取る。足りなければ書き換えの候補で埋めずに空ける
  - 通常の最良経路と読み全体の学習表記は、かなの種類だけが違っても書き換えの候補にしない (最良経路がカタカナに
    なる外来語はそのまま先頭に出る)
  - 辞書 (特に UT 辞書) には読み全体を 1 語にした書き換えの項目が多く、2 語に分かれる変換 (「お休み / なさい」)
    より安く出て全体変換の枠を埋めるため。1 件を残すのは、カタカナで書きたい表記を候補バーから選べるようにする
    ため (ほかの書き換えは F6〜F8 で出せる)

### 予測

次のものを打鍵と照合して集める (下記「ファジィ照合」)。

1. ユーザ辞書の短縮よみ
2. ユーザ辞書の名詞系の語
3. 句の学習 (確定履歴)。前文脈があれば、前文脈に続いた文節 (文脈の句の学習) で句の学習に無いものも入れる
4. 同梱辞書の語とインポート辞書の語

- 句の学習は点数の小さい `max_predictions` 件だけを入れる。学習は数千件あり、短い打鍵では多く当たるため
- 表記が読みのかなと同じ予測は出さない。同じ表記の予測は点数の小さいほうの 1 件にする
- 予測は設定 `suggest` 1 で、かなが `min_suggest_chars` 文字以上のときだけ入れる
- 予測の読みは候補の完全な読み (辞書の正しい読み) で、採用の学習にそのまま使う

### 点数

C0 は全体変換の通常の最良経路のコスト (経路が無ければ 0)。

| 候補 | s |
|---|---|
| 全体変換 | その候補の経路のコスト − C0。前の候補の s を下回る値は前の候補の s に切り上げる。経路のコストを持たない候補 (補正で先頭にした候補・数字の書き方など) と、最後に置いた書き換えの候補は前の候補の s (先頭なら 0) |
| 予測 (辞書の語・ユーザ辞書の名詞系の語) | その語 1 語だけの経路のコスト − C0 + ずれのコスト + `PREDICT_BIAS` (2000) |
| 予測 (句の学習) | `PHRASE_BASE` − 句の学習の割引 − 前文脈の文脈の句の学習の割引 − C0 + ずれのコスト |
| 予測 (短縮よみ) | −1 + ずれのコスト (通常の最良経路のすぐ上) |

- 全体変換の切り上げは、CONVNBEST の並びの順を崩さないため
- 1 語だけの経路のコストは、変換の Viterbi と同じ式 (前文脈からの接続・語の学習の割引を引いた単語コスト・文末への
  接続・文節境界ペナルティ) で求める。学習した文節境界の増減は含めない
- `PREDICT_BIAS` は、崩していない打ち終えた入力で、先頭が全体変換の最良経路から変わらない値にする。0 では
  「ひく → 低い」のように、長い語の予測が打ち終えた読みの全体変換より上に出る
- 割引の式と `PHRASE_BASE` などの定数は学習の側 ([learning-score.md](../design/learning-score.md) の B)

### 並べ方

1. 読み全体の学習表記 (CONVNBEST の先頭にあるとき) を先頭に固定する
2. 残りを s の小さい順に並べる。同じ s なら全体変換を先に、同じ種類の中は元の順
3. 表記が同じ全体変換と予測は、並びの位置によらず全体変換を残し、位置は 2 つのうち上にする。全体変換は文節を
   持ち、採用範囲の縮めと全体変換の学習が効くため。それ以外の表記の重複は先に来たほうを残す
4. 通常の最良経路が保護の対象 (学習で表記が変わった・ユーザ辞書の語や英字を含むなど。判定はエンジンの側) なら、
   補正の候補とずれのある予測を、ずれの無い候補のうち s ≤ 0 のものすべての後ろに置く。最良経路の表記が読みの
   かなと同じで並びに入っていなくても同じにする (学習でかなのままの表記を選んだ読みでも、補正をその上に出さないため)
5. 全体変換の先頭 (読み全体の学習表記が無ければ通常の最良経路) が 10 番目以降になるときは 9 番目に入れる
   (1 ページ目に入れる)
6. `max_predictions` 件で切る

### 候補の種類

- `whole` (全体変換)・`typo` (全体変換の補正の候補)・`predict` (予測)・`predict_typo` (ずれを 1 つ以上使った予測)
- `typo` と `predict_typo` は「補正」の表示で出す (テーマのキー `typo`・`tag_typo`。表示の側)
- 予測の候補が未完成のローマ字まで使って照合したかは区別しない (採用では未完成のローマ字を捨てる。下記「採用」)

## ファジィ照合

予測は打鍵のずれを許して常に照合する。ずれは打鍵 (ローマ字) の上で測る。

### 打鍵の受け渡し

- TSF 層は、かな 1 字ごとの由来の打鍵と未完成のローマ字を SUGGEST に付けて送る (書式は
  [docs/protocol.md](../protocol.md) の SUGGEST)。2 字以上のかなを 1 かたまりで作った打鍵 (`kyo` → きょ) は 1 字目に
  付き、2 字目以降は空
- 文書から読んだかな (入力なしの対象のかななど) は打鍵がかなそのもの。エンジンは ASCII でない要素を打鍵なしとし、
  打鍵の無いかなを標準の綴りで補う
- 区間分割した run は、日本語区間の打鍵だけを送り、未完成のローマ字は付けない (英字区間の後ろにあるため)
- 同じ打鍵を CONVNBEST・RERANK にも付け、全体変換の補正に使う (エンジンの側)。変換キーの候補一覧と候補バーで
  同じ補正の候補になる
- かなを標準のローマ字に戻した近似では、`romaji.tsv` を変えた人の綴りと打ちかけのローマ字を扱えないため、
  打鍵そのものを送る

### ずれのモデル

ずれは打鍵の上の重み付きの編集距離で測る (engine/src/typo.rs の `TUNING`)。単位は辞書の単語コストと同じ。

| 種類 | 内容 | 定数 | 値 |
|---|---|---|---|
| 隣のキー | QWERTY で隣のキーに置き換わった | `EDIT_ADJACENT` | 3000 |
| 余分 | 余分な 1 打 | `EDIT_EXTRA` | 3500 |
| 抜け | 1 打の抜け | `EDIT_MISSING` | 3500 |
| 入れ替え | 隣り合う 2 打の入れ替え | `EDIT_SWAP` | 3000 |

- 隣でないキーへの置き換えは誤りとして扱わない
- かなの綴りは、標準の綴り (訓令式・ヘボン式。「っ」の子音の重ね、「ん」の `n` / `nn`) に、この run でそのかなを
  実際に作った打鍵を足した集合とする。`romaji.tsv` で変えた綴りを誤りとみなさないため
- 先頭のかなの打鍵には誤りを認めない。打ち間違いが稀なうえ、誤補正の元になるため
- 許すずれの数は、打鍵の数 n (未完成のローマ字を含む) から `min(MAX_EDITS, n / KEYS_PER_EDIT)` (切り捨て)。
  `KEYS_PER_EDIT` 4・`MAX_EDITS` 3 で、3 打以下は 0、4〜7 は 1、8〜11 は 2、12 以上は 3。短い打鍵は 1 打違いの別の語が
  多く、誤補正ばかりになるため
- 値は評価 (engine/examples/fuzzy_eval.rs) で決めた。コストを下げると崩した入力の回復は少し上がるが、崩していない
  入力で補正が上位に出る件数が増える。`KEYS_PER_EDIT` を 5 以上にすると途中まで打った崩した語の回復が落ち、
  `MAX_EDITS` 2 は誤り 3 か所の回復が落ちる
- 同じモデルを全体変換の補正にも使う (エンジンの側。[unified-suggest.md](../design/unified-suggest.md) の D)
- 設定 `typo_correction` 0 では、ずれを 0 にして照合する (完全な前方一致と同じ結果)

### 予測の照合

- 打鍵の末尾は候補の読みの途中で終わってよい。末尾のかなは綴りの途中まで (`arigat` の `t`) 一致していればよく、
  そこにコストはかけない
- 同梱辞書・インポート辞書 (fst) は、かなの辺をたどりながら辺のかなの綴りと打鍵を DP で照合し、使ったずれが許す数を
  超えた枝を切る。たどるノードの数は `MAX_FUZZY_VISITS` (20 万) で打ち切る (長い打鍵で検索が膨らんだときの安全弁)
- 打鍵を使い切った位置 (読みの接頭辞) を、ずれのコストの安い順に `MAX_FUZZY_PREFIXES` (8) まで取り、その先の語を
  前方一致で列挙する。同じ語は点数の安いほうを残す
- 学習とユーザ辞書は読みを線形に走査し、1 件ずつ照合する
- 採らなかった案: ローマ字をキーにした辞書を別に持つ。照合は単純になるが、辞書のメモリが倍近くになる

## 旧エンジンとの互換

- SUGGEST に「不明なコマンド」を返すエンジンには、その接続では以後送らず、CONVNBEST (打鍵なし) と PREDICT
  (前文脈つき) で並びを作る。並びは英字候補 → 全体変換 (表記がかなと同じ候補を除いた上位 3 件) → 予測候補
  (合計 `max_predictions` 件まで)。区間分割した run では PREDICT を送らない。並べ替えの依頼にも打鍵を付けない
- PREDICT (engine/src/predict.rs の `predict`) は、読みの前方一致で次の順に集める。表記の重複は先勝ちで除き、
  表記がかなと同じ候補は除く
  1. ユーザ辞書の短縮よみ
  2. 文脈の句の学習 (前文脈があるとき。割引の大きい順)
  3. ユーザ辞書の名詞系
  4. 句の学習 (確定履歴。割引の大きい順)
  5. 同梱辞書とインポート辞書の語 (コスト順に混ぜる。同じコストは同梱辞書が先)
- ユーザが登録した語 (1・3) は履歴より先に出す。インポート辞書は数十万語になりうるため、履歴より前に置くと枠を
  占領する。同梱辞書と同じ一般語として扱う
- 5 までで枠が埋まらず、読みが 3 文字以上なら、かなを標準の綴りに戻した打鍵で照合し、ずれを使って一致した位置から
  続く同梱辞書の語を単語コスト順で足す。枠が埋まれば照合しない。短い読みは 1 かな違いの別の語が多く、誤補正ばかりに
  なるため 3 文字からにする
- かなが `min_suggest_chars` 文字未満のときと `suggest` 0 のときは候補なしを返す

## 選択

- Tab / ↓ で次、Shift+Tab / ↑ で前の候補を選ぶ。未選択から次で先頭を選ぶ。未選択からの前は何もしない
  (キーは食べる)。末尾から次は先頭へ、先頭から前は末尾へ循環する。未選択に戻すのは Esc
- キャレット行の上に反転して出した縦積みの入力パネルでは、↑ / ↓ を見た目の向きに合わせて入れ替える
  ([panel-above-caret.md](../design/panel-above-caret.md))
- 横一列のテーマ (`layout row`) で候補を選んでいるときは、← / → も前 / 次の候補へ選択を動かす (先頭で ← は末尾へ)。
  候補が横に並ぶので左右の矢印で動かせるほうが見た目に合うため
  - 未選択の ← / → はキャレット移動としてアプリへ渡す (run を終える・後続語の予測を消す)。選ぶ前に奪うとキャレットを
    動かせなくなるため
  - 縦積みのテーマと、Shift / Ctrl / Alt を併せた ← / → は対象外
- 選択では文書を書き換えない
- バーに候補があるときの run 中の Tab・↑ / ↓ は選択に使い、アプリへ渡さない
- 候補選択中の Tab / Shift+Tab は、変換を取り消して run に戻り、候補バーの先頭を選ぶ
- 数字キー 1〜9 (修飾なし) は選択に使わず、ほかの印字キーと同じに扱う (選んでいれば採用してその数字から続ける)。
  番号での採用は Ctrl+1〜9 (下記「採用」)

## 採用

### 採用の操作

- 確定キー: 選んでいる候補を採用する。採用範囲を縮めた全体変換は run を続け、それ以外は run を終える
- Enter / Ctrl+M: 採用して run を終え、Enter をアプリへ渡す
- Space: 採用して run を終え、スペースを入れる。幅は設定 `space` に従い、Shift+Space と、モードレスが有効なときの
  英字モード中・英字候補の採用は半角 (英文の語の区切りのため)
- 印字キー (数字を含む): 採用し、その打鍵から続ける
- Ctrl+1〜9 (Shift・Alt なし): 選択によらず、今出しているページ内のその番号の候補を、確定キーと同じく採用する。
  番号で選び直すので、採用範囲を縮めていても全体を採用する。ページに無い番号は食べて何もしない
  - 候補バーが出ている間は、アプリの Ctrl+数字 (ブラウザのタブ切り替えなど) より候補バーの操作を優先する
- 上記以外のアプリへ渡すキー (Home / End / Delete、縦積みのテーマの ← / → など) は、候補を選んでいても採用せずに
  run を終えて渡す

### 採用の結果

| 候補 | 文書に入れるもの | run |
|---|---|---|
| 全体変換 | 読み (確定済みかな) 全体を候補の表記にする | run を終える採用では、未完成のローマ字 (区間分割した run では英字区間も) を後ろに続けて入れる。印字キーでは、残り (未完成のローマ字・英字区間) とその打鍵で run を続ける |
| 採用範囲を縮めた全体変換 | 範囲の文節の表記 | 確定キー・印字キー: 残りのかなで run を続け、前文脈を範囲の最後の文節にしてバーを作り直す。Enter・Space: 残りのかなも文書に入れて run を終える (残りは採用せずに終えた run と同じ扱い) |
| 予測候補 | 候補の表記 | 未完成のローマ字を捨てる |
| 英字候補 | 英字候補の形 | 読みを英字候補の状態に置き換え、採用した部分は英字区間になる。印字キーは英字区間に打鍵を続け、それ以外は run を終える |

- 予測の採用で未完成のローマ字を捨てるのは、予測が未完成のローマ字も含めて照合しているため (`arigat` で「ありがとう」を
  採用すると `t` は残らない)。全体変換は確定済みかなだけから作るので、未完成のローマ字を残す
- 文書への入れ方は入力方式による (composition 入力は composition を採用の文字列で終え、パネル保持入力は
  キャレット位置に挿入する。[input.md](input.md)「入力中の読みの表示 (`input_buffer`)」)
- 採用した部分は run から外す。以後その文字列を IME が書き換えることはない

### 採用の後

- 学習 (学習しないアプリでは送らない)
  - 全体変換: 候補の文節ごとの (読み, 表記, 直前の文節の表記) と、2 文節以上なら読み全体 → 表記の連結 (文脈なし) を
    1 回の LEARN2 で送る。変換キーの入力全体の候補の確定と同じ ([conversion.md](conversion.md)「学習」)
  - 採用範囲を縮めた全体変換: 範囲の文節ごとの (読み, 表記, 直前の文節の表記)。読み全体は送らない
  - 全体変換の補正の候補 (`typo`): 範囲を縮めたときも送らない。打ち間違えた読みで学習データを汚さないため
  - 予測候補 (`predict_typo` を含む): 候補の読み (辞書の正しい読み) と表記を、前文脈の表記を付けて送る
  - 英字候補: 変換せずに確定したときと同じ (英字を含む読みは 読み = 表記)
- 次の前文脈は、採用した最後の文節 (予測候補は候補の読みと表記)
- 採用した部分を採用した文字列の記憶に 1 件として足す ([conversion.md](conversion.md)「採用した文字列の記憶」)。
  LLM の左文脈の履歴にも足し、run が続くときは run の左文脈に採用した文字列を足す (文書を読み直さない)
- 確定アンドゥの記憶は、run を終えた採用では文書に入れた文字列全体 (スペースを含む) と採用前の読み。採用範囲を
  縮めて Enter・Space で終えたときは、残りのかなの部分だけを記憶する。採用の後に run が続いている間は、
  それより前の確定アンドゥの記憶を捨てる (続く run の手前が採用した文字列になるため)

### 採用範囲の縮め

長い入力を前から順に片付けられるよう、選んだ全体変換の先頭の文節だけを採用できる。

- run のバーで全体変換 (`whole`・`typo`) を選んでいるとき、Shift+← で採用する範囲を末尾から 1 文節縮め、Shift+→ で
  1 文節伸ばす。単位はその候補の文節で、範囲は先頭の 1 文節から全文節まで
- 選びはじめは全文節。選択を動かすと (番号での選び直しを含む) 全文節に戻る
- 文節が 1 つの候補・予測候補・英字候補・範囲の端・文節の読みの連結が読みと一致しない候補では何もしない。
  キーは食べる (バー選択中にキーの意味を候補によって変えないため)
- 未選択の Shift+← / → は run を終えてアプリへ渡す
- 縮めている候補は採用する部分と外した部分を描き分け、種類のタグを「文節」にする (見た目は表示の側)
- 採らなかった案
  - 先頭文節の候補を並びに混ぜる。部分採用は前から片付ける操作で、選ぶ候補と意味が違う。長い入力で上位に来やすく、
    全体変換・予測の枠を取る
  - 読みの 1 字ごとに採用範囲を動かす。どんな区切りにもできるが、切るたびに前の部分を変換し直すので表記が
    変わりうる。区切りの違いは変換キー (範囲の伸縮) で直せる

## ページ送り

候補バー (run のバーと後続語の予測) はページに区切って出し、選択で全候補に届く (tsf/src/suggest_panel.cpp)。

- 1 ページは最大 9 件 (`SuggestPanel::kMaxItems`)。番号はページ内で 1〜9。選択中の候補を含むページを出す
- 区切りは先頭から順に決め、選択によって変えない (同じ候補は常に同じページ・同じ番号)
  - 縦積み (`layout column`): 1 ページの行数は、9 と、入力パネルを出す側 (キャレット行の下か上) に収まる行数の
    小さいほう。位置の表示の行を含めて数える
  - 横一列 (`layout row`): 先頭から入力パネルの幅に収まるだけ (最大 9 件) を 1 ページにし、次のページはその続きから
    同じように詰める。ページごとに件数が違ってよい。1 件で幅を超える候補は単独で 1 ページにする。幅には位置の表示の
    幅も含める (パネルの幅は表示の側)
- 全体が 1 ページに収まるときは位置の表示を出さない。超えるときは `12/24` (全 24 件中 12 番目を選択中。未選択は
  `-/24`) を出す (置き場所は表示の側)
- 選択の移動はページの境目で隣のページに切り替わる。未選択のとき (Esc で未選択に戻ったときを含む) は 1 ページ目を出す
- Ctrl+1〜9 は今出しているページ内の番号に対応する
- PageUp / PageDown はページ送りに使わない (run 中は run を終えてアプリへ渡す)
- 採らなかった案: 縦積みで画面に収まるだけ全部並べ、10 件目以降は番号なしにする。横一列のテーマでは幅で切れて
  件数が増えず、並べ方によって届く候補が変わるため

## LLM の並べ替えの結果の反映

- 設定 `llm` 1 のとき、確定済みかなが `min_suggest_chars` 文字以上の読みでバーを作り直すたびに、同じ読み・前文脈・
  打鍵で RERANK を依頼する。結果は 20 ms ごとに RERANKGET で問い合わせ、1 秒を過ぎたら問い合わせをやめる。
  並べ替えと生成の規則 (9 文字未満の読みは並べ替えないなど) はエンジンの側 ([llm-rerank.md](../design/llm-rerank.md)・
  [llm-generate.md](../design/llm-generate.md))
- 結果が届いたら、次をすべて満たすときだけバーを組み直す
  - 依頼が最新 (バーを作り直すたびに依頼し直す)
  - 候補を選んでいない。選んでいる最中に並びを変えると、選んだ候補が動くため
  - 候補選択中でない
  - バーを作った読みが依頼した読みと同じ
  - 組み直した並びが表示中の並びと違う
- 組み直しでは、全体変換の枠を結果の候補の上位から埋め直す。枠の位置と数、予測候補・英字候補の位置は変えない
  - 結果の候補を先頭から順に枠へ入れる。表記が読みのかな・バーの予測候補と英字候補・すでに入れた候補と同じものは飛ばす
  - 結果で埋まらない枠には、元の全体変換を元の順で入れる (すでに入れた表記は飛ばす)
  - 入れた候補の文節と補正の印は、結果の候補のものを使う
- 組み直しても横の位置は動かさない
- 変換キーの候補一覧は、結果が出ていれば結果の並びをそのまま使う ([conversion.md](conversion.md)「入力全体の候補選択 (`segment_ui` 0)」)

## 学習の削除の後の候補

候補を選んでいる間の Ctrl+Delete (`key.forget_learning`) は、選んでいる候補の学習を消して候補を作り直す。
消す組・作り直し・選択の扱いは学習の側 ([forget-learning.md](../design/forget-learning.md))。

## 後続語の予測

run を終えた直後、読みを打つ前に、直前の語に続きそうな語を候補バーに出す (POBox 風の連続予測)。

### 候補

前文脈 (最後に確定した文節の読みと表記) で NEXTWORD を引く (engine/src/predict.rs の `next_words`)。

1. 文脈の句の学習 (前文脈の表記の末尾 16 文字で引く。割引の大きい順)
2. 文節の連なりの統計の文節の表 (前文脈の表記の末尾 16 文字で引く。回数の多い順)
3. 統計のバックオフの表 (前文脈の最後の自立語の表記で引く。回数の多い順)。前文脈を辞書の語に分けられないとき・
   自立語が無いときは引かない

- 表記の重複は先勝ちで除き、`max_predictions` 件で切る
- 学習が無効 (`learning` 0) でも、既存の学習と統計は使う。`suggest` 0 では何も返さない
- 辞書 (Mozc) には語の連接の統計が無く、zenz はかな漢字変換の形式のモデルで読みなしの生成に向かないため、
  どちらも使わない
- 打ち始めた後の予測には統計を使わず、前文脈は文脈の句の学習としてだけ効かせる (上記「点数」と、旧エンジンの PREDICT)。
  統計の利用は [roadmap.md](../roadmap.md) の見送り
- 採らなかった案: 学習と統計を 1 つの点数で混ぜる。まずは学習を先に並べ、評価で必要が見えたら検討する

### 出すとき・消すとき

- 出すとき: 確定キーで run を終えたとき (候補バーの採用・候補選択の確定・かなのまま)、候補バーの Ctrl+1〜9 の採用で
  run を終えたとき、後続語の予測を確定キーか Ctrl+1〜9 で採用したとき (続けて次の語を出す)
- 出さないとき: Space・Enter・アプリへ渡すキーで run を終えたとき、候補選択中の Ctrl+1〜9 で確定したとき (Enter と
  同じ確定)、前文脈が無いとき、候補が無いとき、`candidate_bar` 0・`next_word` 0 のとき、エンジン未接続のとき
  (接続を待たない)、NEXTWORD を知らない旧エンジンのとき
- 横の位置は、出すたびにその時点のキャレットの位置にする (run のバーと違って読みが伸びないため)
- 消すとき
  - 選んでいないときに、選択の機能 (`NextWordNext` / `NextWordPrev`) と Ctrl+1〜9 以外のキーを押した。そのキーは
    予測が無いときと同じに処理する
  - 選んでいるときに、下記の選択・採用に使うキー以外を押した
  - IME の外でキャレット (選択) が動いた・フォーカス移動・IME オフ・キー入力が無効な文書で打鍵した

### 選択と採用

- `NextWordNext` (`key.next_word_next`、既定 Ctrl+↓) で、未選択から先頭を選ぶ。`NextWordPrev` (`key.next_word_prev`、
  既定 Ctrl+↑) で、未選択から末尾を選ぶ。予測が出ていないときは食べずにアプリへ渡す
- 選んだ後は、run のバーと同じ選択のキー (Tab / ↓ / Shift+Tab / ↑、横一列のテーマの ← / →) が働く
- 採用はキャレット位置への追記で行い、既存の文字列は書き換えない
  - 確定キー: 候補を入れ、続けて次の語の予測を出す
  - Ctrl+1〜9: 選択によらず、今出しているページ内のその番号の候補を確定キーと同じく入れる。予測が出ている間は、
    ページに無い番号でも食べる (アプリの Ctrl+数字は効かない)
  - Enter / Ctrl+M: 候補を入れてから Enter をアプリへ渡す
  - Space: 候補を入れてからスペースを入れる。幅は設定 `space` に従い、Shift+Space と、モードレスが有効で候補が
    英数字だけのときは半角
  - 印字キー (数字を含む): 候補を入れてから、その打鍵で新しい run を始める。`digits half` の数字もアプリへ渡さずに
    run を始める (予測の採用と数字の入力を 1 打鍵で順序どおりに行うため)
  - Esc: 予測を消す (キーは食べる)
  - 変換キーなどの機能 (確定キーと学習の削除を除く): 予測を消し、入力なしの機能として処理する
- 学習: (読み, 表記, 前文脈の表記) を送る (学習しないアプリでは送らない)。採用した語を次の前文脈にする
- 採用した語を採用した文字列の記憶に足す。確定アンドゥの記憶にもし、Ctrl+Backspace でスペースを含めて読みのかなに戻る
- 採らなかった案: 選んでいるときだけ Ctrl+数字を食べる。アプリのショートカットとの衝突は避けられるが、入力パネルが
  出ている間は IME が食べる、という規則のほうが分かりやすいため

## 文節の連なりの統計

日本語版ウィキペディアの本文から数えた文節の連なりの表 (next_word.tsv) で、学習の無い前文脈でも後続語の予測を出す。
学習だけでは、使い始めや初めて確定した語の後で何も出ない。公開されている日本語の n-gram (Google 日本語 N-gram など) は
配布の条件が厳しく同梱できない。

### コーパス

- 日本語 Wikipedia の本文だけを使う (CC BY-SA 4.0)。生成した表に出典とライセンスを付けて同梱する
- 取得元は `https://dumps.wikimedia.org/other/cirrus_search_index/<日付>/index_name=jawiki_content/` の
  `jawiki_content-<日付>-NNNNN.json.bz2` (wiki 記法を除いた本文を持つ JSON。14 分割)
  - この置き場所は週ごとに作られ、直近 4 週だけが残るので、版を固定して取り直せない。取得スクリプトは日付を引数に取り、
    取得したファイルの名前・サイズ・SHA-256 を `references/jawiki/manifest.tsv` に書く
  - 置き場所は `references/jawiki/` (git 管理外)。生成した表もコミットしない (UT 辞書と同じ扱い)
- 同梱する表は 14 分割のうち 4 分割 (00000〜00003) から作る。1 分割の取得に約 30 分かかり、全分割では約 7 時間かかるため。
  使う分割は取得スクリプトの引数で指定する
- 採らなかった案: Web コーパス (CC-100 など) を使う・併用する。話し言葉に近いが、権利と規約が曖昧でノイズも多い。
  書き言葉に偏る点は受け入れる

### 文節への分け方

- 本文の各行を、逆変換の対象の文字 (かな・漢字・数字・〇・〆) の連続ごとに区切る。句読点・記号・英字・空白は区切りに
  なり、区切りをまたいだ文節の組は数えない
- 区切った連続を逆変換 (engine/src/reverse.rs) で語の列 (読み, 表記) にする。学習とユーザ辞書は空にし、利用者のデータに
  依らない表にする。逆変換が失敗した連続 (格子が繋がらない・読みが長すぎる) は捨てる
- 語の列を、変換と同じ規則で文節にまとめる (付属語は前の語にまとめる。先頭の付属語は単独の文節にする)
- 隣り合う 2 つの文節 (前, 次) を数える。次の組は数えない
  - 前か次の表記に数字を含む組
  - 前か次が付属語だけの文節 (区切りの直後の先頭の付属語) の組。読点の直後の「と」「は」などは予測の文脈としての
    価値が低いため
  - 前か次が未知語を含む組。「ー」「ベイカ」のような断片が文脈にも候補にも入るため。未知語は次のもの
    - どの語にも当たらないかなの 1 文字として格子に入れた語
    - 本文のカタカナ (ー を含む) の 2 文字以上の連続を、逆変換が 1 文字の語を含む語の列に割ったときの、その連続の
      すべての語。辞書に無いカタカナ語 (ベイカー) は辞書にある 1 文字の語を使って「ベイカ|ー」のように割られ、上の
      未知語の印が付かないため。1 語で引けたカタカナ語 (タワー) と、2 文字以上の語だけに割れた連続
      (コンピュータ|ウイルス) は残す
    - 表記が「ー」で始まる語 (ひらがなの後の長音 `すごーく` → ー|く は、カタカナの連続の判定に掛からないため)
  - 単漢字辞書の読みの語は未知語にしない (辞書の読みで読めているため)
- Wikipedia の定型文 (「時点の → オリジナルより」「脚注の → 使い方」など) は除かない。利用者がまず打たない文脈でしか
  出ないため
- 逆変換の読み誤り (何の → なにの、一日 → ひといち) は表に入る。採用するとその読みで学習されるが、読みと表記の対応としては
  誤りでないことが多く、実害は小さいため受け入れる

### 表

- 2 つの表を持つ。値は次の文節の (読み, 表記) と回数
  - 文節の表 (`c`): 前の文節の表記 (文脈の句の学習と同じく末尾 16 文字) → 次の文節
  - バックオフの表 (`b`): 前の文節の最後の自立語の表記 → 次の文節。前の文節に自立語が無い組は数えない
- 出現が 15 回未満の組は捨てる。表が 30MB 以内に収まる最小の値で、4 分割では最小回数 10 で 44.6MiB、15 で 28.5MiB、
  20 で 20.7MiB だった。表の大きさを決めるのは最小回数で、文脈の 9 割以上は候補が 9 件以下のため上位の件数を減らしても
  小さくならない
- 文脈ごとに回数の多い順に上位 36 件 (`max_predictions` の上限) を残す。同じ回数は表記の順
- ファイルは next_word.tsv (UTF-8、BOM なし)。1 行 1 件で、表の区別・文脈・読み・表記・回数のタブ区切り。文脈ごとに
  まとめ、回数の多い順に並べる

```
c<TAB>今日は<TAB>いいてんき<TAB>いい天気<TAB>12
b<TAB>今日<TAB>いいてんき<TAB>いい天気<TAB>15
```

- 形式は TSV のままにする。最小回数 15 の表 (約 81 万行、約 28MiB) の読み込みは約 0.12 秒で、別の形式は要らない

### 生成

- `scripts/fetch-wiki-ngram.ps1`: 日付と分割の番号を引数に取り、ダンプを `references/jawiki/` に取得して manifest.tsv を書く。
  取得済みでサイズが取得元と一致する分割は取り直さない。取得後に生成ツールを実行する
- `engine/examples/build_next_word.rs`: ダンプの .json.bz2 の本文 (1 行 1 文書のうち `text` を持つ行) を読み、上の規則で
  next_word.tsv を書く。辞書は Mozc 辞書と UT 辞書を使う。終わりに、文書数・連続の数・逆変換に失敗した連続の数・
  数えた組の数・残した文脈の数と件数・所要時間を出す。手順は [docs/development.md](../development.md)

### エンジンでの読み込み

- next_word.tsv の場所は UT 辞書と同じ規則で決める。辞書ディレクトリ直下を優先し、無ければプロジェクトルートの
  `references/jawiki/next_word.tsv`。`QUICKLIME_DICT_DIR` を指定したときはプロジェクトルートを見ない
- 起動時に別スレッドで読み込む。読み込みが終わるまでと、ファイルが無いときは、表が無いものとして学習だけで動く
- インストーラでの同梱とライセンスの表示は配布の側 ([next-word-ngram.md](../design/next-word-ngram.md) の F)
- 採らなかった案: 品詞の連接 (Mozc の連接コスト) だけで次の語を出す。助詞程度しか出ず、語の予測にならない

## 設定

値の書式と設定ツールでの名前は [設定一覧](../user/settings.md)。

| 設定 | 既定 | 読む側 | 本書での働き |
|---|---|---|---|
| `candidate_bar` | 1 | TSF 層 | 0 で候補バー・英字候補・後続語の予測を出さない |
| `min_suggest_chars` | 2 | エンジン・TSF 層 | 候補バーを出し、予測を入れる確定済みかなの文字数 (1〜5) |
| `max_predictions` | 9 | エンジン・TSF 層 | 候補バーの合計の上限 (9 / 18 / 27 / 36) |
| `suggest` | 1 | エンジン | 0 で予測と後続語の予測を返さない (候補バーは全体変換だけ) |
| `typo_correction` | 1 | エンジン | 0 で照合のずれを許さない (全体変換の補正の候補も作らない) |
| `next_word` | 1 | TSF 層 | 0 で後続語の予測を出さない (打ち始めた後の予測での前文脈の効き方は `suggest` に従う) |
| `llm` | 0 | エンジン・TSF 層 | 1 で全体変換を LLM で並べ替え、結果を候補バーに反映する |
