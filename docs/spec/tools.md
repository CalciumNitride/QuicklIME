# 設定ファイルと設定ツール

設定ファイル (config.tsv) と、それを書き換える設定ツール (quicklime-config.exe) の仕様。設定ファイルの書式・読む側・
読み込みと反映、設定ツールの起動・画面の構成・保存・各ページ、キー割当とアプリのページ、入力パネルの見本の表示、
単語登録ツール (quicklime-regword.exe) の画面を扱う。

- 利用者向けの説明は [設定一覧](../user/settings.md)・[アプリごとの設定](../user/app-settings.md)・
  [キー割当](../user/keymap.md) にある
- 各設定キーの意味・既定値は、その機能の仕様書の「設定」の節などにある (下記「設定キーの一覧」)。本書はキーごとの意味を
  重複させず、設定ファイルの書式・読み込みと、設定ツールでの見せ方と書き出し方を書く
- キー割当の行 (`key.*`) の書式・割り当てられないキー・照合は [keys.md](keys.md)「設定ファイルの書式」
  「割り当てられないキー」「割当の照合」。本書は設定ツールのキー割当のページを書く
- テーマの選び方とテーマファイルの読み込みは [display.md](display.md)「テーマ」、入力パネルの見本を描く DLL の関数は
  [display.md](display.md)「入力パネルの見本の描画」。本書は設定ツールでの選択肢と見本の表示を書く
- 単語登録ツールの起動・登録・インポートの働きは [dictionary.md](dictionary.md)「単語登録ツール」。本書は画面だけを書く
- RELOADCONFIG の形式は [docs/protocol.md](../protocol.md)。設定ツール・単語登録ツールの exe の探し方とインストーラは実行と
  配布の側 ([runtime.md](runtime.md)「exe の探し方」「インストーラ」)
- 実装は engine/gui/src/config.rs (設定ファイルの読み書き・選択肢)、engine/gui/src/keys.rs (キー割当の表記と検査)、
  engine/gui/src/apps.rs (アプリごとの設定)、engine/gui/src/preview.rs (見本の DLL の呼び出し)、engine/gui/src/win32.rs
  (キーの取り込み・ファイル選択・実行中のアプリとフォントの列挙・二重起動の防止)、engine/gui/src/bin/quicklime-config.rs
  (設定ツールの画面の状態と保存)、engine/gui/ui/ (画面)、engine/gui/src/bin/quicklime-regword.rs と
  engine/gui/ui/regword.slint (単語登録ツールの画面)。読む側は engine/src/config.rs (エンジン)、tsf/src/config.cpp
  (TSF 層)、tsf/src/text_service.cpp `RefreshConfig` (TSF 層の読み直しの機会)。AppContainer のアプリ向けの読み取りの ACE を
  足す処理は engine/src/package_acl.rs (設定ツールは `#[path]` で共有する) で、エンジンは engine/src/main.rs
  `spawn_grant_app_packages_read` から呼ぶ

## 設定ファイル

### 場所と書式

- `%APPDATA%\QuicklIME\config.tsv`。環境変数 `QUICKLIME_CONFIG_FILE` があればそのパス (エンジン・TSF 層・設定ツールで同じ)
- UTF-8 の `キー<TAB>値` の行。行末の CR は除く。`#` で始まる行はコメント。タブの無い行は読み飛ばす。最初のタブで分け、
  値にはそれより後ろを全部使う
- TSF 層は先頭の UTF-8 BOM を除いて読む。エンジンと設定ツールは除かない。設定ツールは BOM を付けずに書く
- 知らないキーは無視する。読めない値の行は無視し、そのキーは前の行の値か既定値のままにする。同じキーの行が複数あれば
  後の行が勝つ
- エンジンは自分の読むキーだけを、TSF 層も自分の読むキーだけを読む (互いのキーは知らないキーとして無視する)。設定ツールは
  全部のキーを読む。3 か所の値の規則 (範囲・丸め・読めない値) は同じにする

### 読み込みと反映

- エンジンは起動時と RELOADCONFIG を受けたときに読む。読み直したときの LLM の子プロセスの起動・終了は
  [docs/protocol.md](../protocol.md) の RELOADCONFIG
- TSF 層は、アクティブ化 (`ActivateEx`)・文書へのフォーカスの移動 (`OnSetFocus`)・IME のオン/オフの切替のときに、
  設定ファイルの更新時刻を確かめる。初回と、更新時刻が変わったとき (ファイルが無くなったときを含む) だけ、既定値に
  戻してから読み直す。消したキーを既定に戻すため。打鍵ごとには読まない
  - 設定ツールで値を変えてアプリに戻る操作自体がフォーカスの移動なので、実質すぐ反映される
  - テーマの読み直しも同じ機会に行う ([display.md](display.md)「読み直し」)
  - `modeless` だけは、読み直しの通知が来ないアプリでも効くよう、打鍵ごとにも読んだ値を渡し直す
- エンジンは RELOADCONFIG を受けないと読み直さない。設定ツールは書くたびに RELOADCONFIG を送る (下記「保存」)
- ファイルが無い・開けないときは既定値で動く

### AppContainer のアプリから読むための権限

AppContainer で動くアプリ (スタートメニューの検索欄・UWP アプリなど) の TSF 層は、`%APPDATA%\QuicklIME\` のファイルを
そのままでは読めず、既定値で動く。そこで、TSF 層が読む設定のファイルとフォルダに、ALL APPLICATION PACKAGES
(S-1-15-2-1) の読み取り (FILE_GENERIC_READ) の ACE を足す。

- 対象は config.tsv・ローマ字テーブル (romaji.tsv。[input.md](input.md)「ローマ字テーブル」)・テーマのフォルダ (themes。
  [display.md](display.md)「テーマ」)。パスは TSF 層と同じ規則で求める (`QUICKLIME_CONFIG_FILE`・`QUICKLIME_ROMAJI_FILE`・
  `QUICKLIME_THEME_DIR` を `%APPDATA%\QuicklIME\` 配下より優先)
- 今の DACL に足す (置き換えない)。同じ ACE がすでにあれば何もしない。DACL が NULL (誰にでも許す) なら何もしない
- テーマのフォルダの ACE は中のファイルとフォルダに継承させる (OI|CI)。今ある中身にも継承させ、中のファイルを置き換えても
  継承で付く
- 学習 (learning*.tsv)・ユーザ辞書 (userdict.tsv)・インポート辞書 (imported) には付けない。入力の履歴を UWP アプリに
  丸ごと読ませないため
- `%APPDATA%\QuicklIME\` のフォルダ自体には付けない。AppContainer のトークンも走査のチェックを省く特権
  (SeChangeNotifyPrivilege) を持つので、ファイルをフルパスで開ける
- 足すのは次の 2 か所。どちらも失敗しても動作を続ける (エンジンは標準エラーに出し、設定ツールは無視する)。AppContainer の
  アプリで既定値になるだけのため
  - エンジンの起動時。辞書の読み込みを待たせないよう別のスレッドで足す。無いパスは飛ばす
  - 設定ツールが config.tsv を書いた後 (下記「保存」)。一時ファイルからの置き換えで、置き換えたファイルは親のフォルダから
    継承した ACL になり、足した ACE が消えるため
- 手で編集したエディタがファイルを置き換えた場合や、romaji.tsv・themes を新しく作った場合は、次にエンジンが起動するまで
  AppContainer のアプリでは既定値で動く

## 設定ツール

### 起動

- 設定の画面は引数なしで起動する。入力なしの状態の `key.open_config` (既定 Ctrl+F12、[keys.md](keys.md)「機能」) か、言語バーの
  メニューの「設定...」([display.md](display.md)「言語バー」) で TSF 層が起動する。TSF 層は起動の前に
  `AllowSetForegroundWindow(ASFW_ANY)` を呼ぶ。IME を持つアプリのプロセスから起動したウィンドウが前面に出られるようにするため
- 引数 `--add-language-list` があれば画面を出さず、起動した利用者の言語の一覧 (日本語のキーボード) に QuicklIME を足して
  終わる。インストーラがインストールの後に動かす ([runtime.md](runtime.md)「インストーラ」)。`input.dll` の
  `InstallLayoutOrTip` を `0x0411:{QuicklIME の CLSID}{プロファイルの GUID}` と `ILOT_INSTALL` で呼ぶ。`input.dll` は
  SDK に import library が無いので、System32 から読み込んで呼ぶ。CLSID とプロファイルの GUID は TSF 層
  (tsf/src/globals.cpp) と同じ値を定数で持つ。失敗しても何も出さない。設定の画面を開いていても動くよう、下の二重起動の
  防止より前に処理する
- 二重に起動しない。名前付き mutex `QuicklimeConfig` が既にあれば、タイトル「QuicklIME の設定」のウィンドウを探して
  (最小化されていれば元に戻して) 前面に出し、終了する。winit のウィンドウクラス名は自分で決められないので、タイトルで探す。
  mutex の名前はパイプ名や `QUICKLIME_CONFIG_FILE` によらず 1 つ
- Slint のバックエンドは winit に固定する。キーの取り込みとファイル選択に HWND が要り、winit 以外では取れないため
- 起動時に設定ファイルを一度だけ読む。開いている間に外で書き換えた内容は読み直さず、次に値を変えたときに設定ツールの
  値で上書きされる
- 起動時は「変換」のページを出す。最後に開いたページは覚えない
- AppContainer で動くアプリ (スタートメニューの検索欄など) の TSF 層は、`key.open_config` でも言語バーのメニューでも設定ツールを
  起動しない。AppContainer の中から起動したツールは同じ AppContainer で動き、設定を保存できないため
  ([runtime.md](runtime.md)「AppContainer のアプリ」)

### 画面の構成

- Slint 1.16 の fluent スタイル。ウィンドウタイトルは「QuicklIME の設定」。大きさは変えられ、最小 720 × 480、
  初めは 1000 × 720 (論理ピクセル)
- 左に幅 280 のナビ、右にページ。ページは見出しが固定で、その下をスクロールする。各項目は Windows 11 の設定アプリの
  カード (見出し・説明・右端のコントロール) で並べる。オン/オフは Switch、選択肢 (数値を含む) は ComboBox
- 展開カードは、見出しの行を押すと開閉する。閉じた状態の右端に要約の文字かキーのチップを出す。見出しの行に Switch を
  置けるのは展開カードの決まった位置だけで、任意の部品を差し込む口は作らない (Slint の `@children` は 1 か所にしか置けない)
  - 見出しの行は UIA では Invoke のできるボタンとして出し、読み上げの説明の先頭に「展開」「折りたたみ」を付ける。
    `accessible-expandable` を付けると、Slint 1.16 + AccessKit では UIA に ExpandCollapse も Invoke も出ず、ナレーターが
    状態を読まず操作もできないため。見出しの行の Switch は別の項目として UIA に出る
  - フォーカスの枠は Tab で移ってきたときだけ出す (設定アプリと同じ)
- UI のフォントは Yu Gothic UI、ナビとカードのアイコンは Segoe Fluent Icons の字形
- 配色はライト・ダークとも Windows 11 の設定アプリの既定に合わせた単色で、OS のダークモードに fluent スタイルが追従するのに
  連動する。ハイコントラストの配色と Mica は無い ([roadmap](../roadmap.md) の未着手)
- エラーはウィンドウ上部の InfoBar で知らせ、メッセージボックスは使わない
- 旧ツールにあった Esc で閉じる・Enter で保存・Ctrl+Tab でのページの移動・アプリの一覧の [既定に戻す] は無い。保存の操作が
  無く、Windows 11 の設定アプリにも無い操作のため

### 保存

- 保存のボタンは無い。値を変えるたびに、300 ms まとめてから設定ファイルを書き、エンジンへ RELOADCONFIG を送る。300 ms の間に
  次の変更があれば待ち直す。コンボを続けて切り替えたときに、書き込みと LLM の子プロセスの起動・終了を繰り返さないため
- ウィンドウを閉じるときに、書いていない変更があれば書く
- 書き込みは、同じディレクトリの一時ファイル (`config.tsv.tmp`) に書いてから置き換える。書き込みの途中を TSF 層・エンジンが
  読まないため。TSF 層は削除の共有を許さずに読むので、読んでいる瞬間は置き換えが失敗しうる。20 ms おきに 5 回までやり直す
- ディレクトリが無ければ作る。書けなければ、ウィンドウ上部に「設定を保存できませんでした」の InfoBar (エラー。閉じる
  ボタンなし) を出し、次に書けたら消す
- 書いた後に、config.tsv へ AppContainer のアプリ向けの読み取りの ACE を足す (上記「AppContainer のアプリから読むための
  権限」)。失敗しても知らせない
- RELOADCONFIG はパイプを開いて送るだけで、エンジンを起動しない。開けない・応答を読めないときは何もしない
  (ファイルが正なので、エンジンの次の起動で読まれる)

### 書き出す内容

- 全部のキーを、決まった順に、節ごとのコメント行を付けて書く (engine/gui/src/config.rs `file_text`)。読み込んだファイルの
  コメント・知らないキー・読めなかった行は書き戻さない。読めない値は既定値で、丸めた値 (`max_predictions` など) は丸めた後で書く
- `key.*` は機能ごとに基本の割当を書き、状態別の上書きがあれば続けて状態の順に `key.<機能>@<状態>` を書く。割当の無い値は `none`
- `newline_apps`・`ime_start_apps`・`no_learning_apps` は空でも書く (`newline_apps` を空で書くと対象なし)
- `debug_log` は値があるときだけ書く
- `input_buffer` と `panel_input` は下記「入力中の読み」の規則で書く
- `fuzzy_level` を書き、`typo_correction` の行は書かない。読み込みでは、`fuzzy_level` の行が無く `typo_correction 0` が
  あれば −1 として読む (エンジン・TSF 層と同じ規則)

### ページと項目

| ページ | 項目 (設定キー) |
|---|---|
| 変換 | 学習する (`learning`)、ファジィ入力の強さ (`fuzzy_level`。下記のスライダー)、文節単位で変換する (`segment_ui`)、AI で候補を並べ替える (`llm`。展開カードの見出しの Switch。展開すると実行環境 `llm_backend`) |
| 候補バー | 候補バーを表示する (`candidate_bar`)、入力中に予測を表示する (`suggest`)、確定の後に次の語を予測する (`next_word`)、次の語の予測を消すまでの時間 (`next_word_timeout`)、件数 (`max_predictions`)、表示を始める文字数 (`min_suggest_chars`)、表示位置 (`candidate_position`) |
| 入力 | 入力中の読み (`input_buffer`・`panel_input`)、スペース (`space`)、句読点 (`punctuation`)、数字 (`digits`)、モードレス入力 (`modeless`)、数字やメールアドレスの欄では日本語入力を使わない (`input_scope_passthrough`) |
| 見た目 | 入力パネルのテーマ (`panel_theme`。横に [テーマのフォルダを開く])、フォント (`candidate_font`)、サイズ (`candidate_font_size`)、オン/オフの切り替え時に「あ」「A」を表示する (`mode_popup`)、プレビュー (下記「入力パネルの見本」) |
| キー割当 | 下記「キー割当のページ」 |
| アプリ | 下記「アプリのページ」 |
| 詳細 | 診断ログを出力する・診断ログの出力先 (`debug_log`) |
| QuicklIME について | 版・Slint の帰属表示・同梱物とライセンス |

- コンボの選択肢: 実行環境は CPU (`cpu`) / GPU (Vulkan) (`vulkan`)、件数は 9 / 18 / 27 / 36、表示を始める文字数は 1〜5、
  表示位置はキャレットの下 (`caret`) / 画面中央 (`center`)、スペースは全角スペース (`full`) / 半角スペース (`half`)、
  句読点は `、。` / `，．` / `、．` / `，。` (値をそのまま出す)、数字は半角 (`half`) / 全角 (`full`)、サイズは 10〜40
- 文言は、ページの名前で分かる部分は省く。「サジェスト」とは書かず「予測」にする
- ファジィ入力の強さは、ほかの設定と同じカードの右端に「弱い」・スライダー・「強い」を並べて選ぶ (Windows の設定のスライダーの
  項目と同じ形)。スライダーは −1〜3、1 刻みで整数に吸い付き、目盛りは無い。選べる値が 5 つしかないので、幅は 100px の短いものにする。
  カードの説明には今の値の挙動を 1 行で出し、値を変えると切り替える。段階に名前を付けないのは、名前からは段階ごとの
  違いが分からないため (強さの程度はスライダーの位置で分かる)

| 値 | カードの説明に出す 1 行 |
|---|---|
| −1 | 打ち間違いを直さず、打ったとおりに変換する |
| 0 | 標準。確かな打ち間違いだけを直す (最後の文字は直さない) |
| 1 | 最後の文字の打ち間違いも直し、直した候補を先頭に並べる |
| 2 | 1 に加えて、打ち間違いの多い入力も直す |
| 3 | 直せる打ち間違いの数をさらに増やす。候補が出るまで少し遅くなる |

### 入力中の読み

`input_buffer` と `panel_input` を、入力のページの 1 つのコンボ「入力中の読み」で選ぶ。読みを出す場所を 1 か所で選べるように
するため (`input_buffer panel` のときは `panel_input` が効かない)。設定キーと TSF 層の働きはこの組で決まる
([input.md](input.md)「入力中の読みの表示 (`input_buffer`)」、[display.md](display.md)「入力行」)。

| 選択肢 (並び順) | 書く値 |
|---|---|
| 文書に下線付きで出す | `input_buffer composition`、`panel_input 0` |
| 文書と入力パネルの両方に出す | `input_buffer composition`、`panel_input 1` |
| 入力パネルだけに出す | `input_buffer panel`。`panel_input` は読み込んだ値のまま |

- 読み込むときは、`input_buffer` が `panel` なら 3 番目、そうでなければ `panel_input` の値で 1 番目か 2 番目を選ぶ
- 3 番目で `panel_input` を読み込んだ値のまま書くのは、手で書いた値を、設定ツールで別の項目を変えただけで変えないため
  (このとき `panel_input` は効かないので、どちらでも働きは同じ)
- テーマの `input_row always` は、どの選択肢でも入力行を出す ([display.md](display.md)「入力行」)
- 採らなかった案: `panel_input` を見た目の側のチェックボックスとして残し、`input_buffer panel` のときは無効にする。
  読みの表示先を 2 か所で選ぶ構造が残り、ページをまたいだ連動も要る

### 入力パネルのテーマとフォント

- テーマの選択肢は、組み込みのテーマ (カプセル (横一列) `capsule`・カプセル (縦積み) `capsule-column`・カプセル (ぼかし)
  `capsule-blur`・ゴースト `ghost`) に続けて、テーマフォルダの `*.tsv` (拡張子は大文字小文字を問わない) のファイル名
  (拡張子なし) を、大文字小文字を区別しない名前順に並べる。組み込みと同名のファイルは組み込みの項目だけを出し、大文字小文字
  だけ違うファイルは 1 つにまとめる (Windows のファイル名と同じく大文字小文字を区別しない)。テーマフォルダの決め方は TSF 層と同じ
  ([display.md](display.md)「テーマの選び方」)
- 組み込みのテーマの名前と表示名の対応は engine/gui/src/config.rs `BUILTIN_THEMES` に持ち、TSF 層の組み込みテーマと合わせる
- 今の設定値が選択肢に無ければ (ファイルを消したときなど)、その値を末尾に足す。選び直さずに保存しても値が変わらないため
- テーマとフォントの選択肢は起動時に作る。開いている間にテーマフォルダへ足したファイルは出ない
- [テーマのフォルダを開く] は、フォルダが無ければ作ってからエクスプローラーで開く。作れない・開けないときは
  「テーマのフォルダを開けませんでした」の InfoBar (エラー。閉じるボタンあり) を出し、開けたら消す
- フォントの選択肢は、インストールされているフォントの面名 (全 charset。縦書き用の `@` で始まる面名は除く) を、大文字小文字を
  区別しない名前順に並べる。今の設定値が列挙に無ければ足す (テーマと同じ理由)。31 文字を超える面名は、選んでも設定値を
  変えない (`candidate_font` に書けないため。[display.md](display.md)「設定」)
- 入力パネル (DirectWrite) で描けないビットマップ・ベクタのフォント (`System`・`Terminal`・`MS Sans Serif`・`Modern` など)
  は選択肢から外す。列挙のコールバックの `font_type` に `TRUETYPE_FONTTYPE` が立つか、`NEWTEXTMETRICW` の `ntmFlags` に
  `NTM_PS_OPENTYPE` か `NTM_TT_OPENTYPE` が立つ面名だけを残す (engine/gui/src/win32.rs `font_families`)。CFF の OpenType
  (UD 新ゴ・源ノ角ゴシック Code など) は `TRUETYPE_FONTTYPE` が立たず `DEVICE_FONTTYPE` で列挙されるため `ntmFlags` で拾う。
  コールバックの第 2 引数はビットマップフォントでも `NEWTEXTMETRICEXW` を先頭に持つ構造体を指すので、どの種類でも読める
- 選択肢を DirectWrite のファミリ名で作る方法は採らない。太さ違いの面名 (UD 新ゴ L など) を選べなくなり、`candidate_font`
  に保存してある GDI の面名とも合わなくなるため

### 診断ログ

- `debug_log` は TSF 層の診断ログの出力先のパス。空か行が無ければ出さない。TSF 層は 1 件ごとに、日時・プロセス ID・
  スレッド ID を前に付けた UTF-8 の行をファイルに追記する (tsf/src/debug_log.cpp)。キー入力が無効な文書 (パスワード欄など) の
  打鍵も記録するので、詳細のページのカードの説明で、調査が終わったらオフにするよう知らせる
- 詳細のページは、オン/オフの Switch と出力先の入力欄に分ける。入力欄は打鍵ごとではなく、Enter かフォーカスが外れたとき
  (とウィンドウを閉じるとき) に確定して保存する
- オンで出力先が空なら、`%APPDATA%\QuicklIME\debug.log` を書く。`QUICKLIME_CONFIG_FILE` で設定ファイルを移していても
  同じ場所。設定ファイルに `debug_log` が無いときも、入力欄には初めからこのパスを出す。オフにすると `debug_log` の行を書かない

## キー割当のページ

- 機能ごとに 1 枚の展開カードを、[keys.md](keys.md)「機能」の表の並びで並べる。見出しは機能の表示名、説明は働く状態の
  表示名を「・」でつないだもの。閉じた状態の右端には割り当てたキーのチップを出し、状態別の上書きのある機能では
  チップの代わりに「状態ごとに設定」と出す
- 状態の表示名は 入力なし (`idle`)・入力中 (`run`)・候補選択中 (`candidate`)・予測選択中 (`suggest`)。「run 中」は
  内部の呼び名で利用者に伝わらないため「入力中」に、「サジェスト」は「予測」にする
- 展開すると次を出す
  - キーのチップ (× で削除) と [+ キーを追加]。キーが無ければ「(なし)」
  - 「状態ごとに変える」のチェック。オンにすると、その機能が働く状態ごとに同じ形のキーの行を出す。オンにしたときは、
    各状態の行を今の基本の割当の写しで始める (オンにしただけでは働きを変えない)。オフに戻すと状態別の上書きを捨てる
  - [既定に戻す] (既定のままなら押せない)。状態別の上書きも捨てる
- ページ上部に [すべて既定に戻す]
- 機能の表示名と既定の割当は engine/gui/src/keys.rs `KEY_ITEMS` に持ち、並び・働く状態・既定を TSF 層 (tsf/src/config.h
  `KeyFunc`・tsf/src/config.cpp) と合わせる

### キーの取り込み

- [+ キーを追加] を押すと、その行が「キーを押してください」と [キャンセル] になり、次に押したキーを取り込む。Esc か
  [キャンセル] でやめる。取り込み中は全キーを受けるので Tab で [キャンセル] に移れない。Esc は元から割り当てられないキーなので、
  やめる操作に使っても失うものがない
- 取り込んだキーが割り当てられないキー ([keys.md](keys.md)「割り当てられないキー」) か、下記「重なりの検査」で重なるキーなら、
  足さずにカードの中に理由を出し、取り込みを続ける。足せたら取り込みを終える。同じ行に既にあるキーは重ねて足さない
- 修飾キーだけの押し始めは無視して、続けて押すキーを待つ。Win を押しているときは「Win キーとの組み合わせは割り当てられません」、
  IME が打鍵を処理した (`VK_PROCESSKEY`) ときは「IME がこのキーを処理したため取り込めません」を出す
- 理由に添えるキーの表記は設定ファイルの表記と同じ。ただし 0xF3・0xF4・0x19 は「半角/全角」と出す。半角/全角キーは押した
  状態で仮想キーがこれらに変わり、`VK_F3` などと出すと F3 キーに見えるため (どれも割り当てられないので設定ファイルには書かれない)
- 取り込みは、Slint のキーイベントではなく、取り込みの間だけウィンドウをサブクラス化して `WM_KEYDOWN`・`WM_SYSKEYDOWN` の
  仮想キーを読む。Slint のキーイベントでは変換・無変換・`VK_PROCESSKEY` を確実には受けられないため
  - `WM_KEYUP`・`WM_SYSKEYUP`・`WM_CHAR`・`WM_SYSCHAR` は捨てる。Alt・F10 を離したときのメニューの起動と、`WM_SYSCHAR` の
    警告音を出さないため
  - 取り込みの間は `ImmAssociateContextEx` で IME を外す (IME が打鍵を食べると元のキーが届かない)。終わったら、取り込みを
    始めた時点の状態に戻す。winit はフォーカスのある部品に応じて IME を付け外ししており、常に付けて戻すとボタンに
    フォーカスがあるときにも IME が効いてしまうため
- ページを移ったとき、取り込み中の機能の「状態ごとに変える」を切り替えたとき・[既定に戻す] を押したとき、
  [すべて既定に戻す] を押したとき、ウィンドウを閉じるときは、取り込みをやめる

### 重なりの検査

- キーを足すときに、足す先の状態 (状態ごとの行ならその状態、そうでなければその機能が働く全部の状態) で、別の機能が今使って
  いるキー (状態別の上書きがあればそれ、なければ基本の割当) と重なれば足さない。理由には、重なる状態と機能の表示名を出す
- 今の割当のどこかで、同じ状態で同じキーを 2 つの機能が使っていれば、ページ上部に警告の InfoBar を出し、最初に見つかった
  1 組 (状態・2 つの機能・キー) を示す。保存は止めない (TSF 層は [keys.md](keys.md)「割当の照合」の順で 1 つの機能に決める)。
  警告は割当を変えるたびに検査し直す

## アプリのページ

### アプリごとの設定と設定キー

- アプリごとに 1 枚の展開カード。見出しは exe 名。閉じた状態には、改行キーなし・自動・学習するから変えた設定の要約
  (「改行キーで Shift+Enter」「起動時の IME: オン」「学習しない」を「・」でつなぐ) を出す
- 展開すると、改行キーで Shift+Enter を送る (`newline_apps`)、起動時の IME (自動・オン・オフ。`ime_start_apps`)、
  このアプリでは学習しない (`no_learning_apps`)、[一覧から外す]
- 設定ファイルのキーは機能ごとに分けたまま、設定ツールの中ではアプリを軸にした 1 つの一覧として持つ (engine/gui/src/apps.rs)。
  あるアプリにどの設定をしているかを 1 か所で見られるようにし、TSF 層の読み方と既存の設定ファイルを変えないため
- 読み込み: `newline_apps` の順にアプリを並べ (改行キーあり)、続けて `ime_start_apps`、`no_learning_apps` にだけあるアプリを
  その順に足す。exe 名は大文字小文字を区別せずに照合し、表記は先に出たものを使う。値の読み方 (区切り・前後の空白・重複) は
  TSF 層と同じ ([input.md](input.md)「改行キー」「起動時の IME の状態」、[learning.md](learning.md)「学習しないアプリ」)
- `newline_apps` の行が無ければ、既定のアプリ (改行キーあり・自動・学習する) が並ぶ。既定のアプリの一覧は
  engine/gui/src/apps.rs `DEFAULT_NEWLINE_APPS` に持ち、TSF 層の既定と合わせる
- 保存: 一覧の順のまま、改行キーありのアプリを `newline_apps` へ、起動時の IME が自動でないアプリを `ime_start_apps` へ、
  学習しないアプリを `no_learning_apps` へ書く
- どの設定も既定 (改行キーなし・自動・学習する) のアプリは、どのキーにも書かれないので、開き直すと一覧から消える。
  設定の意味は変わらないので、そのままにする
- [一覧から外す] は、そのアプリをすべてのキーから消す

### アプリの追加

- ページ上部の [実行中のアプリから追加] と [exe を選ぶ] で足す。足したアプリは改行キーなし・自動・学習するで一覧の末尾に
  入る。一覧に既にある exe (大文字小文字を区別しない) は足さない
- [実行中のアプリから追加] は、押すたびに一覧を作り直して、ボタンの下にポップアップで出す。項目を押すと、そのアプリを足して
  閉じる。項目には exe 名とウィンドウタイトルを出す (アイコンは出さない)。出すものが無ければ「表示中のウィンドウを持つ
  アプリがありません」
  - 見えているトップレベルウィンドウ (表示中・所有者なし・タイトルが空でない) を持つプロセスだけを出す。バックグラウンドの
    プロセスまで並べると探せないため
  - exe 名は `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` と `QueryFullProcessImageNameW` のファイル名の部分。取れない
    プロセス (権限不足など) は飛ばす
  - ストアアプリのウィンドウは `ApplicationFrameHost.exe` が持つので、子ウィンドウのうち別のプロセスのものをたどって、
    そのプロセスの exe 名を出す。たどれなければ飛ばす
  - 設定ツール自身と、一覧に既にある exe は出さない。exe 名で重複をまとめ (タイトルは最初に見つかったウィンドウのもの)、
    大文字小文字を区別しない exe 名順に並べる
- [exe を選ぶ] は、ファイルを開くダイアログ (`GetOpenFileNameW`、`*.exe`) で選んだファイルのファイル名の部分を足す。ダイアログは
  作業ディレクトリを変えない (`OFN_NOCHANGEDIR`)。変わると、相対パスで指定した `QUICKLIME_*` の環境変数の解決先がずれるため
  (他の IME の辞書を選ぶ単語登録ツールのダイアログも同じ)

## 入力パネルの見本

見た目のページの下に「プレビュー」の小見出しを置き、入力パネルと変換の候補一覧の見本を縦に並べる。それぞれに小さな見出し
(「入力パネル」「変換の候補一覧」) を付ける。見本の中身と描き方は [display.md](display.md)「入力パネルの見本の描画」。

- 見本は、アプリが実際に読む TSF の DLL に描かせる。`HKEY_CLASSES_ROOT\CLSID\{QuicklIME の CLSID}\InprocServer32` の
  既定値のパスの DLL を `LoadLibraryW` で読み、`QuicklimePanelPreview` を呼ぶ。開発版とインストール版のうち、後から登録した
  方になる ([docs/development.md](../development.md)「開発版 DLL の切替とインストール版の更新」)
- 読み込んだ DLL は解放しない。TSF が同じ DLL を設定ツールのプロセスに読み込んでいることがあり (同じパスなので同じ
  モジュールが返る)、DLL も読み込まれたら常駐する前提で作られているため
- 画素のバッファは、1 回目で大きさを聞き、足りなければその大きさで描き直す。返った BGRA を RGBA に並べ替えて画像にする
- 描くときは、画面で選んでいる (保存前の) テーマ・フォント・サイズを渡す
- 描き直すとき
  - テーマ・フォント・サイズの選択が変わったとき
  - 見た目のページを開いたとき、起動したとき
  - 設定ツールのウィンドウがフォーカスを得たとき。テーマファイルを外のエディタで書き換えた後に読み直すため。winit のイベントの
    処理中に画面を変えないよう、イベントループに回してから描く
- 表示
  - 実物と同じ画素の大きさで出す (Slint のウィンドウの拡大率で割った論理サイズ)。プレビューの領域より広い見本は、縮小せずに
    右側を切る
  - 文書を模した背景 (ライトは #FFFFFF、ダークは #1F1F1F。DLL が返したダークかどうかで決める) の上に置く。ゴーストのように
    枠の無いテーマでも見えるようにするため
  - テーマのぼかしが on なら、見本の下に「ぼかしはプレビューでは再現されません」と出す
- 描けないときは、見本の代わりに理由の文を出す。設定ツールのほかの機能には影響させない
  - CLSID が登録されていない: 「QuicklIME が登録されていないため、プレビューを表示できません」
  - DLL を読めない: 「QuicklIME の本体を読み込めないため、プレビューを表示できません」とエラーの番号と DLL のパス
  - 関数が無い (プレビューに対応していない古い DLL): 「インストールされている QuicklIME はプレビューに対応していない版です。
    QuicklIME を更新してください」と DLL のパス
  - 描画に失敗した: 「プレビューを描けませんでした」とエラーの番号

## 単語登録ツールの画面

起動の引数・初期フォーカス・登録・インポートの働きと、登録の後に閉じるか開いたままにするかは [dictionary.md](dictionary.md)
「単語登録ツール」。

- 幅 420 の固定の大きさのウィンドウで、高さは中身 (InfoBar の有無) で決まる。利用者は大きさを変えられない。ウィンドウタイトルは
  「QuicklIME 単語登録」。画面の作りは設定ツールと同じ Slint の fluent スタイルと配色
- 上から、結果の InfoBar、単語・よみ (LineEdit。見出しは欄の上)、品詞 (ComboBox。項目は [dictionary.md](dictionary.md)「品詞」の
  名詞系と短縮よみ)、下部の左に [インポート...]、右に [登録] (accent) [キャンセル]
- Enter (修飾キーなし) で登録、Esc で閉じる。どちらもフォーカスのある部品によらない。IME で変換中の Enter・Esc は
  `VK_PROCESSKEY` として届くので拾わない
- 結果とエラーはメッセージボックスではなく上部の InfoBar に出す。入力が空なら警告、登録できたら成功、登録できなかったとき・
  インポートできなかったときはエラー、インポートできたら成功の InfoBar

- ウィンドウを作った直後に前面に出す。TSF 層から起動されたときに、起動元のアプリの後ろに隠れないため
- 二重起動は防がない

## 採らなかった案

- 設定ツールと単語登録ツールの画面の基盤
  - Direct2D での自前描画: 部品 (コンボのドロップダウン・一覧・フォーカスの移動・IME の効く入力欄) と UIA provider を
    すべて自作することになり、工数のほとんどが設定ツールの本質でない部分に取られる
  - WinUI 3: 設定ファイルの読み書き・キー割当の検査を C# などへ移して二重に持つことになり、Windows App SDK のランタイムを
    同梱する必要がある
  - Win32 の標準コントロールのまま見た目を直す: 標準コントロールのダークモード対応が不完全で、Fluent には寄り切らない
- 入力パネルの見本を設定ツールの側で描く: [display.md](display.md)「入力パネルの見本の描画」
- AppContainer のアプリから設定のファイルを読ませる方法
  - `%APPDATA%\QuicklIME\` に継承する ACE を付ける: 確実で単純だが、学習やユーザ辞書 (入力の履歴) もどの UWP アプリ
    からでも読めるようになる
  - TSF 層がパイプでエンジンから設定を受け取る: ファイルの権限には触れないが、プロトコルの追加と TSF 層の読み込みの経路の
    分岐が要り、大がかり
  - 何もせず既定値で動かす: キー割当・ローマ字テーブル・テーマの変更がスタートメニューの検索欄では効かない
  - CorvusSKK のように、保護された DACL で丸ごと置き換える: 利用者が付けた権限を消してしまう
- AppContainer のアプリから開いた設定ツール・単語登録ツールを、エンジンに起動させる (CorvusSKK の設定ツールの起動と同じ):
  どこからでも開けるが、プロトコルの追加と、UWP アプリからエンジンにプロセスを起動させられる経路ができる。スタートメニューの
  検索欄でツールを開く必要はまずない
