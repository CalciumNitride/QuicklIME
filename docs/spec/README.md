# 仕様書の索引

機能の領域ごとの、今の仕様の一覧。仕様書は今の挙動と、コードから復元できない WHY・採らなかった案の要点を書く。
コードの変更と同じ commit で書き換え、経緯は書かない。

- 実装前の合意は設計書 ([docs/design/README.md](../design/README.md)) に置く。仕様書をまだ作っていない
  領域は、設計書と索引を見る
- 利用者向けの操作の説明は [README.md](../../README.md) と [docs/user/](../user/) にあり、仕様書では重複させない
- 全体の構成は [docs/architecture.md](../architecture.md)、TSF 層とエンジンの間のプロトコルは
  [docs/protocol.md](../protocol.md)
- 未着手の項目と既知の問題は [docs/roadmap.md](../roadmap.md)

## 仕様書の区分

| 仕様書 | 領域 | 状態 |
|---|---|---|
| [input.md](input.md) | 入力方式 (run・`input_buffer`・読める文書の判定・確定と取消・確定アンドゥ・改行キー・ローマ字テーブル・InputScope・パスワード欄・起動時の IME の状態) | 作成済み |
| [keys.md](keys.md) | キー割当 (状態・機能・割当の照合・状態別のコア操作の表・設定ファイルの書式) | 作成済み |
| [conversion.md](conversion.md) | 変換キーの候補選択 (変換の対象・`segment_ui`・範囲の伸縮・文節 UI・後置再変換・採用した文字列の記憶・F4〜F10・数字の書き方・生ローマ字・対記号) | 作成済み |
| [engine.md](engine.md) | 変換エンジン (Viterbi・文節の分け方・N-best・タイプミス補正・逆変換・LLM の並べ替えと生成・評価セット) | 作成済み |
| dictionary.md | 辞書 (システム辞書・語彙補強・取り込み・ユーザ辞書・単語登録ツール) | 未作成 |
| [suggest.md](suggest.md) | 候補バーと予測 (SUGGEST・ファジィ照合・予測・後続語予測・文節の連なりの統計・ページ送り・採用範囲の縮め) | 作成済み |
| [learning.md](learning.md) | 学習 (語・句・文脈の句の学習・点数・学習を消す・学習しないアプリ) | 作成済み |
| [modeless.md](modeless.md) | モードレス入力と英字 (判定・英字区間・英字混じりの変換・英字候補・大文字小文字の補正) | 作成済み |
| [display.md](display.md) | 表示 (画面の部品の呼び名・入力パネル・テーマ・ぼかし・表示位置と表示位置のフォールバック・キャレットの印・入力モードのアイコンとポップアップ・言語バー) | 作成済み |
| tools.md | 設定ファイルと設定ツール (config.tsv・画面の構成・アプリごとの設定・入力パネルの見本) | 未作成 |
| runtime.md | 実行と配布 (エンジンの自動起動・二重起動の防止・パイプのアクセス権・インストーラ・第三者の著作権表示) | 未作成 |

- キーの状態別の挙動の表は keys.md だけに置く。各仕様書は機能の中身を書き、キーの表は keys.md を参照する
- 区分に収まらない機能は、仕様書を足す前に既存の区分に入るかを検討する
- 仕様書と設計書の分担と移行の進め方は [docs/design/spec-docs.md](../design/spec-docs.md)
