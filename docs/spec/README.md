# 仕様書の索引

機能の領域ごとの、今の仕様の一覧。

- 利用者向けの操作の説明は [README.md](../../README.md) と [docs/user/](../user/) にある
- 全体の構成は [docs/architecture.md](../architecture.md)、TSF 層とエンジンの間のプロトコルは
  [docs/protocol.md](../protocol.md)
- 未着手の項目と既知の問題は [docs/roadmap.md](../roadmap.md)

## 仕様書と設計書

| 層 | 置き場所 | 中身 | 更新のタイミング |
|---|---|---|---|
| 仕様書 | docs/spec/ | 今の挙動と、コードから復元できない WHY・採らなかった案の要点 | コードの変更と同じ commit で書き換える |
| 設計書 | [docs/design/](../design/README.md) | 実装前の合意 (背景・決定事項・変更対象・手順・検証・未決事項) | 実装中に設計が変わったときだけ書き換える |

- 仕様書は最新のスナップショットだけを書く。完了日・「当初は〜」「〜を廃止した」などの経緯、
  設計書の名前による置き換えの注記は書かない
- 採らなかった案は、仕様書に 1〜2 行の要点 (案と採らない理由) を残す。同じ案を後で検討し直さないため。
  詳しい比較が要るときは archive の設計書へリンクする
- 利用者向けの操作の説明は README.md・docs/user/ に書く。仕様書は開発者向けで、操作を重複して説明せず、
  内部の仕様と WHY を書く。挙動を変えたら仕様書と docs/user/ の両方を同じ commit で直す
- docs/protocol.md (プロトコル) と docs/architecture.md (全体の構成) も今の仕様のスナップショットとして扱い、
  docs/spec/ の外に置いて、この索引からリンクする
- 実験の結果のうち今の仕様の WHY になる数値は、該当する仕様書に要点を書き、実験の記録へリンクする

## 変更の流れ

1. 設計書を書いて合意する。「変更対象ファイル」に、書き換える仕様書と節を含める
2. 実装と同じ commit で仕様書を書き換える。実装を implementer に委譲するときは、仕様書の書き換えも
   委譲の範囲に含める
3. 実装後、設計書の内容が仕様書に移ったことを確かめて、設計書を docs/archive/
   ([一覧](../archive/README.md)) へ移す (同じ commit でよい)

- 設計書の要らない小さな変更は、該当する仕様書に直接書く

## 仕様書の区分

| 仕様書 | 領域 |
|---|---|
| [input.md](input.md) | 入力方式 (run・`input_buffer`・読める文書の判定・確定と取消・確定アンドゥ・改行キー・ローマ字テーブル・InputScope・パスワード欄・起動時の IME の状態) |
| [keys.md](keys.md) | キー割当 (状態・機能・割当の照合・状態別のコア操作の表・設定ファイルの書式) |
| [conversion.md](conversion.md) | 変換キーの候補選択 (変換の対象・`segment_ui`・範囲の伸縮・文節 UI・後置再変換・採用した文字列の記憶・F3〜F10・数字の書き方・生ローマ字・対記号) |
| [engine.md](engine.md) | 変換エンジン (Viterbi・文節の分け方・N-best・ファジィ入力・逆変換・LLM の並べ替えと生成・評価セット) |
| [dictionary.md](dictionary.md) | 辞書 (システム辞書・語彙補強・取り込み・ユーザ辞書・単語登録ツール) |
| [suggest.md](suggest.md) | 候補バーと予測 (SUGGEST・ファジィ照合・予測・後続語予測・文節の連なりの統計・ページ送り・採用範囲の縮め) |
| [learning.md](learning.md) | 学習 (語・句・文脈の句の学習・点数・学習を消す・学習しないアプリ) |
| [modeless.md](modeless.md) | モードレス入力と英字 (判定・英字区間・英字混じりの変換・英字候補・大文字小文字の補正) |
| [display.md](display.md) | 表示 (画面の部品の呼び名・入力パネル・テーマ・ぼかし・表示位置と表示位置のフォールバック・キャレットの印・入力モードのアイコンとポップアップ・言語バー) |
| [tools.md](tools.md) | 設定ファイルと設定ツール (config.tsv・画面の構成・アプリごとの設定・入力パネルの見本) |
| [runtime.md](runtime.md) | 実行と配布 (エンジンの自動起動・二重起動の防止・パイプのアクセス権・インストーラ・第三者の著作権表示) |

- キーの状態別の挙動の表は keys.md だけに置く。各仕様書は機能の中身を書き、キーの表は keys.md を参照する
  (状態別の表が複数の仕様書に分かれると、それ自体が食い違うため)
- 区分に収まらない機能は、仕様書を足す前に既存の区分に入るかを検討する
