# 入力方式

打鍵した読みを IME が持ち、採用・確定で文書へ入れる入力の仕様。run、入力中の読みの表示 (`input_buffer`)、
印字キーとローマ字テーブル、run の終わり方と送り直し、読める文書の判定、確定アンドゥ、改行キー、IME のオン/オフと
起動時の状態、入力パネルの外のマウスの押下、InputScope の欄、キー入力が無効な文書を扱う。

- 利用者向けの操作の説明は [入力と変換](../user/input.md) と [アプリごとの設定](../user/app-settings.md) にある
- 変換キーの候補選択 (入力なしの対象・範囲の伸縮・後置再変換・採用した文字列の記憶) は [conversion.md](conversion.md)、
  候補バーの選択と採用・後続語の予測は [suggest.md](suggest.md)
- キーの状態別の表と割当の照合は [keys.md](keys.md)。本書は機能の中身を書き、どのキーがどの状態で何をするかは keys.md を見る
- モードレス入力の判定と英字区間は [modeless.md](modeless.md)、入力パネルの見た目・表示位置・
  入力モードの一時表示は [display.md](display.md)、
  学習の中身は [learning.md](learning.md)
- 実装は tsf/src/text_service_direct.cpp (run・文書の分類・確定アンドゥ・送り直し)、tsf/src/text_service.cpp
  (キーの入口・フォーカス・IME のオン/オフ・入力パネルの外のマウスの押下・InputScope)、tsf/src/romaji.cpp (ローマ字)、
  tsf/src/config.cpp (設定)、tsf/src/edit_session.cpp (文書の読み書き)

## 原則

| 原則 | 内容 | 理由 |
|---|---|---|
| 文書を自動で書き換えない | 文書の文字列を書き換えるのは、利用者が候補を採用・確定したときと、変換キーなどで明示的に文書の文字列を対象にしたとき (後置再変換・確定アンドゥ) だけ | 後続の打鍵で前方の変換結果が書き換わる・英字の判定を覆すたびに文書が変わる (チラつき・アプリの Undo) と、見えている文字列を信用できない。モードレスの英字の切り替えも、入力中の読み (composition か入力行) を書き換えるだけにする |
| 1 つのキーには 1 つの機能 | Space はスペース、Enter はアプリの Enter (改行・送信)、変換キーは変換、確定キーは確定 | Enter が「確定」と「改行・送信」を兼ねると、送信まで 2 打かかり、状態によって Enter の意味が変わる。候補選択中・候補バーの選択中の Enter は確定してからアプリへ渡し、1 打で送信まで進む |
| 打鍵を外部に送らない | 打鍵と入力した文字列は、TSF 層と同じ PC のエンジン・LLM の子プロセスの間でだけ扱う | IME は全アプリの打鍵を扱うため |

## run

- run は IME が持つ入力中の状態で、読み (`RomajiComposer`。確定済みのかな・かなごとの打鍵・未完成のローマ字・
  英字区間)、候補バー、変換の状態をまとめたもの。読みは採用・確定するまで文書に入れない
  (composition 入力の composition は未確定文字列で、確定まで文書の内容ではない)
- run は 1 つだけ持つ。入力なし・run 中・候補選択中・サジェスト選択中の状態の区別は [keys.md](keys.md)「状態」
- run を始めるもの: IME オンで入力なしのときの印字キー (下記「印字キー」)、入力なしの対象の変換 ([conversion.md](conversion.md)
  「入力なしの対象から候補選択に入る流れ」)、確定アンドゥ、候補選択中の印字キー (確定して次の run を始める)
- 候補選択中は run を composition に昇格して候補を選ぶ。昇格・変換の取消での降格・範囲の伸縮は [conversion.md](conversion.md)

## 入力中の読みの表示 (`input_buffer`)

設定 `input_buffer` で、入力中の読みを出す場所を選ぶ。2 つの方式は読みを出す場所と文書への入れ方だけが違い、
run・キーの意味・候補バー・変換・学習・前文脈・モードレスの判定は共通にする。

| | `composition` (既定) | `panel` |
|---|---|---|
| 入力中の読み | 文書の composition。打鍵ごとに読みの表示 (確定済みのかな + 未完成のローマ字) で更新し、入力中の表示属性 (下線) を付ける | 入力パネルの入力行だけ |
| 入力パネルの入力行 | 設定 `panel_input` 1 かテーマの `input_row always` のとき (`candidate_bar` 1 のときだけ) | 常に出す。`candidate_bar` 0 でも入力行だけの入力パネルを出す |
| 採用・確定で文書に入れる | composition をその文字列で終える | キャレット位置に挿入する (選択があれば置き換える) |
| 採用の後も run が続く (採用範囲を縮めた採用・採用に続く打鍵) | 採用した部分で composition を終え、同じ edit session で次の composition を張る | 採用した部分を挿入し、残りを入力行に残す |
| 変換キー・F3〜F10 | run の composition をそのまま候補選択に使う | キャレット位置に空の composition を張る。張れなければ変換せずに run を続ける |
| 変換の取消 | composition を読みの表示に戻し、run の composition として続ける | composition を空で終え、読みを入力行に戻す |
| クリック・キャレット移動 | アプリが composition を終えたら、アプリが残した文字列のまま run を終える (学習しない)。終えなければ run を続ける | run を続け、採用・確定した時点のキャレット位置に入れる |
| 入力パネルの位置の基準 | composition の矩形 | 選択範囲の矩形 (取れなければシステムキャレット) |

- `panel` 以外の値 (不正な値を含む) は `composition` として扱う
- 方式は run を始める時点の設定で決め、その run が終わるまで変えない (設定を読み直しても run の途中では変えない)。
  決める時点は、印字キーで新しい run を始めたとき、入力なしの対象の変換を始めたとき (取消で戻る run の方式になる)、
  確定アンドゥ、候補選択中の印字キーで次の run を始めたとき
- composition を張れない (失敗・拒否) ときは、その run をパネル保持入力 (`panel`) として続ける。採用の後に次の
  composition を張り直せなかったときも、残りの run を `panel` として続ける
- composition の開始と文字列の設定は別々の edit session で行う。開始と同じ session で文字列を設定すると、CUAS が
  WM_IME_COMPOSITION を生成せず、CUAS 経由のアプリ (WezTerm など) で未確定文字列が出ない
- 採用の後も run が続くとき、composition の終了と次の開始を 1 つの edit session で行う。別々の session にすると、
  ロックの合間にアプリが確定の処理を進め、Word や CUAS 経由のアプリで次の composition が生き残らない
- `panel` で入力行を常に出すのは、出さないと入力中の読みがどこにも見えないため
- 設定ツールでの選び方 (`panel_input` と合わせた 3 つの選択肢) は [tools.md](tools.md)「入力中の読み」

### `panel` を選ぶ理由

- 打鍵ごとに文書が変わらないので、逐次検索する欄・文字数カウンタが途中のかなに反応せず、アプリの Undo 履歴に
  入力途中の状態が積まれない

### 採らなかった案

- 文書書き込み入力 (打鍵したかなを文書に直接追記し、IME が覚えた run を後から置き換える。未完成のローマ字は文書の外の
  小窓に出す): 追記前の照合、Chromium の選択と置換の制約、読み戻せない文書での擬似 Backspace、Discord の内部モデルとの
  食い違いなど、アプリのエディタ実装に依存する問題が続いたため。半角前提のフォームの崩れも、原因は composition かどうか
  ではなく、全角になること・composition 中のフォーカス移動・値の書き換え・maxlength だった。Chromium は composition を
  使わない挿入もページへは一瞬の composition として届けるので、直接入力にしても避けられない。フォームに効くのは run の外の
  半角数字の素通し (下記「印字キー」) と InputScope の素通し (下記「InputScope の欄」)
- `panel` への一本化: 読みが文書に出ないので、ほかの IME から移る人には分かりにくい
- `composition` で Space を変換・Enter を確定だけにする古典的なキー体系: 方式ごとにキーの意味が変わり、キーマップと
  状態別の処理が二重になる。変換キーの割当 (`key.convert`) で近づけられる
- `panel` で候補選択中もパネルの中で完結させる (文書に composition を出さず、入力行に変換結果を出す): 候補選択の表示経路が
  もう 1 つ要り、範囲の伸縮も作り直しになる。候補選択中だけ文書に未確定文字列が出ても、打鍵ごとに文書が変わる問題には当たらない

## 印字キー

英字・記号・数字・テンキーの打鍵は、run があれば読みに足し、無ければ新しい run を始める。

| キー | 読みに入るもの |
|---|---|
| 英字 | ローマ字として読みに足す (下記「ローマ字テーブル」) |
| Shift+英字 | 大文字をそのまま入れ、英字モードに入る。以降の英字はローマ字に変換せずに続く (モードレス入力での扱いは [modeless.md](modeless.md)「英字区間」) |
| 記号キー・Shift+数字キー | 日本語キーボード (JIS 配列) の刻印どおりの全角記号 (`-` は「ー」、`[` は「「」など。tsf/src/text_service.cpp `FindSymbolKey`)。読点・句点は設定 `punctuation` に従う。打鍵文字そのもの (`,`・`[` など) も打鍵として持つ (生ローマ字の候補・英字モードに使う) |
| 数字キー | 設定 `digits` に従って半角か全角 |
| テンキー | 数字は `digits` に従い、演算記号 (`*` `+` `-` `.` `/`) は常に半角。テンキーは数値の入力用のため |

- 入力なしのときの数字キー・テンキーの数字と演算記号は、`digits half` なら食べずにアプリへ素のキーを渡す (run を
  始めない)。電話番号・郵便番号・認証コードなど 1 文字ずつ次の欄へ移るフォームは、keydown・keyup・input を素のキー入力の
  まま受け取る必要があるため。数字で始まる run の候補 (助数詞など) は出ない。Shift+数字で記号になる打鍵は対象外
  - 後続語の予測を選んでいるときの数字は、`digits half` でも食べて、予測を採用してから run を始める ([suggest.md](suggest.md)
    「選択と採用」)
- 入力なしの Space は、設定 `space full` で Shift なしのときだけ食べて全角スペースを入れる (モードレスが有効で、直前の確定が
  英数字だけなら半角)。それ以外は食べずにアプリへ渡す

## ローマ字テーブル

- 既定のテーブルは TSF 層に持つ (tsf/src/romaji.cpp `kDefaultTable`)。ユーザのテーブル `%APPDATA%\QuicklIME\romaji.tsv`
  (`QUICKLIME_ROMAJI_FILE` で変更可) を既定のテーブルへ追加・上書きする。書式は
  [辞書とローマ字](../user/dictionary.md#ローマ字テーブルのカスタマイズ)
  - かなの列が空の行は、そのローマ字の項目を消す
  - ローマ字の列の英大文字は小文字にして照合する (打鍵は小文字で照合するため)
  - 3 列目が空でない行 (Google 日本語入力の「次の入力」付きの形式) は対応せず読み飛ばす。`kk<TAB>っ<TAB>k` を
    `kk` → っ と読むと促音の連打が壊れるため
- テーブルはプロセスごとに初回の参照で一度だけ作る。IME の DLL はアプリのプロセスごとにロードされるため、ファイルの変更は
  アプリの再起動後に反映される
- AppContainer で動くアプリ (スタートメニューの検索欄など) でも読めるよう、エンジンが起動時に romaji.tsv へ読み取りの ACE を
  足す ([tools.md](tools.md)「AppContainer のアプリから読むための権限」)
- テーブルに無い綴りの扱い
  - テーブルのどれかの項目の先頭と一致する間は、未完成のローマ字として続きを待つ
  - `n` 以外の同じ子音が 2 つ続いたら、前の 1 つを「っ」にする
  - `n` の後に続けられない文字が来たら、`n` を「ん」にする
- 未完成のローマ字のまま run を終えるときの扱いは、終え方による (下記「run の終わり方」)
- AZIK 風のプリセット [data/romaji-azik.tsv](../../data/romaji-azik.tsv) は撥音拡張と二重母音拡張を持つ。本家 AZIK の
  「x = しゃ行」「q = ん」は、既定のテーブルの小書き文字 (`xa` = ぁ) と くぁ行 (`qa`) に衝突するため含めない。
  使えなくなる既定の打ち方はプリセットの先頭のコメントにある

## 読みの編集

- Backspace / Ctrl+H (run 中、候補選択中を除く): 常に食べて、未完成のローマ字があればその末尾 1 字、無ければかな 1 字を
  読みから削る。読みは IME が持っているので、文書には触れない。読みが空になったら run を終える (`composition` では
  composition を空で終える)。次の Backspace はアプリへ渡る
- Esc (run 中): 候補バーで選んでいれば選択を外す。選んでいなければ run を捨てる。文書には何も入らない
  (`composition` では composition を空で終える)
- 候補選択中の Backspace・Esc は変換の取消 ([conversion.md](conversion.md)「確定と取消」)

## run の終わり方

| 契機 | 文書に入れるもの |
|---|---|
| 確定キー (候補バーで選んでいない) | 見えているとおりの読み (未完成のローマ字もそのまま)。キーはアプリへ渡さない |
| Space | 読み (末尾の未完成の `n` は「ん」、ほかの未完成のローマ字はそのまま) + スペース。幅は設定 `space` に従い、Shift+Space と、モードレスが有効なときの英字モード中は半角 |
| run を終えてアプリへ渡すキー (どのキーかは [keys.md](keys.md)「run のある状態のキー」) | 見えているとおりの読みを入れてから、キーをアプリへ渡す (下記「送り直し」) |
| IME オフ | 見えているとおりの読み (下記「IME のオン/オフ」) |
| 入力パネルの外でマウスのボタンを押した | 見えているとおりの読み (下記「入力パネルの外のマウスの押下」) |
| フォーカス移動 | 何も入れない。`panel` は読みを捨て、`composition` は composition を終えずに手放す (残った文字列の扱いはアプリに任せる) |
| アプリが composition を終えた (`composition`) | アプリが残した文字列のまま |
| キー入力が無効な文書での打鍵 | 何も入れずに捨てる (下記「キー入力が無効な文書」) |

- 候補バーで選んでいるときは、採用に使うキー ([keys.md](keys.md)「run のある状態のキー」) で採用する ([suggest.md](suggest.md)
  「採用」)。候補を選んでいなければ候補もモードレスの run 終了時の判定も当てない ([suggest.md](suggest.md)「採用せずに run を終えたとき」)
- 候補選択中の確定は [conversion.md](conversion.md)「確定と取消」
- 文書に入れて run を終えたときは、学習 (英字を含む読みだけ。[learning.md](learning.md)「学習しない確定」)、前文脈 (run 全体のかなを読み = 表記の前文脈にする)、
  採用した文字列の記憶 (末尾のスペースを除く。[conversion.md](conversion.md)「採用した文字列の記憶」)、確定アンドゥの記憶
  (下記「確定アンドゥ」)、LLM の左文脈の履歴を更新する
- フォーカス移動・アプリによる composition の終了・キー入力が無効な文書では、学習も前文脈も更新しない
- フォーカス移動で何も入れないのは、フォーカスを失った文書への edit session が同期で走らないことがあり、失敗や
  挿入位置のずれが起こりうるため
- Alt 併用 (Ctrl+Alt 併用を含む) の打鍵では run を終えず、キーを食べずにアプリへ渡す。Alt 併用の打鍵が key event sink に
  届かないアプリ (WezTerm・メモ帳で確認) があり、そこでは run を終える契機が無いため。届くアプリでもキャレット移動と同じ扱いにそろえる。読みは IME が持っているので、Alt 併用の
  ショートカットでキャレットや文書が変わっても読みは壊れない。候補選択中の Alt 併用は確定してから渡す
- 確定キーと Enter で、見えている読みをそのまま入れるのは、Enter で送信するアプリで見えている文字と送られる文字を
  食い違わせないため
- 採らなかった案: 矢印などのアプリへ渡すキーで読みを捨てる (Esc だけを捨てる操作にする)。気づかずに入力を失いやすい

## 送り直し

run を終えて文書に入れてからアプリへ渡すキーは、文書に入れた文字列より先にアプリへ届かないようにする。

- 読める文書 (下記「読める文書の判定」) では、キーを食べずに、`OnTestKeyDown` / `OnKeyDown` の中で run を終えてから
  アプリへ渡す。読める文書への書き込みは TSF の文書へ同期的に入るため
- 読めると判定されていない文書では、キーを食べて run を終え、その後に同じ打鍵を `SendInput` で送り直す。CUAS 経由の
  アプリ (WezTerm など) は確定した文字列を IME メッセージで後から受け取るため、食べずに渡すと確定より先にキーが処理される。
  送り直した打鍵は入力キューの後ろに並ぶので、確定のメッセージより後に処理される
- 送り直すキー
  - run 中 (候補バーで選んでいるときを含む): run を終えてアプリへ渡すキーのすべて ([keys.md](keys.md)「run のある状態のキー」)。
    IME が食べて処理するキーと、run を終えない Alt 併用は対象外
  - 候補選択中と後続語の予測の選択中: Enter・Ctrl+M だけ。それ以外のアプリへ渡すキーは、確定してから送り直さずに渡す
  - 改行キー: 文書の分類によらず常に送り直す (下記「改行キー」)
- 送り直す打鍵の修飾キーは、送る時点で押されている修飾キーのうち要らないものを送る間だけ離し、要るのに押されていないものを
  送る間だけ押す。Alt・Win を離すときは、前後に割り当ての無い仮想キー (0xE8) の打鍵を挟む。Alt・Win を単独で押して離すと
  アプリのメニュー・スタートメニューが開くため
- 送り直した打鍵は run の無い状態で届くので、IME は食べずにアプリへ渡す

## 読める文書の判定

文書 (フォーカス中の文書) を、IME が入れた文字列をキャレット直前から読み戻せるかで分類する
(tsf/src/text_service_direct.cpp `ClassifyByLastInsert`)。

- 分類は「読める」と「未判定」の 2 つ。IME が直前に文書へ入れた文字列 (挿入・composition の確定) をキャレット直前から
  読み戻し、一致すれば読める文書にする
- 確かめる時点は次の 3 つ
  - run の始め (最初の打鍵。`TypeAppend`)
  - IME オンで入力なしのときの、変換キー・F6〜F10・確定アンドゥに割り当てた打鍵 (`ClassifyBeforeIdleKey`)。これらは
    キャレット直前を読める文書でしか働かず、キーを食べるかどうかを分類で決めるため、食べるかを決める前に確かめる
  - 確定アンドゥの実行 (`UndoCommit`)
- 照合に使った直前の挿入は、一致してもしなくても捨てる。一致しなければ未判定のまま残し、次に入れた文字列でまた確かめる。
  挿入の後にアプリへ渡したキーで文書が変わったのか、読めない文書なのかを区別できないため。CUAS 経由のアプリは確定した
  文字列を後から受け取るので、未判定のまま残る
- 読めると判定した後は、フォーカスが移るまで確かめ直さない。フォーカス移動 (`OnSetFocus`) で未判定に戻し、直前の挿入も
  捨てる。読めるかどうかは文書 (アプリ・編集コントロール) の性質で決まるため、文書ごとに判定し直す

| 分類で変わるもの | 読める文書 | 未判定の文書 |
|---|---|---|
| 入力なし・選択なしの変換キー・F6〜F10 ([conversion.md](conversion.md)「変換の対象」) | キャレット直前の記憶かかなを対象にする | 対象なし (アプリへ渡す) |
| 確定アンドゥ | 働く | 働かない (アプリへ渡す) |
| アプリへ渡すキー (上記「送り直し」) | 食べずに確定してから渡す | 食べて確定してから送り直す |
| LLM の左文脈 ([engine.md](engine.md)「左文脈」) | run の前の文書の文字列を読む | IME が文書に入れた文字列の履歴を使う |

- 採らなかった案
  - 挿入した直後に読み戻して判定する: CUAS 経由の文書は、composition の外の文字列を同じロックの中では読み戻せても、
    次の打鍵では読めない (`ka` が「kあ」になる)
  - `TS_SS_TRANSITORY` で CUAS を見分ける: Chrome も立てる (Chromium は IMM32 互換の再変換の経路を IME に使わせるため、
    意図して transitory を宣言している)
  - 一致しなかった文書を「読めない」と決める: 上記のとおり、読めない文書と、挿入の後に文書が変わった場合とを区別できない

## 文書の文字列の置き換え

文書にすでにある文字列を IME が書き換えるのは、入力なしの対象の変換 (対象の文字列を消して composition に昇格する。
[conversion.md](conversion.md)) と確定アンドゥだけ。どちらも文書を読み戻して照合してから置き換える。

- 照合は、選択の開始を基準に対象の文字列の範囲を作って読み、対象の文字列と比べる。一致しなければ何もしない
- 読める文書で範囲が作れないのは、キャレットが動いたためとみなして不一致と同じに扱う
- 選択が末尾に潰れたキャレットでなければ、先に選択だけを末尾に潰してから置き換える。置き換えた後に選択を設定するときも、
  別の edit session で行う。Chromium 系 (Chrome・Vivaldi) は、潰れていない選択と違う範囲の置き換えを正しく反映せず (古い
  文字列が残り、新しい文字列がその後ろに入る)、文字列を変えた session の中で設定した選択を捨てる (キャレットを入れた文字列の
  末尾に置く) ため
- 読めると判定されていない文書では、文書の既存の文字列を書き換えない。入力なし・選択ありの変換は、文書の分類によらず選択の
  読み戻しで照合できるときだけ働く ([conversion.md](conversion.md)「変換の対象」)
- 採らなかった案
  - 読めない文書で、Backspace の擬似打鍵で文字列を消してから入れ直す: キャレットの移動を見落とすと関係ない文字を消し、
    修飾キー付きの操作から送るとアプリには Ctrl+Backspace などとして届く。不安定さの原因そのものを残すことになる
  - 後置再変換・確定アンドゥをやめる: 読める文書では安定して動いており、打ってから直す使い方の一部を担う

## 確定アンドゥ

確定アンドゥ (`key.undo_commit`、既定 Ctrl+Backspace) は、直前の確定の文字列を文書から消し、確定前の読みの run に戻す。

- 直前の確定 1 件の、文書に入れた文字列と確定前の読みの状態 (`RomajiComposer`) を記憶する

| 確定 | 記憶する文字列と読み |
|---|---|
| run を終えた (上記「run の終わり方」) | 入れた文字列全体 (Space で終えたときはスペースを含む) と run の読み |
| 候補選択の確定 | 外したかな + 選んだ候補と、外したかなを含む読み ([conversion.md](conversion.md)「確定と取消」)。割当の無い Space で確定したときはスペースも含める |
| 候補バーの採用・後続語の予測の採用 | [suggest.md](suggest.md)「採用の後」「選択と採用」 |

- 記憶を捨てるとき: 確定アンドゥを実行したとき (成否によらない)、フォーカス移動、採用の後に run が続いているとき (続く
  run の手前が採用した文字列になるため)
- 働くのは入力なしのときで、読める文書でキャレット直前が記憶した文字列で終わるときだけ。働かないときは打鍵を食べずに
  アプリへ渡し、記憶は残す。読めると判定されていない文書では、消す範囲を照合できないため
- 実行すると
  1. 文書を分類し、読める文書でなければ何もしない
  2. キャレット直前の記憶した文字列を照合込みで消す (上記「文書の文字列の置き換え」)。消せなければ何もしない
  3. 採用した文字列の記憶の最新 1 件が、消した文字列の先頭と一致すれば捨てる
  4. 記憶した読みの状態で run を再開する。方式は確定アンドゥの時点の設定 `input_buffer` で決め、`composition` なら
     composition を張る。候補バーを作り直す
- 確定を取り消すので、その確定を前提にした前文脈と LLM の左文脈も捨てる
- 確定キーはアプリへキーを渡さないので、読める文書では確定キーで確定した直後に確定アンドゥが働く。Enter などアプリへ渡した
  キーでアプリが文書を変えたとき (改行を入れた・送信して欄を空にした) は、キャレット直前が一致しなくなり働かない

## 改行キー

改行キー (`key.insert_newline`、既定 Ctrl+J) は、対象のアプリでアプリへ Shift+Enter を送って改行を入れる。Enter で送信する
アプリ (Discord・Slack など) で、どこでも同じキーで改行を入れるため。

- 対象のアプリは設定 `newline_apps` (exe 名のカンマ区切り。前後の空白・タブは除く)。ホストのプロセスの exe 名
  (`GetModuleFileNameW` のファイル名の部分) と、大文字小文字を区別せずに照合する。exe 名はプロセスごとに変わらないので、
  `TextService` を作るときに一度だけ取る
- 値が空なら対象なし。設定ファイルに行が無ければ既定の `Discord.exe,slack.exe,ms-teams.exe,Teams.exe,LINE.exe`。
  ブラウザは Ctrl+J (ダウンロード) を奪うため既定に入れない
- 対象外のアプリでは食べない (キーの扱いは [keys.md](keys.md)「割当の照合」)。IME オフでは働かない
- 入力なしでは Shift+Enter を送り、run 中・候補選択中は Enter と同じに run を終える・採用する・確定してから Shift+Enter を
  送り直す (状態ごとの働きは [keys.md](keys.md)「機能」と状態ごとの表)。確定より先に改行が届かないよう、入力中は文書の分類に
  よらず常に食べて送り直す (上記「送り直し」)
- Shift+Enter にするのは、チャットのアプリで Shift+Enter が改行の事実上の標準のため
- 採らなかった案
  - TSF で改行の文字を挿入する: 改行コードの扱いがアプリごとに違い (`\r`・`\r\n`・`\n`)、Web のエディタが文字としての改行を
    改行として扱うかも不確か。TSF に対応していないアプリでは効かない
  - 全アプリで有効にする: ターミナルでは Shift+Enter が Enter と同じになりやすくコマンドが実行される。Excel では
    Shift+Enter がセルの移動になる。ブラウザ (ダウンロード)・VS Code (パネルの切替) の Ctrl+J を奪う

## IME のオン/オフ

- オン/オフは OPENCLOSE compartment で持つ。半角/全角キー (`VK_KANJI`・`VK_OEM_AUTO`・`VK_OEM_ENLW`。修飾キーや IME の状態で
  届き方が変わるため全部) を切り替え、`VK_IME_ON` / `VK_IME_OFF` をオン / オフにする preserved key として登録する
- アクティブ化 (`ActivateEx`) で OPENCLOSE が未設定ならオンにする。compartment を取れない環境はオンとして扱う
- IME オフの間は何も食べない
- オフになったとき (切替キー・言語バー・アプリからの切替のどれでも)
  - run 中は、見えているとおりの読み (未完成のローマ字もそのまま) を文書に入れて run を終える
  - 候補選択中は、今の選択で確定する
  - 前文脈・LLM の左文脈の履歴・後続語の予測・採用した文字列の記憶 (オフの時点で確定した文字列を含む) を捨てる。オフの間に
    キャレットが動かされうるため
- オン/オフの切替は、設定ファイルの変更を確かめる契機にもする (フォーカス移動と同じ)

## 入力パネルの外のマウスの押下

同じアプリの中で入力欄以外 (余白・ボタン・メニューなど) を押しても、TSF の文書のフォーカスが変わらず
(`ITfThreadMgrEventSink::OnSetFocus` が来ない)、キャレットも動かないことがある (WezTerm・マビノギ)。そのままでは入力パネル
(run の候補バー・入力行・変換の候補一覧・後続語の予測) が出たまま残るため、入力パネルを出している間にパネルの外で
マウスのボタンが押されたら、IME オフになったとき (上記「IME のオン/オフ」) と同じ後始末をして入力を終える。IME はオンのまま。

- 入力パネルを出している間だけ、文書のスレッドに限ったマウスフック (`SetWindowsHookEx(WH_MOUSE, proc, nullptr,
  GetCurrentThreadId())`) を付け、パネルを消したら外す。パネルを出していないときはフックを付けない
- 働くのは左・右・中・X ボタンの押下 (`WM_*BUTTONDOWN`) とダブルクリック (`WM_*BUTTONDBLCLK`)、その非クライアント領域版
  (`WM_NC*`)。ホイール・移動・ボタンを離す操作では働かない
- 押した先 (`MOUSEHOOKSTRUCT::hwnd`) が入力パネルのウィンドウなら働かない。入力欄の中を押したときは、キャレットを同じ位置に
  置いたときも含めて働く (パネルの外の押下はすべて同じに扱う)
- マウスの操作は食べずにアプリへ渡す。文書への書き込みはフックの中で、アプリが押下を処理する前に行う

| 状態 | 処理 |
|---|---|
| run 中 (候補バーで選んでいるときを含む) | 見えているとおりの読み (未完成のローマ字もそのまま) を文書に入れて run を終える。候補バーの選択は採用しない |
| 候補選択中 | 今の選択で確定する |
| 後続語の予測 | 消す |

- いずれも、続けて後続語の予測を出さない。前文脈・LLM の左文脈の履歴・採用した文字列の記憶 (押した時点で確定した文字列を
  含む) を捨てる。押した操作でキャレットが動かされうるため
- 文書は、そのとき TSF のフォーカスにある文書の最上位の context (IME オフと同じ)。フックの中で edit session が同期で走らず
  書き込めなかったときは run を捨てる
- 診断ログには、押下で入力を終えたこと (そのときの状態と押下のメッセージ) を出す
- 採らなかった案
  - 押したときに読みを捨てる (フォーカス移動と同じ): うっかり押すと入力を失う
  - 後続語の予測だけを消し、入力中のパネルは残す: マビノギはチャット欄の外ではキーを TSF に通さず、外での Esc などのキーで
    消せないため、パネルが残り続ける
  - 入力欄の外での Esc でパネルを消す: マビノギではチャット欄の外の打鍵が TSF に届かない。スレッドに限ったキーボードフックも
    届かない見込みが高く、低レベルのキーボードフック (`WH_KEYBOARD_LL`) はゲームのプロセスから全アプリのキーを見ることになり、
    チート対策のソフトに疑われる恐れがある
  - `ITfThreadFocusSink::OnKillThreadFocus` で消す: ウィンドウの切替では今も消えており、同じアプリの中の押下は捉えられない

## 起動時の IME の状態

アプリの起動時に IME をオンで始めるか、オフで始めるか、自動にするかを exe ごとに決める (設定 `ime_start_apps`)。
アプリによってはオフで始まって毎回オンにする手間がかかり、ターミナルのように英字の入力が主なアプリではオフで始まってほしいため。

- 値は `exe名:状態` のカンマ区切り。状態は `on` / `off` (大文字小文字を区別しない)。例: `Notepad.exe:on,WindowsTerminal.exe:off`
  - 区切りは最後の `:`。exe 名と状態のそれぞれから前後の空白・タブを除く。`:` の無い項目・状態が `on` / `off` 以外の項目・
    exe 名が空の項目は捨てる。同じ exe 名 (大文字小文字を区別しない) が重なれば最初の項目を使う
  - exe 名の照合は改行キーと同じ (大文字小文字を区別しない)
- 一覧に無いアプリは自動: 何もしない (アクティブ化の「未設定ならオン」だけが働き、多くのアプリではその後にシステムの値で
  上書きされる)。自動は一覧に載せないことで表し、`auto` のような状態は設けない
- 適用するのは、プロセスで最初に文書へフォーカスしたとき 1 回だけ (アクティブ化の時点でフォーカスがあればそこ、無ければ
  最初の `OnSetFocus`。フォーカス先が無い通知は数えない)。`on` なら compartment の値によらずオン、`off` ならオフにする
  - アクティブ化の時点では適用しない。メモ帳ではアクティブ化の時点の compartment は未設定で、そこでオンにしても最初の文書
    フォーカスまでにシステムが 0 に書き換える (IMM の入力コンテキストのオン/オフとの同期と思われる)
  - プロセスで 1 つのフラグを持つ (`TextService` はスレッドごとに作られるため)。同じプロセスの 2 つ目以降のスレッド、ほかの
    IME からの切替による再アクティブ化、新しく開いたウィンドウには適用しない。利用者がアプリの中で切り替えたオン/オフを
    上書きしないため
- 設定はアクティブ化の中で、適用より前に読み込む。起動済みのプロセスには、設定を変えても効かない (次に起動したプロセスから)
- 診断ログ (`debug_log`) には、アクティブ化と最初の文書フォーカスの時点の OPENCLOSE の値と、最初の文書フォーカスから 5 秒間の
  OPENCLOSE の変更を出す。適用した後にシステムが値を書き換えていないかを確かめるため
- 適用したときに出す入力モードの一時表示は [display.md](display.md)「入力モードの一時表示」

## InputScope の欄

半角英数字を前提にした InputScope の欄では、IME オンのままキーを一切食べない (設定 `input_scope_passthrough`、既定 1)。
IME を通った文字は全角になったり composition になったりして、1 文字 1 枠の認証コード欄などで崩れ、利用者が IME をオフに
する手間がかかるため。

| 種類 | InputScope |
|---|---|
| 数字 | `IS_DIGITS`・`IS_NUMBER` (`IS_NUMBER_FULLWIDTH` は対象外) |
| 電話番号 | `IS_TELEPHONE_FULLTELEPHONENUMBER`・`IS_TELEPHONE_COUNTRYCODE`・`IS_TELEPHONE_AREACODE`・`IS_TELEPHONE_LOCALNUMBER` |
| メール | `IS_EMAIL_SMTPEMAILADDRESS`・`IS_EMAIL_USERNAME` |
| 半角英数 | `IS_ALPHANUMERIC_HALFWIDTH` |
| パスワード・PIN | `IS_PASSWORD`・`IS_NUMERIC_PASSWORD`・`IS_NUMERIC_PIN`・`IS_ALPHANUMERIC_PIN`・`IS_ALPHANUMERIC_PIN_SET` |

- フォーカス中の文書の InputScope の一覧に、上のどれかが含まれていれば対象にする
- `IS_PRIVATE` は対象にしない。シークレットウィンドウでは通常の欄にも付くため。`IS_SEARCH`・`IS_DEFAULT` などだけの欄も対象外
- `IS_URL` は対象にしない。ブラウザのアドレスバー (Firefox など) が `IS_URL` を申告し、アドレスバーは検索語も打つ欄であるため。
  ページ内の `type="url"` の欄も日本語入力を使う (モードレス入力が有効なら英字はそのまま入る)
- Chromium は HTML の欄を次の InputScope にする (ui/base/ime/win/tsf_input_scope.cc): `inputmode="numeric"` → `IS_DIGITS`、
  `type="number"`・`inputmode="decimal"` → `IS_NUMBER`、`tel` → `IS_TELEPHONE_FULLTELEPHONENUMBER`、`email` →
  `IS_EMAIL_SMTPEMAILADDRESS`、`url` → `IS_URL`、`search` → `IS_SEARCH`、`type="password"` → `IS_PRIVATE`
  (シークレットウィンドウ・ゲストの欄は `IS_PRIVATE` を足す)
- 対象の欄では、IME オフと同じく何も食べない。変換キー・機能キーの割当も働かない。言語バーと入力モードの表示は変えない
  (IME はオンのまま)。対象でない欄へ移れば、そのまま日本語入力に戻る
- フォーカス移動で run は終わっているので、対象の欄で run が残ることはない

### 取得の時点

- フォーカス移動 (`OnSetFocus`) のたびに未取得に戻し、読み取りの edit session (`TF_ES_ASYNCDONTCARE | TF_ES_READ`) で読む。
  同期で走らなければ、走った時点で結果を入れる。Chromium は欄を移るたびに `ITfThreadMgr::SetFocus` を呼び直し (同じ種類の欄の
  間では空の文書を挟んで同じ文書へ戻す)、InputScope は取り出す時点の欄の種類から作られるため、フォーカスのたびに読めば欄ごとの
  値が取れる
- 後から走った取得の結果は、そのフォーカスの世代のものだけを使う (フォーカスが移った後に届いた古い結果で上書きしない)
- キーの判定の時点で未取得なら、同期の読み取り (`TF_ES_SYNC | TF_ES_READ`) を試みる。読めなければ対象外として扱い (IME を使う
  側に倒す)、未取得のまま次の打鍵と後から走る取得を待つ
- 設定 0 で診断ログも出さないときは、フォーカス移動で読みに行かない
- 診断ログには、フォーカス先の InputScope の一覧と、素通しにするかの判定を出す

### 採らなかった案

- 対象の欄で IME のモードを半角英数に切り替え、言語バーにも出す (MS-IME に近い): QuicklIME には入力モードが無く (オン/オフ
  だけ)、オフにすると欄を出たときに戻す処理が要る。キーを食べないだけで目的を果たせる
- 数字系だけを対象にする: メールアドレスの欄でも、かなに化けて IME をオフにする手間が残る
- InputScope の指定が無い英数字の欄 (`inputmode` なしの認証コード欄) を推測で見分ける: 判断の材料が無く、誤ると通常の欄で
  日本語が打てなくなる。IME をオフにして入力してもらう ([roadmap.md](../roadmap.md) の見送り・既知の問題)

## キー入力が無効な文書

- フォーカス中の文書・最上位の context が無いとき、または context の compartment `GUID_COMPARTMENT_KEYBOARD_DISABLED`・
  `GUID_COMPARTMENT_EMPTYCONTEXT` が立っているときは、キーを食べない (SampleIME・CorvusSKK と同じ判定)。アプリが IME を
  無効にする手段に従えば足りる
- そのとき残っている run は、学習・LLM の左文脈・前文脈に残さずに捨てる。後続語の予測も消す
- この判定に InputScope は使わない。Chrome のパスワード欄は両方の compartment を立てるが、InputScope は `IS_PASSWORD` ではなく
  `IS_PRIVATE` を返すため (半角英数字を前提にした欄でキーを食べない扱いは上記「InputScope の欄」)
- 診断ログには、フォーカス先の無効化の状態と InputScope を出す

## フォーカス移動

フォーカスが別の文書に移ったら、文書に結びついた状態を捨てる。

- run (上記「run の終わり方」)、後続語の予測、確定アンドゥの記憶、採用した文字列の記憶、前文脈、直前の挿入、文書の分類
  (未判定に戻す)、InputScope の判定
- 設定ファイルの変更を確かめ、変わっていれば読み直す (設定ツールで保存してアプリに戻る操作自体がフォーカス移動なので、
  実質すぐ反映される)

## 設定

値の書式と設定ツールでの名前は [設定一覧](../user/settings.md)。

| 設定 | 既定 | 読む側 | 本書での働き |
|---|---|---|---|
| `input_buffer` | `composition` | TSF 層 | 入力中の読みを出す場所 (`composition` / `panel`) |
| `space` | `full` | TSF 層 | Space で入れるスペースの幅 |
| `punctuation` | `、。` | TSF 層 | 読点・句点のキーで入る文字 |
| `digits` | `half` | TSF 層 | 数字キー・テンキーの数字の幅。`half` では入力なしの数字をアプリへ素通しする |
| `newline_apps` | `Discord.exe,slack.exe,ms-teams.exe,Teams.exe,LINE.exe` | TSF 層 | 改行キーが働くアプリ |
| `ime_start_apps` | 空 | TSF 層 | 起動時の IME の状態をアプリごとに決める |
| `input_scope_passthrough` | 1 | TSF 層 | 1 で半角英数字を前提にした InputScope の欄ではキーを食べない |
| `key.undo_commit` | `Ctrl+Backspace` | TSF 層 | 確定アンドゥ |
| `key.insert_newline` | `Ctrl+J` | TSF 層 | 改行キー |
| `key.commit_run` | `NonConvert` | TSF 層 | 確定キー |
