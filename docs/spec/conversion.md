# 変換キーの候補選択

変換キー・F4〜F10 で入る候補選択の仕様。変換の対象の決め方、範囲の伸縮、入力全体の候補選択と文節 UI、
後置再変換 (採用した文字列の記憶・漢字を含む選択の逆変換)、確定と取消、学習、ファンクションキー変換と
候補に足すもの (数字の書き方・生ローマ字・対記号) を扱う。

- 利用者向けの操作の説明は [入力と変換](../user/input.md) にある
- 候補の作り方 (N-best の生成と並び・補正の求め方・逆変換の格子) はエンジンの側で、今は設計書にある
  ([nbest.md](../design/nbest.md)・[typo-conversion.md](../design/typo-conversion.md)・
  [typo-segment-ui.md](../design/typo-segment-ui.md)・[selection-reconversion.md](../design/selection-reconversion.md) の B)
- キーの状態別の表は今は [keymap.md](../design/keymap.md) にある。本書は機能の中で候補選択中のキーの挙動を書く
- 実装は tsf/src/text_service.cpp (候補選択・確定・学習) と tsf/src/text_service_direct.cpp (入力なしの対象・
  範囲の伸縮・記憶)

## 変換の対象

| 状態 | 変換キー・F6〜F10 の対象 |
|---|---|
| run 中 | run 全体 (確定済みのかなと未完成のローマ字。末尾の `n` は「ん」にする) |
| 入力なし・選択あり | 選択範囲 (127 文字まで)。ひらがな・カタカナ・ー だけの選択はそのまま読みにし、漢字などを含む選択は逆変換で推測した読みにする (下記「漢字を含む選択の再変換」) |
| 入力なし・選択なし・読める文書 | キャレット直前の記憶 (下記「採用した文字列の記憶」) か、キャレット直前のかな (下記「範囲の初期値」) |
| 入力なし・選択なし・未判定の文書 | 対象なし |

- 対象が無いときは、変換キー・F6〜F10 を食べずにアプリへ渡す。食べるかどうかは、キーの処理の前に対象を
  読んで決める (`CanRunKeyFunc` から `ReadIdleTarget`)
- 選択なしの対象は読める文書に限る。未判定の文書はキャレット直前を読めるかどうかが分からないため。
  入力なしの変換キー・F6〜F10 は、食べるかを決める前に文書を分類する
  ([basics.md](../design/basics.md)「読める文書の判定」)
- 選択ありの対象は、文書の分類によらず、選択の開始から読み戻して選択の文字列と照合できるときだけにする
  (`MatchRunEditSession`)。照合できない文書では、選択を消して composition に昇格できないため
- F4 (記号・日付変換)・F5 (ユーザ語変換) は入力なしでは働かない。キャレットがかなの直後にあるだけで、
  ブラウザの F5 (再読み込み) などを奪わないため
- 範囲より後ろの文字列 (右の文脈) は変換に使わない。文の途中で変換したときに同音異義語の判別に効くのは
  主に LLM だが、zenz のプロンプトの形式に右の文脈が無く、効果を実験で確かめる必要があるため
  ([roadmap.md](../roadmap.md) の未着手)

### 入力なしの対象から候補選択に入る流れ

1. 対象を読みとして run を作る
   - かなの対象: 読みはひらがなに直し、打鍵列は元の文字にする (F7〜F10 で元の形へ戻せるように)
   - 記憶の対象: 記憶した読みの状態 (`RomajiComposer`) を使う (F9・F10 で打鍵どおりの英字に戻せる)
   - 逆変換の対象: 読みは逆変換の読みの連結、打鍵列は読みの文字そのもの
2. 文書の対象の文字列を照合込みで消し、キャレット位置に空の composition を張る (昇格。`PromoteRun`)
3. 範囲の伸縮の状態を始め、変換キーなら通常の変換、F6〜F10 なら文字種変換に入る

- 照合が食い違ったときは何もしない (run を捨てる)。composition を張れないときは消した文字列を入れ直し、
  変換しない
- 取消で戻る run の方式 (`input_buffer` の composition 入力・パネル保持入力) は、変換キーを押した時点の設定で決める
- 採らなかった案: 対象の文字列の範囲にそのまま composition を張る。composition を独自に解釈するエディタ
  (Discord の入力欄) が確定済みの文字列を内部のモデルから消さず、確定時に元のかなが残るため

### 範囲の初期値 (入力なし・選択なし)

- キャレット直前が有効な記憶で終わり、最新の記憶の表記がひらがな・ー だけでなければ、その記憶 1 件
- それ以外は、キャレット直前から左へ、ひらがなと ー が続くところまで (127 文字まで)
- カタカナ・漢字・英数字・記号・空白・改行で止める。カタカナは意図して入れたものが多いため区切りにする
  (カタカナを含めたいときは選択して変換する)
- 範囲の先頭のずれ (「今日はいしゃに」で「は」を含むなど) は、入力全体の候補 (「は医者に」) と範囲の伸縮で直す

## 前の文脈

| 対象 | エンジンの前文脈 (CONVNBEST・CONVCTX の文脈) | LLM の左文脈 |
|---|---|---|
| run | 直前の確定の最後の文節 | run を始めたときに取ったもの |
| 選択 (かな・逆変換) | 無し | 無し |
| 選択なし・範囲の直前が有効な記憶 | その記憶の最後の文節 (読み, 表記) | 範囲の前の文書の文字列 |
| 選択なし・それ以外 | 範囲の直前の文書が直前の確定の表記で終わるときだけその確定、それ以外は無し | 範囲の前の文書の文字列 |

- 選択の文字列と直前の確定は無関係で、選択の前の文字列の読みも分からないため、選択では前文脈を使わない
- 選択なしで記憶が無いとき、文書の漢字の読みは分からないので、直前の確定と一致するときだけ使う
- LLM の左文脈は、範囲の前の文書の文字列の最後の改行より後ろ
- 範囲を縮めて外したかながあるときは、外したかなを読み = 表記の前文脈にする。外したかなが無くなったら、
  範囲を始めたときの前文脈に戻す

## 範囲の伸縮

候補選択中の ← / → で、変換の範囲の左端を 1 文字ずつ動かす。右端はキャレットに固定する。

- ← で 1 文字広げ、→ で 1 文字縮める (左端が矢印の向きに動く)
- 伸縮するのは次をすべて満たすとき
  - `segment_ui` 0 (文節 UI では ← / → は文節の移動)
  - run の変換キー・F4〜F10、または入力なしの対象から始めた候補選択
  - 読みに英字を含まないか、F6〜F10 の文字種変換中
- 伸縮は文書の分類によらず同じに動く
- 縮めて外したかなは、文書に戻さず composition の先頭に入力中の表示属性 (下線) で残し、強調 (現在文節の
  表示属性) は範囲の変換結果だけにかける。文書は確定まで変わらない。入力パネルの入力行にも同じ内容を出す
- 広げられるのは、縮めて外したかなを戻すところまで。run・入力なしの対象の先頭より左の文書の文字列へは広げない
  (外したかなを文書に書かないため)
- 縮めるのは、範囲の確定済みのかなが 2 文字以上のときに限る (未完成のローマ字は数えない)
- 広げられない・縮められないときは何もしない (キーは食べる)
- 範囲を変えたら、その範囲の読みで変換をやり直し、候補は先頭に戻る。F6〜F10 の文字種変換中は同じ文字種変換を
  やり直し、F4・F5 の特殊変換の後は通常の変換をやり直す
- 伸縮しない候補選択 (英字を含む読みの通常の変換など) の ← / → は、Shift+← / Shift+→・PgUp / PgDn と同じく
  確定してアプリへ渡す
- 変換の候補一覧の位置は composition の矩形を基準にする (外したかながあると、範囲の先頭ではなく composition の
  先頭の下に出る)

### 英字を含む読み

- 英字を含む読み (英単語の打鍵・モードレスの英字区間・末尾の未完成のローマ字) の通常の変換では伸縮しない。
  打鍵したローマ字の候補 (apple / Apple / APPLE) が、範囲を変えると成り立たないため
- F6〜F10 の文字種変換中は、英字を含む読みでも伸縮する。読みはかなごとに打鍵を持つので、先頭のかなを外しても
  残りを打鍵どおりに変換し直せる。モードレスの判定から外れた英単語を手で直すのに使う
  (F10 で打鍵どおりの英字にして、→ で先頭の日本語の部分を外す)
- 1 回の打鍵で入ったかなのまとまり (`kyo` → きょ) の打鍵は、まとまりの先頭のかなが持つ。まとまりの途中で
  切ると、残った側のかなは打鍵を持たない (まとまりの境目まで縮めるか、← で戻せば元に戻る)

### 外した文字の打鍵の復元

- → で縮めるたびに、縮める直前の読みの状態 (`RomajiComposer` 全体。かな・打鍵・未完成のローマ字・英字区間の
  位置) を積む。← で広げるときは最後に積んだ状態に戻す。外した文字は、文字の種類によらず打鍵ごと戻る
- 変換の取消で外したかなを範囲に戻すときは、最初に積んだ状態 (縮める前の読み) に戻す
- 積んだ状態は、範囲の追跡を始めるときと、確定・取消で終えるときに空にする
- 採らなかった案: 打鍵の列だけを覚える。英字区間の位置も合わせて戻す必要があり、状態ごと戻すほうが取りこぼしが無いため

### 採らなかった案

- `ITfComposition::ShiftStart` で composition の先頭を動かす。広げるときに確定済みの文字列を composition に
  取り込むことになり、Discord の入力欄で確定時に元のかなが残る問題と同じことが起きうるため
- 外したかなを確定してアプリへ送り、残りで composition を張り直す (広げるときは消して戻す)。CUAS 経由のアプリ
  (WezTerm など) では、伸縮のたびに文書の書き換えが走り、その間に続けて押した ← / → (キーリピートなど) が
  アプリへ渡ってキャレットを動かすため。端末に 1 文字ずつ確定が届き、アプリ側の補完などが反応するおそれもある

## 確定と取消

- 確定 (確定キー・Enter・Ctrl+1〜9・印字キー・割当の無い Space・アプリへ渡す編集キー・IME オフなど、
  候補選択を確定するすべての経路) では、`外したかな + 選んだ候補` を文書に入れる
- 確定アンドゥ (Ctrl+Backspace) の記憶は、外したかなを含めた全体にする (確定文字列 = `外したかな + 選んだ候補`、
  読み = 外したかな + 範囲の読み)。確定アンドゥで全体のかなに戻る
- 次の前文脈は、確定した最後の文節にする
- 取消 (Esc・Backspace・Ctrl+H・Tab) では、外したかなを範囲に戻した全体のかなの run に戻る
  (取消の後、run を始めたときの方式で続く。Tab は続けて候補バーの先頭を選ぶ)
- 記憶・選択から始めた変換の取消も、元の表記ではなく読みのかなの run に戻す。元の表記は昇格のときに文書から
  消えている。逆変換の読みが誤っていたときに、そのまま読みを打ち直して変換し直せる。元の表記のまま
  終えたいときは、候補の先頭 (元の表記) を確定する
- 候補選択中にアプリが composition を終えたとき (クリックなど) は、候補選択の状態を捨てる (学習しない)

## 学習

| 確定したもの | 送る学習 |
|---|---|
| 入力全体の候補 (`segment_ui` 0) | 候補の文節ごとの (読み, 表記, 直前の文節の表記) と、2 文節以上なら読み全体 → 表記の連結 (文脈なし) を 1 回の LEARN2 で |
| 文節 UI の確定 (`segment_ui` 1) | 文節ごとの学習と、2 文節以上なら読み全体の学習。文節を伸縮したときだけ LEARNSEG・LEARNWORD |
| 入力全体の補正の候補 | 送らない |
| 文節 UI で補正の表記を選んだ文節を含む | 下記「文節 UI」の「補正の候補」 |
| 漢字を含む選択の逆変換から始めた変換 | 下記「漢字を含む選択の再変換」の「学習」 |

- 範囲を縮めて外したかなは学習しない (範囲だけを学習する)
- 先頭の文節の文脈は前文脈の表記、2 文節目からは 1 つ前の文節の表記
- 読み全体の学習は句の学習に入るので、予測の確定履歴にも載る。一度確定した文が前方一致で予測候補に出る
  (短い読みで同じ文を呼び出せるので許容する)
- 文節 UI で 2 文節以上を確定したときも読み全体を送るのは、文節を直して確定した結果を、次から入力全体の候補の
  先頭に出すため
- LEARNSEG・LEARNWORD は文節の伸縮 (Shift+← / Shift+→) でしか起きないので、文節 UI のときだけ送る
- 候補バーの全体変換の採用 (採用範囲を縮めない採用) も、入力全体の候補の確定と同じ学習を送る
- 学習しないアプリ (`no_learning_apps`) では何も送らない

## 入力全体の候補選択 (`segment_ui` 0)

既定の候補選択。run の読み全体を 1 単位にした候補 (CONVNBEST の全件) を変換の候補一覧に出す。

- 内部では読み全体の 1 文節として扱い、候補ごとに CONVNBEST の文節を覚えて確定時の学習に使う
- LLM の並べ替えの結果がその読みと前文脈で出ていれば、その並びを使う (待たない)
- 英字を含む読みは、文節に分けても意味を成さないので、CONVSEG・CONVCTX で全体を 1 文節に固定して変換する。
  モードレスの英字区間と日本語区間が混じる run は固定せず、日本語の部分だけを変換する
- エンジンに接続できないときは、読みのかな (と生ローマ字の候補) だけを候補にする
- 文節の操作は無い。← / → は範囲の伸縮、Shift+← / Shift+→・PgUp / PgDn は確定してアプリへ渡す
- F4〜F10 は読み全体にかかる
- 次候補・前候補は変換キー・Shift+変換キー・↓ / ↑ など (割当は [キー割当](../user/keymap.md))。
  Ctrl+1〜9 は表示中のページのその番号の候補で確定する

## 文節 UI (`segment_ui` 1)

設定 `segment_ui` (既定 0。設定ツールの「文節単位で変換する」) を 1 にすると、候補選択を文節ごとに行う。
`segment_ui` は TSF 層だけが読む。候補バーは `segment_ui` によらない。

- 変換は CONVSEG・CONVCTX。← / → で文節の移動、Shift+← / Shift+→ で現在の文節の伸縮、PgUp / PgDn で
  先頭 / 末尾の文節へ移動する
- 伸縮した文節は長さを固定して変換し直し (前文脈は 1 つ前の文節、先頭の文節なら要求の前文脈)、それより後ろは
  長さを固定せずに区切り直す。伸縮した文節より前の文節は今の候補のまま残す
- 後ろを固定長のまま引き継がないのは、Shift+→ の直後に Shift+← で戻したときに元の区切りに戻らず、不自然な文節に
  割れるため
- 記憶・逆変換から始めた変換で文節が 2 つ以上になったときは、元の表記を候補の先頭に置かない
  (複数の文節には 1 候補として置けないため)

### 補正の候補

- 文節の長さを指定しない変換 (変換キーと、伸縮した文節より後ろの区切り直し) の CONVSEG・CONVCTX には `kinds` を
  付け、補正の表記を受け取る (`ConversionSegment::typoSurfaces`)。長さを固定した変換と、英字を含む読みの
  1 文節固定の変換には付けない。補正の区切りと候補の求め方はエンジンの側 ([typo-segment-ui.md](../design/typo-segment-ui.md))
- 長さを固定した文節には補正を入れない。指定された区切りを動かせず、短い読みでのしきい値も計測していないため。
  伸縮した文節より後ろは区切り直すので補正が効き、伸縮した文節より前は補正の候補を含めて今の候補のまま残る
- 変換の候補一覧は、今の文節の候補のうち `typoSurfaces` にある表記を補正の候補として出す (「補正」のタグと
  テーマの `typo` 色は入力全体の補正の候補と同じ)。候補の並びは後から変わる (生ローマ字の候補・対記号・記憶の表記)
  ので、候補と並ぶ配列ではなく表記で引く
- 補正の表記を選んだ文節の学習 (文節の学習・文脈学習) は送らない。打ち間違えた読みで学習データを汚さないため。
  ほかの文節は送り、その文脈は直前の文節の表記 (補正の表記を含む)
- 補正の表記を選んだ文節が 1 つでもあれば、読み全体の学習と伸縮の学習 (LEARNSEG・LEARNWORD) を送らない。
  どちらも打ち間違えた読みを含むため
- 前文脈と採用した文字列の記憶は、ほかの候補と同じく打ったかなを読みとして更新する

## 採用した文字列の記憶

IME が文書に入れた文字列とその読みを、文書と一致する間だけ覚えておき、漢字を含む部分も読みを打ち直さずに
変換キーで直せるようにする。

### 記憶する内容

- run が文書に残した出力を 1 件 (記憶) として覚える: 候補バーの採用、候補選択の確定、かなのままの run の終了、
  後続語の予測の採用
- 1 件が持つもの
  - 表記 (文書に入れた文字列)
  - 文節ごとの (読み, 表記) の列。かなのままの run と予測候補は 1 文節。文節の読み・表記の連結が読み・表記と
    食い違うときも 1 文節にする
  - 確定前の読みの状態 (`RomajiComposer`)
- Space で終えた run は、末尾のスペースを表記に含めない (スペースで照合が途切れる)
- 記憶は文書に入れた順に並べ、新しいものから読みの合計で 127 文字まで持つ。超えた分は古いものから捨てる
- メモリ上だけに置き、ファイルには保存しない。フォーカス移動と IME オフで捨てる (オフの時点で確定した文字列も含む)
- 未判定の文書でも記憶し、使う時点で読める文書と判定されていて照合で一致したものだけを使う。文書は IME が入れた
  文字列を後から読み戻して分類するので、記憶する時点では未判定のことがある (フォーカス直後の最初の入力など)

### 照合

- 使う時点でキャレット直前の文書の文字列を読み、新しい記憶から順に、表記が文書の末尾から連続して一致する分を
  有効とする。一致しない記憶に当たったら、そこより古い記憶も捨てる
- 記憶の間に IME を通らない文字 (run の外の Space で入れたスペース、アプリへ渡した Enter の改行、アプリでの編集)
  が入ると、それより前の記憶は照合で途切れて使えなくなる
- 選択があるときは照合しない (選択の再変換になる)

### 記憶から始める変換

- 最新の記憶の表記がひらがな・ー だけのときは記憶を使わない。キャレット直前のかなの対象が同じ範囲 (かそれより
  左まで) を含むため
- 候補の先頭に記憶の表記を置く (変換キーを押しただけでは文書は変わらない)。エンジンの候補に同じ表記があれば
  先頭へ寄せ、無ければ足す。そのまま確定したときは記憶の文節で学習する。2 回目の変換キーから次の候補へ進む
- 範囲を縮めている間は記憶の表記を置かない。外したかなをすべて戻すと再び置く
- F6〜F10 で始めたときは、記憶の表記を今の選択として文字種の循環を始める (F10 で打鍵どおりの英字、F7 で全体の
  カタカナから始まる)
- 範囲を縮めて外した読みは、記憶の漢字の文節を途中で切っても、外した側はかなになる (「今日は」の範囲で → を
  2 回押すと「きょ」+「うは」の変換結果)

### 確定と確定アンドゥ

- 確定は候補選択の確定と同じ経路で、学習も同じく送る。確定した範囲を新しい 1 件として記憶し、範囲が覆っていた
  記憶 (範囲に一部だけ入った記憶を含む) を置き換える。縮めて外したかなは、かなの 1 件として記憶する
- 確定アンドゥの記憶 (直前の 1 件の確定文字列と読みの状態) は、記憶とは別に持つ。確定アンドゥで読みに戻した確定の
  記憶は捨てる

### 採らなかった案

- 縮める・広げる単位を文節にして、外した部分を元の表記のまま残す。外した側が書き換わらない利点はあるが、文節の
  途中で切りたい場合に対応できず、かなの範囲の伸縮 (1 文字ずつ) と操作感が揃わないため
- 読めると判定されていない文書でも記憶を使う。文書を読み戻して照合できず、記憶を捨てる契機の漏れが別の文字の
  書き換えにつながるため

## 漢字を含む選択の再変換

漢字を含む選択範囲を、エンジンの逆変換 (REVERSE) で推測した読みから変換キー・F6〜F10 で変換し直す。ほかの
アプリ・別の IME で入れた文字列や、記憶を捨てた後の文字列も直せる。逆変換の格子と語の引き方はエンジンの側
([selection-reconversion.md](../design/selection-reconversion.md) の B)。

### 対象

- 入力なし・選択ありで、選択がかなだけでないとき
- 選択の文字は、ひらがな・カタカナ・ー・漢字・々・〇・〆・数字 (半角 `0`〜`9`・全角 `０`〜`９`) に限る。
  英字・記号・空白・改行を含む選択は対象外。漢字かどうかの細かい判定 (サロゲートペアの CJK 拡張漢字など) は
  エンジンに任せる
- 選択の長さは 127 文字まで。逆変換した読みも 127 文字までとし、超えたら対象外にする
- 選択の読み戻しの照合に失敗したとき、逆変換に失敗したとき (読めない文字がある・エンジンの逆引きの索引が
  できる前) は対象外にする
- 選択が無いときの対象 (記憶・キャレット直前のかな) には逆変換を使わない
- 1 回の打鍵の中では、食べるかの判定と処理で同じ逆変換の結果を使い、REVERSE を 1 度だけ送る。選択の文字列が
  同じでも文書が変わっている可能性があるので、打鍵をまたいでは使わない

### 変換

記憶から始める変換と同じ経路を通る。

- 候補の先頭には元の表記を置く (変換キーを押しただけでは文書は変わらない)。2 回目の変換キーから次の候補へ進む
- F6〜F10 は読みに対して働く (漢字の選択に F7 でカタカナの読み)
- 前文脈と LLM の左文脈は無し
- 範囲の伸縮は選択の中だけで行う。→ で縮めて外した部分は読みのかなになる
- 取消は逆変換の読みのかなの run に戻す (縮めて外した部分も含む)
- 確定は候補選択の確定と同じ経路。確定した範囲は新しい 1 件として記憶する

### 学習

逆変換の読みは推測で、誤ること (「今日」→「こんにち」など) がある。読みを推測したままの文節が学習に入らない
よう、表記が変わった文節だけを学習する。

- 範囲を縮めず、元の表記のまま確定したときは何も学習しない (文節の区切りが逆変換の語の境界とずれていても)
- それ以外は、確定した文節ごとに、その読みの範囲が逆変換の語の境界で区切れ、その範囲の逆変換の表記の連結が
  確定した表記と同じなら、その文節は変わっていないとして学習しない。変わった文節は文節の学習を送る
- 範囲全体の読みの学習・文節境界の学習 (LEARNSEG)・複合語の学習 (LEARNWORD) は送らない。範囲の読みの一部が
  推測のままのため

### 採らなかった案

- ITfFnReconversion (TSF の再変換の機能) を実装し、アプリ・システムからの再変換の依頼を受ける。自分で変換キーを
  押す場合は今の経路で足り、使う場面が無いため見送り ([roadmap.md](../roadmap.md) の見送り・既知の問題)
- 逆変換の読みを複数返して選ばせる。読みの選び方の UI が要るので 1 通りにし、誤った読みは Esc で戻して打ち直す
- 範囲全体を学習する。誤った読みで学習が入るため

## ファンクションキー変換 (F4〜F10)

対象は、run 中なら読み全体、候補選択中なら現在の文節 (`segment_ui` 0 では読み全体)、入力なしなら上の
「変換の対象」(F6〜F10 だけ)。割当は [キー割当](../user/keymap.md)。

- F4 (記号・日付変換): エンジンの CONVSYM で、記号辞書の候補と日付・時刻の候補だけを出す (記号 → 日付・時刻の
  順。日付・時刻の候補は [basics.md](../design/basics.md)「日付・時刻の候補」)。候補が無い読みでは何もしない。
  同じ候補を出している間の F4 は次候補
- F5 (ユーザ語変換): エンジンの CONVUSER で、読みに完全一致するユーザ辞書の語だけを出す (短縮よみ → 名詞系 →
  インポート辞書の名詞系)。連打の扱いは F4 と同じ
- F6〜F10 (文字種変換): エンジンを使わず TSF 層で変換する (tsf/src/kana_forms.cpp)。結果は一意か連打で
  循環するので、変換の候補一覧は出さない
  - F6: ひらがな
  - F7・F8: 全角・半角カタカナ。連打で末尾から 1 文字ずつひらがなに戻す
  - F9・F10: 打鍵したローマ字の全角・半角英字。連打で 打鍵どおり → 先頭だけ大文字 → 全部大文字 → 全部小文字 と
    循環する (同じ形になるものは飛ばす)
- F4・F5 の候補が出た後に範囲を伸縮すると、通常の変換をやり直す

## 数字の書き方の候補

数字で打った数 (`1234`) に、別の書き方の候補を足す (engine/src/number.rs)。かなで読んだ数
(`にせんにじゅうろく`) は対象外。

### 対象の数

- 読みの中の、数字 (半角 `0`〜`9`・全角 `０`〜`９`) だけが続く部分。経路上で 1 語にまとめた数字の語
  (`merge_digit_runs`) のうち、区切り記号を含まないもの
- 区切り記号を含む数字の語 (`0.5`・`1,000`・`12:30`・`2026-09-08`) は対象外。小数・時刻・日付などで、
  書き換えの規則が数とは違うため
- 桁数は 1〜16 桁 (9999兆9999億9999万9999 まで)
- 半角と全角の数字が混ざった数は対象外。桁区切りなどに使う幅と、全角/半角の書き方の向きが決まらないため

### 書き方

数ごとに次の書き方を作る。打ったとおりの表記と同じになるもの・ほかの書き方と同じになるものは作らない。

| 書き方 | 例 (`1234`) | 例 (`120005`) | 条件 |
|---|---|---|---|
| 位取りの漢数字 | 千二百三十四 | 十二万五 | 先頭が `0` でない (1 桁の `0` は 〇) |
| 並べた漢数字 | 一二三四 | 一二〇〇〇五 | 2 桁以上 |
| 桁区切り | 1,234 | 120,005 | 4 桁以上、先頭が `0` でない |
| 万の単位まじり | (作らない) | 12万5 | 5 桁以上、先頭が `0` でない |
| 全角 / 半角 | １２３４ | １２０００５ | 打ったのが半角なら全角、全角なら半角 |

- 位取りの漢数字: 十・百・千の前の「一」は書かない (千二百、十五)。万・億・兆の前は書く (一万、一億)。
  値が 0 の位は書かない (千五、一万五)
- 並べた漢数字: 0 は 〇
- 桁区切り・万の単位まじりは、打ったのが半角なら半角数字、全角なら全角数字で書く (区切りは半角のとき `,`、
  全角のとき `，`)
- 万の単位まじり: 万・億・兆の単位で区切り、値が 0 の単位は書かない (`1200000000` → 12億、`100005000` → 1億5000)
- 大字 (壱・弐・参) と、`1千2百` のような千・百の単位まじりは作らない

### 候補の位置

- 文節の候補 (CONVSEG・CONVCTX) と入力全体の候補 (CONVNBEST) の両方に出し、打ったとおりの数より後ろに置く。
  並びの詳細はエンジンの側 ([number-forms.md](../design/number-forms.md) の C)
- 入力全体の候補で、1-best の文節の表記が学習で数字ごと変わっている (`1,234円` など) ときは、数字に続く部分に
  経路の表記を使う
- 新しい設定は設けない。候補は打ったとおりの数より後ろに出るだけで、文書を自動では書き換えないため
- 学習は文節ごとの読み → 表記のまま。数字の書き方は打った数字で決まり、時間で古くならないため

## 生ローマ字の候補

- 変換の候補が 1 文節のときは、打鍵したローマ字そのもの (`apple` / `Apple` / `APPLE` など。打鍵どおり →
  先頭だけ大文字 → 全部大文字 → 全部小文字のうち重ならないもの) を候補に足す。英単語の大文字小文字を直した表記
  (ASCIIFORM) があれば、その先頭に入れる ([english-case.md](../design/english-case.md))。すでにある候補は動かさない
- 英字を含む読み (英単語の打鍵、末尾の未完成のローマ字など) は、全体を 1 文節に固定して変換し、生ローマ字の候補を
  先頭の候補の直後に入れる。かなだけの読みでは、邪魔にならないよう候補の末尾に入れる
- 英字区間と日本語区間が混じる run では生ローマ字の候補を出さない (run 全体を英字にするなら F10。
  [mixed-conversion.md](../design/mixed-conversion.md))

## 対記号の両側同期

- 候補選択中に文節の候補を変えると、対になる記号の文節も対応する形に揃える (`SyncPairedSegment`)。対象の読みは
  記号キーで入る （）｛｝「」 と ”’
- 開き・閉じの対応は、同じ読みの入れ子の深さを数えて決める。左右同形のクオートは、同じ読みの文節を前から交互に
  開き・閉じとして対にする。対の相手が無ければ何もしない
- 変換を始めたとき (学習で片側だけ変わっている場合など) と、候補を変えたとき・F4〜F10 のときに揃える
- 文節が複数になる変換 (`segment_ui` 1) で働く。`segment_ui` 0 では読み全体が 1 文節なので対象が無い
