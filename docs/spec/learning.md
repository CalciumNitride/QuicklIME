# 学習

確定・採用の結果を覚えて変換と予測に効かせる仕組みの仕様。語・句・文脈の句の学習と使った度合いの割引、
確定の数え方、文節境界と複合語の学習、学習しない確定、学習ファイル、学習の削除、学習しないアプリを扱う。

- 利用者向けの操作の説明は [学習](../user/learning.md) にある
- LEARN・LEARN2・LEARNSEG・LEARNWORD・FORGET の形式は [docs/protocol.md](../protocol.md)
- 確定・採用のときに TSF 層がどの組を送るかは、変換キーの候補選択の確定は [conversion.md](conversion.md)「学習」、
  候補バーの採用は [suggest.md](suggest.md)「採用の後」、後続語の予測の採用は [suggest.md](suggest.md)「選択と採用」。
  本書はエンジンでの数え方と、各所に共通の規則を書く
- 割引が変換・予測の中でどこにどう効くかは [engine.md](engine.md) と [suggest.md](suggest.md)。本書は効く所の一覧
  (下記「学習の効く所」) だけを置く
- 学習の削除のキーの働く状態は [keys.md](keys.md)「機能」、削除の後の候補の作り直しは [suggest.md](suggest.md)
  「学習の削除の後の候補」
- 実装は engine/src/learn.rs (3 種類の学習・度合いと割引・learning_stats.tsv・文節境界・削除)、engine/src/convert.rs
  (`split_words`・`split_path`。文節を辞書の語に分ける)、engine/src/userdict.rs (学習した複合語と learning_word.tsv)、
  engine/src/main.rs (LEARN・LEARN2・LEARNSEG・LEARNWORD・FORGET の受付)、tsf/src/text_service.cpp
  (確定の学習・文節の伸縮の学習・学習の削除・`IsNoLearningApp`)、tsf/src/text_service_direct.cpp (採用と run の終わりの学習)

## 学習の種類

| 学習 | 単位 | 覚えるもの | ファイル |
|---|---|---|---|
| 語の学習 | (読み, 表記) | 確定した文節を辞書の語に分けたときの自立語 | learning_stats.tsv |
| 句の学習 | (読み, 表記, 種類) | 確定した文節 (種類 `seg`) と、2 文節以上の確定の読み全体 (種類 `whole`) | learning_stats.tsv |
| 文脈の句の学習 | (文脈, 読み, 表記) | 直前の文節の表記 (末尾 16 文字) に続いて確定した文節 | learning_stats.tsv |
| 文節境界の学習 | 読み | 文節を伸縮して区切りを直した文節の読み | learning_boundary.tsv |
| 複合語の学習 | (読み, 表記) | 文節を伸縮して割った・まとめた範囲の語 | learning_word.tsv |

- 語・句・文脈の句の学習は、どれも使った度合い (下記「使った度合いと割引」) を持つ。文節境界と複合語の学習は
  度合いを持たず、古くならない
- 句の学習は辞書の語に分けられない文節も覚える。語の学習は辞書の語の単位なので、覚えたとおりの文節でなくても
  効く (「今日は」を確定すると「きょうも」が「今日も」になる)

## 確定の数え方 (LEARN・LEARN2)

LEARN・LEARN2 の組 (読み, 表記, 直前の文節の表記) ごとに次を行う (engine/src/main.rs `learn_entries`、
engine/src/learn.rs `learn_segment`)。

1. 確定の通し番号 N を 1 増やす
2. 文節を辞書の語に分ける (下記「文節を辞書の語に分ける」)。分けられたら、自立語ごとに語の学習を 1 回数える。
   下記「語の学習に数えない語」は数えない
3. 直前の文節の表記があれば、文脈の句の学習を 1 回数える
4. 句の学習 (種類 `seg`) を 1 回数える。分けられなかった文節もここで覚える

- 3 組以上で、末尾の組の読みと表記がそれより前の組の読みと表記の連結なら、末尾の組は TSF 層が足した読み全体
  ([conversion.md](conversion.md)「学習」) とみなし、句の学習 (種類 `whole`) だけを数える。N は増やさない
- 同じ (読み, 表記) の句を `seg` と `whole` の両方で数えたときは `seg` にする (文節として確定したことのある句は、
  下記「辞書の語に分けられない句」でラティスに載せる対象に残す)
- 読みか表記が空の組は数えない。日付・時刻の候補と同じ表記の組も数えない ([engine.md](engine.md)「日付・時刻の候補」)
- 文脈の句の学習の文脈は、直前の文節の表記の末尾 16 文字 (`MAX_CONTEXT_KEY_CHARS`)。長文の貼り付けなどで異常に
  長い文脈を、そのままキーにしないため
- LEARN2 の先頭の組に前文脈の読みと 1 つ前の文節が付いていれば、直前の文節の表記は前文脈の連結
  ([engine.md](engine.md)「前文脈」) を当てたものにする (「東京」→「に」の後の文節は、文脈「東京に」で数える)

### 文節を辞書の語に分ける

確定した文節 (読み, 表記) の読みで、表記が文節の表記の対応する位置と一致する辞書の語だけを通る経路のうち、
コストの最も小さいものを選ぶ (engine/src/convert.rs `split_path`)。

- 辞書の語は、システム辞書・ユーザ辞書の名詞系の語 (学習した複合語を含む)・インポート辞書の語。未知語・英字の連続・
  辞書の語に分けられない句の語は通らないので、それらを含む文節は分けられない
- コストは学習の割引を引かない単語コスト・連接コスト・自立語ごとの文節境界ペナルティ・文末への連接コストの和。
  前文脈は使わず、文頭の直後の付属語の例外 ([engine.md](engine.md)「文節境界ペナルティ」) は持たない
- 付属語 (左の品詞 ID が助詞・助動詞・接尾語の語。[engine.md](engine.md)「コスト」) は語の学習に数えない。
  接続コストが受け持ち、回数が極端に多くなって割引の上限に張り付き、区別がなくなるため

### 語の学習に数えない語

自立語でも、次の語は語の学習に数えない (engine/src/learn.rs `counts_as_word`)。

- 読みが 1 文字の語
- 表記が読みと同じで、ひらがな (と ー) だけの語
- 表記に数字 (半角・全角) を含む語

これらに割引が付くと、ほかの文で 1 文字やひらがなの語に細かく割れたり (「て|い|…」)、数字に置き換わったり
(いち → 1) するため。

### 辞書の語に分けられない句

分けられなかった文節の句の学習は、名詞の 1 語として変換のラティスに載る
([engine.md](engine.md)「ラティスの語」)。

- 載せるのは種類 `seg` の句だけ。読み全体の句 (`whole`) は読み全体の学習表記 ([engine.md](engine.md)「候補の並び」) が
  受け持つ
- 表記に数字を含む句は載せない。「1,234円」の 1 語が 1-best になり、数字の書き方の候補が出なくなるため
- 分けられたかどうかは数えるたびと、エンジンの起動時 (learning_stats.tsv は分けた結果を持たない) に求め直す。
  辞書が変わると起動時に変わりうる

## 使った度合いと割引

語・句・文脈の句の学習の 1 件は (度合い d, 最後に数えたときの通し番号 t) を持つ (engine/src/learn.rs)。

- 古さは確定の回数で測る。今の度合いは `d_now = d × 2^(−(N − t) / HALF_LIFE)`
- 数えるときは `d ← d_now + 1`、`t ← N`
- N は確定した文節を数えるたびに 1 増える。読み全体の句・複合語の句 (LEARNWORD)・古い learning_context.tsv の
  取り込みで数えるときは増やさない
- 割引は `min(上限, 重み × log2(1 + d_now))` を整数に丸めた値。単位は辞書の単語コストと同じ

| 定数 | 値 | 使う所 |
|---|---|---|
| `HALF_LIFE` | 2000 | 度合いが半分になる確定の回数 (3 種類共通) |
| 語の学習の重み・上限 | 1000・1500 | Viterbi の単語コストの割引 |
| 文脈の句の学習の重み・上限 | 2500・8000 | 前文脈付きの予測の点数・並び |
| 句の学習の重み・上限 | 1500・6000 | 句の学習の並び・ラティスに載せる句・予測の点数 |
| `PHRASE_BASE` | 6000 | 予測の句の学習の点数の基準 ([suggest.md](suggest.md)「点数」) |

- 値は再生評価 ([engine.md](engine.md)「再生評価」) で決めた。語の学習の上限を単語コストの差より大きくすると
  (3000 以上)、学習した語に細かく割れた経路が勝ち、変換の 1 位の割合が大きく下がる
- 同じ読みで「最後に選んだ表記を先頭にする」規則は持たない。並びは使った度合いだけで決まり、1 回だけ別の表記を
  選んでも、よく使う表記が先頭のままになりうる
- 学習を割引の大きい順に並べるときは、割引が同じなら今の度合い、次に t の大きい順にする (上限に張り付いた件どうしを
  使った度合いで分けるため)
- 評価で定数を振れるよう、定数はストアごとに持つ (engine/examples/learning_eval.rs の `--weights`)

## 学習の効く所

| 学習 | 効く所 |
|---|---|
| 語の学習 | Viterbi の自立語の単語コストの割引 ([engine.md](engine.md)「コスト」)。全体変換・文節の候補・N-best・予測の 1 語の経路のコスト ([suggest.md](suggest.md)「点数」)・逆変換 ([engine.md](engine.md)「逆変換 (REVERSE)」) に同じ割引を使う |
| 句の学習 | 文節の候補の経路の表記の次 ([engine.md](engine.md)「文節の候補 (CONVSEG・CONVCTX)」)、読み全体の学習表記 ([engine.md](engine.md)「候補の並び」)、予測の確定履歴と頭の語 ([suggest.md](suggest.md)「予測」「頭の語」)、名詞で終わる前文脈の後続語の予測の付属語 ([suggest.md](suggest.md)「後続語の予測」)、辞書の語に分けられない句のラティスの語 ([engine.md](engine.md)「ラティスの語」)、逆変換の読みの優先 ([engine.md](engine.md)「学習の優先」) |
| 文脈の句の学習 | 前文脈付きの予測 ([suggest.md](suggest.md)「点数」) と後続語の予測 ([suggest.md](suggest.md)「後続語の予測」) |
| 文節境界の学習 | 文節境界ペナルティの増減 ([engine.md](engine.md)「学習した文節境界」) |
| 複合語の学習 | ユーザ辞書の名詞系の語としてラティスに載る ([engine.md](engine.md)「ラティスの語」) |

- 文脈の句の学習は変換の経路には効かない ([engine.md](engine.md)「前文脈」)
- 学習で候補の保護 (LLM の並べ替えで動かさないなど) が決まる候補は [engine.md](engine.md)「保護の印」

## 文節境界と複合語の学習 (LEARNSEG・LEARNWORD)

文節 UI (`segment_ui` 1) で文節を伸縮して確定したときだけ、TSF 層が伸縮の前後の区切りを比べて送る
(tsf/src/text_service.cpp `LearnResizedSegments`)。比べる前の区切りは、その変換で最初に伸縮する前の区切り。

| 伸縮の前後の区切り | 送るもの |
|---|---|
| どちらかの区切りの位置がもう一方にすべて含まれる (1 文節を割った・複数の文節をまとめただけ) | LEARNWORD: 割った・まとめた範囲ごとに、範囲の読みと表記の連結。どちらの区切りでも 1 文節の範囲は送らない |
| それ以外 (区切りの位置を動かした) | LEARNSEG: 確定した全文節の読み |

- 割った・まとめただけのときは、辞書に無い語を入れようとしたとみなす。このとき境界を学習すると、次も同じ語が
  割れる方向に効くため、境界ではなく 1 語として覚える
- 伸縮せずに確定したときは送らない。人が直していない区切りまで境界として強めるため
- 補正の表記を選んだ文節を含む確定と、漢字を含む選択の逆変換から始めた変換では送らない
  ([conversion.md](conversion.md)「補正の候補」「漢字を含む選択の再変換」)

### 文節境界の学習

- エンジンは届いた読みを境界として覚え、learning_boundary.tsv に 1 行 1 読みで追記する。2 文字未満の読みは覚えない
  (「は」のような 1 文字の付属語まで境界にすると、どこでも切れる方向に効くため)。覚えている読みは追記しない
  (追記ログが際限なく伸びないため)
- 変換での効き方は [engine.md](engine.md)「学習した文節境界」

### 複合語の学習

- エンジンは範囲 (読み, 表記) を名詞の 1 語として覚え、learning_word.tsv に `読み\t表記` で追記する
  (engine/src/userdict.rs `learn_word`)
  - 読みが 2 文字未満の語と、表記が読みと同じ語は覚えない
  - 同じ読みの複合語は 1 つだけ持ち、別の表記を覚えると置き換える (読み込みでは後の行が勝つ)。同じ組は追記しない
- 単語コストは `LEARNED_WORD_COST` (12000) で、ユーザ辞書の名詞系の語としてラティスに載る。辞書の語の組み合わせで
  経路が作れる読み (「けいしょうか」= 継承+化) はその経路が勝ち、未知語まじりの経路しか無い読み (「まいぐらふぃ」) だけ
  1 語になる。1 語に置き換えると、先頭の語を入れ替えた候補 (継承化・敬称化…) が消えて別の表記を選べなくなるため
- 同時に、範囲 (読み, 表記) の句の学習 (種類 `seg`) を 1 回数える。候補の並びは句の学習が受け持つ。語の学習は数えず、
  N も増やさない
- 複合語はユーザ辞書 (userdict.tsv) と混ぜず、別のファイルに持つ。誤った学習だけを捨てられるようにするため
- 日付・時刻の候補と同じ表記の範囲は覚えない (LEARN と同じ)

## 学習しない確定

| 確定 | 扱い |
|---|---|
| かなのままで run を終えた (変換・採用をしない) | 学習しない。英字を含む読みは、読み = 表記で学習する (tsf/src/text_service_direct.cpp `EndRun`) |
| 補正の候補・補正の表記を選んだ文節 | 学習しない ([conversion.md](conversion.md)「学習」「補正の候補」・[suggest.md](suggest.md)「採用の後」) |
| 漢字を含む選択の逆変換から始めた変換 | 表記が変わった文節だけを学習する ([conversion.md](conversion.md)「漢字を含む選択の再変換」) |
| 日付・時刻の候補 | エンジンが学習しない ([engine.md](engine.md)「日付・時刻の候補」) |
| フォーカス移動・アプリによる composition の終了・キー入力が無効な文書 | 学習しない ([input.md](input.md)「run の終わり方」) |
| 設定 `learning` 0 | エンジンが記録しない (下記「設定」) |
| 学習しないアプリ | TSF 層が送らない (下記「学習しないアプリ」) |

- かなのままの確定を学習しないのは、学習が変換の候補の並びにも効き、「きょう → きょう」を覚えるとひらがなの候補が
  上に来るため
- 英字を含む読みを学習するのは、予測の確定履歴に載せて英単語を省入力で出すため

## 学習ファイル

学習ファイルは `%APPDATA%\QuicklIME\` に置く。`QUICKLIME_LEARN_FILE` で learning.tsv の場所を `<名前>.tsv` に変えると、
同じディレクトリの `<名前>_stats.tsv`・`<名前>_boundary.tsv`・`<名前>_word.tsv` を使い、古いファイルも `<名前>.tsv`・
`<名前>_context.tsv` から取り込む。保存先が決まらない (`APPDATA` が無い) ときは、学習はメモリ上だけで動く。

### learning_stats.tsv

語・句・文脈の句の学習を 1 行 1 件のタブ区切りで持つ。行の頭が種類。

```
n\t<N>
w\t<読み>\t<表記>\t<d>\t<t>
p\t<読み>\t<表記>\t<d>\t<t>\t<seg|whole>
q\t<文脈>\t<読み>\t<表記>\t<d>\t<t>
```

- 数えるたびに、その件の行と `n` の行を追記する。読み込みでは同じ件は後の行が勝つ。書式に合わない行は飛ばす
- エンジンの起動時に、読んだ有効な行の数が件数の 2 倍を超えていれば、メモリの内容で書き直す。書き直すときに
  今の度合いが `MIN_KEEP` (0.05) 未満の件を捨てる。書き直しは同じディレクトリの一時ファイル (`<ファイル名>.tmp`) に
  書いてから置き換える (学習の削除と learning_word.tsv の書き直しも同じ)
- 書き直したファイルは `n` の行の後に、件を t の順に並べる。古さは t と N で決まるので、エンジンを再起動しても
  度合いと新しさの順は変わらない

### 古いファイルの取り込み

learning_stats.tsv が無く、古い形式の learning.tsv か learning_context.tsv があるときは、それらから作る。

| ファイル | 書式 | 取り込み方 |
|---|---|---|
| learning.tsv | `読み\t表記` | 行の順に、各行を前文脈なしの 1 回の文節の確定として数える (上記「確定の数え方」の 1・2・4) |
| learning_context.tsv | `文脈\t読み\t表記` | 行の順に、文脈の句の学習だけを 1 回数える |

- learning_context.tsv で語の学習と句の学習を数えないのは、その行の確定が learning.tsv にも同じく書かれており、
  両方で数えると二重になるため
- 取り込んだ後は learning_stats.tsv を書き直して作り、learning.tsv と learning_context.tsv には書かない。古いファイルは
  消さずに残す (古いエンジンに戻したときに使えるようにするため)

## 学習の削除 (FORGET)

候補バーと後続語の予測で選んでいる候補の学習を、`key.forget_learning` (既定 Ctrl+Delete) で消す。誤って確定した
表記を覚えると、確定し直すまで上位に出続けるため。

### 送る組

| 選んでいる候補 | 送る (読み, 表記) |
|---|---|
| 予測候補 (後続語の予測・ずれのある予測を含む) | 候補の (読み, 表記) |
| 全体変換 (補正の候補を含む) | 読み全体と表記の組と、候補の文節ごとの (読み, 表記) |
| 英字候補 | 送らない (学習に由来する候補ではない) |

- 全体変換で文節ごとの組も送るのは、文節ごとの学習で表記の決まった 1-best が同じ表記を作り続けるため。学習していない
  文節は表記が一致する学習が無いので影響しない。正しく覚えていた文節の学習も消えるが、次の確定で覚え直される
- TSF 層はエンジンの自動起動も接続の待ちもしない。エンジンに接続できない・FORGET を知らない旧エンジン・候補を選んで
  いない・英字候補のときは、打鍵を食べて何もしない ([keys.md](keys.md)「機能」)
- 消した件数が 0 なら表示を変えない。1 以上なら候補を作り直す ([suggest.md](suggest.md)「学習の削除の後の候補」)。
  文書と確定アンドゥの記憶は変えない

### 消すもの

組ごとに次を消す (engine/src/learn.rs `forget`・engine/src/userdict.rs `forget_learned`)。

- 句の学習の (読み, 表記)
- 文脈の句の学習のうち、(読み, 表記) が一致するもの (文脈によらず)
- 語の学習のうち、(読み, 表記) を辞書の語に分けた自立語。ほかの文節で覚えた分もまとめて消える (候補を上位から外す
  目的に合わせる)。学習した複合語を消す前に分けるので、複合語を 1 語として数えた分も消える
- learning_word.tsv の、読みと表記が一致する複合語

- 辞書・ユーザ辞書 (手動登録・インポート辞書) の語と、文節境界の学習は消さない。文節境界の学習は (読み, 表記) の組を
  持たないため
- 応答の件数は消した件の合計。読みか表記の欠けた組が 1 つでもあれば、どの組も消さずに ERR を返す
- 消した件があったファイルだけを、メモリの内容で書き直す (learning_stats.tsv は上記「learning_stats.tsv」と同じ書き方、
  learning_word.tsv は保持している順)。書き直しに失敗してもファイルは元のまま残り、メモリからは消えたまま
  (エンジンの再起動で戻る)
- 設定 `learning` 0 と学習しないアプリでも消す (記録ではないため)

### 採らなかった案

- 削除を表す行 (tombstone) を追記する。追記ログに新しい書式が増え、旧エンジンでは消した学習が戻る

## 学習しないアプリ

設定 `no_learning_apps` のアプリでは、TSF 層が学習の要求 (LEARN・LEARN2・LEARNSEG・LEARNWORD) を送らない。ターミナルや
ゲームのように、ふだんの文章と違う語 (コマンド・略語・一時的な文字列) を打つアプリで学習が進むと、ほかのアプリでの
候補の並びが崩れるため。

- ホストの exe 名を `no_learning_apps` の exe 名と大文字小文字を区別せずに比べる (tsf/src/text_service.cpp
  `IsNoLearningApp`)。exe 名が取れないときは学習する
- 学習の送り先のすべて (変換キーの確定・文節の伸縮の学習・候補バーの採用・後続語の予測の採用・run の終わりの英字の学習)
  の手前で判定する
- 止めるのは記録だけで、既存の学習は変換・予測・後続語の予測に使う (`learning` 0 と同じ)
- 前文脈 (直前に確定した文節) はメモリ上の状態で記録ではないので、更新して後続語の予測と変換に使う
- 単語登録ツールでの登録 (ADDWORD) と学習の削除 (FORGET) は止めない。人が明示的に行う操作のため
- 設定の書式は `newline_apps` と同じ exe 名のカンマ区切り (前後の空白は無視)。TSF 層の設定の読み直しで反映する
- 採らなかった案: エンジンでアプリを判定する。エンジンはどのアプリからの要求かを知らないので、プロトコルに exe 名を
  足す必要がある。TSF 層で送らなければエンジンとプロトコルを変えずに済む

## 設定

値の書式と設定ツールでの名前は [設定一覧](../user/settings.md)。

| 設定 | 既定 | 読む側 | 本書での働き |
|---|---|---|---|
| `learning` | 1 | エンジン | 0 で LEARN・LEARN2・LEARNSEG・LEARNWORD を記録せずに OK を返す。既存の学習は使い続け、FORGET は消す |
| `no_learning_apps` | 空 | TSF 層 | 学習の要求を送らないアプリの exe 名 |
| `key.forget_learning` | `Ctrl+Delete` | TSF 層 | 学習の削除 |

## 採らなかった案

- 文節の単位のままラティスに語を足す: 覚えたとおりの文節にしか効かず、語の品詞を確定のたびに求め直す必要があり、
  作りは語の単位と同じくらい重い
- 最後に選んだ表記を先頭にする規則を残す: 並びの予測はしやすいが、1 回の選び間違いで並びが入れ替わる
- 日付で古さを測る: 使わない期間で学習が古くならない利点はあるが、いつ何を打ったかが学習ファイルに残る
- 付属語も語の学習で数える: 回数が極端に多くなり、割引の上限に張り付いて区別がなくなる
- 前文脈による変換の使い分け (「服を|着る」「紙を|切る」): 語の単位の文脈の割引を試したが、評価で変換の 1 位の割合が
  下がった (割引を 0 にすると上がった)。前文脈は予測と後続語の予測にだけ使う ([roadmap.md](../roadmap.md) の見送り)
