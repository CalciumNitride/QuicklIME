# 辞書

エンジンが引く辞書の仕様。辞書の種類と置き場所、システム辞書 (Mozc 辞書と UT 辞書) の書式と検索、UT 辞書の取得と
生成、単漢字辞書と記号辞書、辞書ごとの語のコスト、ユーザ辞書、インポート辞書と他の IME の辞書の取り込み、
単語登録ツールを扱う。

- 利用者向けの操作の説明は [辞書とローマ字](../user/dictionary.md) にある
- ADDWORD・RELOADUSER・CONVUSER・CONVSYM・CONVNAME の形式は [docs/protocol.md](../protocol.md)
- 辞書の語を変換・予測の中でどう使うか (ラティス・文節の候補・入力全体の候補の並び・予測の並び) は
  [engine.md](engine.md)「ラティスの語」「文節の候補 (CONVSEG・CONVCTX)」「候補の並び」と
  [suggest.md](suggest.md)「予測」「旧エンジンとの互換」。本書は辞書の中身と、どの辞書がどの候補に入るかを書く
- 英単語辞書 (english-words.txt・english-names.txt) とユーザ辞書の英字の語はモードレス入力の側
  ([modeless.md](modeless.md)「英単語辞書」「大文字小文字の補正」)、後続語の統計 (next_word.tsv) は候補バーの側
  ([suggest.md](suggest.md)「文節の連なりの統計」)、学習した複合語 (learning_word.tsv) は学習の側
  ([learning.md](learning.md)「複合語の学習」)
- F3〜F5 の候補選択は [conversion.md](conversion.md)「ファンクションキー変換 (F3〜F10)」、単語登録ツールを起動する
  キーの働く状態は [keys.md](keys.md)「機能」
- 単語登録ツールの画面 (部品の配置・InfoBar・Enter と Esc) は [tools.md](tools.md)「単語登録ツールの画面」。
  インストーラへの辞書の同梱とライセンス文書は [runtime.md](runtime.md)「インストール先の構成」「インストーラのビルド」
  「同梱するライセンス文書」
- 実装は engine/src/dict.rs (システム辞書・単漢字辞書・記号辞書と fst の検索)、engine/src/userdict.rs (ユーザ辞書と
  インポート辞書)、engine/src/import.rs (他の IME の辞書の取り込み)、engine/src/pos.rs (品詞 ID 表)、
  engine/src/matrix.rs (連接行列)、engine/src/main.rs (辞書の探索と読み込み、ADDWORD・RELOADUSER・CONVUSER・
  CONVSYM・CONVNAME の受付)、engine/gui/src/regword.rs と engine/gui/src/bin/quicklime-regword.rs (単語登録ツール)、
  tsf/src/text_service.cpp (`LaunchWordRegister`)、engine/examples/build_ut_dict.rs と scripts/fetch-ut-dict.ps1
  (UT 辞書の生成と取得)

## 辞書の種類

| 辞書 | ファイル | 中身 |
|---|---|---|
| Mozc 辞書 | `dictionary00.txt`〜`dictionary09.txt` | Mozc OSS の辞書 |
| UT 辞書 | `dictionary_ut.txt` | mozc-ut の元データから作った一般語・地名・人名 (下記「UT 辞書」) |
| 連接行列 | `connection_single_column.txt` | Mozc の品詞 ID 間の連接コスト |
| 品詞 ID 表 | `id.def` | Mozc の品詞 ID と品詞名 |
| 単漢字辞書 | `single_kanji.tsv` | Mozc の読みごとの単漢字 |
| 記号辞書 | `symbol.tsv` | Mozc の読みごとの記号 |
| ユーザ辞書 | `userdict.tsv` | 単語登録ツールで登録した語と、手で書いた語 |
| インポート辞書 | `imported\*.tsv` | 他の IME の辞書から取り込んだ語 |

- 本書の「システム辞書」は Mozc 辞書と UT 辞書を合わせたもので、エンジンの中では 1 つの辞書として引く
  ([suggest.md](suggest.md) などの「同梱辞書」も同じもの)
- 辞書はどれもエンジンの起動時に読む。読み直すのはユーザ辞書とインポート辞書だけ (下記「登録と読み直し」)
- 辞書のどれかが無くても、エンジンはその辞書なしで起動を続ける

## 辞書ディレクトリ

システム辞書・連接行列・品詞 ID 表・単漢字辞書・記号辞書は辞書ディレクトリから読む。辞書ディレクトリは
次の順に決める (engine/src/main.rs `dictionary_dir`)。

1. 環境変数 `QUICKLIME_DICT_DIR`
2. exe と同じディレクトリの `dict\` (インストール先のレイアウト。ディレクトリがあるときだけ)
3. 開発レイアウトの `references/mozc/src/data/dictionary_oss` (exe が `engine/target/{debug,release}/` にある前提で
   リポジトリのルートを決める)

辞書ディレクトリに置かないファイルは、辞書ごとに次の場所も見る。

| 辞書 | 1 番目 | 無ければ |
|---|---|---|
| UT 辞書 | 辞書ディレクトリ直下 | リポジトリの `references/mozcdic-ut/dictionary_ut.txt`。`QUICKLIME_DICT_DIR` を指定したときは見ない |
| 単漢字辞書 | 辞書ディレクトリ直下 | Mozc の配置 (辞書ディレクトリと並ぶ `single_kanji/single_kanji.tsv`) |
| 記号辞書 | 辞書ディレクトリ直下 | Mozc の配置 (辞書ディレクトリと並ぶ `symbol/symbol.tsv`) |

- `QUICKLIME_DICT_DIR` は「この辞書一式で動かす」指定なので、UT 辞書をリポジトリから補わない。engine/tests/pipe.rs
  などの隔離した起動に本物の UT 辞書が混ざると、候補も読み込みの時間も変わるため
- 英単語辞書は辞書ディレクトリを使わずに探す ([modeless.md](modeless.md)「英単語辞書」)。後続語の統計は UT 辞書と
  同じ規則で探す ([suggest.md](suggest.md)「エンジンでの読み込み」)

## システム辞書

### システム辞書の書式

- 1 行 1 語の `読み\t左文脈ID\t右文脈ID\tコスト\t表記` (UTF-8)。6 列目からは読まない。列が足りない行と、
  ID・コストが数値でない行は読み飛ばす
- Mozc 辞書の 10 ファイルを番号の順に読み、続けて UT 辞書を読む。同じ読みの語は読んだ順に持ち、候補の並びは
  コストで決める (同じコストなら読んだ順)
- Mozc 辞書が 1 ファイルも無いときと、Mozc 辞書か UT 辞書に読めない行 (UTF-8 として不正な行など) があったときは、
  システム辞書なし (Mozc 辞書も UT 辞書も使わない) で起動する
- 起動のログに、読み込んだ語の数と、読んだ Mozc 辞書のディレクトリと UT 辞書のパスを出す

### 検索

読みをキー、語の並びの位置を値にした fst (有限状態トランスデューサ) の `fst::Map` 1 つで、次の検索をする。

| 検索 | 使う所 |
|---|---|
| 完全一致 | 文節・入力全体の候補 |
| 共通接頭辞検索 | ラティスの構築。読みの各位置から 1 回の走査で、`MAX_READING_CHARS` (16) 文字までの語を短い順に引く |
| 前方一致 | 予測。コストの小さい順に返す。一致する読みが 20,000 を超えたら走査を打ち切る (短い読みで一致範囲が巨大になるのを避けるため) |
| 打鍵のファジィ照合 | 候補バーの予測 ([suggest.md](suggest.md)「予測の照合」) |

- fst はキーの共通接頭辞・接尾辞を圧縮するので、ハッシュ表と前方一致用の読みの配列を別に持つよりメモリが少ない
- 表記から読みを引く逆引きの索引は、別の構造としてエンジンの待ち受けを始めてから作る
  ([engine.md](engine.md)「逆引きの索引」)
- 採らなかった案: ダブル配列のクレート (yada・crawdad)。前方一致で語を列挙する API が無く、予測に使えないため

### 連接行列と品詞 ID 表

- 連接行列 (`connection_single_column.txt`) が無いか読めなければ、連接コストを 0 にして動く
- 品詞 ID 表 (`id.def`) は、付属語の判定 ([engine.md](engine.md)「コスト」)・人名の判定と、ユーザ辞書・インポート辞書の
  品詞名から文脈 ID を引くのに使う。無いか読めなければ、どの語も自立語として扱い (1 語が 1 文節になる)、人名を判定せず、
  ユーザ辞書・インポート辞書の語は一般名詞の ID (1851) にする
- 人名は、品詞名が `名詞,固有名詞,人名,` で始まる ID (Mozc では人名一般・名・姓) を左文脈 ID に持つ語。ID の数値は
  固定せず、品詞 ID 表を読んだときに品詞名から求める (表ごとに ID が違うため)。システム辞書の人名を変換・予測の候補で
  抑えるのと ([engine.md](engine.md)「文節の候補 (CONVSEG・CONVCTX)」、[suggest.md](suggest.md)「予測」)、人名変換
  (F3) の CONVNAME で人名を集めるのに使う
- F3 の CONVNAME は、読みに完全一致する人名を、ユーザ辞書の名詞系の語 (記載順) → インポート辞書の名詞系の語 (記載順) →
  システム辞書 (コスト順。変換の候補で抑えた人名も含む) の順に、同じ表記を除いて返す

## UT 辞書

Mozc 辞書に無い固有名詞・地名・人名・複合語を補う辞書。Mozc 向けの追加辞書 mozc-ut (utuhiro78 氏) の元データから、
同梱しやすいライセンスのものを選んで生成する。

### 元データ

| 元データ | リポジトリ | ライセンス | 品詞 (id.def の品詞名) |
|---|---|---|---|
| SudachiDict | utuhiro78/mozcdic-ut-sudachidict | Apache 2.0 (一部 UniDic 由来で BSD) | `名詞,一般,*,*,*,*,*` |
| 日本郵便の郵便番号データ (地名) | utuhiro78/mozcdic-ut-place-names | 日本郵便は著作権を主張しない | `名詞,固有名詞,地域,一般,*,*,*` |
| 人名 | utuhiro78/mozcdic-ut-personal-names | Apache 2.0 | `名詞,固有名詞,人名,一般,*,*,*` |

- 採らなかった案
  - NEologd: 更新が止まっており、「ぁまのじゃく」のような崩した表記が多く誤変換の元になりやすい。mozc-ut の既定の
    構成でも除かれている
  - jawiki・EDICT (CC BY-SA)、SKK-JISYO・alt-cannadic (GPL): 同梱するときのライセンスの条件が重い
  - mozc-ut の公式のマージスクリプト (merge-ut-dictionaries): コストの調整に Wikipedia のタイトルの一覧 (CC BY-SA、
    数百 MB) を取得して使い、品詞もすべて名詞,一般にする。最新の Mozc を取りに行くので、手元の Mozc 辞書とも食い違う

### 取得

scripts/fetch-ut-dict.ps1 が、元データ 3 つと SudachiDict のライセンス文書 (`LEGAL`・`LICENSE-2.0.txt`) を、コミットを
固定した GitHub の URL からリポジトリの `references\mozcdic-ut\` (git 管理外) に取得し、生成まで行う。

- ファイルごとにサイズと SHA-256 を確かめる。取得済みで一致するファイルは取り直さない。一致しない取得物は消して止まる
- 途中で失敗したファイルを正しい名前で残さないよう、一時ファイルに取ってから置き換える
- `references\mozc\src\data\dictionary_oss` が無ければ止まる (生成に Mozc 辞書と id.def を使うため)

### 生成

engine/examples/build_ut_dict.rs が元データ (bz2) を読み、`dictionary_ut.txt` を書く。bz2 の展開と Unicode の正規化の
クレートは dev-dependency にし、エンジン本体の依存を増やさない。

- 元データの各行 `読み\tID\tID\tコスト\t表記` を読む。列が足りない行・コストが数値でない行・読みか表記が空の行は捨てる
- 表記を NFKC で正規化し、`~` を `〜` にする (mozc-ut と同じ)
- 次の行を除く (この順に判定する)
  1. 表記が 1 文字、または 26 文字以上
  2. 表記が ASCII だけ (英単語はモードレス入力の英単語辞書が受け持つ)
  3. (読み, 正規化した表記) が Mozc 辞書にある (Mozc 辞書の表記にも同じ正規化をかけて比べる)
  4. (読み, 正規化した表記) が先に出力した行と同じ (元データは上の表の順に読むので、上の元データが優先される)
- 品詞 ID は `--mozc` の id.def から、上の表の品詞名と 2 列目が一致する行の ID を引く (数値を固定しない)。左右の ID は
  同じ値にする。引けなければ止まる
- コストは元データの値に `--cost-offset` (取得のスクリプトでは 0) を足した値。i16 に収まらなければ範囲の端に切り詰める
- 出力は Mozc 辞書と同じ書式 (UTF-8、BOM なし) で、読みの順に並べる。同じ読みの中は元データの順 → 記載順
- 終わりに、元データごとの読んだ行・捨てた行・除いた理由ごとの行・出力した行の数を出す

### 変換の差分の確認

engine/examples/ut_diff.rs は、読みの一覧を Mozc 辞書だけの辞書と UT 辞書を足した辞書で変換し、第 1 候補 (文節の
表記の連結) が変わった読みだけを出す。学習・ユーザ辞書・前文脈は使わない。読みの一覧は、llm_cases.tsv の読みの列と、
日常の文を集めた engine/examples/data/ut_diff_cases.txt。

### UT 辞書の読み込み

- Mozc 辞書の後に積み、システム辞書の一部として引く (上記「システム辞書の書式」)。ラティス・候補・予測に Mozc 辞書の
  語と同じ扱いで入り、特別扱いはしない
- UT 辞書が無くても起動する

## 単漢字辞書

Mozc の `src/data/single_kanji/single_kanji.tsv` (`読み\t漢字を連結した文字列`)。Mozc 辞書には単漢字だけの語が
少なく (「あられ」で 霰 が出ない)、Mozc 本体はこの表で補っているため、同じものを読む。

- `#` で始まる行と空行は読まない。同じ読みの行が複数あれば後ろに足し、同じ読みに同じ字は重ねない。字の並びは記載順のまま
  候補の順にする
- ラティスには入れず、候補の一覧の末尾近くに足すだけにする。ラティスに入れると「あ」→ 亜 のような 1 字の語が経路に
  割り込み、区切りと第 1 候補が崩れるため
- 足す所は文節の候補・入力全体の候補・CONVERT の候補で、どれも辞書の語の後ろ・記号の前。候補の件数の枠には数えない
  ([engine.md](engine.md)「文節の候補 (CONVSEG・CONVCTX)」「候補の並び」)
- 漢字から読みを引く向きにも使う (逆変換の漢字 1 文字の語。[engine.md](engine.md)「格子の語」)
- `references/mozc` は sparse checkout なので、開発環境では `git -C references/mozc sparse-checkout add src/data/single_kanji`
  で取得する

## 記号辞書

Mozc の `src/data/symbol/symbol.tsv` (`品詞\t記号\t読み (空白区切りで複数)\t説明...`)。「やじるし」→「→」のように引く。

- 1 行目が `POS\t` で始まれば見出しとして読まない。列が足りない行と記号が空の行は読まない。同じ読みに同じ記号は重ねず、
  読みごとの並びは記載順
- ラティスには入れず (連接の情報を持たないため)、文節の候補・入力全体の候補・CONVERT の候補の末尾近く (単漢字の後ろ) と、
  F4 の CONVSYM の候補に使う
- 読みに完全一致する記号が無ければ、読みの全角英数記号を半角にしてから引き直す (全角の空白・￥・“”・‘’ も半角の形にする)。
  記号キーは全角形で run に入る ([input.md](input.md)「印字キー」) が、symbol.tsv の読みは半角形で載っているため
  (「（」を変換すると ［ 〔 などが出る)

## 語のコスト

ラティスと候補の並びで使う、辞書ごとの単語コスト。

| 語 | 単語コスト |
|---|---|
| システム辞書の語 | 辞書のコスト |
| ユーザ辞書の名詞系の語 | `USER_WORD_COST` (3000) |
| インポート辞書の名詞系の語 | `IMPORTED_WORD_COST` (5000) |
| 学習した複合語 | `LEARNED_WORD_COST` (12000。[learning.md](learning.md)「複合語の学習」) |

- ユーザ辞書の 3000 は、同じ読みの一般語より上に来やすい中位の値。並びはさらに学習で変わる
- インポート辞書の 5000 は、手動の登録より下の一般名詞並み。配布されている辞書には馴染みの薄い語も多く含まれるため
- ラティスの語のうち、システム辞書とインポート辞書の語は読みの位置ごとに 16 文字までを引く。ユーザ辞書の名詞系の語
  (学習した複合語を含む) は読みの長さによらず載る
- 短縮よみはラティスに載せず、コストを持たない (下記「品詞」)

## ユーザ辞書

### ユーザ辞書の書式

- 場所は `%APPDATA%\QuicklIME\userdict.tsv` (`QUICKLIME_USER_DICT_FILE` で変えられる)。`APPDATA` が無いなど場所が
  決まらないときは、登録はエンジンのメモリ上だけになる
- 1 行 1 語の `読み\t表記\t品詞[\tコメント]` (UTF-8)。Mozc のユーザ辞書のエクスポートと同じ形
- `#` で始まる行はコメント。品詞の列が無い行は短縮よみとして読む。表記の列が無い行、読みか表記が空の行、対応しない
  品詞の行、すでに読んだ行と同じ語の行 (下記「登録と読み直し」の重複) は読み飛ばす
- 読めない行 (UTF-8 として不正な行) があると、そこから後ろは読まない
- 表記が ASCII 英字だけの語は、英単語辞書にも入る ([modeless.md](modeless.md)「英単語辞書」)

### 品詞

品詞は短縮よみと、名詞系の 7 つ。それ以外の品詞 (動詞など) には対応しない (活用の展開をしない)。

| 品詞 | id.def で引く品詞名 (前方一致の最初の行) |
|---|---|
| 名詞 | `名詞,一般` |
| 固有名詞 | `名詞,固有名詞,一般` |
| 人名 | `名詞,固有名詞,人名,一般` |
| 姓 | `名詞,固有名詞,人名,姓` |
| 名 | `名詞,固有名詞,人名,名` |
| 地名 | `名詞,固有名詞,地域,一般` |
| 組織 | `名詞,固有名詞,組織` |

- 名詞系: 引いた ID を左右の文脈 ID にし、システム辞書の語と同じくラティスに載せる (文の途中でも変換される)。
  引けなければ一般名詞の ID (1851) にする
- 短縮よみ: 連接の情報を持たない定型文 (メールアドレスなど)。ラティスには載せず、読みに完全一致したときに候補へ
  そのまま入れる。入る位置は、文節の候補では経路の表記と句の学習の表記の直後、入力全体の候補では辞書の語の先頭
  ([engine.md](engine.md)「文節の候補 (CONVSEG・CONVCTX)」「候補の並び」)、候補バーの予測では通常の最良経路の
  すぐ上 ([suggest.md](suggest.md)「点数」)
- F5 の CONVUSER は、読みに完全一致する短縮よみ → 名詞系の語 (手動の登録 → 学習した複合語) → インポート辞書の
  名詞系の語の表記を、同じ表記を除いて返す

### 登録と読み直し

- ADDWORD は語をメモリに足してから、ユーザ辞書のファイルの末尾に `読み\t表記\t品詞` を追記する。エンジンを
  起動し直さずに変換・予測に効く。ファイルに書けなくても登録は成り立つ (そのエンジンのあいだだけ効く)
- ADDWORD が断るのは、読みか表記が空・対応しない品詞・すでにある語。すでにある語は、短縮よみなら短縮よみどうし、
  名詞系なら名詞系どうしで (読み, 表記) が同じもの (品詞が違っても同じ語とみなす)。インポート辞書と学習した複合語は
  見ない
- RELOADUSER は、インポート辞書・ユーザ辞書・学習した複合語のファイルを読み直す。手で編集したユーザ辞書と、
  単語登録ツールで取り込んだ・ファイルを消したインポート辞書を、エンジンを起動し直さずに反映するため
- 学習した複合語はユーザ辞書と同じ候補の作り方で引くが、別のファイルに持つ ([learning.md](learning.md)「複合語の学習」)

## インポート辞書

他の IME (MS-IME・ATOK・Mozc / Google 日本語入力) から書き出したユーザ辞書や、それらの形式で配布されている辞書
(ニコニコ大百科 IME 辞書・pixiv 辞書など) を取り込んだもの。配布されている辞書は数万〜数十万語あるため、大きくても
変換を遅くしないことを前提にする。

### 保存形式と置き場所

- 1 つの元のファイルを `%APPDATA%\QuicklIME\imported\<元のファイル名から拡張子を除いた名前>.tsv` の 1 ファイルにする
  (`QUICKLIME_IMPORT_DIR` でディレクトリを変えられる。エンジンと単語登録ツールで同じ)
- 中身は `読み\t表記\t品詞` (UTF-8、BOM なし)。品詞は上の「品詞」の 8 つの名前に直してある
- 同じ名前のファイルを取り込み直すと上書きする (配布されている辞書の更新のため)。外すときはファイルを消す。一覧と
  削除の画面は無い
- 採らなかった案: userdict.tsv へ追記する。手動の登録と混ざって辞書の単位で外せず、ユーザ辞書の名詞系は線形に走査する
  ので、大きい辞書で変換が遅くなるため

### インポート辞書の読み込み

- エンジンは起動時と RELOADUSER で、ディレクトリの拡張子 `.tsv` (大文字小文字を区別しない) のファイルをすべて読み直す。
  同じ読みの候補の並びが起動ごとに変わらないよう、ファイル名の順に読む。ディレクトリが無ければ空にする
- 名詞系の語はシステム辞書と同じ fst の辞書に入れ、品詞の名前から文脈 ID を引く (上記「品詞」)。逆引きの索引も読み込みの
  たびに作り直す ([engine.md](engine.md)「逆引きの索引」)。短縮よみは、手動の登録の短縮よみの後ろに並べる
- 品詞の列が無い行・読みか表記が空の行・対応しない品詞の行は読まない
- 変換・予測では次のように引く
  - ラティス: システム辞書と同じく共通接頭辞検索で載せる
  - 文節・入力全体の候補: システム辞書・ユーザ辞書の名詞系の語とコストの順に混ぜる。手動の登録と (読み, 表記) が同じ語は
    手動の登録の側を残して除く。ラティスでは除かない (コストの低い手動の登録が経路に選ばれ、候補でも表記の重複は
    除かれるので、毎回の走査の手間をかける意味が無い)
  - 予測: SUGGEST ではシステム辞書の語と同じ点数で並べる ([suggest.md](suggest.md)「予測」)。PREDICT ではシステム辞書の
    語とコストの順に混ぜ、句の学習の後ろに置く ([suggest.md](suggest.md)「旧エンジンとの互換」)。手動の登録と同じく
    句の学習より前に置くと、大きい配布辞書で予測の枠がインポートした語だけで埋まるため

### 取り込み

単語登録ツールが元のファイルを読んで変換し、保存する (engine/src/import.rs。エンジンと単語登録ツールで同じソースを
使い、エンジンでは単体テストのためだけに含める)。

文字コードは次の順に決める。

1. 先頭が UTF-16LE の BOM (FF FE) なら UTF-16LE、UTF-16BE の BOM (FE FF) なら UTF-16BE
2. 先頭の UTF-8 の BOM を除き、UTF-8 として正しければ UTF-8
3. それ以外は CP932 (Win32 の `MultiByteToWideChar`。不正なバイト列なら取り込まない)

形式は、デコードした先頭の行で決める。

| 形式 | 先頭の行 | 読まない行 |
|---|---|---|
| MS-IME | `!Microsoft IME Dictionary Tool` で始まる | `!` で始まる行 |
| ATOK | `!!ATOK_TANGO_TEXT_HEADER_1` で始まる | `!` で始まる行 |
| Mozc / Google 日本語入力 | それ以外 | `#` で始まる行 |

各行は `読み\t表記\t品詞[\t...]` として読む。

- 空行は読まない。列が足りない行と、読みか表記が空の行は「不正な行」に数える
- 読みのカタカナ (ァ〜ヶ) はひらがなにする
- 品詞は前後の空白を除き、末尾の `$`、続けて末尾の `*` を 1 つずつ除いてから対応づける。ATOK が自動登録の語と手動で
  登録した語を分ける印で、Mozc の取り込みも同じ扱いをしている。形式によらず除く
- 対応しない品詞は「未対応の品詞」に数える

品詞は、完全一致の表を先に引き、無ければ規則を上から当てる。品詞名は Mozc の他の IME の品詞の対応表
(`src/data/rules/third_party_pos_map.def` の MS-IME・ATOK の節) で確かめた。

| 元の品詞 | 取り込む品詞 |
|---|---|
| 人名・固有人他・固有人名(姓名) | 人名 |
| 姓・固有人姓 | 姓 |
| 名・固有人名 | 名 |
| 地名・固有地名・地名その他 | 地名 |
| 組織・固有組織・社名 | 組織 |
| 固有名詞・固有一般・固有商品・物品 | 固有名詞 |
| 短縮よみ・短縮読み・顔文字・記号 | 短縮よみ |
| (規則) 「固有」で始まる、または「固有名詞」を含む (ことえりの「その他の固有名詞」など) | 固有名詞 |
| (規則) 「名詞」を含む (普通名詞・さ変名詞・名詞サ変・形動名詞・副詞的名詞・代名詞など) | 名詞 |
| それ以外 (動詞・形容詞・副詞・数・サジェストのみ・品詞なしなど) | 取り込まない |

重複は「重複」に数えて取り込まない。

- ファイルの中で (読み, 表記, 取り込む品詞) が同じ 2 行目以降
- (読み, 表記) が userdict.tsv か、ほかのインポート辞書のファイルにある語。上書きする同じ名前のファイルは見ない
  (配布されている辞書を更新すると、全部の語が重複になるため)。同じ名前の判定は大文字小文字を区別しない (Windows の
  ファイル名に合わせる)

取り込む語が 1 つも無ければファイルを作らず、RELOADUSER も送らない (同じ名前のファイルがあれば元のまま残る)。

## 単語登録ツール

quicklime-regword.exe。ユーザ辞書へ 1 語ずつ登録し、他の IME の辞書を取り込む。

### 起動

- 入力なしの状態の `key.register_word` (既定 Ctrl+F7) か、言語バーのメニューの「単語登録...」で TSF 層が起動する。
  exe は [runtime.md](runtime.md)「exe の探し方」で探し、見つからなければ何もしない
- キーで起動したときは、文書の選択の先頭 128 文字のうち 1 行目を単語の欄の初期値にする (変換できなかった語を選択して
  そのまま登録する用途)。引数に渡せない `"` は除く。言語バーから起動したときは選択を見ない
- 単語の欄が埋まっていれば、よみの欄から入力を始める
- 起動の引数は `[単語の初期値] [よみの初期値]`。TSF 層はよみを渡さない

### 登録

- 単語とよみの前後の空白を除き、よみのカタカナをひらがなにしてから、エンジンへ ADDWORD を送る。品詞の初期値は名詞
- エンジンに接続できなければ、userdict.tsv (場所の決め方はエンジンと同じ) に直接追記する。エンジンの次の起動で反映される。
  直接追記するときは重複を確かめない (エンジンが読むときに読み飛ばす)
- 登録できたら結果を出してから 1.5 秒で閉じる。直接追記したときと、登録できなかったときは結果を出したまま開いておく
- エンジンを起動はしない (パイプを開けなければ直接追記する)

### インポート

- 「インポート...」でファイルを選ばせ (テキスト `*.txt;*.tsv` と、すべてのファイル)、上記「取り込み」のとおり変換して
  保存してから、エンジンへ RELOADUSER を送る
- 結果に、取り込んだ語・重複・未対応の品詞・不正な行の数 (3 桁区切り) と保存先を出す。エンジンに接続できなければ、
  反映はエンジンの次の起動になることを添える
- 取り込んだ後もウィンドウは閉じない (入力の途中の登録の内容を消さないため)
- 保存は一時ファイル (`<名前>.tsv.tmp`) に書いてから置き換える

| 環境変数 | 読む側 | 働き |
|---|---|---|
| `QUICKLIME_DICT_DIR` | エンジン | 辞書ディレクトリ (上記「辞書ディレクトリ」) |
| `QUICKLIME_USER_DICT_FILE` | エンジン・単語登録ツール | ユーザ辞書のファイル |
| `QUICKLIME_IMPORT_DIR` | エンジン・単語登録ツール | インポート辞書のディレクトリ |
| `QUICKLIME_PIPE_NAME` | エンジン・単語登録ツール | ADDWORD・RELOADUSER を送るパイプの名前 |
