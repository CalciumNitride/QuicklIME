# QuicklIME ロードマップ

未着手の項目と、見送り・既知の問題の一覧。実装済みの機能は [仕様書の索引](spec/README.md)、
全体の構成は [architecture.md](architecture.md) にある。

## 未着手

- 打ち間違えやすいキーの組の学習。補正の候補を選んだ記録から、その人の打ち間違えやすいキーの組を学ぶ
  ([unified-suggest.md](archive/unified-suggest.md))
- 補正の候補の LLM での採点 ([unified-suggest.md](archive/unified-suggest.md))
- 子音だけ・途中までの省略した打鍵 (`yrsk` → よろしく) の照合 ([unified-suggest.md](archive/unified-suggest.md))
- モードレス入力の修正の学習。英字区間の境界を F10 / F6 で直したことを次の判定に使う
  ([modeless.md](spec/modeless.md)「境界の決め方」)
- LLM の右文脈の利用。範囲より後ろの文字列を同音異義語の判別に使う。zenz のプロンプトの形式に右の文脈が無く、
  効果を実験で確かめる必要がある ([conversion.md](spec/conversion.md)「変換の対象」)
- LLM の並べ替えのフィードバック学習。採用・却下を、生の文脈を保存せずに記録して候補コストに反映する
  ([llm-rerank-notes.md](archive/llm-rerank-notes.md))
- 設定ツールと単語登録ツールのハイコントラスト対応。Slint の fluent スタイルにハイコントラストの配色が無い
  ([tools.md](spec/tools.md)「画面の構成」)
- 設定ツールと単語登録ツールの背景の Mica。winit の unstable な API と透明ウィンドウの組み合わせが要り
  壊れやすいため、今は Fluent の単色 ([tools.md](spec/tools.md)「画面の構成」)
- Space・Enter で run を終えたときに後続語の予測を出さないことの見直し。出さない理由が設計書にもコードにも無く、
  確定キーで終えたときとの違いを残すかを決める ([suggest.md](spec/suggest.md)「後続語の予測」)
- PageUp / PageDown を候補バーのページ送りに使わないことの見直し。run 中は run を終えてアプリへ渡しているが、
  その理由が残っておらず、ページ送りに割り当てるかを決める ([suggest.md](spec/suggest.md)「ページ送り」)
- run を終えるキーによる末尾の `n` の扱いの違いの見直し。Space では「ん」にし、Enter・確定キー・IME オフでは `n` のまま
  入れる。違えている理由が残っていない ([input.md](spec/input.md)「run の終わり方」)
- 確定アンドゥが働かないとき (読める文書でない・キャレット直前が一致しない) に、キーをアプリへ渡して記憶を残すことの
  見直し。記憶を残す理由が残っていない ([input.md](spec/input.md)「確定アンドゥ」)
- 読めない文書の候補選択中に、確定の完了を待って送り直すキーが Enter だけであることの見直し。入力中は矢印・Home などの
  キーも送り直しているが、候補選択中に送り直さない理由が残っていない ([input.md](spec/input.md)「送り直し」)
- 候補選択中のフォーカス移動の扱いを決める。composition 入力では、アプリが composition を終えなかったときの挙動を
  コードで決めていない ([input.md](spec/input.md)「フォーカス移動」)
- キー入力が無効な文書で、候補選択中の composition を捨てないことの見直し。捨てるのは run 中だけで、それが意図かどうかが
  残っていない ([input.md](spec/input.md)「キー入力が無効な文書」)
- 表示ごとの DPI の扱いの違いの見直し。入力パネルとキャレットの印は DPI 96 に固定して拡大せず、入力モードの一時表示は
  モニタの DPI で、入力モードのアイコンは画面の DC の DPI で拡大する。違えている理由が残っていない
  ([display.md](spec/display.md)「ウィンドウと描画」)
- キャレット行の上に出すときの作業領域の上端での止め方の見直し。横一列の候補バーと入力モードの一時表示は上端で止めず、
  画面の上端近くでは見切れうる。縦積みの候補バーと変換の候補一覧は止めている
  ([display.md](spec/display.md)「キャレット行の上に出すときの反転」)
- 文節境界の学習 (learning_boundary.tsv) を古くする仕組みと消す手段。今は FORGET でも消えず、消すにはファイルを手で
  編集するしかない ([learning.md](spec/learning.md)「文節境界の学習」)。学習なしの変換でも同じ境界で切れる読みを
  要らない学習として消す案がある ([roman-ime-notes.md](roman-ime-notes.md))
- 単語登録ツールのよみの初期値。選択した文字列が、採用した文字列の記憶 ([conversion.md](spec/conversion.md)
  「採用した文字列の記憶」) か確定アンドゥの記憶にあれば、その読みを渡す。今は TSF 層がよみを渡さない
  ([dictionary.md](spec/dictionary.md)「単語登録ツール」、[roman-ime-notes.md](roman-ime-notes.md))
- 英単語辞書が空のときの ASCIIWORD の扱い。今は常に「前方一致あり」(英字区間を閉じない) を返し、ユーザ辞書の英字の語を
  見ない。ユーザ辞書の語で照合する ASCIISTART とそろっていない ([modeless.md](spec/modeless.md)「英字区間を閉じる」)
- modeless が無効なときに Shift+英字で入った英字モードを、Backspace で英字区間が空になっても抜けないことの見直し。
  理由が残っていない ([modeless.md](spec/modeless.md)「Backspace」)
- ラティスに載せる語の読みの長さの上限 (16 文字) がユーザ辞書の名詞系の語 (学習した複合語を含む) にだけ無いことの見直し。
  理由が残っていない ([dictionary.md](spec/dictionary.md)「語のコスト」)
- RELOADUSER がユーザ辞書のロックを持ったままインポート辞書の索引を作り直すので、大きいインポート辞書ではその間の変換が
  止まるおそれがある。計測はしていない ([dictionary.md](spec/dictionary.md)「登録と読み直し」)
- 設定ファイルに書き出すコメントの見出し (`# 候補ウィンドウ`。engine/gui/src/config.rs) と、tsf/src/config.h・
  tsf/src/text_service.cpp のログの文言に残る「候補ウィンドウ」を、[display.md](spec/display.md)「画面の部品の呼び名」の
  呼び名に直す。コメントは利用者がファイルで目にする
- 改行キーで送り直すアプリの既定の一覧の exe 名 (ms-teams.exe・Teams.exe・LINE.exe) が、実際のプロセス名と合っているかを
  実機で確かめる ([input.md](spec/input.md)「改行キー」)
- ツールを前面に出す方法の見直し。設定ツールの起動では TSF 層が `AllowSetForegroundWindow` を呼び、単語登録ツールの起動では
  呼ばずにツールが自分で `SetForegroundWindow` する。違えている理由が残っていない ([tools.md](spec/tools.md)「起動」)
- インストーラの `CloseApplications=no`・`RestartApplications=no` (installer/installer.iss) の見直し。理由が残っていない
  ([runtime.md](spec/runtime.md)「インストーラ」)
- scripts/dev-deploy.ps1 はエンジンを crt-static なしでビルドしてインストール先へコピーする。インストーラのビルド
  (installer/build.ps1) は crt-static で、そろっていない ([runtime.md](spec/runtime.md)「CRT のリンク」)
- installer/build.ps1 は LLM の exe があるかだけを確かめ、古い exe があってもそのまま同梱する
  ([runtime.md](spec/runtime.md)「インストーラのビルド」)
- 辞書の読み込みを速くする (バイナリキャッシュなど)。エンジンは辞書を読み終えてからパイプを作るので、起動から
  パイプができるまで約 2 秒かかる ([runtime.md](spec/runtime.md)「起動の間隔と待ち」「採らなかった案」)

## 見送り・既知の問題

- アプリ・システムからの再変換の依頼の入口 (TSF の ITfFnReconversion) は見送り。Word の右クリックの再変換や、
  サクラエディタ・秀丸エディタなど IMM32 アプリの再変換コマンド (CUAS 経由) の依頼を受ける入口だが、
  使う場面が無いため。今の後置再変換は、自分で変換キー・F6〜F10 を押したときだけ働く
  ([conversion.md](spec/conversion.md)「漢字を含む選択の再変換」)
- 初めて打つ句の予測が、学習した句に押し出されやすい。再生評価 ([engine.md](spec/engine.md)「再生評価」) の初出の
  `p` の行で、予測が 9 位以内に入る割合は学習なし 4.0%・学習あり 2.2% (266 行) と下がり、予測の上位 9 件の多くを
  学習した句が占める。全体では学習で予測が上がり (11.6% → 26.6%)、件数も少ないので点数の調整は見送り
  ([suggest.md](spec/suggest.md)「点数」)
- 同音異義語の学習の割引の上限の例外 (学習の度合いが最も大きい語が勝つようにする) は見送り。再生評価
  ([engine.md](spec/engine.md)「再生評価」) の学習ありのモードで、同音で 1 位を外した行はすべて正解に学習が無く、
  例外で直る「どちらも学習あり」「正解の方が多く使われている」の行が 0 行だったため
  ([learning.md](spec/learning.md)「使った度合いと割引」)
- 前文脈による変換の使い分け (「服を|着る」「紙を|切る」) は見送り。今は前文脈を予測と後続語の予測にだけ使う。
  語の単位の文脈の割引は評価で変換の 1 位の割合を下げ、再生評価の学習ありのモードで 1 位は 93.6% あり、
  残る外れも分類に薄く散らばっているため ([learning.md](spec/learning.md)「採らなかった案」)
- 前文脈つきの予測 (PREDICT・SUGGEST) への文節の連なりの統計の利用は見送り。今は統計を読みなしの後続語予測
  (NEXTWORD) にだけ使う。再生評価の学習ありのモードの後ろの `q` の行で、正解の表記が統計の表 (文節の表か
  バックオフの表) のどこかに入るのは既出 983 行のうち 111 行、初出 280 行のうち 1 行で、伸ばしたい初出の句には
  順位の付け方によらず効かない。初出の行のうち 110 行は前文脈の自立語がバックオフの表にあっても正解が無く、
  表の大きさより Wikipedia の書き言葉と打つ文の内容の違いが効いている ([suggest.md](spec/suggest.md)「文節の連なりの統計」)
- 短い文節の表記ゆれ (こと / 事、できます / 出来ます) を、読み全体の学習表記の固定で取り違える。同じ読みで両方の表記を
  使うと、決め手が無い。再生評価の学習ありのモードでは、固定した 322 行のうち固定で当てた行が 13 行、外した行が
  12 行とほぼ同数で、度合いや読みの長さでも分かれない ([engine.md](spec/engine.md)「再生評価」)
- ファジィ入力の段階 0 (標準) の打ちかけの読みで、補正の候補が候補バーの先頭に出ることがある (打ち間違いの無い文を
  1 打ずつ打った途中の状態の 3%。fuzzy_eval)。末尾の 1 文字は補正で変えないが、末尾から 2〜3 文字目を直す補正が残る
  (すみま → 隙間、きま → 今) ([engine.md](spec/engine.md)「ファジィ入力」、[typo-tail.md](archive/typo-tail.md))
- ずれのある予測 (候補バーの「ファジィ」の予測) に、UT 辞書の不自然な表記の語 (「おやすまないと → おやスマナイト」)
  が出ることがある。辞書の質の問題 ([unified-suggest.md](archive/unified-suggest.md))
- マビノギで Ctrl 併用のキー割当 (Ctrl+Space の変換など) が効かない (対応は見送り)。回避策は Convert キーを使うこと
  - ゲームは OnTestKeyDown を呼び、IME が食べると答えても OnKeyDown を呼ばない (Ctrl なしのキーでは呼ぶ)。
    key-up では OnTestKeyUp だけが呼ばれ、OnKeyUp は来ない
  - composition 中に Ctrl 併用のキーを受けると、ゲームが選択中の候補のまま composition を確定させる
    (OnTestKeyDown と OnTestKeyUp の間に起き、IME からは止められない)
  - 試した対策: OnKeyDown が来ないまま OnTestKeyUp が来たら機能を実行する方式。変換の開始はできても、
    候補選択中の候補送りはできなかった
  - 入力パネル類の位置は [display.md](spec/display.md)「入力位置がウィンドウの外を指すとき」で扱う
- マビノギではチャット欄の外の打鍵が IME に届かないため、チャット欄の外での Esc などのキーでは入力パネルを消せない。
  マウスの押下では消え ([input.md](spec/input.md)「入力パネルの外のマウスの押下」)、後続語の予測は時間でも消える
  ([suggest.md](spec/suggest.md)「出すとき・消すとき」)
- 逆変換で、数字の後の助数詞の複合語の、単位の後ろの部分の読みを誤ることがある (10キロ位 → きろい、
  5パーセント増 → ぱーせんとます)。数字の後の読みの表は語の先頭だけを見る
  ([engine.md](spec/engine.md)「数字の直後の助数詞の読み」)
- 後続語の予測の統計に逆変換の読み誤り (何の → なにの、一日 → ひといち) が入る。採用するとその読みで学習される
  ([suggest.md](spec/suggest.md)「文節への分け方」)
- InputScope の指定が無い英数字の欄 (`inputmode` の無い認証コード欄など) では IME をオフにする必要がある。
  素通しは InputScope で欄の種類が分かるときだけ ([input.md](spec/input.md)「InputScope の欄」)
- 変換の区切りの誤り。再生評価 ([engine.md](spec/engine.md)「再生評価」) の学習が空のモード (8066 行) で、1 位を外した
  行のうち区切りが 209 行、同じ区間 (区切りは同じで、自立語と付属語の別が違う) が 120 行ある
  - 区切りの中心は、境界の位置のずれ (79 行) と、正解では複数の語の部分を Mozc 辞書の長い 1 語にまとめる誤り (69 行)
  - 区切りの 209 行のうち 79 行は、正解が辞書に無いカタカナ語で、正解の表記を辞書のカタカナの断片に分けたために
    区切りに数えたもの。長い 1 語にまとめる誤りの残り 30 行の多くは、長い語の表記ゆれ (手をつける → 手を付ける、
    ちょうど良い → 丁度いい) と固有名詞で、連接や長い語のコストで直す対象は少ない
  - 学習ありでも、語の学習で覚えた表記の部品 (手・つける) が、別の表記の複合語 (手を付ける) に負けることがある
  - 同じ区間の多くは、正解の語が語の学習に数えない語 (読みが 1 文字の語・ひらがなのままの語) か、学習の無い語で、
    学習でも直りにくい
- Windows の透明効果がオフの環境でぼかしのテーマ (`blur on`) と `caret_marker pointer` を使うと、入力パネルのウィンドウを
  新しく作った最初の描画にだけ尻尾が付かないと読める (ウィンドウを作る前は、ぼかしで作る見込みで尻尾の有無を決めるため)。
  実機では確かめていない ([display.md](spec/display.md)「ぼかし」)
- 文節 UI の補正の文節で、区間の通常の先頭候補が学習で変わっていても、補正の表記が先頭に来る。区間の候補の先頭は、
  学習を効かせて解いた経路の表記そのものなので、比べても変化が分からない (engine/src/convert.rs の `typo_segment`)。
  全体の 1-best が学習で変わったときは保護で 2 番目になるので、補正の文節と通常の 1-best の区切りがずれるときだけ起きる。
  テストで再現を確かめた (辞書を作り込んだもの。実際の辞書での頻度は未確認)
- 文節長を指定した変換と文節 UI の補正の文節では、数字の語をまとめないまま文節の候補を作る。「1234えん」で
  「一234円」「１234円」が出て、「千二百三十四円」「1,234円」と助数詞の入れ替え (「1234縁」) が出ない
  (engine/src/convert.rs の `convert_segments_fixed`・`typo_segment`。数字をまとめるのは `group_path` だけ)。テストで確かめた
- SUGGEST で、全体変換の補正の候補が無いと、文節の一部の学習で表記が変わった 1-best を保護しない。ずれのある予測が
  その 1-best より上に出る (「京」を学習した「きょうは」で「驚愕」が「京は」の上)。学習で表記が変わったかを補正の候補が
  あるときだけ求めるため ([engine.md](spec/engine.md)「保護の印」)。テストで確かめた
- 1 つ前の文節を付けた文脈のフィールド ([protocol.md](protocol.md)) を、それを知らない古いエンジンは文脈の表記の一部として
  読み、前文脈が崩れる。インストーラは TSF 層とエンジンを一緒に入れ替えるので、DLL だけを差し替えたときや古いエンジンの
  プロセスが残っているときにだけ起きる
- 和暦の元号を西暦の年だけで決めるので、2019 年 1〜4 月の日付も「令和元年」になる (engine/src/datetime.rs)。
  今の日付の候補にしか使わないので、実害はほぼない
- 単語登録ツールを開くとき、選択した文字列の末尾が `\` だと、コマンドラインの引用符の囲みが崩れる
  (tsf/src/text_service.cpp `LaunchWordRegister`)
- 直前の確定が英字のときの英字判定 (ルール 6) と、run の無いときの Space を半角にする判定は、確定アンドゥの記憶を見る。
  この記憶はキャレットの移動やクリックでは消えず、キャレットの前の文字列とも照らさないので、別の場所へ移っても英文の
  途中とみなすことがある ([modeless.md](spec/modeless.md)「直前の確定が英字のとき (ルール 6)」)
- ASCIIFORM (大文字小文字の補正) の応答のキャッシュが、単語登録 (ADDWORD・RELOADUSER) の後も消えない。登録した語の
  正しい表記は、別の文字列を問い合わせるまで反映されない (tsf/src/text_service.cpp の `asciiFormText_`)
- 設定ツールの二重起動を防ぐ mutex が、パイプ名や `QUICKLIME_CONFIG_FILE` によらず 1 つなので、常用の設定ツールを開いている
  間に隔離したメモ帳から開くと、常用の設定ファイルを編集しているウィンドウが前面に出る
  (engine/gui/src/bin/quicklime-config.rs の `MUTEX_NAME`。[tools.md](spec/tools.md)「起動」)
- 設定ファイルの読み書きのずれ ([tools.md](spec/tools.md)「設定ファイル」「保存」)
  - 設定ツールは起動時に 1 回だけ設定ファイルを読むので、開いている間に外で書き換えた内容は、次に値を変えたときに上書きされる
  - 手で編集したエンジン向けの設定 (`learning`・`max_predictions` など) は、エンジンが読み直すまで (起動時と、設定ツールで
    値を変えたとき) 反映されず、TSF 層とエンジンで `max_predictions` などが食い違う
- 設定ツールのフォントの選択肢に 32 UTF-16 以上の面名が出るが、選んでも黙って値を変えない
  ([tools.md](spec/tools.md)「入力パネルのテーマとフォント」)
- 設定ツールのテーマの選択肢を起動時にしか作らないので、開いている間に置いたテーマファイルは出ない
  ([tools.md](spec/tools.md)「入力パネルのテーマとフォント」)
- キー割当のページで、キーを足すときは重なりを弾くが、[既定に戻す]・[すべて既定に戻す]・「状態ごとに変える」のオフを経ると
  重なりを作れる (警告は出る。[tools.md](spec/tools.md)「重なりの検査」)
- 環境変数 `QUICKLIME_PIPE_NAME` が空のとき、TSF 層は既定のパイプ名を使うが、エンジン・設定ツール・単語登録ツールは空の名前の
  まま使う (tsf/src/engine_client.cpp と engine/src/main.rs の `pipe_name`。[runtime.md](spec/runtime.md)「パイプ名」)
- 2 人のユーザが同時にサインインしていると、2 人目のエンジンが起動できない可能性がある。二重起動を防ぐ mutex はセッションごと
  (`Local\`) だが、パイプ名はセッションをまたいで共通で、アクセス権は他のユーザを拒むため。コードからの推測で、確かめていない
  ([runtime.md](spec/runtime.md)「パイプのアクセス権」「二重起動の防止」)
- インストーラがエンジンを終了してからファイルをコピーするまでの間に文字を打つと、TSF 層がエンジンを起動し直して exe が
  ロックされ、置き換えが再起動待ちになる可能性がある。コードからの推測で、確かめていない
  ([runtime.md](spec/runtime.md)「インストーラ」)
- 手で編集したエディタが置き換えた設定ファイルと、新しく作った romaji.tsv は、次にエンジンが起動するまで AppContainer の
  アプリ (スタートメニューの検索欄など) で読めず、そのアプリでは既定値で動く。読み取りの ACE を足すのはエンジンの起動時と
  設定ツールの保存の後だけのため ([tools.md](spec/tools.md)「AppContainer のアプリから読むための権限」)
