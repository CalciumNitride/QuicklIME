# 基本機能の仕様

専用の設計書が無い基本機能について、コードから読み取りにくい仕様と、その理由 (WHY) をまとめる。
利用者向けの操作の説明は [README.md](../../README.md) にあり、ここでは重複させない。
各機能の設計書は [設計書の索引](README.md) から引ける。

## 辞書

- 同梱辞書は Mozc OSS 辞書 (`dictionary00.txt`〜`09.txt`。書式は `読み\t左文脈ID\t右文脈ID\tコスト\t表記`)。
  単漢字辞書と UT 辞書による語彙の補強は [dict-expansion.md](dict-expansion.md)
- 辞書の場所 (engine/src/main.rs `dictionary_dir`) は、環境変数 `QUICKLIME_DICT_DIR` → exe と同じ
  ディレクトリの `dict\` (インストール先のレイアウト) → 開発レイアウトの
  `references/mozc/src/data/dictionary_oss` の順に探す。読み込めなければ辞書なしで起動を続ける
- 検索は fst (有限状態トランスデューサ) の `fst::Map` 1つで行う (engine/src/dict.rs)。読みをキー、
  エントリ列の位置を値にし、次の3種類を同じ構造で引く
  - 完全一致 (候補の生成)
  - 共通接頭辞検索 (Viterbi のラティス構築。入力の各位置から1回の走査で辞書語を列挙する)
  - 前方一致 (予測)。短い読みで一致範囲が巨大になるのを避けるため、走査は 20,000 読みで打ち切る
- fst はキーの共通接頭辞・接尾辞を圧縮するため、ハッシュ表と前方一致用の読み配列を別々に持つより
  メモリが少ない
- ダブル配列のクレート (yada / crawdad) は前方一致の列挙の API が無く、予測入力に使えないため採らない

## 変換 (Viterbi と文節)

- 変換は Viterbi で最小コスト経路を求める。コストは単語コストと連接コスト (Mozc の連接行列、
  engine/src/matrix.rs) の和
- 自立語ごとに文節境界ペナルティ (1000) を足す。辞書にはコストの低い短いかな語が多く、素のコストでは
  細切れの経路が複合語より安くなるため
- 経路は品詞で文節にまとめる。入力全体を1単位とした候補 (N-best) と、文節単位の UI
  (設定 `segment_ui`) は [nbest.md](nbest.md)
- 文節の候補の並び (engine/src/convert.rs `segment_from_group`):
  1. 経路上の表記
  2. ユーザ辞書の短縮よみ (読みが文節の読みに完全一致するもの)
  3. 文節の読み全体の完全一致の辞書候補
  4. 先頭の自立語を入れ替えた候補 (「きょうは」に「京は」)
  5. 数字で始まる文節では、数字に続く部分 (助数詞など) を入れ替えた候補 (「10時」と「10次」)
  6. 単漢字、記号
  7. カタカナ、ひらがな

  3〜5 は、1・2 を含めた候補が 24 件になるまで積む。読み全体の完全一致を先頭語の入れ替えより先に積むのは、先頭語が1文字の
  読みで入れ替え候補が枠を使い切り、求める同音異義語が落ちるのを防ぐため。単漢字・記号は枠に数えない
  (単漢字や記号が多い読みで通常語が押し出されるため)。最後に学習済みの表記、続いて前文脈付きの学習の
  表記を先頭へ移す
- エンジンに接続できないときの変換は、読みのかな (と下記の生ローマ字の候補) だけを候補にする

## 学習

学習データは `%APPDATA%\QuicklIME\` に置く (`QUICKLIME_LEARN_FILE` で learning.tsv の場所を変えると、
他のファイルも同じディレクトリに対で作る)。どれも追記ログで、読み込み時は後の行が優先される。

| ファイル | 内容 | 使い道 |
|---|---|---|
| learning.tsv | 読み → 最後に確定した表記 | 文節候補の先頭へ移す。予測の確定履歴 (行順が新しさ) |
| learning_context.tsv | (前文脈, 読み) → 表記。前文脈は直前の文節の表記の末尾 16 文字 | 文節候補の最優先。予測の前文脈の順位付けと後続語予測 ([next-word-prediction.md](next-word-prediction.md)) |
| learning_boundary.tsv | 文節伸縮で直した分割の文節読み (2文字以上) | 変換時の文節境界を寄せる |
| learning_word.tsv | 辞書に無い語を文節伸縮で割って確定した複合語 | 経路が作れない読みだけ1語としてラティスに載せる |

- 方式は「読みごとに最後に確定した表記を先頭にする」単純なもの
- learning_word.tsv はユーザ辞書と混ぜずに別に持つ。誤学習だけを捨てられるようにするため。
  単語コストを高く (12000) して、辞書語の組み合わせで経路が作れる読みは1語にしない
  (1語にすると先頭語の入れ替え候補が消え、別の表記を選べなくなる)
- かなのままで run を終えたときは学習しない。学習は変換候補の並びにも効き、「きょう → きょう」を
  覚えるとひらがなの候補が先頭に来るため。英字を含む入力をそのまま終えたときは読み = 表記で学習し、
  予測の確定履歴に載せる (英単語の省入力)
- 日付・時刻の動的候補は学習しない (下記「日付・時刻の候補」)
- 設定 `learning` が 0 のときは記録しないが、既存の学習データは使い続ける
- 候補パネルで選んでいる候補の学習は Ctrl+Delete (`key.forget_learning`) で消せる。消すとその
  ファイルを書き直す ([forget-learning.md](forget-learning.md))

## 予測

予測候補 (PREDICT) は候補バーに出す ([candidate-bar.md](candidate-bar.md))。
読みの前方一致で次の順に集め、表記の重複は先勝ちで除く (engine/src/predict.rs)。

1. ユーザ辞書の短縮よみ
2. 前文脈付きの学習 (前文脈があるとき。新しい順)
3. ユーザ辞書の名詞系
4. 確定履歴 (learning.tsv。新しい順)
5. 同梱辞書とインポート辞書の名詞系 (コスト順に混ぜる)
6. タイプミス補正 (下記)。5 までで枠が埋まらないときだけ

- 表記が入力のかなそのままの候補は出さない
- ユーザが明示的に登録した語 (1・3) は履歴より先に出す。インポート辞書は数十万語になりうるため、
  履歴より前に置くと枠を占領する。同梱辞書と同じ一般語として扱う
- 件数は設定 `max_predictions` (1〜8、既定 8)、出す読みの長さは `min_suggest_chars` (既定 2)。
  `suggest` が 0 なら予測を返さない

## タイプミス補正

- 読みのかなに1箇所の誤り (1かなの置換・隣接かなの入れ替え・1かなの脱落・1かなの余分) を許した
  前方一致を、fst のノードを自前でたどって引く (engine/src/dict.rs `fuzzy_predict_prefix`)
- 予測の補充だけに使う。読みが3文字以上で、完全な前方一致で枠が埋まらないときに、コスト順で足す。
  短い読みは1かな違いの別の語が多く、誤補正ばかりになるため
- 先頭のかなは誤りとみなさない。打ち間違いが稀なうえ、誤補正の元になるため
- 打鍵列 (ローマ字) は TSF 層で消費され、エンジンにはかなしか届かない。そのため隣接キーのモデルではなく、
  かな単位の編集距離1で近似する (母音の隣接キーのミスや「ん」の抜けは、かな1文字の誤りになる)
- 設定 `typo_correction` (既定 1) で切り替える

## 記号辞書と記号キー

- 記号辞書は Mozc の symbol.tsv (辞書ディレクトリ直下、無ければ Mozc の配置の `symbol/`)。
  「やじるし」→「→」のように引く。無ければ記号候補なしで動く
- 記号キーと Shift+数字キーは、日本語キーボード (JIS 配列) の刻印どおりの全角記号として run に入る
  (tsf/src/text_service.cpp `FindSymbolKey`)。読点・句点は設定 `punctuation`、数字は `digits` に従う。
  テンキーは数値の入力用なので、演算記号は常に半角で入る (数字は `digits` に従う)
- 記号辞書を引くときは、読みの全角英数記号を半角にしてから引き直す。記号キーは全角形で run に入るが、
  symbol.tsv の読みは半角形で載っているため (「（」を変換すると ［ 〔 などが出る)
- Shift+英字は大文字をそのまま入れて英字モードに入り、以降の英字はローマ字変換せずに続く
  (モードレス入力での扱いは README の「モードレス入力」と [modeless.md](modeless.md))

## 対記号の両側同期

- 候補選択中に文節の候補を変えると、対になる記号の文節も対応する形に揃える
  (tsf/src/text_service.cpp `SyncPairedSegment`)。対象の読みは記号キーで入る （）｛｝「」 と ”’
- 開き・閉じの対応は、同じ読みの入れ子の深さを数えて決める。左右同形のクオートは、同じ読みの文節を
  前から交互に開き・閉じとして対にする
- 文節が複数になる変換 (`segment_ui` 1) で働く。`segment_ui` 0 では入力全体が1文節なので対象が無い

## 生ローマ字の候補

- 変換の候補が1文節のときは、打鍵したローマ字そのもの (`apple` / `Apple` / `APPLE` など) を候補に足す。
  英単語の大文字小文字を直した表記があれば、その先頭に入れる ([english-case.md](english-case.md))
- 英字を含む入力 (英単語の打鍵、末尾の未完成のローマ字など) は、文節に分けても意味を成さないため
  全体を1文節に固定して変換し、生ローマ字の候補を先頭の候補の直後に入れる。かなだけの入力では、
  邪魔にならないよう候補の末尾に入れる
- 英字区間と日本語区間が混じる run では生ローマ字の候補を出さない ([mixed-conversion.md](mixed-conversion.md))

## ファンクションキー変換

キー割当は README の「キー割当」、run が無いときの対象は README の「後置再変換」にある。
対象は、run 中なら入力全体、候補選択中なら現在の文節 (`segment_ui` 0 では入力全体)。

- F4 (記号・日付変換): エンジンの CONVSYM で、記号辞書の候補と日付・時刻の候補だけを出す
  (記号 → 日付・時刻の順)。候補が無い読みでは何もしない。同じ候補を出している間の F4 は次候補
- F5 (ユーザ語変換): エンジンの CONVUSER で、読みに完全一致するユーザ辞書の語だけを出す
  (短縮よみ → 名詞系 → インポート辞書の名詞系)。連打の扱いは F4 と同じ
- F6〜F10 (文字種変換): エンジンを使わず TSF 層で変換する (tsf/src/kana_forms.cpp)。結果は一意か
  連打で循環するので、候補ウィンドウは出さない
  - F6: ひらがな
  - F7・F8: 全角・半角カタカナ。連打で末尾から1文字ずつひらがなに戻す
  - F9・F10: 打鍵したローマ字の全角・半角英字。連打で 打鍵どおり → 先頭だけ大文字 → 全部大文字 →
    全部小文字 と循環する

## 日付・時刻の候補

- 「きょう」「あした」「あす」「あさって」「きのう」「おととい」に日付 (`2026/07/15`・`2026年7月15日`・
  `7月15日(水)`・`令和8年7月15日`)、「ことし」「らいねん」「きょねん」に年 (`2026年`・`令和8年`)、
  「いま」に時刻 (`14:30`・`14時30分`・`午後2時30分`) を出す (engine/src/datetime.rs)。和暦は平成以降
- F4 の候補だけに出し、通常の変換には混ぜない。同音異義語の多い読みでは候補の奥に埋もれるため
- 学習しない (LEARN・LEARN2・LEARNWORD で除く)。学習すると翌日以降も古い日付が先頭に来るため

## 確定アンドゥ

操作は README の「入力方式」(Ctrl+Backspace) と「読める文書」にある。

- 直前の確定の文字列と、確定前の読みの状態 (`RomajiComposer`) を1件だけ覚える
- 一度きりの操作で、成否によらず押した時点で記憶を消す。確定後に別の編集があって文書と一致しないとき、
  以降の Ctrl+Backspace を奪い続けないため
- 読める文書でキャレット直前が確定の文字列と一致するときだけ、その文字列を消して読みの run に戻す。
  読めると判定されていない文書では消す範囲を照合できないので働かず、打鍵はアプリへ渡す
  ([input-buffer-modes.md](input-buffer-modes.md))
- 戻した run の方式 (composition 入力・パネル保持入力) は、確定アンドゥの時点の設定 `input_buffer` で決める
- 確定を取り消すので、その確定を前提にした前文脈と LLM の左文脈も捨てる

## ローマ字テーブル

- 既定のテーブルは TSF 層に持つ (tsf/src/romaji.cpp `kDefaultTable`)。ユーザのテーブル
  `%APPDATA%\QuicklIME\romaji.tsv` (`QUICKLIME_ROMAJI_FILE` で変更可) を既定のテーブルへ追加・上書きする。
  書式は README の「ローマ字テーブルのカスタマイズ」
- 3列目が空でない行 (Google 日本語入力の「次の入力」付きの形式) は対応せず読み飛ばす
- テーブルはプロセスごとに初回の参照で一度だけ作る。IME の DLL はアプリのプロセスごとにロードされる
  ため、ファイルの変更はアプリの再起動後に反映される
- AZIK 風のプリセット [data/romaji-azik.tsv](../../data/romaji-azik.tsv) は撥音拡張と二重母音拡張を持つ。
  本家 AZIK の「x = しゃ行」「q = ん」は、既定のテーブルの小書き文字 (`xa` = ぁ) と くぁ行 (`qa`) に
  衝突するため含めない。使えなくなる既定の打ち方はプリセットの先頭のコメントにある

## ユーザ辞書と単語登録ツール

- ユーザ辞書は `%APPDATA%\QuicklIME\userdict.tsv` (`QUICKLIME_USER_DICT_FILE` で変更可)。書式は
  Mozc のユーザ辞書のエクスポートと同じ `読み\t表記\t品詞[\tコメント]` で、`#` で始まる行はコメント、
  品詞の列が無い行は短縮よみとする (engine/src/userdict.rs)
- 品詞は短縮よみと名詞系7種 (名詞・固有名詞・人名・姓・名・地名・組織)。それ以外の品詞の行は読み飛ばす
  (活用の展開には対応しない)
  - 短縮よみ: 連接の情報を持たない定型文 (メールアドレスなど)。ラティスには載せず、文節候補の経路表記の
    直後と予測の先頭に入れる
  - 名詞系: id.def から文脈 ID を引き、通常の辞書語としてラティスに載せる (文中でも変換される)。
    単語コストは 3000 (同じ読みの一般語より上に来やすい中位の値。並びは学習で調整される)
- 登録 (ADDWORD) はファイルへの追記とメモリへの反映を一緒に行い、エンジンの再起動なしに使える。
  手で編集したファイルは RELOADUSER で読み直す
- 単語登録ツール quicklime-regword.exe (engine/src/bin/quicklime-regword.rs) は、入力なしの状態の
  `key.register_word` (既定 Ctrl+F7) か、言語バーのメニューから起動する。選択中の文字列 (1行目だけ) を
  単語欄の初期値にする (変換できなかった語を選択してそのまま登録する用途)。よみのカタカナはひらがなに直す。
  エンジンに接続できないときは userdict.tsv へ直接追記し、エンジンの次の起動で反映される
- 他の IME の辞書の取り込みは [dict-import.md](dict-import.md)

## 設定ファイルと設定ツール

- 設定ファイルは `%APPDATA%\QuicklIME\config.tsv` (`QUICKLIME_CONFIG_FILE` で変更可)。`キー\t値` の TSV で、
  `#` で始まる行はコメント。エンジンと TSF 層が同じファイルを読み、知らないキーは無視し、読めない値は
  そのキーだけ既定値にする
- エンジンは起動時と RELOADCONFIG の受信時に読む。TSF 層はフォーカスの切替と IME のオン/オフの切替で
  ファイルの更新時刻を確かめ、変わっていれば読み直す (アプリの再起動は要らない)。設定ツールで保存して
  アプリに戻る操作自体がフォーカスの切替なので、実質すぐ反映される
- 設定ツール quicklime-config.exe (engine/src/bin/quicklime-config.rs) は、保存で全キーをコメント付きで
  書き出し、エンジンへ RELOADCONFIG を送る。起動は入力なしの状態の `key.open_config` (既定 Ctrl+F12) か
  言語バーのメニューから。タブの構成は [config-tabs.md](config-tabs.md)。「開発用」タブで診断ログの
  出力先 (`debug_log`。空なら出さない) を設定する
- README で説明していない基本の設定:

  | キー | 値 | 既定 | 読む側 |
  |---|---|---|---|
  | `learning` | 0 / 1 | 1 | エンジン |
  | `suggest` | 0 / 1 | 1 | エンジン |
  | `typo_correction` | 0 / 1 | 1 | エンジン |
  | `max_predictions` | 1〜8 | 8 | エンジン |
  | `space` | `full` / `half` (Space で入れるスペースの幅) | `full` | TSF 層 |
  | `punctuation` | `、。` / `，．` / `、．` / `，。` | `、。` | TSF 層 |
  | `digits` | `full` / `half` | `half` | TSF 層 |
  | `candidate_font` / `candidate_font_size` | 候補ウィンドウのフォント名 / 高さ (10〜40 px) | `Yu Gothic UI` / 18 | TSF 層 |
  | `debug_log` | 診断ログの出力先のパス | 空 (出さない) | TSF 層 |

- キー割当 (`key.*`) は README の「キー割当」と [keymap.md](keymap.md)

## 言語バー

- タスクバーの入力インジケータ (`GUID_LBI_INPUTMODE`) に項目を出す (tsf/src/lang_bar.cpp)。アイコンは
  IME オンで「あ」、オフで「A」
- 左クリックで IME のオン/オフ、右クリックで「設定...」「単語登録...」のメニュー (CorvusSKK と同じ方式)

## エンジンの自動起動

設計は [engine-autostart.md](engine-autostart.md)。

- TSF 層はアクティブ化 (`ActivateEx`) のときにエンジンのパイプへ接続してみて、開けなければエンジンの exe を
  探して起動する (コンソールなし)。起動の完了は待たない (tsf/src/engine_client.cpp)。ログオン時は explorer
  などでも TSF がアクティブ化されるので、ログオンと同時にエンジンが立ち上がる
- 候補バー・ライブ変換・予測のように打鍵ごとに呼ぶ問い合わせでも、パイプを開けなければエンジンを起動だけする。
  接続は待たず、その打鍵の問い合わせは失敗として扱う (打鍵を止めないため)
- 明示的な変換などの待ってよい問い合わせでは、最後にエンジンを起動できてから 5 秒以内なら新たには起動せず、
  起動から 5 秒経つまでパイプが開くのを待つ (100 ms ごと)。それ以外なら起動を試みて 5 秒まで待つ。
  エンジンは辞書を読み終えてからパイプを作り、PC の起動直後は数秒かかるため
- 起動の試行はどの経路でも 10 秒に1回まで。exe が見つからないなどで起動できなかった試行は待つ対象にしない
- exe の探索 (`FindExePath`) は DLL と同じディレクトリ → 親ディレクトリ (インストール先の `x86\` の
  32bit DLL から 64bit の exe を使う) → 開発レイアウトの `engine\target\release\` → `engine\target\debug\`
  の順。設定ツール・単語登録ツールも同じ探索で起動する
- エンジンは起動の直後、辞書を読む前に named mutex `Local\quicklime-engine-<パイプ名>` (パイプ名の `\` は
  `_` に置き換える) を作り、すでにあれば終了する。辞書の読み込み中はパイプが無いので、多くのプロセスから
  同時に起動されてもパイプへの接続だけでは見分けられないため。パイプ名ごとに分かれるので、
  `QUICKLIME_PIPE_NAME` で隔離したエンジンは常用のエンジンと並んで動ける
- あわせて、同じ名前のパイプへ接続できたら既に動いているとみなして終了する
- 自動起動したエンジンは TSF 層のプロセスの環境変数を引き継ぐ (`QUICKLIME_PIPE_NAME` などの隔離設定が効く)

## インストーラ

利用者向けの説明は README の「インストーラでの導入」にある。Inno Setup (installer/installer.iss) で作り、
installer/build.ps1 がバイナリ・辞書・ライセンスを集めてから ISCC を呼ぶ。

- 64bit DLL を `%ProgramFiles%\QuicklIME\` に、32bit DLL を `x86\` に置き、それぞれ regserver で登録する
  (32bit 側は Wow6432Node)。登録の中身は DLL の DllRegisterServer に任せる
- 更新時は先にエンジン・設定ツール・単語登録ツール・LLM の子プロセスを taskkill で止める。ロード中の DLL は
  restartreplace で再起動時に置き換える (初回のインストールは未ロードなので再起動は要らない)
- アンインストールでも `%APPDATA%\QuicklIME\` (設定・ユーザ辞書・学習) には触れない
- TSF の DLL は CRT を静的リンクする (/MT、tsf/CMakeLists.txt)。DLL は全アプリのプロセスにロードされ、
  exe を基準にする DLL 探索では DLL の隣に置いた msvcp140.dll などが見つからないため。エンジン・ツールの
  release ビルドも build.ps1 で crt-static にする。LLM の子プロセスは CRT を動的にリンクし、再頒布可能な
  DLL を同梱する

## パスワード欄などキー入力が無効な文書

- フォーカス中の文書・context が無いとき、または context の compartment `GUID_COMPARTMENT_KEYBOARD_DISABLED`・
  `GUID_COMPARTMENT_EMPTYCONTEXT` が立っているときは、キーを食べない (SampleIME・CorvusSKK と同じ判定)。
  アプリが IME を無効にする手段に従えば足りる
- そのとき残っている run は、学習・LLM の左文脈・前文脈に残さずに捨てる
- この判定に InputScope は使わない。Chrome のパスワード欄は両方の compartment を立てるが、InputScope は
  `IS_PASSWORD` ではなく `IS_PRIVATE` を返すため。半角英数字を前提にした InputScope の欄でキーを食べない
  扱いは [input-scope.md](input-scope.md)
- 診断ログ (`debug_log`) には、フォーカス先の無効化の状態と InputScope を出す
