# 読みなしの後続語予測

## 背景と目的

予測候補 (PREDICT) は打った読みの前方一致で引くため、読みを1文字も打たないうちは何も出ない。
また、直前に何を確定したか (前文脈) は予測の順位に使っていない。

エンジンには文脈付きの学習 (learning_context.tsv、直前文節の表記 → 読み → 表記) がすでに
貯まっている。これは「この語の次にこの語を確定した」という記録なので、次の2つに使う。

- 採用・確定の直後、読みを打つ前に、次に来そうな語を候補バーに出す (POBox 風の連続予測)
- 読みを打ち始めた後の予測候補で、前文脈に続いて確定したことのある語を上位に寄せる

## 決定事項

### 予測の材料

- 文脈付きの学習 (`LearningStore` の ctx_map) を文脈キー (直前文節の表記の末尾 16 文字) で引き、
  記録が新しい順に (読み, 表記) を返す。表記の重複は先勝ちで除く
- 辞書 (Mozc) には語の連接の統計が無く、zenz はかな漢字変換の形式のモデルで読みなしの
  生成には向かないため、どちらも使わない
- エンジンは文脈キーごとの索引を持ち、打鍵ごとの問い合わせで ctx_map を線形走査しない
- 学習が無効 (`learning 0`) でも、既存の学習データは予測に使う (LEARN2 と同じ扱い)
- サジェスト無効 (`suggest 0`) のときは、本書の予測もすべて出さない

### プロトコル

- 新コマンド NEXTWORD を足す

```
要求:   NEXTWORD\t<文脈読み>\x1f<文脈表記>\n
成功:   OK\t<読み>\x1f<表記>\t<読み>\x1f<表記>...\n   (候補なしは OK のみ)
失敗:   ERR\t<メッセージ>\n   (文脈の欠落時)
```

- 件数の上限は PREDICT と同じ (`max_predictions`)
- PREDICT に前文脈のフィールドを任意で足す

```
要求:   PREDICT\t<かな>[\t<文脈読み>\x1f<文脈表記>]\n
```

- 前文脈があるときは、文脈付きの学習のうち読みが <かな> で始まるものを、短縮よみの直後
  (名詞系のユーザ辞書・確定履歴・辞書より前) に入れる。順は記録が新しい順
- 前文脈のフィールドが無い要求は今どおり (旧 TSF 層との互換)。旧エンジンは NEXTWORD に
  「不明なコマンド」を返すので、TSF 層はそのとき読みなしの予測を出さない

### 読みなしの予測の表示

- 出すとき: 次のいずれかで run が終わり、アプリへ打鍵を渡していないとき
  - 確定キーで run を終えた (候補バーの採用、候補選択の確定、かなのまま、のいずれも)
  - 候補バーの採用で run が終わった (残りのかなが無い)
  - 読みなしの予測の候補を採用した (続けて次の語を出す)
- 出さないとき: Space・Enter・アプリへ渡すキーで run を終えたとき、前文脈が無いとき、
  候補が無いとき、設定 `candidate_bar` か `next_word` がオフのとき、エンジン未接続のとき
- 前文脈は今の確定の文脈 (`contextReading_` / `contextSurface_`、最後に確定した文節) を使う
- 表示位置と見た目は今の候補バーと同じ (キャレット行の下、番号付きの横一列)。
  エンジンの呼び出しは自動起動や接続待ちをしない方式 (`Predict` と同じ)
- 消すとき: 選択していない状態で、選択キー以外のキーを押した (そのキーは今どおり処理する)、
  キャレットの移動・クリック・フォーカス移動・IME オフ

### 選択と採用

- 機能 `NextWordNext` (`key.next_word_next`、既定 Ctrl+↓) と `NextWordPrev`
  (`key.next_word_prev`、既定 Ctrl+↑) を足す。働く状態は入力なしで、読みなしの予測が
  出ているときだけ打鍵を食べる (出ていなければアプリへ渡す)
- 未選択から `NextWordNext` で先頭、`NextWordPrev` で末尾を選ぶ
- 選択した後は状態「サジェスト選択中」(run なし) に入り、今の候補バーの選択と同じキーが働く:
  Tab / ↓ / Shift+Tab / ↑ で選択の移動、数字 1〜9 でその番号を選ぶ、先頭で Shift+Tab / ↑ を
  押すと未選択に戻る。`NextWordNext` / `NextWordPrev` も引き続き選択を動かす
- 選択では文書を書き換えない。採用は今の候補バーと同じ操作で行う

| 操作 | 選択中の動作 |
|---|---|
| 確定キー | 選択中の候補をキャレット位置に入れる。続けて次の語の予測を出す |
| Enter / Ctrl+M | 候補を入れてから Enter をアプリへ渡す |
| Space | 候補を入れてからスペースを入れる |
| 印字キー | 候補を入れてから、その打鍵で新しい run を始める |
| Esc | 選択を外して予測を消す (打鍵は食べる) |
| 変換キー | 選択を外して予測を消し、今どおり入力なしの変換キーとして処理する |

- 候補は追記で入れる (読める文書・追記のみの文書とも、既存の文字列は書き換えない)
- 学習: 採用時に LEARN2 で (読み, 表記, 前文脈の表記) を送り、採用した語を次の前文脈にする
- 採用した語は確定アンドゥの記憶にする (Ctrl+Backspace で読みのかなに戻る)。
  読める文書では、採用した文字列の再変換 (docs/design/adopted-reconversion.md) の記憶にも足す

### 設定

- `next_word` (TSF 層、既定 1) を新設する。0 なら読みなしの予測を出さない
  (打ち始めた後の予測候補の前文脈による順位付けは `suggest` に従い、本設定とは無関係)
- 設定ツールに「確定の後に次の語を予測する」チェックボックスを足す
- キー割当の一覧に `NextWordNext` / `NextWordPrev` を足す

## 実装手順

1. エンジン: 文脈キーごとの索引と引き当て、NEXTWORD、PREDICT の前文脈フィールド (単体テスト付き)。
   docs/protocol.md を更新する
2. TSF 層: `EngineClient` の `NextWord` と `Predict` の前文脈。打鍵ごとの PREDICT に今の前文脈を渡す
3. TSF 層: config の `next_word` と2機能・既定の割当
4. TSF 層: run 終了時の読みなしの予測の表示と破棄
5. TSF 層: 選択 (2機能、サジェスト選択中の run なしの扱い) と採用 (確定キー・Enter・Space・
   印字キー、学習、前文脈の更新、続けての予測、確定アンドゥ)
6. 設定ツールのチェックボックスとキー割当の一覧
7. ドキュメントの更新 (README.md、keymap.md、candidate-bar.md)
8. 手動テスト (下記)

## 検証方法

学習ファイルは `QUICKLIME_LEARN_FILE` で隔離し、事前に文脈付きの学習を作っておく
(例: 「今日は」→「いい天気」を数回採用する)。エンジンは `QUICKLIME_PIPE_NAME` で隔離する。

### 単体テスト (エンジン)

- 文脈キーで引くと記録が新しい順に返り、表記の重複が除かれる
- 16 文字を超える文脈は末尾で切り詰めたキーで引ける
- PREDICT の前文脈つきの要求で、文脈付きの学習が短縮よみの直後、確定履歴より前に入る
- 前文脈のフィールドが無い PREDICT の結果は今と同じ
- `suggest 0` で NEXTWORD・PREDICT が候補ゼロを返す
