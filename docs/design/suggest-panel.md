# サジェストパネル (候補バーの見た目の刷新と中央固定表示)

## 背景と目的

候補バー (docs/design/candidate-bar.md) と読みなしの後続語予測 (docs/design/next-word-prediction.md)
により、読みを少し打って候補を採用し、採用後は次の語の予測から選んでいく入力ができるようになった。
この「単語ごとに候補から選んで進める」入力をスマートフォンの文字入力のような感覚で使えるよう、
表示を次のように改める。

- 候補バーの見た目をモダンにする (半透明・角丸・影、丸いチップ状の候補)
- 候補の表示位置を、キャレットの下だけでなく、ディスプレイ中央の固定位置にも選べるようにする。
  視線の行き先を一か所に固定し、アプリごとのキャレット位置の取り方の違いにも左右されないようにする
- 入力中の読み (run のかなと未完成ローマ字) も同じパネルに表示できるようにする

見た目は 5 案のモックから「A. カプセル」を採用した。候補を丸いチップとして横一列に並べ、
その上に入力行を置く形で、今の横一列の候補バーの延長にあたる。

本書の範囲は次の 2 段階とする。

- 段階1: A の描画 (半透明・角丸・影)、表示位置の設定、入力行の表示
- 段階2: 背景のぼかし (アクリル風) の実験

## 決定事項

### 範囲

- A の見た目を適用するのは、候補バー (run 中の候補と読みなしの後続語予測) と、未完成ローマ字の小窓
- 変換キーで入る縦の候補一覧は今のまま (`CandidateWindow` の GDI 描画、キャレット位置に表示)。
  `candidate_position = center` のときもキャレット位置に出す
- 入力中のかなは今どおり文書にも書く (直接入力方式・追記型入力は変えない)。入力行は文書の内容を
  パネルに重ねて見せるだけ
- 採らなかった案: 「入力中のかなを文書に書かず、採用・確定までパネルだけに持つ」設定。
  BS を IME 側で処理する、採用を置き換えではなく挿入にする、などの入力モデルの追加になり、
  追記型入力・後置変換・採用済み文字列の再変換・UndoCommit のすべてに関わるため、別の設計書で扱う
- 見た目の値は内部の `PanelTheme` 構造体にまとめるが、設定にはまだ出さない
  (ユーザが変えられる範囲は、案 D (ゴースト HUD) を作るときに合わせて決める)

### 設定

config.tsv に次の 2 項目を足す。TSF 層が読み、設定ツールで変えられるようにする。

| キー | 値 | 既定 | 内容 |
|---|---|---|---|
| `candidate_position` | `caret` / `center` | `caret` | パネルの表示位置。`caret` はキャレット行の下 (今の候補バーと同じ)、`center` はディスプレイ中央 |
| `panel_input` | `0` / `1` | `0` | パネルに入力行 (run のかなと未完成ローマ字) を出す |

- 不正な値は既定値として扱う (他の設定と同じ)
- 設定ツールでは、候補バーの設定と同じタブに「候補の表示位置 (キャレットの下 / 画面中央)」と
  「入力中の読みも候補と同じ場所に表示する」を置く
- `candidate_bar 0` のときはパネルを出さない (`panel_input 1` でも出さない)。
  未完成ローマ字の小窓は今どおり出す

### 描画方式

- 新しいクラス `SuggestPanel` (tsf/src/suggest_panel.h / .cpp) を作り、候補バーと未完成ローマ字の
  小窓の表示をここへ移す。`CandidateWindow` は縦の候補一覧だけを受け持ち、`ShowBar`・
  `ShowInline` と横一列・小窓の描画は削除する
- ウィンドウは `WS_POPUP`、拡張スタイルは今の候補ウィンドウと同じ
  (`WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`) に `WS_EX_LAYERED` を足す。
  マウス操作は今と同じく扱わない
- 描画は Direct2D + DirectWrite で行う。32bpp の DIB section に `ID2D1DCRenderTarget`
  (premultiplied alpha) で描き、`UpdateLayeredWindow` (`ULW_ALPHA`) で画素ごとの不透明度つきで出す
  - 透過背景の上では ClearType が使えないため、文字のアンチエイリアスはグレースケールにする
  - D2D の factory は `SuggestPanel` ごとに single-threaded で作る (TextService はスレッドごとに
    1 インスタンスのため)。DirectWrite の factory は共有でよい
  - 依存ライブラリ `d2d1.lib`・`dwrite.lib` をリンクに足す
- 影はパネルの外側に余白を取り、半透明の角丸矩形を少しずつ広げて重ねて近似する
  (`ID2D1DCRenderTarget` ではブラーのエフェクトが使えないため)。ウィンドウの矩形は影の余白を含み、
  位置の計算は影を除いたパネルの矩形で行う
- 大きさは設定 `candidate_font_size` (以下 f) を基準に比例させる。DPI による拡大は今と同じく行わない
- フォントは設定 `candidate_font` を DirectWrite で使う。見つからなければ Yu Gothic UI

### 見た目

モックの A に合わせる。数値は f = 18 のときの目安で、f に比例させる。

- パネル: 角丸の半径 f × 1.4。内側の余白 f × 0.6。背景は不透明度 0.92 の単色 (ぼかしを使わないぶん
  モックより不透明にする)。外周に 1px の淡い縁
- 入力行 (`panel_input 1` のとき): 文字の高さ f × 1.15。チップ列との間に 1px の区切り線
  - run のかなはアクセント色の下線 (2px)、未完成ローマ字は副次色の文字と点線の下線、末尾にアクセント色の
    キャレット (点滅はさせない)
  - run が無く、読みなしの後続語予測を出しているとき: 直前の確定の表記 (`contextSurface_`) の末尾を
    最大 8 文字、副次色で出し (切り詰めたときは先頭に「…」)、その後ろに小さく「次の語」のラベルを付ける
- チップ列: 横一列。チップどうしの間隔 f × 0.35
  - チップ: 高さ f × 1.9、両端が半円の角丸 (半径 = 高さ / 2)、左右の余白 f × 0.65。背景はチップ色
  - 先頭に候補番号の丸いバッジ (直径 f × 0.95、番号の文字高 f × 0.62、副次色・細い縁)
  - 候補文字列は f。部分採用 (先頭文節) の候補は末尾に「…」を付ける (表示だけ。今と同じ)
  - 選択中のチップ: 背景をアクセント色、文字とバッジを白
  - 読みなしの後続語予測の候補: チップの内側に 1px の「次の語」色の縁
- 未完成ローマ字の小窓 (`panel_input 0` のとき): チップ 1 つ分の小さなカプセルにローマ字だけを出す。
  位置は今と同じ (キャレットの左上に重ねる)

配色は Windows のアプリモード (`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize`
の `AppsUseLightTheme`、値が無ければライト) に合わせる。読み直しは設定の読み直し (`ConfigLoader::Refresh`)
と同じ契機で行い、打鍵ごとには読まない。

| 色 | ダーク | ライト |
|---|---|---|
| パネル背景 | #1C1C22 (不透明度 0.92) | #FCFCFE (不透明度 0.92) |
| 外周の縁 | 白 (不透明度 0.08) | 黒 (不透明度 0.08) |
| 文字 | #F2F2F6 | #16161C |
| 副次色 | #A0A0AD | #6B6B78 |
| チップ背景 | 白 (不透明度 0.07) | 黒 (不透明度 0.045) |
| 区切り線 | 白 (不透明度 0.09) | 黒 (不透明度 0.08) |
| アクセント | #2B86EE | #2B86EE |
| 次の語の縁 | #3CC48A | #2E9E6B |
| 影 | 黒 (最大不透明度 0.45) | 黒 (最大不透明度 0.28) |

これらと上の寸法の比率は `PanelTheme` にまとめ、描画コードには直接書かない。

### 表示位置

- `caret`: 今の候補バーと同じ。キャレット行の下 (入らなければ行の上) の、run でバーを最初に出した
  時点の x に置く。パネルの幅は候補の数に合わせて伸び縮みする。作業領域の右端に収まる先頭からの
  候補だけを出す (今と同じ)
- `center`: キャレットの矩形を含むモニタ (`MonitorFromRect`、`MONITOR_DEFAULTTONEAREST`) の
  作業領域の中央にパネルの中心を置く
  - キャレットの矩形が取れないときは、前景ウィンドウ (`GetForegroundWindow`) のモニタを使う。
    `center` ではキャレットの矩形が取れなくてもパネルを出す
  - パネルの幅は固定にする: min(f × 36, 作業領域の幅 × 0.9)。チップと入力行は左詰めにし、
    打鍵ごとに候補の位置が左右へ動かないようにする。幅に収まらない後ろの候補は出さず、
    選択の対象からも外す (今の作業領域の右端と同じ扱い)
  - パネルの高さは、`panel_input` の設定で決まる行数で一定になる。候補が無いときもチップ列の高さを
    確保して、入力行の位置が上下しないようにする
- 未完成ローマ字の小窓 (`panel_input 0`) は `center` のときもキャレットの位置に出す

### 表示する条件

- `panel_input 0`: 今の候補バーと同じ条件で出し、同じ条件で消す
- `panel_input 1`: 今の候補バーを出す条件に加え、run がある間 (かなが 1 文字以上か、未完成ローマ字が
  ある間) は候補が無くても入力行だけのパネルを出す。未完成ローマ字の小窓は出さない (入力行に含める)
  - 追記型入力 (文書を読み戻せないアプリ) でも同じ
- 縦の候補一覧 (変換キーの候補選択) に入るときはパネルを消し、抜けて run に戻るときは再び出す
  (今の候補バーと同じ)

### 既存の処理との対応

- `TextService` は候補バーの表示と未完成ローマ字の小窓を `SuggestPanel` で行う。
  今 `candidateWindow_` で行っている候補バーの表示・選択の更新・消去と、`pendingWindow_` の表示を
  `SuggestPanel` へ移す。縦の候補一覧の表示は `candidateWindow_` のまま
- 候補バー向けのタイマー (LLM の並べ替え結果のポーリング、`StartTimer`) は `SuggestPanel` に持たせる
- `SetFont`・`SetLogger`・`WindowRect`・`Visible` など、候補バーの経路で使っている `CandidateWindow`
  の機能は `SuggestPanel` にも同じ意味で用意する。診断ログの出力 (`LogShow` 相当) も残す
- 入力行に出す文字列は、run の表示中の文字列 (文書に入っている run 由来の文字列) と未完成ローマ字を
  `TextService` から渡す。パネル側は内容を解釈しない

### 段階2: 背景のぼかしの実験

段階1 の検証が終わってから行う。結果を見て採るかどうか決める。

- 設定 `panel_blur` (`0` / `1`、既定 `0`) を足す。設定ツールの「表示」タブに「候補の背景をぼかす」として出す
- `panel_blur 1` のときは layered window をやめ、通常の `WS_POPUP` に
  `SetWindowCompositionAttribute` (非公開 API) の `ACCENT_ENABLE_ACRYLICBLURBEHIND` を当てる。
  角丸は `DwmSetWindowAttribute` の `DWMWA_WINDOW_CORNER_PREFERENCE` (`DWMWCP_ROUND`) に任せ、
  中身は Direct2D の `ID2D1HwndRenderTarget` で透明背景の上に描く。影は DWM に任せる
- API が無い・失敗したときは段階1 の描画に戻す
- 確かめること: メモ帳・Chrome・ゲーム (フルスクリーンでないもの) の上でぼかしが効くか、
  角丸と影が出るか、打鍵ごとの再描画でちらつかないか、`WS_EX_NOACTIVATE` のままで動くか。
  結果は本書の「段階2」に書き足し、採らない場合はその理由を書く

#### 段階2 の細部

- 対象は候補バーのパネルと未完成ローマ字のカプセルの両方 (`SuggestPanel` の 2 インスタンスとも)
- 設定: TSF 層の config.tsv に `panel_blur` (`0` / `1`、既定 `0`、不正な値は既定) を足す。
  `TextService::RefreshConfig` でパネルに渡し、表示中なら
  一度隠して次の表示から新しい方式で作る (ウィンドウの作り直しが必要なため)
- 色味: ぼかしの上に重ねる色は `ACCENT_POLICY` の `GradientColor` で指定する。色はパネル背景と同じ
  (ダーク #1C1C22、ライト #FCFCFE)、不透明度はダーク 0.6、ライト 0.7。`PanelTheme` に
  `blurTint` として持つ
- D2D 側ではパネル背景・外周の縁・影を描かない。背景は透明 (0,0,0,0) で Clear し、
  区切り線・チップ・バッジ・文字・下線・キャレットだけを描く。文字は段階1 と同じくグレースケール
- 角丸は `DWMWA_WINDOW_CORNER_PREFERENCE` = `DWMWCP_ROUND` (半径は DWM 固定の約 8px)。
  段階1 の f × 1.4 の角丸や、カプセルの両端の半円にはならない。`SetWindowRgn` で大きな角丸に
  切る方法は、縁がギザギザになり DWM の角丸・影も効かなくなるため採らない。外周の 1px の縁も
  DWM が描くものに任せる
- 影は DWM に任せ、自前の影と影の余白は取らない (ウィンドウの矩形 = パネルの矩形)。
  DWM の影が出なかった場合は、その結果を記録したうえで `CS_DROPSHADOW` を付けたウィンドウクラスを試す
- 描画先は `ID2D1HwndRenderTarget` (premultiplied alpha、DPI 96 固定)。まず
  `D2D1_RENDER_TARGET_TYPE_SOFTWARE` で作り、透明部分が黒くなるなど alpha が失われる場合は
  `D2D1_RENDER_TARGET_TYPE_DEFAULT` (hardware) も試す。どちらで動いたかを記録する
  (hardware はホストのプロセスに D3D のデバイスを作るため、採るかどうかの判断材料にする)
- ちらつき対策: `WM_ERASEBKGND` は何もせず 1 を返す。位置・大きさを変えたら WM_PAINT を待たずに
  その場で描く (`ID2D1HwndRenderTarget::Resize` してから描く)。WM_PAINT でも同じ内容を描く
- 段階1 の描画に戻す条件: `SetWindowCompositionAttribute` が user32 に無い・失敗した、
  `DWMWA_WINDOW_CORNER_PREFERENCE` の指定が失敗した (Windows 10 など)、描画先を作れなかった、
  Windows の透明効果がオフ (`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize`
  の `EnableTransparency` が 0。オフだと Acrylic がぼかさず単色になるため)。
  戻したことと理由は診断ログに出す
- ウィンドウの拡張スタイルは `WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`
  (`WS_EX_LAYERED` は付けない)

#### 段階2 の結果

Windows 11 (ダークモード) で確かめた。描画先は software (`D2D1_RENDER_TARGET_TYPE_SOFTWARE`) で
alpha が失われず、透明な部分は黒くならずにぼかしが透けた。hardware は試していない。

- ぼかし: メモ帳・Chrome・非フルスクリーンのゲームの上で効く。未完成ローマ字のカプセルも同じ
- 角丸: DWM の小さい角丸 (約 8px) と、DWM が描く 1px の縁が出る
- 影: DWM の影が出る (暗い背景の上では見えず、白い背景の上で確認できる)。`CS_DROPSHADOW` は不要
- 打鍵ごとの再描画: `caret`・`center` とも、ちらつきや黒い表示は見られない
- `WS_EX_NOACTIVATE`: パネルをクリックしてもフォーカスは移らない
- 透明効果がオフの環境では、段階1 の描画に戻る
- 色味: ダーク 0.6 のままでよい。白い背景の上では明るいグレーになり、チップと地の区別が弱まるが、
  文字は読める

採る。`panel_blur` を正式な設定にして設定ツールと README に出す。既定は `0` (段階1 の描画) のまま。

#### 設定ツール・README での見せ方

- 設定ツール: 「表示」タブの「入力中の読みも候補と同じ場所に表示する」の直後 (フォントの前) に
  チェックボックス「候補の背景をぼかす」を置く。補足の括弧書きは付けない
- config.tsv の書き出し: `# 候補ウィンドウ` の節、`panel_input` の直後に `panel_blur` を書く
- README: `panel_input` の項の後に `panel_blur` の項を足す。設定ツールでの表記、既定 0、
  対象が候補バーのパネルと未完成ローマ字のカプセルであること、角丸が DWM の小さい角丸になること、
  Windows の透明効果がオフのときや API が使えないときは通常の描画に戻ることを書く

## 実装手順

段階1:

1. `SuggestPanel` と `PanelTheme` を作り、Direct2D/DirectWrite と layered window でチップ列を描けるようにする
   (位置は `caret` のみ)。`TextService` の候補バーの表示をこれに切り替える
2. 未完成ローマ字の小窓を `SuggestPanel` のカプセル表示に移し、`CandidateWindow` から横一列・小窓の
   コードを削除する
3. config に `candidate_position`・`panel_input` を足し、`center` の位置計算と入力行を実装する
4. 配色のライト/ダークの切り替え
5. 設定ツールへの追加、ドキュメントの更新

段階2 (段階1 の検証後に別途委譲する):

6. `panel_blur` の実験と結果の記録
7. 設定ツール・README への `panel_blur` の追加

## 検証方法

開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、メモ帳などのテスト用アプリで行う。
config.tsv は `QUICKLIME_CONFIG_FILE` で隔離したものを使い、`debug_log` を設定する。
TSF 層のテスト前に `taskkill /IM Notepad.exe /F` でメモ帳を終了しておく。
