# 候補の統一した並びと打鍵のファジィ照合

## 背景と目的

雑に打っても候補から選んで入力できるよう、予測とファジィ照合を入力の中心にする。今は次の点がその妨げに
なっている。

- 候補バーの並びが候補の種類で決まる。`BuildBarItems` (tsf/src/text_service.cpp) が「英字 → 全体変換
  3 件 → 予測 → 先頭文節 3 件」の順に組み、確からしさで比べていない。TSF 層には候補のコストが届かないため、
  この層では比べられない
- 予測のファジィ照合は、かなの編集距離 1 で、前方一致で枠が埋まらないときだけ足す
  ([basics.md](basics.md) の「タイプミス補正」)。普段は枠が埋まるので働かず、2 か所以上のずれも拾えない
- 打鍵 (ローマ字) は TSF 層でかなにした時点で捨てられ、エンジンはかなを標準のローマ字に戻した近似で
  誤りを戻している ([typo-conversion.md](typo-conversion.md))。`romaji.tsv` を変えた人の綴りや、
  打ちかけのローマ字は扱えない
- 先頭文節の候補 (「今日は…」) が全体変換・予測と同じ並びに混ざり、枠を取る

本書の目的は次のとおり。

- 打鍵をエンジンに送り、打鍵の上でずれを測る
- 全体変換・予測・補正の候補をエンジンで 1 つの点数で並べ、TSF 層はその順に出す
- ずれを許す量を読みの長さに応じて増やし、予測でも常にファジィ照合を行う
- 先頭文節の候補を並びから外し、選んだ全体変換の候補の採用範囲を別の操作で縮める

連文節変換はできるだけ使わない方針で、入力は「打つ → 並びから選ぶ」を基本にする。

## 決定事項

### A. 打鍵の受け渡し

- TSF 層は、かな 1 字ごとの由来の打鍵 (`RomajiComposer` の `raw_`) と未完成のローマ字 (`pending_`) を
  エンジンに送る
- 書式は `<打鍵> = <1 字目の打鍵>\x1f<2 字目の打鍵>\x1f...\x1e<未完成のローマ字>`。`\x1f` で区切った
  要素の数は、送るかなの文字数と同じにする
  - 2 字以上のかなを 1 かたまりで作った打鍵 (`kyo` → 「きょ」) は 1 字目に付き、2 字目以降は空になる
    (今の `raw_` のまま)
  - 文書から読んだかな (`PrependKana`) は打鍵がかなそのもの。エンジンは ASCII でない要素を「打鍵なし」と
    みなす
- 打鍵が無いかな (打鍵なしの要素と、それにかたまりで続く空の要素) は、エンジンが標準の綴り
  (engine/src/typo.rs の表) で打鍵を補う
- 区間分割した run (`SplitAsciiRun`) は、バーの読み (日本語区間) にあたる部分の打鍵だけを送る。
  未完成のローマ字は送らない (英字区間の後ろにあるため)

### B. ずれのモデル

- ずれは打鍵の上の重み付きの編集距離で測る。誤りの種類とコストは次のとおり (単位は辞書の単語コストと同じ。
  値は評価で決めた。下げると崩した入力の回復は少し上がるが、崩していない入力で補正が上位に出る件数が増える)

| 種類 | 内容 | 定数 | 値 |
|---|---|---|---|
| 隣のキー | QWERTY で隣のキーに置き換わった (今の typo.rs の隣接の定義) | `EDIT_ADJACENT` | 3000 |
| 余分 | 余分な 1 打 | `EDIT_EXTRA` | 3500 |
| 抜け | 1 打の抜け | `EDIT_MISSING` | 3500 |
| 入れ替え | 隣り合う 2 打の入れ替え | `EDIT_SWAP` | 3000 |

- 隣でないキーへの置き換えは誤りとして扱わない (照合しない)
- かなの綴りは、標準の綴り (訓令式・ヘボン式。「っ」の子音の重ね、「ん」の `n` / `nn` の規則は typo.rs の
  とおり) に、**この run で実際にそのかなを作った打鍵**を足した集合とする。`romaji.tsv` で変えた綴りを
  誤りとみなさないため
- 先頭のかなの打鍵には誤りを認めない (今の補正と同じ)
- 許すずれの数は打鍵の数 n (未完成のローマ字を含む) から `min(MAX_EDITS, n / KEYS_PER_EDIT)`
  (切り捨て) で決める。`KEYS_PER_EDIT` 4・`MAX_EDITS` 3 (3 打以下は 0、4〜7 は 1、8〜11 は 2、
  12 以上は 3)。`KEYS_PER_EDIT` を 5 以上にすると途中まで打った崩した語の回復が落ちる。`MAX_EDITS` 2 は
  速いが、誤り 3 か所の回復が落ちる
- 予測の照合では、打鍵の末尾が候補の読みの途中で終わってよい。末尾のかなは綴りの途中まで (`arigatou` の
  `t` まで打った所) 一致していればよく、そこにコストはかけない

### C. 予測のファジィ照合

- 対象: 同梱辞書とインポート辞書 (どちらも fst)、確定履歴、前文脈付きの学習 (学習の種類は
  [learning-score.md](learning-score.md) の A で置き換え)、
  ユーザ辞書の名詞系の語と短縮よみ。常に照合し、「枠が埋まらないときだけ」の条件はなくす
- fst は、かなの辺をたどりながら、その辺のかなの綴りと打鍵を DP で照合し、使ったずれが許す数を超えた枝を
  切る。たどるノードの数は `MAX_FUZZY_VISITS` (20 万) で打ち切る (長い打鍵で検索が膨らんだときの安全弁)。
  ローマ字をキーにした辞書は別に持たない (メモリが倍近くになるため)
- 打鍵を使い切った位置ごとに、その先の語を今の前方一致 (`predict_prefix_scored`) と同じ方法で列挙する。
  列挙する位置は、ずれのコストの安い順に `MAX_FUZZY_PREFIXES` (8) まで
- 学習とユーザ辞書は今も読みを線形に走査しているので、同じ走査の中で 1 件ずつ DP で照合する
- 今の `fuzzy_predict_prefix` (かなの編集距離 1) は、この照合で置き換える
- 設定 `typo_correction` が 0 なら、ずれを 0 にして照合する (今の完全な前方一致と同じ結果)

### D. 全体変換の補正

- 補正の語を作る元を、かなを戻した近似から A の打鍵に変える。補正の語の作り方
  ([typo-conversion.md](typo-conversion.md) の A・B) は、1 語に 1 か所の誤りのまま変えない
- 補正の語のコストは、一律の `TYPO_COST` から、その誤りの種類の B のコストに変える
- Viterbi の状態を「補正の語を通った数」 0〜K (K は B の許すずれの数) に広げる。補正の候補は状態 1〜K の
  最良の経路で、今と同じく 1 件だけ。Δ は今と同じく「通常の最良経路 − 補正の最良経路」を打ったかなの
  文字数で割った値
- `TYPO_SHOW` -50・`TYPO_TOP` 0 は今の値のまま。採る条件と置く位置 (typo-conversion.md の C) も変えない。
  評価で `TYPO_SHOW` を下げると、崩していない入力で補正の候補が上位に出る件数が増えた
- CONVNBEST と RERANK も A の打鍵を受け取り、同じ補正を使う (変換キーの候補一覧と並べ替えで同じ候補になる
  ようにするため)。打鍵が無い要求では、補正の語は今のかなを戻した近似で作り、コストと状態の数だけを本節に
  合わせる (状態の数は補った打鍵の数から決める)

### E. 統一した並び (SUGGEST)

- エンジンに新しいコマンド SUGGEST を足し、全体変換・予測を 1 つの並びにして返す。TSF 層は返った順に
  並べる。英字候補 (TSF 層で作る) は今どおり先頭に置く
  - 英字候補を足すときは、合計を `max_predictions` 件に収めるため、エンジンの並びの最後の 1 件を落とす。
    ただし最後の 1 件が全体変換の先頭 (並びで最初の全体変換) なら、その 1 つ前を落とす (下の 5 で 9 番目に
    入れた全体変換の先頭を 2 ページ目に送らないため)
  - 区間分割した run (日本語区間の後ろに開いた英字区間が続く run。`SplitAsciiRun`) では、SUGGEST の予測の
    候補を出さず全体変換だけにする。読みの後ろに英単語が続き、読みを延ばす予測は合わないため (今の候補バーと
    同じ)
- 並びに入れる候補:
  - 全体変換: CONVNBEST の並び (D の補正を含む) の先頭から、表記が読みのかなと同じ候補を除いて
    `MAX_WHOLES` (3) 件
    - 書き換えの候補 = 表記をひらがなに直すと読みと同じになる候補 (かなの種類だけが違う。「ヨロシクオネガイシマス」
      「オヤスミなさい」「おやすみなサイ」)。ただし通常の最良経路と読み全体の学習表記は書き換えの候補として扱わない
      (最良経路がカタカナになる外来語はそのまま先頭に出る)
    - `MAX_WHOLES` 件のうち、書き換えの候補は 1 件までにし、取った全体変換の最後に置く。残りの枠は CONVNBEST の
      並びの順に、書き換えでない候補から取る。書き換えでない候補が足りなければ、空いた枠は書き換えの候補で埋めず
      空けておく
    - 最後に置いた書き換えの候補の点数は、その前の候補の s にする (並びの単調さを保つ)
    - 辞書 (特に UT 辞書) には読み全体を 1 語にした書き換えの項目が多く、2 語に分かれる変換 (「お休み / なさい」)
      より安く出て全体変換の枠を埋めるため。1 件は残すのは、カタカナで書きたい表記をバーから選べるようにする
      ため (ほかの書き換えは F7 / F6 などで出せる)
  - 予測: C の照合の結果
- 点数 s (小さいほど上)。C0 は全体変換の通常の最良経路のコスト (経路が無ければ 0)
  - 全体変換: s = その候補の経路のコスト − C0。CONVNBEST の並びの順を崩さないよう、前の候補の s を
    下回る値は前の候補の s に切り上げる。経路のコストを持たない候補 (補正で先頭にした候補・数字の
    書き方など) は前の候補の s を使う (先頭なら 0)
  - 予測 (辞書の語・ユーザ辞書の名詞系の語): s = その語 1 語だけの経路を今の Viterbi と同じ式
    (前文脈からの接続・単語コスト・文末への接続・`SEGMENT_PENALTY`。学習した文節境界の増減は含めない) で
    評価したコスト − C0 + ずれのコスト + `PREDICT_BIAS` (2000)
  - 予測 (学習と短縮よみ): 次の仮の値にずれのコストを足す。前文脈付きの学習は `100 × i`、確定履歴は
    `500 + 100 × i` (i は新しい順の位置)、短縮よみは −1 (通常の最良経路のすぐ上)。学習の点数と、辞書の語の
    点数に入る学習の割引は [learning-score.md](learning-score.md) の D で置き換え (短縮よみは −1 のまま)
- 並べ方:
  1. 読み全体の学習表記 (CONVNBEST の先頭にあるとき) は先頭に固定する
  2. 残りを s の小さい順に並べる。同じ s なら全体変換を先に、同じ種類の中は元の順を保つ
  3. 表記が同じ全体変換と予測は、並びの位置によらず全体変換を残す (文節を持ち、F の操作と全体変換の学習が
     効くため)。残す全体変換の位置は、2 つのうち上のほうにする。それ以外の表記の重複は先に来たほうを残す。
     表記が読みのかなと同じ予測は出さない (今どおり)
  4. 通常の最良経路が保護の対象 (学習・ユーザ辞書の語・英字。CONVNBEST の protected) のときは、補正の
     候補とずれのある予測を、ずれの無い候補のうち s ≤ 0 のものすべての後ろに置く。通常の最良経路の表記が
     読みのかなと同じで並びに入っていなくても同じにする (学習でかなのままの表記を選んだ読みでも、補正を
     その上に出さないため)
  5. 合計は `max_predictions` 件まで。全体変換の先頭 (読み全体の学習表記が無ければ通常の最良経路) が 10 番目
     以降になるときは 9 番目に入れる
- `PREDICT_BIAS` は、崩していない打ち終えた入力で先頭が全体変換の最良経路から変わらない値にする
  (0 では「ひく → 低い」のように、長い語の予測が打ち終えた読みの全体変換より上に出る)
- 応答の候補には種類を付ける: `whole` (全体変換)、`typo` (全体変換の補正の候補)、`predict` (予測)、
  `predict_typo` (ずれを 1 つ以上使った予測)
- 予測の候補が未完成のローマ字まで使って照合したかは区別しない。予測の候補を採用したら、未完成の
  ローマ字は捨てる (予測は未完成のローマ字も含めて照合しているため)。全体変換の採用では今どおり残す
- `predict_typo` の候補は「補正」のタグと縁 (テーマのキー `typo`・`tag_typo`) で出す。採用したときの
  学習は今の予測と同じく候補の読み (辞書の正しい読み) と表記で送る。全体変換の補正の候補は今どおり
  学習しない
- `suggest` が 0 のときは予測を入れず、全体変換だけの並びにする

### F. 採用範囲の縮め (先頭文節の置き換え)

- 先頭文節の候補 (`BarKind::Head`) は並びから外す
- バー選択中に全体変換の候補 (`whole`・`typo`) を選んでいるとき、Shift+← で採用する範囲を先頭から 1 文節
  縮め、Shift+→ で 1 文節伸ばす。単位はその候補の文節の区切りで、範囲は 1 文節〜全文節
  - 選びはじめは全文節。別の候補に選択を動かすと、その候補の全文節に戻る
  - 文節が 1 つの候補、予測の候補、英字候補では Shift+← / → は何もしない (キーは食べる)。バー選択中に
    キーの意味を候補によって変えないため
  - バー未選択の Shift+← / → は今どおり run を終えてアプリへ渡す
- 範囲を縮めている候補は、採用する部分を今どおりの色、残りを文字の色の不透明度 0.5 で描き、種類のタグを
  「文節」 (`tag_partial`) にする
- 範囲を縮めた候補の採用は、今の先頭文節の採用と同じに動く
  - 確定キー・印字キー: 範囲の文節だけを置き換え、残りのかなで run を続ける。前文脈は範囲の最後の文節
  - Enter・Space: 範囲の文節を置き換え、残りのかなを文書に残して run を終え、キーを渡す
  - 学習: 範囲の文節ごとの (読み, 表記) を前文脈つきで送る。補正の候補は今どおり送らない
- 範囲が全文節のときは、今の全体変換の採用と同じ

### G. LLM の並べ替え

- RERANK は今どおり送る。TSF 層は、並びで全体変換が占めている枠を、結果の候補 (全体変換) の上位から
  埋め直す。枠の位置と数、予測・英字の候補の位置は変えない (規則は [llm-generate.md](llm-generate.md) の
  「候補バー」)
- LLM による候補の生成は [llm-generate.md](llm-generate.md)。補正の候補の LLM での採点は扱わない

### H. 互換と変換キー

- SUGGEST に「不明なコマンド」を返す旧エンジンには、その接続では以後送らず、今の CONVNBEST と PREDICT
  で並びを作る (打鍵は送らない)。このときも先頭文節の候補は出さない (F の操作は全体変換の文節で働く)
- PREDICT の並びは今どおり (完全な前方一致の後、枠が埋まらないときだけ補正で補う)。補う照合だけを C の
  照合 (打鍵は標準の綴りで補う) に替える。「常に照合」は SUGGEST だけにする
- 変換キーの候補一覧 (CONVNBEST・RERANK) の並びは今どおり。打鍵を送り、D の補正を使うことだけが変わる
- 文節 UI (`segment_ui` 1) の CONVSEG・CONVCTX は本書の対象外 (今のかなを戻した近似のまま。補正のコスト・
  状態の数・`TYPO_SHOW`・`TYPO_TOP` も今の値を使い、入力全体の候補の値とは別に持つ)

### プロトコル

```
要求:   SUGGEST\t<文脈読み>\x1f<文脈表記>\t<かな>\t<打鍵>\n
成功:   OK\t<候補1>\t<候補2>\t...\n
候補 = <種類>\x1d<読み>\x1f<表記>\x1e<読み>\x1f<表記>...
失敗:   ERR\t<メッセージ>\n
```

- 種類は E の `whole` / `typo` / `predict` / `predict_typo`
- 全体変換の候補は文節ごとの (読み, 表記)。予測の候補は 1 つの (候補の完全な読み, 表記)
- CONVNBEST と RERANK は `kinds` の後ろに省略できるフィールド `<打鍵>` を足す。`<打鍵>` を送るときは
  `kinds` も送る。無ければ今どおりかなを戻した近似で補正する

```
要求:   CONVNBEST\t<文脈読み>\x1f<文脈表記>\t<かな>[\tkinds[\t<打鍵>]]\n
        RERANK\t<LLM 文脈>\t<文脈読み>\x1f<文脈表記>\t<かな>[\tkinds[\t<打鍵>]]\n
```

- `<打鍵>` の要素の数がかなの文字数と合わない要求は ERR を返す

### 採らなかった案

- ローマ字をキーにした辞書を別に作る: 照合は単純になるが、辞書のメモリが倍近くになる
- TSF 層で並べ替える: 候補のコストが TSF 層に届かず、届けるにはプロトコルでコストを渡すことになり、
  点数の規則がエンジンと TSF 層に分かれる
- 先頭文節を点数で他の候補と混ぜる: 部分採用は「前から片付ける操作」で、選ぶ候補と意味が違う。長い入力で
  上位に来やすく、全体変換・予測の枠を取る
- 読みの 1 字ごとに採用範囲を動かす: どんな区切りにもできるが、切るたびに前の部分を変換し直すので表記が
  変わりうる。区切りの違いは変換キー (変換の範囲の伸縮) で直せる

## 検証方法

### 評価 (engine/examples/fuzzy_eval.rs)

- 入力: typo_cases.tsv と llm_cases.tsv の正解の文。正解の読みを標準のローマ字にして、次の 2 つを作る
  - 崩した打鍵: B の誤りの種類を乱数 (種を固定) で 1〜3 か所入れる (先頭のかなは崩さない)
  - 途中までの打鍵: 正解の語・文の読みの先頭から 50%・75% の打鍵 (崩したものと崩さないもの)
- 測るもの (学習とユーザ辞書は空)
  - 崩さない打ち終えた入力で、SUGGEST の先頭が CONVNBEST の先頭と変わった件数 (0 件を目標)
  - 崩した打ち終えた入力で、正解が 1 位・3 位以内・9 位以内に入る割合
  - 途中までの入力で、正解の語・文が 9 位以内に入る割合 (崩したもの・崩さないもの)
  - SUGGEST 1 回の処理時間 (中央値・p95)
- 値を決める基準: 崩さない入力で先頭が変わる件数を 0 にしたうえで、崩した入力の 3 位以内の割合を上げる

### 自動テスト

- 打鍵の書式: 要素の数がかなの文字数と合わない要求は ERR。ASCII でない要素は打鍵なしとして標準の綴りを使う
- 綴りの集合: 標準の綴りに無い打鍵 (`romaji.tsv` で独自に割り当てた綴り) で作ったかなは、ずれ 0 で一致する
- 許すずれの数: 打鍵 3 では照合が完全一致だけ、4 で 1 つ、12 以上で 3 つまで
- 先頭のかなの打鍵の誤りは照合しない
- 予測の末尾: `arigat` (未完成のローマ字 `t`) で「ありがとう」が、ずれ 0 で出る
- 並び: 読み全体の学習表記は先頭。同じ s で全体変換が予測より先。保護された最良経路より上に補正の候補と
  ずれのある予測が来ない。全体変換の先頭が 9 番目より後ろにならない
- 表記が同じ全体変換 (補正の候補を含む) と予測は全体変換が残り、2 つのうち上の位置に来る
  (`よろしくおねぎあします` で、補正の候補が文節つきの `typo` のまま残る)
- 通常の最良経路が保護されていて表記が読みのかなと同じとき (学習でかなを選んだ読み)、補正の候補と
  ずれのある予測が、ずれの無い s ≤ 0 の候補より上に来ない
- `typo_correction` 0 で、予測が完全な前方一致と同じ結果になる
- CONVNBEST に `<打鍵>` を付けたときと SUGGEST の全体変換の補正の候補が同じ
