# LLM による候補の生成

LLM の並べ替え ([llm-rerank.md](llm-rerank.md)) に、zenz の貪欲法の生成で作った候補を 1 件足す。
並べ替えは N-best の上位 10 件の中でしか順位を直せず、そこに正解が無い件 (長い読みで 1 か所だけ語の選び方を
誤った件など) には届かないため。

## 背景と目的

実験 0c ([experiment-0c-llm-gen.md](../archive/experiment-0c-llm-gen.md)、結果は [experiment-0c-llm-gen-results.md](../archive/experiment-0c-llm-gen-results.md))
で、生成の方式と条件を測った。

- AJIMEE-Bench (197 件) の 1 位は、並べ替えだけで 141 件 (72%)。生成した候補を先頭に置くと、Vulkan + small の貪欲法で
  169 件 (86%)。遅延の p95 は 84 ms (並べ替えとの合計)
- CPU + xsmall は得 31 件に対して失が 13〜15 件あり、得が小さい
- 辞書のラティスに制約した照合 (Zenzai 方式、C) と、読みから外れた出力だけを C に代える組み合わせは、どちらも
  貪欲法だけより 1 位が低い。読みから外れた出力は数の書き方の正解が多く、代えると得が減って失は減らない
- 実ユーザの句のセットでは、短い読みに生成をかけると 1 位が下がる (全件で 85.2% → 81.1%)。9 文字以上だけにすると
  損得はほぼ無く (85.2%・91.1% のまま)、AJIMEE-Bench の得 (72% → 83%) は残る

本書の目的は次のとおり。

- Vulkan 版で、9 文字以上の読みの並べ替えに、貪欲法で生成した候補を 1 件足す
- 生成した候補を候補バーにも出す (今のバーは並べ替えの結果で全体変換の枠の中を入れ替えるだけで、N-best に
  無い候補は出ない)
- CPU 版・LLM 無効・短い読みでは今と同じに動く

## 決定事項

### 生成する条件

- 次をすべて満たす依頼で生成する
  - `llm` 1 で、子プロセスが Vulkan 版で動いている (設定が `vulkan` でも、CPU 版に切り替えて動いている間は生成しない)
  - 並べ替えをする依頼 (読みが `RERANK_MIN_CHARS` (9) 文字以上)。生成のしきい値は並べ替えと同じ定数を使う
- 新しい設定キーは作らない。`llm` 1 と `llm_backend vulkan` で有効になる
  - 採らなかった案: 生成の有効・無効の設定を足す。CPU 版では得が小さく、Vulkan 版では使わない理由が無いため

### 子プロセス (quicklime-llm) の生成

要求を 1 つ足す。

```
要求:   GENERATE\t<文脈>\t<読み>\n   (文脈・読みは SCORE と同じく前処理済み、読みはカタカナ)
成功:   OK\t<表記>\n   (EOG トークンで止まったとき。止まらずに上限に達したら OK\t (表記は空))
失敗:   ERR\t<メッセージ>\n
```

- 貪欲法 (毎トークン argmax)。プロンプトは SCORE と同じ
- EOG トークン (`vocab().is_eog`。zenz が出す `</s>` を含む) で止める。生成するトークン数の上限は
  読みの文字数 × 2 + 8 (実験 0c と同じ)。上限に達したら表記を空で返す
- 出力のトークンの文字列をつなぎ、UTF-8 として正しくなければ表記を空で返す
- プロンプトと出力が N_CTX (512) に収まらない入力は ERR を返す (SCORE と同じ扱い)

### エンジンの流れ (LLM ワーカー)

- ワーカーは並べ替えの SCORE の応答を受けた後、生成する条件を満たす依頼なら GENERATE を送る
- SCORE が ERR を返したとき (プロンプトと候補が N_CTX に収まらない長い読みなど。子プロセスは正常) も GENERATE を
  送り、並べ替えていない N-best に生成した候補を入れて DONE にする。生成はプロンプトに出力 1 件を足すだけで、
  候補を並べる SCORE より短く収まるため。生成も ERR・空の表記・後処理で捨てた出力なら、今どおり NONE にする
- 保護しない候補が 2 件未満で SCORE を送らない依頼も、GENERATE は送る
- GENERATE の応答待ち・異常の判定は SCORE と同じ (`LLM_TIMEOUT_MS`・`LLM_HANG_MS`・再起動)。ERR を返したとき
  (子プロセスは正常) と、表記が空のときは、生成なしの並べ替えの結果を DONE にする
- 生成した表記に後処理 (次節) を当て、捨てなければ並べ替えた候補の並びに入れる (次々節)

### 後処理

実験 0c の A の後処理と同じ。エンジン側で行い、単体テストする。

- ルビの除去: 括弧 (`(` `)` `（` `）`) の中がかなだけなら括弧ごと消す。ただし読み自体にその括弧があれば消さない
- 捨てる出力
  - 表記の文字数が読みの文字数を超える
  - 同じ 2 文字以上の並びが 3 回以上続けて現れる (読み自体に同じ繰り返しがあれば判定しない)
  - 私用領域の文字 (プロンプトの区切り U+EE00〜) を含む
  - 空

### 並びへの入れ方

並べ替えた候補の並び (RERANKGET の DONE の候補) に、生成した候補を 1 件入れる。

並べ替えで保護する候補 ([llm-rerank.md](llm-rerank.md) の「並べ替えの規則」) を、理由で 2 つに分ける。

- 利用者の選んだ候補: 読み全体の学習表記、学習で表記が変わった 1-best、ユーザ辞書 (手動登録・インポート辞書・
  学習した複合語) の語を含む候補。利用者が選んだ・登録した表記なので、生成した候補より前に置く
- それ以外の保護する候補: 英字を含む候補、数字の書き方の候補、補正の候補。LLM で公平に採点できないので
  並べ替えから外しているだけで、生成した候補より優先する理由は無い。AJIMEE-Bench (誤りの無い読み) では、
  先頭に来たこれらの候補が外れで、生成した正解がその下になる件が 15 件あった

`SentenceCandidate` に、利用者の選んだ候補かどうかの印を足す (並べ替えの保護の印 `protected` は今どおり)。

- 位置は、並びの先頭から見て最初の、利用者の選んだ候補でない候補の位置
- 同じ表記の候補が並びにあるとき
  - 利用者の選んだ候補なら、何もしない
  - それ以外 (利用者の選んだ候補でない保護する候補を含む) なら、その候補を上の位置へ動かす (新しい候補は足さない。
    動かした候補の文節・印はそのまま)
- 同じ表記が無ければ、上の位置に新しい候補として入れ、後ろの候補は 1 つずつ下がる (候補の数が 1 増える)
- 生成した候補は保護しない・補正の候補ではない・利用者の選んだ候補ではない
- 並びのすべてが利用者の選んだ候補なら、末尾に入れる

### 生成した候補の文節

RERANKGET の DONE を返すときに、生成した候補の文節 (読み, 表記) を決める。学習と採用範囲の縮めに使う。

- RERANK の依頼の前文脈と読みで、`convert::constrained_path` を完全一致 (`exact`) で解き、経路があればその文節にする
  (エンジン本体から呼ぶので `#[allow(dead_code)]` を外す)
- 経路が無ければ (数の書き方など、辞書の語でたどれない表記)、読み全体を 1 文節 (読み, 生成した表記) にする
- 採用・確定したときの学習は、ほかの全体変換の候補と同じ
- 文節を決めるには辞書が要り、辞書はワーカーのスレッドから使わないので、ワーカーは生成した表記と入れた位置を
  結果に持たせ、RERANKGET を処理するスレッドが文節を決める。依頼には前文脈を持たせる

## 実装手順

各手順の後にビルドとテストが通り、既存の動作が壊れていないことを確かめる。

1. quicklime-llm: GENERATE。scripts\build-llm.ps1 で CPU 版・Vulkan 版をビルドし、手で GENERATE を送って
   AJIMEE-Bench の数件で llm_gen_eval の A 貪欲法と同じ表記になることを確かめる
2. エンジン: 後処理・並びへの入れ方・生成する条件・GENERATE の送受信・文節の決め方。単体テスト
3. エンジン: `nbest_eval --llm vulkan` で AJIMEE-Bench を測り、並べ替え後の 1 位が llm_gen_eval の A 貪欲法の
   合わせた並び (L=9 で 164/197) とほぼ同じになることを確かめる。`--llm cpu` は今と同じ (124/197)
4. TSF: バーの全体変換の枠の埋め直し
5. ドキュメントの更新

## 検証方法

### 自動テスト (エンジン)

- 後処理: ルビの除去 (読みに括弧があれば消さない)、長さ・繰り返し (読みに繰り返しがあれば判定しない)・私用領域の文字・空で捨てる
- 並びへの入れ方: 最初の、利用者の選んだ候補でない候補の位置に入る。利用者の選んだ候補 (学習・ユーザ辞書) より前には
  入らず、英字・数字の書き方・補正の候補より前には入る。同じ表記が利用者の選んだ候補でなければ (保護する候補を含む)
  そこへ動き、件数は増えない。同じ表記が利用者の選んだ候補なら何もしない
- 利用者の選んだ候補の印: 読み全体の学習表記・学習で表記が変わった 1-best・ユーザ辞書の語を含む候補に付き、
  英字・数字の書き方・補正の候補には付かない
- SCORE が ERR のとき: GENERATE を送り、並べ替えていない N-best に生成した候補を入れて DONE。生成も失敗なら NONE
- 生成する条件: Vulkan 版で動いているときだけ GENERATE を送る。CPU 版・Vulkan から CPU へ切り替えた後は送らない
- GENERATE が ERR・空の表記のとき、生成なしの並べ替えの結果が DONE になる。タイムアウト・終了は SCORE と同じ扱い
- 文節: 辞書でたどれる表記は経路の文節、たどれない表記は読み全体の 1 文節

### 計測

- `nbest_eval --llm vulkan --cases ../references/AJIMEE-Bench/ajimee_cases.tsv`: 1 位が 164/197 前後 (llm_gen_eval は生成した候補を常に先頭に置いて数えるので、利用者の選んだ候補が無い計測では同じ条件になる)。RERANK から DONE
  までの時間の p95 を記録する
- `nbest_eval --llm cpu`: 生成しないので、今と同じ 124/197

### 実機テスト

開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、メモ帳で行う。config.tsv は `QUICKLIME_CONFIG_FILE` で隔離したものを
使い、`debug_log` を設定する。エンジンと quicklime-llm は release もビルドし直し、テスト前に古いエンジンと
quicklime-llm のプロセスを終了する (常用のエンジンを止めたくなければ `QUICKLIME_PIPE_NAME` で隔離する)。
