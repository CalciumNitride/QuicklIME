# 変換精度の評価セット

## 背景と目的

- 変換精度の評価に使っている `engine/examples/data/llm_cases.tsv` は手作りの 50 件で、N-best と LLM の並べ替えの
  定数を決めるのにも使った。調整に使っていない評価専用のセットが無く、変更の良し悪しを判断しにくい
- 学習の評価 (`learning_eval`) の入力は learning.tsv と learning_context.tsv で、これらは読みで初めて確定したときと
  表記が変わったときにしか書かれない。データが表記の変わり目に偏り、今のエンジンはもうこの 2 つを書かない
- 次の 2 つを足し、変換関係・LLM 関係の以後の変更をこれで測れるようにする
  - 公開の評価セット AJIMEE-Bench (評価だけに使う)
  - 実ユーザの learning_stats.tsv を使う再生評価 (学習の評価もこれで行う)

## 決定事項

### A. AJIMEE-Bench の取り込み

- 出典: https://github.com/azooKey/AJIMEE-Bench の `JWTD_v2/v1/evaluation_items.json`。コミット
  `401666cd56d1a570c2021798b64b6da4396bfd45` に固定する (132231 バイト、SHA-256
  `e9eb668fd6aa14b1e26436f429b5550108af0a1dfd443b8cea0bcb3ab3028fca`)
- データのライセンスは CC BY-SA 3.0 (元データの日本語 Wikipedia 入力誤りデータセットに従う)。リポジトリにも
  インストーラにも入れない。`scripts/fetch-ajimee.ps1` で `references/AJIMEE-Bench/` (git 管理外) に取得し、
  サイズと SHA-256 を確かめてから TSV に変換する (`fetch-ut-dict.ps1` と同じ扱い)
- JSON の変換は PowerShell の `ConvertFrom-Json` で行い、エンジンに JSON の依存を足さない
- 変換後は `references/AJIMEE-Bench/ajimee_cases.tsv`。形式は llm_cases.tsv と同じ
  `左文脈<TAB>読み<TAB>候補<TAB>正解` で、候補は空にする
  - 左文脈: `context_text` (200 件中 100 件にある)
  - 読み: `input` のカタカナをひらがなにしたもの (ヴ は ゔ、ー はそのまま)。全角の 、。「」（）・ は残す
    (記号キーで run に入る文字のため)
  - 正解: `expected_output` を `|` で区切って並べる (200 件中 83 件は正解が複数)
- 除外: 読みに 『』… を含む問題 (3 件)。JIS 配列のキーで直接打てないため。ほかの文字はすべてローマ字と記号キーで
  打てる
- `nbest_eval` の正解の列は `|` 区切りで複数の正解を受け、どれかが入れば当たりとする。llm_cases.tsv は
  正解が 1 つなので結果は変わらない
- AJIMEE-Bench は評価専用で、定数の調整には llm_cases.tsv を使う (調整に使ったセットで結果を報告しない)

### B. 再生評価 (`learning_eval` の作り直し)

- 入力を learning_stats.tsv (`--stats`) に替え、learning.tsv と learning_context.tsv を入力にする方式は消す。
  モジュールを直接組み込み、学習はメモリ上にだけ作る作りは今のまま
- learning_stats.tsv は起動時に 1 件 1 行へ書き直されるので、確定の並びは残らず、各件には使った度合い `d` と
  最後に使った通し番号 `t` だけが残る。そこで `t` の順を確定の順の近似として使う
- 書き直しの後に追記された行があるので、エンジンの読み込みと同じく同じ件は後の行を使う (件のキーは `w`・`p` が
  (読み, 表記)、`q` が (文脈, 読み, 表記))。同じ件が前の 8 割と後ろの 2 割の両方に入らないようにするため
- 測る 2 つのモード
  1. 学習が空: すべての `p` の行 (句の学習。`seg` と `whole`) の読みを変換し、行の表記が 1 位・3 位以内に入る
     割合を出す。実際に打った文での基本の変換精度
  2. 学習あり: `w`・`p`・`q` の件を `t` の順に並べ、件の数の 8 割の位置にある件の `t` を分け目の `t` とする。
     `t` が分け目の `t` 以下の件を前、それより大きい件を後ろとし、前の件を `d` と `t` のまま取り込んで、後ろの
     `p` と `q` の件を測る
     - 同じ `t` の件は前と後ろに分けない。1 回の確定で数えた `w`・`p`・`q` は同じ `t` を持つうえ、古い
       learning_context.tsv の取り込み (`import_context`) は通し番号を進めないので、取り込んだ `q` はすべて
       取り込みの終わりの同じ `t` を持つ。件の数で切ると、この取り込みのかたまりの途中で切れて、時間の順に
       なっていない件が後ろに入る
     - 後ろの件のうち `d - 1` が `MIN_KEEP` (0.05) 以上の件は、分け目より前にも使っていたものとみなし、
       `d - 1` の度合いと分け目の `t` で前の学習にも入れる (確定 1 回で度合いは 1 増えるので、最後の確定の前の
       度合いは `d - 1`)。同じ件は後の行にまとめるので、こうしないと繰り返し使った件だけが自分の学習を失い、
       同じ読みの別の表記の学習は残って、学習が不利な方向に測られる
     - 測る行を「既出」(上の前の学習に入れた件か、(読み, 表記) が前の `p` か `q` の件にもある行) と
       「初出」(それ以外) に分けて、全体とあわせて出す
     - 変換 (`p` の行): CONVNBEST と同じ関数で、1 位・3 位以内に入る割合
     - 予測 (`p` と `q` の行): 読みを標準のローマ字にした打鍵の先頭 50% (切り上げ) で SUGGEST を引き、
       9 位以内に入る割合。`q` の行は文脈の表記を前文脈にする (前文脈は変換の経路には効かないので、`q` は
       予測だけを測る)
     - 前の件の `d` と `t` は、分け目より前の使用だけで決まっているので、分け目の時点の学習の状態として
       そのまま使える。取り込みは、前の件の行と、後ろの件から作った前の学習の行と、`n\t<後ろの件の最小の t>` の行を
       `LearningStore::load_stats_from` に渡して行う (古さは `n` と `t` の差で決まるため。learn.rs は変えない)
- 今の `learning_eval` の `--weights` (定数の組ごとに 1 行) と、1 位を外した行の内訳 (学習が空のときとの比較) は残す。
  内訳のうち learning.tsv の最後の表記と比べる項目 (`pinned_last`) は、比べる元が無くなるので消す
- 1 位を外した `p` の行は、正解と 1 位を `split_words` で自立語に分けて片方にだけある語を比べ、固定・分けられない・
  自立語が同じ・同じ区間・区切り・同音 (違う語の今の度合いが正解の方が大きい / どちらも学習あり / 正解に学習なし)・
  その他に分類し、分類ごとに行・3 位以内・前文脈の学習あり (同じ (読み, 表記) の後ろの `q` の文脈の学習が入っている)
  の数を出す。外れが語の学習の割引の上限の例外と前文脈のどちらで直りうるかを見るため
  - 差の語の読みの組が違う行のうち、差の語のすべてについてもう片方の経路に読みの開始と終了の位置が同じ語
    (付属語を含む) がある行を同じ区間とし、残りを区切りとする。区切りの位置は同じで、自立語と付属語の別
    (品詞と表記) だけが違う行 (正解の自立語の部分を 1 位が付属語にした、またはその逆) で、区切りの誤りではないため。
    経路は `convert::split_path` (経路のすべての語を区間と付属語かどうかとともに返す。`split_words` は
    その自立語だけを返す) で、1 位の経路も 1 位の表記を分け直して求める
  - あわせて、1 位が読み全体の学習表記だった `p` の行 (外れに限らない) を、その表記と経路の 1-best の表記で
    固定で当てた・固定で外した・同じ (当たり / 外れ)・どちらも外れに数え、分類の表の後に 1 行で出す。
    固定の得失を見るため
  - 学習が空のモードのすべての `p` の行にも同じ分類を掛け、分類ごとに行・3 位以内の数を出す (前文脈の学習ありは
    出さない。同音はすべて正解に学習なしに入る)。学習によらない変換の弱さの割合を、学習ありより多い行で見るため
  - 分けられない行は、正解の表記の文字の種類 (カタカナだけ・英字を含む・漢字を含む・その他。上から最初に
    当てはまるもの) でも分け、区分ごとに行・3 位以内・候補にあるの数を分類の表の後に出す (両方のモード)。
    カタカナだけの区分では、正解が読み全体のカタカナの行の数と正解の順位の中央値も出す。辞書に無い語がどんな語かを
    見て、カタカナの候補の順位の改善が効くかを判断するため
  - 区切りの行は、向き・長さ・正解の順位で分け、向きごとに行・長さの区分ごとの行・順位の区分ごとの行を分類の表の
    後に 1 つの表で出す (両方のモード)。区切りの外れが辞書や連接のコストのどこで起きているかの見当を付けるため
    - 正解にだけある自立語を正解の差、1 位にだけある自立語を 1 位の差とする (`classify_miss` の多重集合の差)。
      `split_words` は付属語を返さないので、差は自立語だけからなる
    - 向き (上から最初に当てはまるもの): 正解の差が空 (正解では付属語の部分を 1 位が自立語にした)・1 位の差が空・
      正解の方が語が少ない (1 位が細かく切った)・正解の方が語が多い (1 位がまとめた)・同じ数 (境界の位置のずれ)
    - 長さ: 正解の差と 1 位の差の読みの文字数の合計の大きい方を、1–2・3–4・5 以上に分ける。付属語を含まないので
      区間の長さの目安
    - 正解の順位: 2 位・3 位・4–10 位・11 位以下・候補に無い
    - 向きの行の合計が区切りの行の数と、長さの区分の合計と順位の区分の合計が向きごとの行の数と一致することを
      assert する
    - 向きごとに、1 位の差に Mozc 辞書に無い語・正解の差に Mozc 辞書に無い語の行の数も出す。まとめた行が
      UT 辞書の長い語によるかを見るため。Mozc 辞書に無い語は、UT 辞書を積まない Mozc 辞書を別に読み込み、
      差の語の (読み, 表記) がそこに無いもの。記号の辞書の語なども含むので UT 辞書の語とは呼ばない。
      UT 辞書が無いときは `-` を出す
  - 同じ区間の行は、向きで分け、向きごとに行・数えない語・学習あり・学習なしの行の数を分類の表の後に 1 つの表で
    出す (両方のモード)。区切りの位置が合っているのに学習で直らない理由が、語の学習に数えない語か、割引の不足や
    学習の不在かを見るため
    - 向き: 1 位の差が空 (正解の側が自立語)・正解の差が空 (1 位の側が自立語)・その他
    - 数えない語・学習あり・学習なし: 正解の差の語を見て、`learn::counts_as_word` が偽の語を含む行・評価の学習に
      語の度合いがある語を含む行・それ以外の行の順に、最初に当てはまるもので数える。正解の差が空の行は数えない
    - 向きの行の合計が同じ区間の行の数と、数えない語・学習あり・学習なしの合計が正解の差が空でない向きの行の数と
      一致することを assert する
    - 同じ区間で付属語との表記の違いを数える列は持たない。差の語の相手は同じ区間の付属語なので、表記は必ず違い、
      付属語の組もほぼ必ず違って、件数が構造で決まるため
  - `--dump-same-span <file>` を付けたときだけ、同じ区間の行を 1 行ずつ TSV で file に書く (両方のモード)。
    件数だけでは語の中身が分からず直し方を決められないので、ユーザが目で見るため。実際の入力がそのまま入るので、
    標準出力には書かず、file はリポジトリの外に置く
    - 列: モード (学習が空 / 学習あり (方式の名前))・向き・学習の区分 (数えない語 / 学習あり / 学習なし / -)・正解の順位
      (1 始まり。候補に無ければ -)・正解の経路・1 位の経路
    - 経路は語を ` | ` でつなぎ、語を `表記/読み` で書く。付属語は `[` `]` で囲み、差の語は頭に `*` を付ける
- 読みに ASCII 英字を含む `p` の行は、両方のモードの変換の測定 (割合・外れの分類・固定の得失) から除き、除いた行の
  数をデータの節に出す。モードレス入力の英字区間は (読み = 表記) の句として学習に入るが、実際の入力では変換に
  渡らないので、測ると変換の正解率が不当に低く出る。学習の取り込みと既出・初出の判定には含める (エンジンは
  英字区間の学習も持つ)。予測はこれらの読みを打鍵にできないので、もともと測れた行に入らない
- 結果は件数と割合だけを Markdown で標準出力に書き、読み・表記は書かない。入力も結果も git に入れない
- LLM の並べ替えは再生評価では測らない (測るのは `nbest_eval --llm` と AJIMEE-Bench)

### 採らなかった案

- AJIMEE-Bench の TSV をリポジトリに入れる: MIT のリポジトリに CC BY-SA のデータを混ぜることになる。
  取得スクリプトなら再配布しない
- 評価用に確定の記録を別ファイルに貯める: 打った文がそのまま残る。`t` の順の近似で足りなければ改めて検討する
- `nbest_eval` に JSON を直接読ませる: エンジンの crate に JSON の依存が増える

## 実装手順

1. `scripts/fetch-ajimee.ps1`: 取得・サイズと SHA-256 の確認・変換・除外の件数の表示
2. `nbest_eval`: 複数の正解。llm_cases.tsv で今と同じ結果になることを確かめる
3. `learning_eval`: learning_stats.tsv の読み込み、`t` の順の分割、2 つのモード
4. ドキュメント

## 検証方法

- `fetch-ajimee.ps1`: 197 件の TSV ができる (200 件から 3 件を除外)。もう一度実行しても同じ内容になる。
  SHA-256 が違うファイルでは止まる
- `nbest_eval --cases examples/data/llm_cases.tsv`: 変更前と同じ数値になる
- `nbest_eval --cases ../references/AJIMEE-Bench/ajimee_cases.tsv`: 197 件すべてが変換でき、エラーにならない。
  読みの 、。「」（） が CONVNBEST で扱えることも確かめる (扱えない場合は実装を止めて設計に戻す)。
  `--llm cpu` も通る
- `learning_eval --stats <learning_stats.tsv>`: 学習が空のモードの件数と除いた読みに英字を含む行の数の合計が `p` の行の件数と一致する。
  学習ありのモードの、前と後ろの件数の合計が `w`・`p`・`q` の行の件数と一致し、同じ `t` の件が前と後ろの両方に
  入らない。前の学習に入れた後ろの件の数を出す。既出と初出の行の数の合計が測る行の数と一致する。
  `--weights` を 2 つ指定すると 2 行出る
- 合成した learning_stats.tsv (数件) を使う単体テスト: 同じ `t` の件が分かれないこと、`d - 1` が `MIN_KEEP` 以上の
  後ろの件だけが `d - 1` と分け目の `t` で前の学習に入ること
- 実ユーザのファイルは読むだけで変わらない (実行前後でサイズと更新時刻が同じ)
- `cargo test` が通る

## 未決事項

- 後ろの件の `d - 1` には、分け目より後で最後の確定より前の使用も含まれうる (区別する記録が無い)。その分だけ
  既出の行が学習に有利に測られる。後ろの区間は短いので近似として受け入れ、結果が不自然なら見直す
