# モードレス入力の run 終了時の英字判定を候補バーで提示する

## 背景と目的

モードレス入力 (docs/design/modeless.md、docs/design/modeless-detection.md) には、run を終えるときにだけ
働く英字判定 (ルール3・6・7) がある。今は Space と語の区切りの記号キー (`.` `,` `!` `?` `:` `;`) で run を
終えるときに、判定が成立すると英字に書き換えてから確定する (`きょうはわんt` → Space → `きょうはwant `)。
書き換えは確定と同時に行われ、確定する前に結果を見る機会が無い。

方針として、見えている文字列と異なる形で確定することは排除する。一方、これらの判定は語を打ち終えたことが
分かる時点 (run の終了) でしか決められない (`わんt` の `t` は次に母音が来れば `た` になる)。

そこで、run 終了時の書き換えをやめ、「今 run を終えたら英字になる」ことを打鍵中に候補バーの英字候補として
見せ、選んだときだけ英字にする。

あわせて、自動判定で英字になった後に、判定のきっかけになった打鍵を Backspace で消しても英字のままで、
最初から打ち直しになる問題を直す。

## 決定事項

すべて設定 `modeless` が有効なときだけ働く。新しい設定は設けない。

### run 終了時の書き換えをやめる

- Space・語の区切りの記号キーで run を終えるときに、ルール3・6・7 で英字に書き換えない
  (`ApplyModelessCommitRule` の呼び出しをやめる)。どのキーで run を終えても、見えているとおりに確定する
- 記号キーは今の英字モードの有無どおりに入る (日本語区間なら `。` など設定どおり、英字モード中は半角)
- 打鍵中の判定 (ルール1・2・4・5、ルール1・c の保留) と、英字区間を閉じる判定
  (docs/design/mixed-conversion.md) は今どおり

### 英字候補 (候補バー)

#### 出す条件と内容

- run の打鍵のたびに (候補バーを作り直すときに)、`composer_` の複製に run 終了時の判定
  (`FinishForCommit` と `ResolveAsciiRequest`) を当て、複製が英字になるかを調べる。`composer_` 自体は変えない
- 複製が英字になったら、その複製の確定文字列 (`Commit()`) を英字候補としてバーの先頭に出す
  (`きょうはwant`、`pen`、`remote`、`これはfeature`)
- ただし、ルール3 の要求が英単語辞書に一致しなかった場合 (今の扱いでは run 全体 (閉じた英字区間があれば
  その後ろ全体) を英字にする場合) は英字候補を出さない。日本語を打っていて子音を1つ打つたびに
  run 全体の英字が候補に出てしまうため。`watasihant` のような語は F10 で直す
- ルール6 は今どおり、先頭から一致したときだけ (run 全体が1語の英単語)
- 英字モード中 (開いている英字区間がある run、run 全体が英字の run) は出さない (判定の対象外のため)
- 英字候補は `min_suggest_chars` によらず出す (`pen` はかなで2文字、`want` は `わんt` で確定済みかなが2文字)。
  ほかの候補 (全体変換・予測・先頭文節) は今どおりの条件で、英字候補の後ろに並ぶ。ほかの候補が無ければ
  英字候補だけのバーを出す
- 候補バーを無効にしている (`candidate_bar 0`) ときは英字候補も出ない (F10 で直す)
- 英単語辞書の問い合わせ (ASCIISTART) は今の run 終了時と同じ呼び方 (接続待ちしない)。エンジン未接続の
  ときは、辞書を使わないルール7 と、1文字の語 (`a` `i`) のルール6 だけが候補になりうる

#### 採用

- 選択と採用の操作は既存のバーと同じ (Tab・↓ などで選び、確定キー・Enter・Space・印字キーで採用。
  docs/design/candidate-bar.md)
- 採用は、`composer_` を英字候補を作った複製に置き換え、文書の run の文字列を複製の表示に書き換える
  (読める文書は置換、追記のみの文書は今の英字区間への切替と同じ擬似 Backspace の経路)。
  採用した部分は英字区間 (開いている英字区間) になる
- 採用後の扱いは採用の操作で決まる
  - Space: 英字区間の Space と同じく、確定して半角スペースを入れる (`want` → Tab → Space で `want `)
  - 確定キー: 確定して run を終える
  - Enter: 確定して run を終え、Enter をアプリへ渡す
  - 印字キー: run を終えず、英字区間に打鍵を続ける (英字区間を閉じる判定も今どおり働く)
- 学習は今の英字を含む入力と同じ (変換せずに確定したときの扱い)

### Backspace で判定前の日本語に戻す

- 自動判定 (ルール1〜5・7 の打鍵中または採用による切替、英字区間を閉じる操作は除く) で英字に切り替えるたびに、
  切り替える直前の読みの状態 (かな・打鍵列・未変換ローマ字・英字区間の開始位置・閉じた英字区間) と、
  その時点の打鍵数 (`Raw()` の文字数) を積む
- Backspace の後に打鍵数が、積んだ最後の記録の打鍵数より少なくなったら、積んだ状態に戻してから、
  戻した状態に対して Backspace を1回分 (未変換ローマ字の末尾1文字、無ければかなの末尾1文字) 当てる。
  記録は取り除く
  - 積んだ状態の未変換ローマ字の末尾は判定のきっかけになった打鍵なので、それが消えて判定の前に戻る
- Backspace の後は、残った未変換ローマ字に対して打鍵中の判定をやり直す (ルール1 の保留に入る・抜ける、
  英字にする)。英単語辞書の問い合わせが要るときは打鍵のときと同じく `ResolveAsciiRequest` を通す
- 例
  - `korehaxyzw` (4文字で一致せず run 全体が英字) → Backspace → `これは` + 小窓 `xyz` (保留中)
  - `kyouhagithu` (`thu` の `u` で `きょうはgithu`) → Backspace → `きょうはぎ` + 小窓 `th`
  - `apple` (`appl` で英字) → Backspace で `appl` → Backspace で `あっp` 相当の状態 (`l` を消した後の判定で
    再び英字になるかは、そのときの未変換ローマ字の判定による)
- Shift+英字で入った英字モードは対象外 (今どおり、英字区間が空になったら解除する)
- 英字区間を閉じた後の Backspace で英字区間を開き直す動作 (docs/design/mixed-conversion.md) と併用する。
  積んだ記録と閉じた英字区間の積みは、打鍵数の新しいものから順に戻る
- 候補バーの採用で run の先頭を取り除いたとき (`RemoveFront`) と、範囲の伸縮で先頭にかなを足したとき
  (`PrependKana`) は、積んだ記録を捨てる (位置がずれるため)。`Clear()` でも捨てる
- 範囲の伸縮で積む読みの状態 (docs/design/conversion-range.md) は `RomajiComposer` 全体なので、
  この記録も合わせて戻る

## 実装手順

各手順の後に TSF の Debug ビルドが通ることを確かめる。

1. run 終了時の書き換えの削除 (Space・記号キー)
2. 英字候補の生成とバーへの表示
3. 英字候補の採用 (Space・確定キー・Enter・印字キー、読める文書・追記のみの文書)
4. Backspace での判定前の状態への復元と判定のやり直し
5. ドキュメントの更新

## 検証方法

開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、テスト用アプリで行う。config.tsv は
`QUICKLIME_CONFIG_FILE` で隔離したものを使い、`modeless 1`・`candidate_bar 1`・`debug_log` を設定する。

## 未決事項

- ルール3 の英字候補を辞書の一致に限ったことで、辞書に無い語 (`watasihant` の類) は F10 でしか直せない
