# 入力全体の N-best

入力モデル v2 (docs/design/input-model-v2.md) の段階4。入力全体を1単位とした N-best 候補を
エンジンで作り、候補バーと変換キーの候補選択で使う。文節 UI (文節移動・伸縮・文節別の候補選択) は
設定でオンにしたときだけ使うオプションにする。

## 背景と目的

エンジンの変換は Viterbi の最小コスト経路 (1-best) だけを作り、2位以降の候補は文節ごとの
辞書候補と先頭語の入れ替えで作っている。入力全体として別の経路 (「今日は医者に行った」と
「今日歯医者に行った」) は候補に出せない。経路が違う候補を選ぶには、文節伸縮で区切りを
直してから文節ごとに候補を選ぶ必要がある。

本段階の目的は次のとおり。

- 区切りごと違う候補を、入力全体の候補として上位に並べる
- 候補選択の既定を「入力全体から1つ選ぶ」にし、訂正のための文節操作をなくす
- 候補バーの全体変換を複数件にし、変換キーを押さずに選べる範囲を広げる
- 段階5 (LLM による順位補正) の並べ替えの対象になる候補群を用意する

## 決定事項

### N-best の生成 (エンジン)

- 前向きの Viterbi で各ノードの最小コストを求めた後、文末から後ろ向きに A* 探索して、
  コストの小さい経路から順に取り出す。前向きの最小コストを見積もりに使うので、
  取り出す順は経路の総コスト順と一致する
  - ラティス・連接コスト・文節境界ペナルティ・境界学習の調整は `viterbi_path` と同じものを使う
  - 文頭の文脈 ID は前文脈から復元する (CONVCTX と同じ)
- 取り出した経路は、`convert_segments` と同じ規則 (連続する数字をまとめ、付属語を前の自立語に
  付ける) で文節に分ける
- 重複は次の2段で抑える
  1. 表記の連結が同じ経路は1件にまとめる (区切りだけが違う経路。先に出たものを残す)
  2. 1-best と違う文節が同じ候補は最大4件 (`MAX_NBEST_PER_CLASS`) までにする。「違う文節」は、
     1-best に (開始位置, 読み, 表記) の同じ文節が無い文節とし、その (開始位置, 読み) の並びで
     候補を分類する
     - 例: 1-best が「今日は|医者に|行った」なら、「今日は|医者に|言った」と
       「今日は|医者に|いった」は同じ分類 ((8, いった)) で、この分類の5件目からは除く。
       「今日|歯医者に|行った」は別の分類なので残る
- 同じ分類の中は、(1-best に無い単語の数, 経路のコスト) の小さい順に並べ直してから
  `MAX_NBEST_PER_CLASS` 件を残す。「単語」は数字をまとめた後の経路上の語で、1-best に
  (開始位置, 読み, 表記) の同じ語があれば「1-best に有る」とする
  - 区切りを変えた候補のうち、1-best の語を流用したものを先に出すため。例: 「今日|歯医者に|行った」
    (1-best に無い語は「歯医者」) は、同じ分類の「共|歯医者に|行った」(「共」「歯医者」) より前に来る
  - 分類どうしの並びはコスト順のまま変えない。コスト順に並べたときに分類 C が現れる i 番目の
    位置に、並べ直した C の i 件目を入れる
  - 並べ直しのため、探索は件数では打ち切らず、下のコスト差か部分経路の数で止めてから
    `MAX_NBEST` 件に切る
- 次のどれかに達したら探索を打ち切る
  - 経路のコストが 1-best のコスト + `NBEST_COST_MARGIN` (5000) を超えた (未知語まじりなど、
    質の悪い候補を出さない)
  - 探索で取り出した部分経路の数が `MAX_NBEST_EXPANSIONS` (3000) に達した (長い入力で打鍵を止めない)
- 出す件数は最大 `MAX_NBEST` (10) 件
- 定数の値は llm_cases.tsv での計測 (検証方法) で決めた
- N-best の経路には文節ごとの学習を当てない (学習は次の「候補の並び」の 1-best で効かせる)

### 候補の並び

CONVNBEST の候補は、次の順に並べる。表記が同じ候補は先勝ちで除く。

| 順 | 候補 | 文節 |
|---|---|---|
| 1 | 読み全体の学習表記 (`LearningStore::get` で読み全体を引いたもの) | 読み全体の1文節 |
| 2 | 文節ごとの学習を当てた 1-best (`convert_segments` の各文節の先頭候補の連結。段階3の全体変換と同じもの) | `convert_segments` の文節 |
| 3 | N-best の残り (コスト順) | 経路の文節 |
| 4 | 短縮よみ・読み全体の辞書完全一致 (`candidates` の並びと同じ) | 読み全体の1文節 |
| 5 | 記号・カタカナ・ひらがな | 読み全体の1文節 |

- 4・5 は縦の候補リストで「読みそのものの別表記」を選べるようにするため。候補バーでは
  件数の上限 (後述) で実際にはほぼ出ない
- 全体の件数は 1〜3 の合計で `MAX_NBEST` + 2、4 は `MAX_DICT_CANDIDATES` までとする

### プロトコル

CONVNBEST を新設する。CONVERT・CONVSEG・CONVCTX はそのまま残す (CONVSEG・CONVCTX は
文節 UI と、英字を含む入力の1文節固定の変換で使い続ける)。

```
要求:   CONVNBEST\t<文脈読み>\x1f<文脈表記>\t<かな>\n   (前文脈なしは文脈フィールドを空にする)
成功:   OK\t<候補1>\t<候補2>\t...\n
失敗:   ERR\t<メッセージ>\n

候補 = <読み>\x1f<表記>\x1e<読み>\x1f<表記>...  (文節ごと。\x1e = ASCII Record Separator)
```

- 候補の表記は文節の表記を連結したもの。TSF 層は文節の (読み, 表記) を学習に使う
- 前文脈の扱い (空なら無し、末尾 64 文字に切り詰める) は CONVCTX と同じ
- かなが空ならエラー
- 旧エンジン (CONVNBEST 未対応) に拒否されたら、TSF 層は CONVCTX / CONVSEG の結果から
  段階3と同じ1件の全体変換を作る (EngineClient の既存の旧コマンド fallback と同じ仕組み)

### 学習

- 入力全体の候補を採用・確定したときは、次の2つを1回の LEARN2 で送る
  - 候補の文節ごとの (読み, 表記, 直前文節の表記)。今の文節ごとの学習と同じ
  - 読み全体 → 候補の表記 (文脈表記は空)。候補が1文節なら文節の学習と同じなので送らない
- 次の前文脈は、採用した候補の最後の文節にする
- 読み全体の学習は learning.tsv に入るので、PREDICT の確定履歴にも載る。一度確定した文が、
  前方一致で予測候補に出るようになる (許容する。短い読みで同じ文を呼び出せる)
- 文節 UI (`segment_ui` 1) で2文節以上を確定したときも、読み全体 → 確定文字列を同じく送る。
  文節を直して確定した結果が、次から N-best の先頭に来るようにするため
- LEARNSEG・LEARNWORD は文節 UI のときだけ送る (今どおり。文節伸縮でしか起きないため)

### 候補バー

段階3 (docs/design/candidate-bar.md) の並びを次のとおり変える。

| 種類 | 内容 | 件数 |
|---|---|---|
| 全体変換 | CONVNBEST の上位 | 最大3 |
| 予測候補 | PREDICT の結果 | 残り枠 |
| 先頭文節 | CONVNBEST の上位の候補から順に、2文節以上の候補の第1文節 (読み, 表記) を重複なく集めたもの | 最大3 |

- 合計は最大9件のまま。予測候補は「9 − 全体変換 − 先頭文節」件まで
- 全体変換は、run のかなと同じ表記の候補を除いてから上位3件を取る
- 先頭文節の候補は、それぞれ自分の文節の読みを持つ (区切りの違う「今日は…」「今日…」が並ぶ)。
  採用の仕方は段階3の部分採用と同じ
- 打鍵ごとの往復は CONVNBEST と PREDICT の2回 (バーでは CONVCTX を呼ばない)。
  CONVNBEST もエンジンの自動起動・接続待ちをしない呼び出しにする
- 確定キー (バー未選択) で採用するのは全体変換の1件目
- 全体変換の採用の学習は「学習」の節のとおり (段階3の文節ごとの学習に、読み全体を足す)

### 候補選択 (変換キー)

設定 `segment_ui` で切り替える。

#### `segment_ui` 0 (既定)

- 変換キーで、run の確定済みかな全体を1単位にした候補リスト (CONVNBEST の全件) を縦の
  候補ウィンドウに出す。内部では読み全体の1文節として扱う
  - 打鍵したローマ字の半角候補は、今の1文節のときと同じく末尾に足す
  - 英字を含む入力は、今どおり1文節固定の CONVSEG / CONVCTX で変換する
  - エンジン未接続ならひらがな1候補 (今どおり)
- 候補ごとに CONVNBEST の文節を覚えておき、確定時の学習に使う
- 文節の操作は無い。候補選択中の ← / → / Shift+← / Shift+→ / PgUp / PgDn は、
  Home / End / Delete と同じく「確定してアプリへ渡す」にする
- F4〜F10 (記号・ユーザ語・文字種変換) は run 全体にかかる (今の1文節のときと同じ)
- 対記号の同期は1文節なので働かない (不要になる)

#### `segment_ui` 1

- 候補選択は今の文節 UI のまま (CONVSEG / CONVCTX、文節移動・伸縮、LEARNSEG・LEARNWORD)
- 候補バーは `segment_ui` によらず上の「候補バー」のとおり

### 設定

- `segment_ui` (既定 0) を新設する。TSF 層の ConfigLoader だけが読む (エンジンは無視する)
- 設定ツールに「文節単位で変換する」チェックボックスを足す

## 実装手順

各手順の後にビルドとテスト (`cargo test`) が通り、既存の動作が壊れていないことを確かめる。

1. エンジン: N-best の探索 (A*・重複除去・打ち切り) と単体テスト
2. エンジン: 候補の並び (`convert_nbest`) と CONVNBEST、単体テスト
3. エンジン: `nbest_eval` で llm_cases.tsv を計測し、定数を調整する
4. TSF: `EngineClient::ConvertNBest` と応答のパース
5. TSF: 候補バーを CONVNBEST に切り替える (全体変換3件・先頭文節・学習)
6. TSF: `segment_ui` の読み込みと、`segment_ui` 0 の候補選択 (候補リスト・学習・← → PgUp PgDn)
7. 設定ツールのチェックボックス
8. ドキュメントの更新 (protocol.md、keymap.md、candidate-bar.md、README.md)

## 検証方法

### エンジンの単体テスト

- 経路がコスト順に取り出され、先頭が `viterbi_path` の 1-best と一致する
- 区切りだけが違う同じ表記の経路は1件になる
- 1-best と違う文節が同じ候補は `MAX_NBEST_PER_CLASS` 件まで
- 同じ分類の中では、1-best の語を流用した候補がコストの安い候補より前に来る。
  分類どうしの並びはコスト順のまま
- 1-best + `NBEST_COST_MARGIN` を超える経路は出ない。`MAX_NBEST` を超えない
- 読み全体の学習表記が先頭、文節学習を当てた 1-best がその次に来る
- 前文脈で先頭語の選択が変わる (CONVCTX と同じ前文脈の効き方)
- CONVNBEST の応答形式 (文節の区切り、文脈フィールドが空、かなが空でエラー)
- LEARN2 で読み全体を学習した後、CONVNBEST の先頭と PREDICT に出る

### N-best の計測 (`nbest_eval`)

- llm_cases.tsv の読み (と左文脈が使える行は前文脈なしで) を CONVNBEST と同じ関数で変換し、
  正解が 1 位・上位3件・上位10件に入る割合と、1回の生成の時間 (中央値・最大) を出す
- 目安: 上位3件・上位10件の割合が 1 位 (統計 1-best、50 件中 25 件) より上がること。
  時間は打鍵ごとに呼んで気にならないこと (長い読みの行で確かめる)
- 結果は本書ではなく、計測時の報告に記す。定数を変えたら本書の初期値の記述も合わせる

config.tsv は `QUICKLIME_CONFIG_FILE` で隔離したものを使い、`debug_log` を設定する。
