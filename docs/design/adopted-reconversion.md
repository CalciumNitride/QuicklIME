# 採用した文字列の再変換 (読みの記憶)

## 背景と目的

run が無いときの変換キー・F6〜F10 の対象は、キャレット直前のひらがな・ー の連続か、
かなだけの選択範囲に限られる (docs/design/conversion-range.md)。漢字・カタカナ・英字を含む
部分は読みが分からないため、採用・確定した後に直すにはアプリの Undo でかなに戻すか、
直前の1件だけを確定アンドゥ (Ctrl+Backspace) で読みに戻すしかない。

IME が文書に入れた文字列とその読みを、文書と一致する間だけ覚えておき、漢字を含む部分も
読みを打ち直さずに変換キーで直せるようにする。

## 決定事項

### 記憶する内容

- run の出力を1件 (以下「記憶」) として覚える。対象は run が文書に残したすべての出力:
  候補バーの採用 (全体変換・予測候補・先頭文節)、候補選択の確定、かなのままの run の終了
- 1件が持つもの:
  - 表記 (文書に入れた文字列)
  - 文節ごとの (読み, 表記) の列。文節の表記を連結すると記憶の表記になる。かなのままの run と
    予測候補は1文節 (読み, 表記) とする
  - 確定前の読みの状態 (`RomajiComposer`。確定アンドゥの `lastComposer_` と同じもの)
- 記憶は文書に入れた順に並べ、新しいものから合計で読み 127 文字 (`kMaxReconvertLength`) まで
  持つ。超えた分は古いものから捨てる
- メモリ上だけに置き、ファイルには保存しない。フォーカス移動・IME オフで捨てる
- 読める文書 (`AppendDocument::Readable`) でだけ記憶する。追記のみの文書・未判定の文書では
  記憶せず、今の確定アンドゥだけが働く
- 記憶の間に IME を通らない文字 (Space で入れたスペース、アプリへ渡した Enter の改行など) が
  入ったら、それより前の記憶は使えなくなる (下記の照合で途切れる)

### 記憶の照合

- 使う時点でキャレット直前の文書の文字列を読み、新しい記憶から順に、表記が文書の末尾から
  連続して一致する分だけを有効とする。一致しない記憶に当たったら、そこより古い記憶は捨てる
- 選択があるときは照合しない (今の後置再変換のまま。選択に漢字を含めば対象なし)

### 変換キー・F6〜F10 の対象 (run なし・選択なし)

| キャレット直前 | 範囲の初期値 |
|---|---|
| 有効な記憶があり、最新の記憶の表記がかなだけでない | 最新の記憶1件 (1回で採用した単位) |
| それ以外 | キャレット直前のひらがな・ー の連続 (今どおり) |

- 範囲の読みは記憶の文節の読みを連結したもの。記憶から作った run の読みの状態は、
  記憶した `RomajiComposer` を使う (F6〜F10 で打鍵どおりの英字に戻せる)
- 候補の先頭には記憶の表記を置く (変換キーを押しただけでは文書が変わらない)。
  エンジンの候補に同じ表記があれば先頭へ寄せ、無ければ足す。2回目の変換キーから次の候補へ進む
- 前文脈: 範囲の直前に有効な記憶があれば、その最後の文節 (読み, 表記) を前文脈にする。
  無ければ今どおり (直前の確定の表記で終わるときだけその確定、それ以外は前文脈なし)

### 範囲の伸縮 (候補選択中の ←→)

conversion-range.md の範囲の伸縮を、記憶にまたがって行えるようにする。右端はキャレットに
固定し、左端を読み1文字ずつ動かす点は変わらない。

- → (縮める): 範囲の先頭の読み1文字を外す。外した読みはかなとして文書に残す
  (記憶の漢字の文節を途中で切っても、外した側はかなになる。例: 「今日は」の範囲で → を2回押して
  「きょ|うは」にすると、文書は「きょ」+「うは」の変換結果)
- ← (広げる): 範囲の先頭の直前が有効な記憶なら、その記憶の最後の文節から読みを1文字足す。
  足した文字を含む文節は、範囲に入らなかった部分を含めてかなとして文書に書き直す
  (例: 「今日」+「は医者に」の範囲で ← を1回押すと、「きょ」+ 範囲「うはいしゃに」)。
  直前がひらがな・ー なら今どおり文書のかなを足す
- 広げられるのは合計 127 文字までで、記憶の照合が途切れたところで止まる
- 外した文字の打鍵の復元 (縮めた直前の状態を積んで ← で戻す) は今どおり

### 確定と取消

- 確定 (確定キー・Enter・印字キー・Space など、今の候補選択の確定と同じ経路) は今の変換と同じで、
  学習も同じく送る。確定した範囲は新しい1件として記憶し、範囲が覆っていた記憶 (範囲に一部だけ
  入った記憶を含む) を置き換える。範囲の外でかなに書き直した部分は、かなの1件として記憶する
- 取消 (Esc・Backspace・Tab など、今の変換の取消の経路): 記憶から始めた変換では、範囲と、
  伸縮でかなに書き直した部分をすべて変換前の表記に戻して終える (かなの run には戻さない)。
  記憶は変換前のまま残す

### 確定アンドゥとの関係

- 確定アンドゥ (Ctrl+Backspace) は今どおり直前の1件を読みのかなに戻す (一度きり)。
  戻した記憶は捨てる
- 確定アンドゥの記憶 (`lastCommitText_` / `lastComposer_`) は本書の記憶とは別に持ち続ける。
  追記のみの文書では確定アンドゥだけが働くため

### 採らなかった案

- 縮める・広げる単位を文節にして、外した部分を元の表記のまま残す案。外した側が書き換わらない
  利点はあるが、文節の途中で切りたい場合に対応できず、かなの範囲の伸縮 (1文字ずつ) と操作感が
  揃わないため採らない
- 追記のみの文書でも記憶を使う案。文書を読み戻して照合できず、記憶を捨てる契機の漏れが
  別の文字の書き換えにつながるため採らない

## 実装手順

1. 記憶の型と列を作り、run の終了・候補バーの採用・候補選択の確定で追加する
   (読める文書のときだけ。上限の切り詰め、フォーカス移動・IME オフでの破棄)
2. 記憶の照合 (キャレット直前の文字列との末尾一致) を作る
3. run なし・選択なしの対象決定に記憶を足し、記憶から run を作って変換に入る
   (読みの状態の復元、候補の先頭の記憶の表記、前文脈)
4. 記憶から始めた変換の取消で、変換前の表記に戻す
5. 範囲の伸縮を記憶にまたがって行えるようにする (← で記憶の文節をかなに書き直して足す、
   確定時の記憶の置き換え)
6. ドキュメントの更新
7. 手動テスト (下記)

メモ帳は `taskkill /IM Notepad.exe /F` してから開き直す。学習ファイルは `QUICKLIME_LEARN_FILE`
