# ドキュメントの整理 (roadmap.md の分割)

## 背景と目的

docs/roadmap.md に、性質の違う次の情報が混在している。

1. プロジェクト概要・アーキテクチャと構成の採用理由 (恒久的な情報)
2. 完了したフェーズの経緯 (完了日、「当初は〜だったが段階2で廃止」など)。git log と重複している
3. 機能の仕様の詳細。docs/design/*.md・README.md と重複しており、廃止済みの機能 (ライブ変換の旧実装、
   composition 方式) の記述も残っている
4. 未着手・見送り・既知の問題 (本来の roadmap の中身)

また、最近の機能 (サジェストパネル、テーマ、パネル保持入力、改行キー、辞書の語彙補強、設定タブ) は
roadmap に載っておらず、「機能を足すたびに roadmap へ追記する」運用は続いていない。

情報の性質ごとにファイルを分け、どれも最新仕様のスナップショットだけを持つようにする。

## 決定事項

| 情報 | 置き場所 |
|---|---|
| 概要・アーキテクチャ・採用理由・参考リンク | docs/architecture.md (新設) |
| 機能と設計書の対応 | docs/design/README.md (設計書の索引、新設) |
| 設計書の無い初期の機能の現行仕様と WHY | docs/design/basics.md (新設) |
| 未着手・見送り・既知の問題 | docs/roadmap.md (書き直し) |
| 完了した経緯 | 置かない (git log にある) |

- 完了したフェーズのチェックリストは索引が引き継ぐため、roadmap からは消す
- 旧 roadmap を docs/archive/ に退避する案は採らない。経緯を docs に残さない方針
  (仕様のスナップショットのみ) に反するため
- 概要を README.md に統合する案は採らない。README は利用者向けの説明で、既に 650 行ある
- 既存の設計書・archive の本文は書き換えない。設計書の「変更対象ファイル」に roadmap.md の
  追記が書かれているのは実装前の合意の記録なのでそのままにする。docs/archive/llm-rerank-notes.md の
  roadmap の行番号への参照も、草案のスナップショットなのでそのままにする
- docs/design/experiment-0b-*.md を archive へ移すなどの配置換えはしない (今回の範囲外)

### docs/architecture.md

roadmap.md の「プロジェクト概要」「アーキテクチャ」「この構成を選んだ理由」「参考リンク」を移す。
内容はほぼそのまま。作成日の行は消す。

### docs/design/README.md (索引)

- docs/design/ と docs/archive/ の全ファイルを載せる
- 機能ごとに 1 行の説明と設計書へのリンクを書く。並びは機能のまとまり (入力方式、候補の表示、変換、
  モードレス入力、辞書、設定・ツール、互換、実験) ごとにする
- 後の設計書で一部または全部が置き換えられた設計書には、置き換えた設計書へのリンクを付ける
  (例: direct-input.md の composition 方式とフォールバックは append-input.md で廃止、
  candidate-bar.md の見た目は suggest-panel.md で刷新)。置き換えの有無は各設計書の本文の記述から
  判断し、本文から判断できないものは推測で書かずに報告する
- basics.md も索引に載せる
- docs/archive/ は「採らなかった案・検討段階の草案」として別の節にまとめる
- protocol.md・theme.md (docs/ 直下) へのリンクも置く

### docs/design/basics.md (初期の機能の仕様)

roadmap.md のフェーズ4・5 のうち、専用の設計書が無い機能について、**現行の**仕様と WHY を書く。
対象 (roadmap から拾える範囲):

- 辞書 (Mozc OSS 辞書、fst 採用の理由とダブル配列を見送った理由)、Viterbi、学習 (learning.tsv)
- 記号辞書、生ローマ字候補、ファンクションキー変換 (F4 記号・日付時刻、F5 ユーザ辞書、F6〜F10)
- 記号キーと Shift+英字の入力、対記号の両側同期変換
- 予測 (履歴・辞書・短縮よみの合成と優先順)
- 日付・時刻の動的候補 (F4 に統合した理由、学習から除外する理由)
- 確定アンドゥ
- ローマ字テーブルの外部ファイル化と AZIK 風プリセット (本家 AZIK から除外した割当とその理由)
- タイプミス補正 (かな単位の編集距離にした理由)
- ユーザ辞書登録と単語登録ツール
- 設定ファイル config.tsv と設定ツール、言語バー
- エンジンの自動起動
- インストーラ (配置、32bit DLL、CRT 静的リンクの理由、更新時の restartreplace)
- パスワード欄の扱い (compartment で判定し InputScope を使わない理由)

書き方:

- roadmap の記述をそのまま写さない。現行のコード・README・後の設計書と照らし、今も正しい内容だけを書く。
  入力モデル v2 で変わった操作 (composition 中の Tab/↓ によるサジェスト選択、ライブ変換の旧実装など) は
  現行の仕様で書くか、後の設計書へのリンクで済ませる
- 完了日・「当初は〜」「〜を廃止した」などの経緯は書かない
- README.md に利用者向けの説明がある機能は、操作の説明を重複させず README へのリンクにして、
  README に無い内部仕様と WHY だけを書く
- コードを読んでも現行の仕様が確定できない項目は、推測で書かずに報告する

### docs/roadmap.md (書き直し)

未着手・見送り・既知の問題だけを、1 項目 1〜3 行で書く。関連する設計書・草案があればリンクする。
節は「未着手」「見送り・既知の問題」の 2 つ。載せる項目:

- 未着手
  - 確定済みの任意の選択範囲の再変換 (TSF の ITfFnReconversion)。現状は、かなのみの選択範囲と、
    採用した文字列の記憶 (adopted-reconversion.md) の範囲だけ
  - 数字表記変換 (「1234」→ 千二百三十四 など)
  - 変換 (CONVERT/CONVSEG) へのタイプミス補正候補の追加
  - 学習の改良 (現状は読みごとに最後に確定した表記を先頭にする単純方式。頻度ベースなど)
  - モードレス入力の修正の学習 (英字区間の境界を F10/F6 で直したことを次の判定に使う)
  - キャレット直前のかなの変換を候補バーの対象にすること (conversion-range.md の未対応)
  - LLM の右文脈の利用
  - LLM の並べ替えのフィードバック学習 (docs/archive/llm-rerank-notes.md)
- 見送り・既知の問題
  - マビノギで Ctrl 併用のキー割当が効かない。原因 (ゲームが OnTestKeyDown だけを呼ぶ、
    composition 中の Ctrl 併用キーで確定される) と試した対策、回避策 (Convert キー) を残す

「リアルタイム変換サジェスト」は入力全体の N-best を使う候補バーで実現済みのため載せない。
「自分で常用しながらの改善サイクルへ」「開発上の注意点」の節は消す。

### 運用ルール

.claude/CLAUDE.md の「ドキュメントファイルの扱い」に次を足す。

- 機能を足したら docs/design/README.md に 1 行足す (設計書があればリンクする)
- docs/roadmap.md には未着手・見送り・既知の問題だけを書く。着手して完了したら項目を消す
  (完了の記録は残さない)
- 設計書の無い小さな機能で、コードから復元できない仕様・WHY があるものは docs/design/basics.md に書く

## 実装手順

1. docs/architecture.md を作る
2. docs/design/basics.md を作る (コード・README・後の設計書との照合を含む)
3. docs/design/README.md を作る
4. docs/roadmap.md を書き直す
5. README.md と .claude/CLAUDE.md を更新する

## 検証方法

- 旧 roadmap.md の各項目が、architecture.md・basics.md・索引・新 roadmap・既存の設計書のどこかに
  対応していること (意図して消した経緯を除く)。対応表を報告に含める
- docs/design/ と docs/archive/ の全ファイルが索引に載っていること
- 新設・書き直したファイル内の相対リンクのリンク先が存在すること
- 新設・書き直したファイルに完了日・「当初」「廃止した」などの経緯の記述が無いこと
- ファイルに絵文字を使っていないこと
