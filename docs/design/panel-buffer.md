# パネル保持入力 (入力中の読みを文書に書かない方式)

## 背景と目的

直接入力方式 (docs/design/direct-input.md、docs/design/append-input.md) は、run のかなを完成した
時点で文書に追記し、候補バーの採用や変換の確定でその文字列を置き換える。サジェストパネル
(docs/design/suggest-panel.md) の入力行は、文書に入っている run の文字列をパネルに重ねて見せているだけである。

候補パネルを画面中央に出し、読みを少し打って候補から選んでいく使い方では、入力中のかなが文書にも
入る必要はない。むしろ次の点が気になる。

- 打鍵ごとに文書が変わるので、逐次検索するフォームや文字数カウンタが途中のかなに反応する
- アプリの Undo 履歴に、かなの追記が 1 文字ずつ積まれる
- 文書を読み戻せないアプリ (追記のみの文書) では、採用のたびに擬似 Backspace で run を消している

そこで、入力中の run をパネルの入力行だけに持ち、採用・確定したときに初めて文書へ挿入する入力方式
(以下「パネル保持入力」) を追加する。今の直接入力方式 (以下「文書書き込み入力」) と設定で切り替えられるようにする。

## 決定事項

### 設定

config.tsv に次の項目を足す。TSF 層が読む。

| キー | 値 | 既定 | 内容 |
|---|---|---|---|
| `input_buffer` | `document` / `panel` | `document` | `document` は文書書き込み入力 (今の方式)。`panel` はパネル保持入力 |

- 不正な値は既定値として扱う (他の設定と同じ)
- 設定ツールでは「入力」タブに「入力中の読みを文書に書かず、候補パネルだけに表示する」のチェックボックスを置く
- 方式は run を始める時点の設定で決め、その run が終わるまで変えない。設定ファイルの読み直しで
  run の途中に方式が変わることはない

### run の持ち方

- パネル保持入力の run は、読み (`composer_`) とパネルの入力行だけで表す。文書には何も書かず、
  `surface_` は常に空のままにする
- 入力行は、`panel_input`・テーマの `input_row`・`candidate_bar` の設定によらず常に出す
  (出さないと入力中の読みがどこにも見えないため)。未完成ローマ字の小窓は出さない
  (未完成ローマ字も入力行に含める)
  - `candidate_bar 0` のときは、入力行だけのパネルを出す。毎打鍵の PREDICT・CONVNBEST は呼ばず、
    バー選択中の状態にも入らない (文書書き込み入力の `candidate_bar 0` と同じ)
- 入力行に出す文字列は、run の読み (`composer_.Display()`。確定したかなと未完成ローマ字) である。
  文書書き込み入力の `surface_` + `AppendPendingText()` に当たる
- run は文書のキャレットに結びつかない。マウスクリック・キャレット移動・`OnEndEdit` の選択変更が
  あっても run は続け、採用・確定した時点のキャレット位置 (選択があればその選択を置き換える) に挿入する。
  パネルの run のためにはマウスフックを仕掛けない

### 文書への挿入

- 採用・確定は、文字列をキャレット位置に挿入する (`InsertText` と同じ edit session)。置換も擬似 Backspace も使わない
- 文書の分類 (読める / 追記のみ / 未判定) は、run の 2 文字目を追記するときの読み戻しでは決まらなくなる。
  代わりに、IME が直前に挿入した文字列を次の時点で読み戻して判定する
  - 判定する時点: 新しい run の最初の打鍵 (左文脈を取る前)、run なしの変換キー・F6〜F10、確定アンドゥ
  - キャレット直前が、IME が直前に挿入した文字列で終わっていれば「読める」にする。一致しないときは
    「追記のみ」にはせず「未判定」のまま残し、次に挿入したときにまた判定する (挿入の後にアプリへ渡したキーで
    文書が変わったのか、読めない文書なのかを区別できないため)
  - `OnSetFocus` で未判定に戻すのは文書書き込み入力と同じ
- 未判定の文書は、追記のみの文書と同じく安全側に扱う (Enter の送り直しなど。下記)
- 採用済み文字列の記憶 (docs/design/adopted-reconversion.md) は、未判定の文書でも記憶する。
  使う時点で「読める」と判定されていて、照合で一致したものだけを使う (今と同じ)。追記のみの文書では記憶しない

### キーの意味 (パネル保持入力、IME オン時)

文書書き込み入力 (docs/design/direct-input.md の表) と違うところだけを書く。書かないキーは文書書き込み入力と同じ。

| キー | 状態 | 挙動 |
|---|---|---|
| 英字・記号・数字・テンキー | run なし / run 中 | 読みに加えて入力行を描き直す。文書には書かない (数字の素通し `digits=half` の run なしの扱いは同じ) |
| Backspace / Ctrl+H | run 中 (候補選択中を除く) | 常に食べて、読みの末尾 (未完成のローマ字があればそれ) を削る。空になれば run を終える (文書には触れない)。次の Backspace はアプリへ渡る |
| Esc | run 中 (バー選択中・候補選択中を除く) | run を捨てる。文書には何も入らない |
| Esc | バー選択中 | 選択を解除する (同じ) |
| Space | run 中 | 読み (未完成のローマ字を含む) + スペースを挿入して run を終える |
| Space | バー選択中 | 選択中の候補 + スペースを挿入して run を終える |
| 確定キー (無変換) | run 中 (バー未選択) | 見えているとおりの読み (未完成のローマ字を含む) を挿入して run を終える |
| 確定キー | バー選択中 | 選択中の候補を挿入する。先頭文節の候補は、残りのかなを入力行に残して run を続ける |
| 印字キー | バー選択中 | 選択中の候補を挿入し、その打鍵から続ける |
| Enter / Ctrl+M | run 中 / バー選択中 | 読み (バー選択中は選択中の候補) を挿入して run を終えてから、アプリへ渡す。読めると判定されていない文書では食べて、挿入の後に送り直す |
| 矢印・Tab (バーなし)・Home/End/Delete・PgUp/PgDn・Ctrl/Alt 併用 | run 中 | 読みを挿入して run を終えてから、アプリへ渡す。読めると判定されていない文書では食べて、挿入の後に送り直す (Alt 併用は未決事項) |
| 変換キー・F4〜F10 | run 中 | 消す文字列が無いので、そのまま空の composition を張って候補選択に入る (下記) |

- 後続語の予測 (docs/design/next-word-prediction.md) は、挿入の後に同じ条件で出す。予測の採用は今も挿入なので変わらない
- モードレス入力 (docs/design/modeless.md) の英字切替・Backspace による判定の巻き戻しは、読みと入力行が
  変わるだけで、文書の書き換え (`RewriteAppendRun`) は要らない
- run を終えるときのモードレスの判定 (ルール3 など) を適用するかどうかは、文書書き込み入力のそれぞれのキーと同じにする

### 送り直し

- 挿入は、CUAS 経由のアプリ (WezTerm など) では後から IME メッセージで届くため、食べずに渡すとキーが先に処理される。
  読めると判定されていない文書 (追記のみ・未判定) で、run を終えて挿入してからアプリへ渡すキーは、すべて食べて
  挿入の後に `SendInput` で送り直す (今の `EnterNeedsResend` / `CommitAndResendEnter` の仕組みを、
  Enter 以外の素通しキーにも広げる)
- 読める文書では食べずに、`OnTestKeyDown` / `OnKeyDown` の中で挿入してから渡す (Enter と同じ)

### 変換 (候補選択)

候補選択中は、今と同じく composition を使う。

- run 中の変換キー・F4〜F10: 文書に run の文字列が無いので、消さずにキャレット位置へ空の composition を張って
  候補選択に入る (今の `BeginAppendConversion` の、文書にまだ何も入っていないときの経路)。擬似 Backspace は使わない
- composition を張れないときは変換できず、run はパネルに残って続く
- 確定 (Enter・候補番号・確定キー・印字キーなど) は composition の確定で文書に入る (今と同じ)
- 変換の取消 (Esc・Backspace・Tab) で run に戻るとき (降格) は、composition を空の文字列で終え、読みを入力行に戻す。
  文書には何も残らない
- 変換の範囲の伸縮 (docs/design/conversion-range.md) は、文書の分類によらず、追記のみの文書と同じく composition の
  中だけで行う。縮めて外したかなは composition の先頭に残し、広げられるのは外したかなを戻すところまで
  (run より前の文書の文字列へは広げない。外したかなを文書に書かないため)
- 候補選択中にアプリが composition を終えたとき (`OnCompositionTerminated`) は、今と同じく run を捨てる

### run なしの変換・再変換

- run なしの変換キー・F6〜F10 の対象 (選択したかな、キャレット直前の採用済み文字列の記憶、キャレット直前のひらがな) は
  文書の文字列なので、今と同じ経路 (文字列を消して composition に昇格) で変換する
- 確定すると文書に入る。取消で降格するときは、文書書き込み入力と違って run の文字列を文書に戻さず、
  読みを入力行に戻したパネルの run になる (元の文字列は composition の開始時に消えている)

### 確定アンドゥ (Ctrl+Backspace)

- 直前に挿入した文字列を文書から消し、記憶した読みでパネルの run を再開する
  - 読める文書: キャレット直前が直前の挿入文字列と一致する場合だけ、置換 (空文字列への置換) で消す
  - 追記のみ・未判定の文書: 擬似 Backspace で消す。記憶を捨てる契機 (アプリへ渡したキー・run の外の Space・マウス・
    フォーカス移動) は今と同じ。マウスフックはこの記憶のためにだけ仕掛ける
- 部分採用の後に run が続いている間は働かない (今と同じ)

### run の中断

| 契機 | 挙動 |
|---|---|
| IME オフ | 読み (未完成のローマ字を含む) を挿入して run を終える。候補選択中は今と同じ |
| フォーカス移動 (`OnSetFocus`) | run を捨てる。元の文書には何も入らない |
| マウスクリック・キャレット移動 | run を続ける (上記「run の持ち方」) |

### 採らなかった案

- 候補選択中もパネル内で完結させる案 (文書に composition を出さず、入力行に変換結果と現在文節の強調を出し、
  確定で挿入する)。候補選択の表示経路を 3 つ目として足すことになり、変換の範囲の伸縮も作り直しが要る。
  候補選択中だけ文書に未確定文字列が出ても、打鍵ごとに文書が変わる問題には当たらないため、composition を流用する
- 読める文書で変換の範囲を run より前の文書の文字列へ広げる案。外したかなを文書に書く形では、取消で外したかなが
  文書に残り「採用・確定まで文書に書かない」に反する。外したかなを composition に残したまま左の文書の文字を取り込む形は、
  採用済み文字列の記憶をかなに書き直す処理まで作り直しが要る
- フォーカス移動で元の文書へ挿入する案。フォーカスを失った文書への edit session は非同期になり、失敗や
  挿入位置のずれが起こりうる
- run を終えて渡すキー・Esc で読みを捨てる案 (Esc は採用)。矢印などで入力が消えると、気づかずに入力を失いやすい

## 実装手順

各手順の後にビルドが通り、`input_buffer document` の動作が変わっていないことを確かめる。

1. config と設定ツールに `input_buffer` を足す。run を始めるときに方式を決めて持つ
2. 打鍵・Backspace・Esc と入力行の表示 (文書に書かない run)。モードレスの英字切替を含む
3. 挿入による run の終え方: Space・確定キー・Enter・素通しキー・IME オフ。フォーカス移動での破棄。送り直しの拡張
4. 文書の分類 (直前の挿入文字列の読み戻し) と、採用済み文字列の記憶の扱い
5. 候補バーの採用 (全体変換・予測候補・先頭文節・英字候補) を挿入にする
6. 変換: 空の composition での候補選択と、取消時の降格。run なしの変換の降格先をパネルの run にする
7. 確定アンドゥ
8. ドキュメントの更新 (README.md、suggest-panel.md、panel-theme.md、direct-input.md)

## 検証方法

ビルド: `cmake --build tsf/build --config Debug` と `cd engine && cargo build`。
反映は `scripts\dev-deploy.ps1 -Dll`、テスト後は `-Restore` で戻す。テストは新しく起動したアプリで行う
(メモ帳は `taskkill /IM Notepad.exe /F` してから開く)。config.tsv は `QUICKLIME_CONFIG_FILE` で隔離し、
`debug_log` を設定してログで文書の分類・挿入・送り直しを確かめる。
