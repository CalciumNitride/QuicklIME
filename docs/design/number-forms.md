# 数字表記変換

## 背景と目的

数字で打った数 (`1234`) は、辞書の数字が 1 桁単位のため、経路上で 1 語にまとめて打ったとおりの表記で出す
(engine/src/convert.rs `merge_digit_runs`)。漢数字・桁区切り・全角などの別の書き方は候補に無く、
`千二百三十四` や `1,234` にするには手で打ち直す必要がある。

本書の目的は、数字で打った数に別の書き方の候補を足すことである。かなで読んだ数
(`にせんにじゅうろく` → 2026) の変換は本書の対象外とする。

## 決定事項

### A. 対象の数

- 読みの中の、数字 (半角 `0`〜`9`・全角 `０`〜`９`) だけが続く部分。経路上で 1 語にまとめた数字の語
  (`merge_digit_runs` の結果) のうち、区切り記号を含まないもの
- 区切り記号を含む数字の語 (`0.5`・`1,000`・`12:30`・`2026-09-08`) は対象外。小数・時刻・日付などで、
  書き換えの規則が数とは違うため
- 桁数は 1〜16 桁 (9999兆9999億9999万9999 まで)。17 桁以上は対象外

### B. 書き方

数ごとに次の書き方を作る。打ったとおりの表記と同じになるもの・ほかの書き方と同じになるものは作らない。

| 書き方 | 例 (`1234`) | 例 (`120005`) | 条件 |
|---|---|---|---|
| 位取りの漢数字 | 千二百三十四 | 十二万五 | 先頭が `0` でない (1 桁の `0` は 〇) |
| 並べた漢数字 | 一二三四 | 一二〇〇〇五 | 2 桁以上 |
| 桁区切り | 1,234 | 120,005 | 4 桁以上、先頭が `0` でない |
| 万の単位まじり | (作らない) | 12万5 | 5 桁以上、先頭が `0` でない |
| 全角 / 半角 | １２３４ | １２０００５ | 打ったのが半角なら全角、全角なら半角 |

- 位取りの漢数字: 十・百・千の前の「一」は書かない (千二百、十五)。万・億・兆の前は書く (一万、一億)。
  値が 0 の位は書かない (千五、一万五)
- 並べた漢数字: 0 は 〇
- 桁区切り・万の単位まじりは、打ったのが半角なら半角数字、全角なら全角数字で書く (区切りの `,` は
  半角のとき `,`、全角のとき `，`)
- 万の単位まじり: 万・億・兆の単位で区切り、値が 0 の単位は書かない (`1200000000` → 12億、
  `100005000` → 1億5000)

### C. 候補の並び

- 文節の候補 (CONVSEG・CONVCTX。`segment_from_group`): 数字で始まる文節で、先頭の数字の語が A の対象のとき、
  数字の部分を B の書き方にし、続く部分は文節の先頭候補の表記のままにした候補を足す
  (`1234えん` → `千二百三十四円`・`一二三四円`・`1,234円`・`１２３４円`)。位置は、数字に続く部分を入れ替えた
  候補 (今ある `10じ` → `10時` の規則) の後ろ、単漢字の前。B の表の順に並べる
- 入力全体の候補 (CONVNBEST): N-best の後ろ (読み全体の辞書完全一致の前) に、1-best の中の A の対象の
  数をすべて同じ書き方にした候補を、書き方ごとに 1 件ずつ足す (`1234えんと5600えん` →
  `千二百三十四円と五千六百円` …)。文節は 1-best の文節のまま、表記だけを置き換える
- LLM の並べ替えでは位置を動かさない (protected)。数字の読みに対する漢数字の尤度で、打ったとおりの数より
  上に来るのを避けるため
- 学習は今どおり (文節ごとの読み → 表記)。数字の書き方は打った数字で決まり、時間で古くならないため

### D. 設定

- 新しい設定は設けない。候補は打ったとおりの数より後ろに出るだけで、文書を自動では書き換えないため

## 実装手順

各手順の後にビルドとテストが通り、既存の動作が壊れていないことを確かめる。

1. engine: number.rs。`cargo test` に B の表の例と、`0`・`7`・`10`・`15`・`100`・`1000`・`10000`・
   `100005000`・`007`・全角の `１２３４`・16 桁・17 桁 (対象外) のテスト
2. engine: `segment_from_group` の候補。`1234えん` の文節の候補に `千二百三十四円` などが今の候補の後ろに
   出るテスト、`0.5` では出ないテスト
3. engine: `convert_nbest` の候補と protected。`1234えんと5600えん` のテスト
4. ドキュメントの更新

## 検証方法

### 自動テスト

- `cargo test` (engine): 手順 1〜3 のテスト

### 実機テスト

開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、メモ帳で行う。`QUICKLIME_CONFIG_FILE`・
`QUICKLIME_LEARN_FILE` を隔離する。エンジンを release・debug の両方でビルドし直し、古いエンジンプロセスが
残っていないことを確かめる。

| # | 操作 | 期待 |
|---|---|---|
| 1 | `1234` → 変換キー | 先頭は `1234`。候補に `千二百三十四`・`一二三四`・`1,234`・`１２３４` |
| 2 | `120005` → 変換キー | 候補に `十二万五`・`12万5`・`120,005` |
| 3 | `1234えん` の候補バー | 全体変換の先頭は `1234円`。候補に `千二百三十四円` など |
| 4 | 3 で `1,234円` を選んで確定 → 同じ入力 | 学習により `1,234円` が先頭 |
| 5 | `0.5` / `12:30` → 変換キー | 数字の書き方の候補は出ない |
| 6 | `segment_ui 1` で `1234えんです` → 変換キー | 先頭文節の候補に `千二百三十四円` など |
| 7 | `llm 1` で 1 | 並べ替えの後も数字の書き方の候補が打ったとおりの数より上に来ない |

## 未決事項

- かなで読んだ数 (`にせんにじゅうろく` → 2026・二千二十六) は本書の対象外。必要になったら別の設計にする
- 大字 (壱・弐・参) と、`1千2百` のような千・百の単位まじりは作らない
