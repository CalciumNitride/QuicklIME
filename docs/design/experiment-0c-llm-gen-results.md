# 実験 0c: LLM による候補の生成の計測結果

仕様は [experiment-0c-llm-gen.md](experiment-0c-llm-gen.md)。計測には engine/examples/llm_gen_eval.rs を使った。
数値はすべて下記の環境で実際に測った値。採否の判断はしていない。

## 計測方法

| 組み合わせ | exe の feature | モデル | スレッド |
|---|---|---|---|
| CPU | `llm-bench` | zenz-v3.2-xsmall (Q5_K_M) | 4 |
| Vulkan | `llm-bench-vulkan` | zenz-v3.2-small (Q5_K_M)、全層を GPU (n_gpu_layers 999) | 4 (llama.cpp の CPU 側の処理) |

- テストセット: AJIMEE-Bench (`references/AJIMEE-Bench/ajimee_cases.tsv`、197 件) と llm_cases.tsv (50 件。
  参考)。左文脈あり、前文脈なし、学習・ユーザ辞書は空
- 統計変換: example の中で辞書を読み込み、`convert_nbest_rerank` を補正あり (設定の既定。打鍵が無いので
  かなを戻した近似) で呼ぶ。nbest_eval が起動するエンジンの RERANK と同じ並び
- 並べ替え: 製品 (quicklime-llm の SCORE とエンジンの規則) と同じ。左文脈は `preprocess_context` を通し、
  上位 10 件のうち保護しない候補を 1 バッチで採点する。コンテキストは製品と同じ 512 トークンで、プロンプトと
  候補が収まらない件 (AJIMEE-Bench で 17 件) は製品と同じく並べ替えない。読みが 9 文字未満の件は並べ替えない
- 生成と照合のコンテキストは 1024 トークン (並べ替えとは別のコンテキスト)。AJIMEE-Bench の最長の読みは
  117 かなで、生成の上限は 242 トークンになり、beam の 3 本の仮説が伸びると 512 に収まらないため
- A 貪欲法: llm_bench の生成と同じ (毎トークン argmax、EOG トークンか上限で止める)
- A beam: 幅 3。各仮説の次のトークンを対数確率の上位 3 個に広げ、終わった仮説と合わせて累積の対数確率の
  上位 3 本を残す。全仮説が終わるか上限で止め、上限まで終わらなかった仮説は捨てる。KV キャッシュは
  仮説ごとのシーケンスに親を複製し、新しいトークンを 1 回の decode で足す
- A の後処理: ルビの除去 (括弧 `(` `（` から次の `)` `）` までの中身が空でなくかなだけ)、長さ (出力の文字数 >
  読みの文字数で捨てる)、繰り返し (2 文字以上の並びが 3 回続く出力を捨てる。読み自体に同じ形の繰り返しが
  あれば捨てない)
- C: 仕様の手順のとおり。最初のドラフトは `convert_nbest_rerank` の通常の最良経路。制約を更新したら、
  最初の N-best の上位 10 件 (補正の候補を除く) から、いま評価したドラフトと違い制約を満たす最上位の候補を
  探し、無ければ制約つきの Viterbi を解く。評価の上限は 10 回
  - zenz は出力の終わりに `</s>` (トークン ID 3) を出す。語彙の EOS (`<s>`、ID 2) とは別の EOG トークン。
    C の照合では、ドラフトの末尾の位置で argmax が EOG トークンのどれかなら合格とした (生成の停止と同じ判定)。
    語彙の EOS (ID 2) との一致で判定すると、どのドラフトも合格しなかった (llm_cases.tsv で確認)
- 合わせた並び: 方式の出力 (A beam は後処理で捨てなかったもの最大 3 件、A 貪欲法と C は 1 件) を先頭に置き、
  並べ替えの結果 (全候補) を続け、同じ表記は先勝ちで除く
- 速さ: 件ごとに 1 回。計測の前に、先頭 3 件と最長の読みの件を全方式で 1 回ずつ流した。並べ替えの時間は
  採点と並べ替え、生成・照合の時間はプロンプトの decode から結果まで (C は制約つきの Viterbi を含む)。
  統計変換 (N-best) の時間は含めない。合計は並べ替えと生成・照合の和
- 検算: 全件で、空の制約つきの Viterbi の経路が統計変換の最良経路と同じことを確かめた (両テストセット・
  両組み合わせとも違った件は 0)

## 結果

この節と「判断の目安との照合」の数値は、並べ替えの尤度の終わりの項が語彙の EOS (`<s>`、ID 2) だったときのもの (今の製品は `</s>`。その条件の値は「追加の計測: A と C の組み合わせ」)。

精度の数値 (件ごとの表を含む) は、同じ組み合わせを 2 回実行して全件同じだった。速さは実行ごとに変わるので
2 回分を載せる。

### A の副作用 (AJIMEE-Bench)

貪欲法は件数 (197)、beam は出力 (仮説) の数 (591)。「読みから外れた」は後処理で捨てなかった出力のうち、
完全一致の制約つきの Viterbi で同じ表記の経路が無いもの。「1 位に来た」は、読みから外れて正解でない出力が
合わせた並びの 1 位になった件数 (beam は 1 件目)。

| 項目 | CPU 貪欲法 | CPU beam | Vulkan 貪欲法 | Vulkan beam |
|---|---|---|---|---|
| 上限で止まった (捨てた) | 1 | 7 | 0 | 3 |
| ルビを除去した | 0 | 0 | 0 | 0 |
| 長さで捨てた | 3 | 9 | 1 | 3 |
| 繰り返しで捨てた | 0 | 0 | 0 | 0 |
| 読みから外れた | 21 | 92 | 15 | 83 |
| うち正解 | 6 | 12 | 7 | 12 |
| 読みから外れて正解でない出力が 1 位に来た | 15 | 13 | 8 | 7 |
| 読みの数字・英字が残っていない | 0 | 0 | 0 | 0 |
| 左文脈のエコー | 0 | 0 | 0 | 0 |

### 件ごとの表から目で見て分かったこと

AJIMEE-Bench の件番号はテストセットの行の順。Vulkan の結果から。

- 読みから外れた出力で正解だったもの (貪欲法 7 件) は、すべて数の書き方の件だった (正解の候補に漢数字や
  算用数字・単位の表記があり、「十六番街」「45km」「1991年」「50cm」のように数を書いた出力)。
  辞書のラティスの経路では数の読みからこれらの表記を作れない
- 読みから外れて正解でない貪欲法の出力 8 件は、辞書に無い語や読みと合わない語 (#18「寺殿」、#167「再左腕」、
  #194「でも緑」、#67「弁し記」「責任務能力者」)、カタカナの混在 (#51「朝ガケ」)、括弧の重複 (#77「（（」)、
  英数字の書き換え (#160「ＭＩ６」→「MISIX」)、同音の語の誤りに数の書き方が重なったもの (#186、正解「弱冠」に
  対し「若干」) だった
- beam の読みから外れた出力には、正しい表記の後ろにプロンプトの区切り文字 (私用領域の U+EE08・U+EE00 など) が
  付いて EOS で終わったものがある (llm_cases.tsv の「記録を更新した[U+EE08]」「本を読む[U+EE00]」など)。
  後処理は区切り文字を除かないので、読みから外れた出力として数えた。読みから外れた beam の出力のうち区切り文字を
  含むものは、CPU で llm_cases.tsv 11 件中 9 件・AJIMEE-Bench 92 件中 11 件、Vulkan で llm_cases.tsv 5 件中 0 件・
  AJIMEE-Bench 83 件中 2 件
- C の「経路なし」は、LLM の予測がラティスに無い表記 (数の書き方、区切り文字の私用領域の文字、辞書に無い語)
  に向かったときに起きた。打ち切ると最後に評価したドラフトが結果になるので、統計変換の 1 位より悪い表記に
  なることがある (#194 は 1 位の「脆く」が正解だったが、C は制約で選び直した「もろく」で打ち切り。#18 は
  1 位が正解で、C は「寺殿下」で打ち切り)
- 並べ替えだけで当たって合わせた並びで外れた件 (失) には、3 方式とも同じ誤りに向かったものがある
  (#115「裸一貫」→「は高一貫」、#136「大政翼賛会」→「大成翼三会」、#171「拡散板」→「各3番」)
- C の評価が 4 回以上の件では、統計変換の 1 位の 1 語を直して合格したもの (#70「府中車」→「不忠者」、
  #133「起動」→「軌道」、#193「保健化」→「保健科」) が見られた

## 判断の目安との照合

並べ替えの尤度の終わりの項が語彙の EOS (`<s>`、ID 2) だったときの数値。

仕様の「判断の目安」と照らした事実だけを記す。

- 精度: AJIMEE-Bench の合わせた並びの 1 位は、並べ替えだけの 131 (66%、Vulkan) に対し、A 貪欲法 169・A beam 170・
  C 163。CPU では並べ替えだけ 121 に対し 137・139・134。llm_cases.tsv の 1 位は、並べ替えだけに対し CPU で
  +14〜+15、Vulkan で +20 で、下がった方式は無かった
- 速さ: 9 文字以上の読みの合計の p95 (9〜19 文字 / 20 文字以上、2 回の実行の大きい方)
  - Vulkan: A 貪欲法 39.3 / 73.1、A beam 67.9 / 127.3、C 37.0 / 38.8。いずれも 300 ms 以下。ただし最大値は
    1 回目の C が 2417.8、2 回目の A 貪欲法・A beam が 1000 ms を超えた
  - CPU: A 貪欲法 66.1 / 151.8、A beam 97.4 / 196.0、C 68.9 / 161.5。いずれも 1000 ms 以下。最大値は 2 回目の
    A beam が 1268.2
- 副作用 (A): 読みから外れて正解でない出力が 1 位に来た件は、Vulkan で貪欲法 8・beam 7 (得はどちらも 45)、
  CPU で貪欲法 15・beam 13 (得はどちらも 31)

## 追加の計測: A と C の組み合わせ

仕様は [experiment-0c-llm-gen.md](experiment-0c-llm-gen.md) の「追加の計測: A と C の組み合わせ」。Vulkan + small だけで測った。

- 方式 A+C: A 貪欲法の出力を使い、後処理で捨てたときと読みから外れたとき (完全一致の制約つきの Viterbi で同じ
  表記の経路が無い) は C の結果に代える。計測では全件で A 貪欲法と C を両方求め、A+C の時間は A 貪欲法の時間に、
  代えた件だけ C の時間を足した
- 並べ替えの尤度の終わりの項は `</s>` (ID 3。今の製品と同じ)。並べ替えだけ・A 貪欲法・A beam・C もこの条件で
  測り直した
- 上記以外の環境と計測方法は前の節と同じ。ソースはコミット 75f0164 に A+C を足したもの。計測中もユーザの常用
  エンジンと quicklime-llm-vulkan.exe が動いていた
- AJIMEE-Bench は 2 回実行し、精度の数値 (件ごとの表・C の評価の回数・A の副作用・C に代えた件を含む) は全件
  同じだった。速さは 2 回分を載せる。llm_cases.tsv は 1 回
- 実行は「再現手順」の Vulkan の 2 行と同じ (`--methods` の既定は a+c を含む全方式)

### 件ごとの表から目で見て分かったこと

AJIMEE-Bench の件番号はテストセットの行の順。

- A 貪欲法の出力が正解で C に代えて外れた 6 件 (#12・#37・#99・#101・#126・#130) は、いずれも数の書き方の件
  (「十六番街」「45km」「1991年」「50cm」「10時間」「2005年9月26日」) だった。C の結果は数の読みを辞書の語で
  埋めた表記 (「十六番外」「4重5km」「船級百級中1年」「5重センチメートル」「従事感」「2戦5年9月に十六日」) になった
- このうち 5 件は並べ替えだけで外れていた件で、A 貪欲法の得 36 と A+C の得 31 の差になっている。#101 は並べ替え
  だけで当たっていた件で、A+C では 2 位になり失に入った
- C だけが正解だった #77 は、A 貪欲法の出力に括弧の重複 (「（（」) があり読みから外れた件
- どちらも外れの 8 件のうち、#18 と #194 は並べ替えだけで当たっていた件で、A+C でも失のまま (C は「寺殿下」
  「もろく」で打ち切り)。#160 は A が「MISIX」、C が「エムアイシックス」、#186 は A が「若干13歳」、C が「若干中3歳」だった
- A+C の失 8 件は、C に代えた件が 3 件 (#18・#101・#194) と、A 貪欲法の出力が読みの経路にあって代えなかった件が
  5 件 (#26・#115・#136・#152・#171)。A 貪欲法の失 8 件との違いは、#77 が失でなくなり #101 が失に加わったこと

## 再現手順

### ビルド

CPU (実験 0b の llm_bench と同じ環境変数):

```
call "<VS>\VC\Auxiliary\Build\vcvars64.bat"
set LIBCLANG_PATH=C:\Program Files\LLVM\bin
set PATH=<VS>\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin;<VS>\Common7\IDE\CommonExtensions\Microsoft\CMake\Ninja;%PATH%
cd /d D:\project\QuicklIME\engine
cargo build --release --example llm_gen_eval --features llm-bench
```

Vulkan (長いパスを避けるため subst したドライブを target ディレクトリにする):

```
call "<VS>\VC\Auxiliary\Build\vcvars64.bat"
set LIBCLANG_PATH=C:\Program Files\LLVM\bin
set VULKAN_SDK=C:\VulkanSDK\1.4.363.0
set PATH=%VULKAN_SDK%\Bin;<VS>\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin;<VS>\Common7\IDE\CommonExtensions\Microsoft\CMake\Ninja;%PATH%
set CMAKE_GENERATOR=Ninja
mkdir D:\project\QuicklIME\engine\target\x
subst Q: D:\project\QuicklIME\engine\target\x
cd /d D:\project\QuicklIME\engine
cargo build --release --example llm_gen_eval --features llm-bench-vulkan --target-dir Q:\
subst Q: /d
```
