# 変換対象の範囲 (キャレット直前のかなの変換と範囲の伸縮)

## 背景と目的

変換キーの対象は run (IME が覚えている、自分が入れた文字列とその読み) に限られている。
run が終わった後 (Space・Enter・確定キーで終えた後、キャレットを動かした後) に残ったかなは、
選択してから変換キーを押す (後置再変換) しか変換する方法が無い。また、変換の範囲は run 全体で
固定されており、「今日|はいしゃに」のように範囲の先頭がずれていても直せない
(文節 UI `segment_ui 1` の文節伸縮を除く)。

ひらがなIME (Esrille) は run を持たず、変換キーを押すたびにキャレット直前の文書の文字列から
対象を決める。確定後・キャレット移動後でも同じ操作で変換でき、範囲は読みの先頭側の伸縮で直す。
これを QuicklIME に取り入れ、次の2点を実現する。

- run が無いときの変換キーで、キャレット直前のかなを文書から読んで変換する
- 候補選択中の ←→ で、変換の範囲の先頭を動かす (右端はキャレットに固定)

確定後に漢字を直す操作は対象外とする。読める文書では、候補の採用は文書の置き換えで行うため、
アプリの Undo (Ctrl+Z) で採用前のかなに戻せる (アプリによっては2回: 空 → かな)。
戻した後は本書の変換キーで変換し直せる。追記のみの文書では、今の確定アンドゥを使う。

範囲より後ろの文字列 (右の文脈) は変換に使わない。文の途中で変換したときに同音異義語の
判別に効くのは主に LLM だが、zenz のプロンプトの形式に右の文脈が無く、効果を実験で
確かめる必要があるため、LLM の右文脈の利用 (docs/roadmap.md) として別に扱う。

## 決定事項

### 変換の対象

| 状態 | 変換キー・F6〜F10 の対象 |
|---|---|
| run 中 | run 全体 (今どおり) |
| run なし・選択あり | 選択範囲 (今の後置再変換。ひらがな・カタカナ・ー のみ、127 文字まで) |
| run なし・選択なし・読める文書 | キャレット直前のかな (下記「範囲の初期値」) |
| run なし・追記のみの文書 / 未判定の文書 | 対象なし (打鍵をアプリへ渡す) |

- 選択なしの対象は、読める文書 (`AppendDocument::Readable`) に限る。追記のみの文書は
  キャレット直前を読めず、未判定の文書は読めるかどうかが分からないため
- 対象のかなは、今の後置再変換と同じく run として作る (読みはひらがなに正規化し、
  打鍵列は元の文字)。以後の候補選択・確定・学習は run の変換と同じ経路を通る
- 対象が無いとき (キャレット直前がかなでない、読めない) は、今どおり打鍵をアプリへ渡す

### 範囲の初期値

- キャレット直前から左へ、ひらがなとー が続くところまで。上限は 127 文字
  (今の後置再変換の上限 `kMaxReconvertLength` と同じ)
- カタカナ・漢字・英数字・記号・空白・改行で止める。カタカナは意図して入れたものが
  多いため区切りにする (カタカナを含めたいときは選択して変換する)
- 範囲の先頭のずれ (「今日|はいしゃに」の「は」を含むなど) は、N-best の候補
  (「は医者に」) と、下記の範囲の伸縮で直す

### 前の文脈

- エンジンの前文脈 (CONVCTX・CONVNBEST の文脈読み・文脈表記) は、範囲の直前の文書の
  文字列が直前の確定の表記 (`contextSurface_`) で終わるときだけ、その確定の文脈を使う。
  それ以外は前文脈なしにする (文書の漢字の読みは分からないため)
- 範囲を縮めて外したかなは、読み = 表記のかなとして前文脈にする (下記「範囲の伸縮」)
- LLM の左文脈は、範囲の先頭より前の同じ行の文字列を文書から読む (今の run 開始時と同じ)

### 範囲の伸縮 (候補選択中の ←→)

- 範囲の右端はキャレットに固定し、左端だけを動かす。← で左へ1文字広げ、→ で1文字縮める
  (左端が矢印の向きに動く)
- 縮めて外したかなは、かなのまま文書に残る。run から外れ、確定しても学習しない
- 縮めて外した文字は、文字の種類によらず ← で戻せる。戻すときは外したときの打鍵も戻る
  (下記「外した文字の打鍵の復元」)
- 外した文字より左へ広げられるのは、範囲の先頭の直前の文字がひらがなかー のときで、
  範囲が 127 文字未満のときに限る。読める文書では run の先頭より左にも広げられる
  (文書から読んだかなは打鍵を持たず、打鍵列はかなの文字そのものにする)。追記のみの文書では
  外した文字を戻すところまで (下記「追記のみの文書での範囲の伸縮」)
- 縮めるのは範囲が2文字以上のときに限る (末尾の未完成のローマ字 `n` は文書に入っていないので数えない)
- 広げられない・縮められないときは何もしない (打鍵は食べる)
- run の変換 (run 中の変換キー)・選択からの後置再変換・キャレット直前のかなの変換の
  いずれでも同じ操作にする
- 範囲を変えたら、その範囲の読みで変換をやり直し、候補は先頭に戻る。F6〜F10 で文字種を
  変えている間に範囲を変えたときは、同じ文字種変換をやり直す (F7 → ←→ でカタカナの範囲を
  調整できる)。F4・F5 の特殊変換中は通常変換に戻す
- 英字を含む run (英単語の打鍵・モードレスの英字区間・末尾の未完成のローマ字を含む run) の
  変換キーでの変換では範囲の伸縮をしない (打鍵したローマ字の候補 apple / Apple / APPLE が、
  範囲を変えると成り立たないため)。←→ は今どおり確定してアプリへ渡す
- F6〜F10 の文字種変換中は、英字を含む run でも伸縮する。run はかな1文字ごとに打鍵を
  持つので、先頭のかなを外しても残りを打鍵どおりに変換し直せる。モードレスの判定から
  外れた英単語を手で直すのに使う (`kyouhawant` → F10 → → を4回 → `きょうは` + `want`)。
  かなのまとまり (`きょ` = `kyo` など) の途中で切ると、残った側の打鍵は欠ける
  (まとまりの境目まで縮めるか、← で戻せば正しく戻る)

### 外した文字の打鍵の復元

- → で縮めるたびに、縮める直前の読みの状態 (`RomajiComposer` 全体。かな・打鍵・未完成の
  ローマ字・英字区間の開始位置) を積む。← で広げるとき、積んだ状態があれば最後に積んだものを
  取り出して読みの状態をそれに戻す。積んだ状態が無ければ文書のかなを足す (上記の条件)
- 打鍵の列だけを覚える案は採らない。英字区間の開始位置も合わせて戻す必要があり、
  状態ごと戻すほうが取りこぼしが無いため
- 追記のみの文書で変換を取り消すとき (外したかなを範囲に戻す) は、最初に積んだ状態に戻す
- 積んだ状態は、範囲の追跡を始めるときと終えるときに空にする。範囲は 127 文字までなので、
  積む数も 127 まで
- 文節 UI (`segment_ui 1`) では範囲の伸縮をしない。←→ は今どおり文節の移動、
  Shift+←→ は文節の伸縮
- 範囲の伸縮は、読める文書 (`AppendDocument::Readable`) と追記のみの文書
  (`AppendDocument::AppendOnly`) で行う (追記のみの文書の扱いは下記)。未判定の文書では
  ←→ は今どおり確定してアプリへ渡す
- 候補選択中の ←→ が「確定してアプリへ渡す」でなくなる。確定してキャレットを動かすには、
  確定キーか Enter を押してから動かす

### 範囲の伸縮の実現方法

範囲を変えるたびに、今の変換を取り消してかなの run に戻し、新しい範囲で run を作り直してから
変換をやり直す。

- 採用: 取り消し (`CancelConversion`)・降格 (`DemoteIfLeftConversion`)・昇格 (`PromoteRun`)・
  変換開始 (`StartConversion` / `ApplyFunctionKey`) の既存の経路を組み合わせる
- 採らなかった案: `ITfComposition::ShiftStart` で composition の先頭を動かす。広げるときに
  確定済みの文字列を composition に取り込むことになり、Discord の入力欄で確定時に元のかなが
  残る問題 (docs/design/direct-input.md「昇格」) と同じことが起きうるため

### 追記のみの文書での範囲の伸縮

追記のみの文書 (WezTerm などの CUAS 経由のアプリ) の候補選択は、擬似 Backspace で run の
文字列を消してから張った composition で行っている。ここでは範囲を変えても composition を
張り直さず、外したかなを composition の先頭に残す。

- composition の文字列は `外したかな + 範囲の変換結果` にする。外したかなは入力中の表示属性
  (下線) で、強調 (現在文節の表示属性) は範囲の変換結果だけにかける
- 伸縮は composition の表示の更新だけで行い、擬似 Backspace・目印の打鍵は使わない。
  文書は確定まで変わらない
- 広げられるのは run の先頭まで (外したかなを戻すだけ)。run より前は文書を読めないので
  広げない。127 文字の上限は読める文書と同じ
- 確定 (Enter・確定キー・印字キー・Home/End など、候補選択を確定するすべての経路) では
  `外したかな + 選んだ候補` を確定する。学習は範囲だけで、外したかなは学習しない
  (読める文書と同じ)。範囲の変換の前文脈は、読める文書と同じく外したかな (読み = 表記) にする
- 確定アンドゥの記憶は run 全体にする (確定文字列 = `外したかな + 選んだ候補`、読み =
  外したかな + 範囲の読み)。Ctrl+Backspace で run 全体のかなに戻る
- 変換の取消 (Esc・Backspace・Tab) では、外したかなを範囲に戻した run 全体のかなに戻す
- 候補ウィンドウの位置は今どおり composition の矩形を基準にする (外したかながあると、
  範囲の先頭ではなく composition の先頭の下に出る)
- 読める文書と見た目が違うのは、外したかなに下線が付く点だけとする
- 採らなかった案: 外したかなを確定してアプリへ送り、残りで composition を張り直す
  (広げるときは擬似 Backspace で消して戻す)。広げるたびに擬似 Backspace と目印の打鍵が
  走り、その間に続けて押した ←→ (キーリピートなど) がアプリへ渡ってキャレットを動かすため。
  端末に1文字ずつ確定が届き、アプリ側の補完などが反応するおそれもある

### F6〜F10 の対象 (カタカナ変換など)

- F6〜F10 (ひらがな・カタカナ・半角カタカナ・全角英字・半角英字) を、入力なしの状態でも
  働くようにする。対象は変換キーと同じ (選択範囲、無ければキャレット直前のかな)。
  初回は対象全体を変換し、←→ で範囲を調整する
- 入力なしで対象が無いときは、打鍵をアプリへ渡す
- F4 (記号・日付変換)・F5 (ユーザ語変換) は入力なしの状態では今どおり働かせない。
  ブラウザの F5 (再読み込み) などを、キャレットがかなの直後にあるだけで奪わないため

## 実装手順

1. RomajiComposer に、確定済みかなの先頭にかなを足すメソッドを追加する (打鍵列は元の文字。
   英字区間の開始位置は足した分だけ後ろへずらす)
2. 入力なしの対象決定を1か所にまとめる: 選択があれば今の `ReadReconvertibleSelection`、
   選択が空なら (読める文書のとき) キャレット直前のかなを読む。`CanRunKeyFunc` と変換キー・
   F6〜F10 の処理の両方から使う
3. キャレット直前のかなから run を作り、昇格して変換に入る (今の `ReconvertSelectionDirect`
   と同じ流れ。選択が潰れているので `surfaceCaret_ = surface_.size()`、
   `surfaceSelectLength_ = 0`)。前文脈は「前の文脈」の規則で決める
4. F6〜F10 の働く状態に入力なしを足し、入力なしでは手順2の対象に対して `ApplyFunctionKey`
   を通す
5. 候補選択中の ←→ (`segment_ui 0`、英字を含まない run) を範囲の伸縮にする:
   変換の種類 (通常変換・F6〜F10) を覚える → 変換を取り消して降格 → run の先頭を縮める
   (`RemoveFront`、外したかなを前文脈にする) か、文書から1文字読んで先頭に足す →
   昇格 → 覚えた種類の変換をやり直す。direct の候補選択と昇格した composition の候補選択の
   両方の経路に入れる
6. 文書 (README.md・docs/design/keymap.md・docs/design/direct-input.md) を最新の仕様に合わせる
7. 手動テスト (下記)
