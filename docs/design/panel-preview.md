# 設定ツールでの入力パネルのプレビュー

## 背景と目的

設定ツールの「見た目」ページでは、入力パネルのテーマ・フォント・サイズを選べるが、選んだ結果は
保存してから実際に文字を打たないと確かめられない。テーマファイルを手で書いているときも、書き換える
たびにメモ帳などで打って確かめる必要がある。

「見た目」ページに、今選んでいるテーマ・フォント・サイズで描いた入力パネルの見本を出す。

## 決定事項

### 方式: DLL の描画をそのまま使う

- TSF の DLL (QuicklIME.dll) に、入力パネルの見本を画素の配列に描いて返す関数を足す。描画は
  `SuggestPanel` の今の描画 (Direct2D で DIB に描く layered window の方式) をそのまま使い、ウィンドウは作らない
- 設定ツールは、今有効な DLL を `LoadLibraryW` で読み、`GetProcAddress` でその関数を呼んで、返った画素を
  画像として表示する
- 採らなかった案: 設定ツール (Slint) の側でパネルの見た目を作り直す。テーマのキー (形・揃え・ゴースト・
  縦積み・種類のタグなど) が多く、C++ の描画と二重に実装するとすぐに実物とずれる

### 読み込む DLL

- `HKEY_CLASSES_ROOT\CLSID\{QuicklIME の CLSID}\InprocServer32` の既定値のパスの DLL を読む。
  開発版とインストール版のうち、後から `regsvr32` した方 (= アプリが実際に読む方) になる
- 設定ツールのプロセスには TSF が同じ DLL を読み込んでいることがあるが、同じパスなので `LoadLibraryW` は
  同じモジュールを返す。読み込んだ DLL は設定ツールの終了まで解放しない
- 次のときはプレビューの代わりに理由の文を出す (設定ツールの他の機能には影響させない)
  - CLSID が登録されていない・DLL が読めない
  - 関数が見つからない (プレビューに対応していない古い DLL)
  - 描画に失敗した

### DLL の関数

`exports.def` に足す C の関数 (名前と引数の形は実装で決めてよいが、次を満たす)。

- 入力: テーマ名 (`panel_theme` の値)、フォント名、フォントの大きさ (px)、見本の種類 (入力パネル /
  変換の候補一覧)
- 出力: 画像の幅・高さ、上から下へ並ぶ BGRA (premultiplied alpha) の画素、テーマを解決したときの
  ダーク/ライト、テーマのぼかし (`blur`) が on か
- バッファは呼び出し側が渡す。足りなければ必要な大きさを返して失敗を返す (呼び出し側はもう一度呼ぶ)
- テーマの解決は TSF 層と同じ `PanelThemeLoader` で行う (テーマフォルダ・`QUICKLIME_THEME_DIR`・組み込み・
  `capsule` への切り替えも同じ)。ダーク/ライトは今の Windows のアプリモード
- 呼ぶたびに `SuggestPanel` を作って捨てる (状態を持たない)。設定ツールの UI スレッドから呼ぶ

### 見本の内容

固定の内容で 2 つの見本を描く。

| 見本 | 入力行 | 候補 | 選択 |
|---|---|---|---|
| 入力パネル (`Show`) | `きょうは` | 今日は (変換)、京は (変換)、今日はいい天気 (予測)、教派 (変換)、kyouha (英字) | 2 番目 |
| 変換の候補一覧 (`ShowConversion`) | 変換中: 文節 `今日は` `いい` `天気`、現在の文節は 1 番目 | 今日は、京は、教派、強は、きょうは | 2 番目 |

- テーマの並べ方 (`layout`)・描き方 (`style`)・揃え (`align`)・入力行 (`input_row`) などはそのまま効く。
  入力行はテーマが `input_row setting` でも出す (見本では設定 `panel_input` を見ない)
- 位置はキャレット位置 (`Caret`) の方式で組む。キャレットの印 (テーマの `caret_marker`: 吹き出しの尻尾・
  キャレットの下の三角) は描かない
- ぼかし (`blur on`) は DWM の効果のため再現できない。見本はぼかしの無い描画で描き、設定ツールは
  見本の下に「ぼかしはプレビューでは再現されません」と出す
- 影・ゴーストのにじみの分の外側の余白も含めて返す (実物の layered window と同じ画像)

### 設定ツールの表示

- 「見た目」ページのカードの並びの下 (「オン/オフの切り替え時に…」の下) に「プレビュー」を置き、
  入力パネル・変換の候補一覧の見本を縦に並べる。それぞれに小さな見出し (「入力パネル」「変換の候補一覧」) を付ける
- 見本は文書を模した背景の上に描く。背景は DLL が返したダーク/ライトに合わせ、ライトは白 (#FFFFFF)、
  ダークは #1F1F1F とする (ゴーストのように枠の無いテーマでも見えるようにする)
- 見本は実物と同じ画素の大きさで出す (Slint のウィンドウの拡大率で割った論理サイズにする)。
  見本がプレビューの領域より広いときは、縮小せずに右側を切る
- 描き直すとき:
  - 「入力パネルのテーマ」「フォント」「サイズ」の選択を変えたとき (保存前の値で描く)
  - 設定ツールのウィンドウがフォーカスを得たとき (テーマファイルを外で書き換えた場合に読み直す)
  - ページを開いたとき (起動時)

### ドキュメント

- docs/user/theme.md と docs/user/settings.md (見た目の項) にプレビューの説明を足す
- docs/design/README.md の設定ツールの節に本書を 1 行足す

## 実装手順

1. `SuggestPanel` に、ウィンドウを作らずに描いて画素を返す経路を足す (今の `Show` / `ShowConversion` の
   表示の動作は変えない)
2. DLL の関数と見本の内容を足し、`exports.def` で公開する
3. 設定ツールに DLL の読み込みと呼び出しを足し、「見た目」ページに表示する。描き直しの契機をつなぐ
4. ドキュメント

## 検証方法

- tsf を Debug でビルドし、`scripts\dev-deploy.ps1 -Dll` で開発版に切り替えて設定ツールを起動する
- テーマフォルダは `QUICKLIME_THEME_DIR` で隔離してよい
- `cargo test` (engine) が通る

### テストケース

| # | 操作 | 期待 |
|---|---|---|
| 1 | 設定ツールの「見た目」を開く | 下に入力パネルと変換の候補一覧の見本が、今の設定のテーマで出る。メモ帳で `kyouha` を打ったときと同じ見た目 |
| 2 | 「入力パネルのテーマ」を カプセル (縦積み) → ゴースト と切り替える | 保存しなくても見本が切り替わる。ゴーストでも背景の上で文字が読める |
| 3 | 「フォント」「サイズ」を変える | 見本の文字が変わる。サイズ 40 でも見本が崩れない (広いときは右が切れる) |
| 4 | カプセル (ぼかし) を選ぶ | ぼかしの無い描画で出て、下に「ぼかしはプレビューでは再現されません」が出る |
| 5 | テーマフォルダの `mine.tsv` を選び、エディタで `accent` を書き換えて保存 → 設定ツールをクリック | 見本のアクセント色が変わる |
| 6 | Windows のアプリモードを切り替えて設定ツールに戻る | 見本の配色と背景がモードに合う |
| 7 | 表示の拡大率 150% のモニタで開く | 見本の大きさがメモ帳で出るパネルと同じに見える |
| 8 | プレビューの関数の無い古い DLL を登録した状態で開く | 見本の代わりに対応していない旨の文が出て、他の設定は普通に使える |
| 9 | `-Restore` でインストール版に戻して開く | インストール版の DLL で描く (インストール版が対応していなければ #8 と同じ) |
