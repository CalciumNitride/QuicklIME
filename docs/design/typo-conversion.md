# 変換へのタイプミス補正

## 背景と目的

今のタイプミス補正は予測 (PREDICT) の補充だけで、かな単位の編集距離 1 の前方一致を引く
(docs/design/basics.md の「タイプミス補正」)。変換 (候補バーの全体変換・変換キーの候補) では、
打ち間違えた読みはそのまま変換され、`よろしくおねぎあします` は `よろしくお願い明日` のような
崩れた候補になる。正しい候補を出すには読みを打ち直す必要がある。

本書の目的は、入力全体の候補 (CONVNBEST) に「打ち間違いを 1 打直した読み」で変換した候補を足し、
打ち直さずに選べるようにすることである。打ち間違いがはっきりしているときは先頭に出す。

## 決定事項

### A. 補正した読みの作り方 (エンジン)

- 打鍵列 (ローマ字) は TSF 層で消費され、エンジンにはかなしか届かない。プロトコルは変えず、エンジンの中で
  かなを標準のローマ字に戻し、ローマ字の上で 1 打の誤りを戻してから、かなに直す
  - かな → ローマ字の表と ローマ字 → かなの表はエンジンに持つ。TSF 層の既定のテーブル
    (tsf/src/romaji.cpp `kDefaultTable`) の主な綴りに合わせる。ユーザのローマ字テーブル
    (`romaji.tsv`) はエンジンから見えないため、標準の綴りでの近似になる
  - 綴りが複数あるかな (し・ち・つ・ふ・じ・拗音) は、訓令式 (si・ti・tu・hu・zi・sya) とヘボン式
    (shi・chi・tsu・fu・ji・sha) の両方から誤りを作る。「っ」は次の子音の重ね、「ん」は `nn`
    (母音・や行・な行・`n` の前以外では `n` も) にする
- 戻す誤りは次の 4 種類 (1 打ぶん):
  - 余分な 1 打を消す
  - 抜けた 1 打を足す。足す文字は、ローマ字の 1 打の抜けに多い字 (母音・`n`・`y`・`h`・`s`・`t`・`k`・`r`)
    と、隣の字の重ね
  - QWERTY で隣のキー (同じ段の左右と、上下の段の隣接する 2 つ) に置き換える
  - 隣り合う 2 打を入れ替える
- ローマ字 → かなで、全部がかなにならないもの・元の読みと同じものは捨てる
- 先頭のかなは変えない (予測の補正と同じ。打ち間違いが稀なうえ、誤補正の元になるため)
- 読みが 3 文字未満のときは作らない (予測の補正と同じ。短い読みは 1 打違いの別の語が多いため)
- 読みにかな以外 (英字・数字・記号) を含むときは、かなの連続の中だけで作る

### B. 補正の語を網に入れる

- 補正した読みごとに読み全体のラティスを作り直すと、毎打鍵の候補バーで遅くなる。代わりに、通常の
  ラティスに「補正の語」のノードを足し、1 回の Viterbi で求める
- 補正した読みで、変わった所を覆う辞書の語 (システム辞書・ユーザ辞書・インポート辞書) を、元の読みの
  対応する区間のノードにする。ノードの読みは打ったかなの区間、表記は辞書の語の表記
  - 補正後の読みの区間 [s, e2) が変わった所 [a, b') を含む語を拾い、打ったかなの区間
    [s, e2 − (b' − b)) に置く (b は打ったかなでの変わった所の終わり)
  - 区間ごとにコストの安い 6 語まで (同じ区間を複数の補正が覆うときも合わせて 6 語まで)
  - 単語コストに `TYPO_COST` を足す
- Viterbi は「補正の語を通っていない」「1 つ通った」の 2 つの状態で行い、補正の語を 2 つ以上通る経路は
  作らない。通常の 1-best・N-best は「通っていない」状態だけから今どおり求め、補正の語を通る経路は
  候補の並びに混ざらない
- 学習済みの文節境界の調整 (`boundary_adjust`) は補正の語にも今どおり効かせる

### C. 採る条件と並び

- 補正の最良経路 = 「1 つ通った」状態の最良の経路。通常の最良経路とのコストの差を、打ったかなの文字数で
  割った値を `Δ` とする (通常 − 補正。大きいほど補正のほうがよい)
- `Δ ≥ TYPO_SHOW` のときだけ、補正の最良経路を 1 件の候補として足す。候補は 1 件だけ
- 位置:
  - `Δ ≥ TYPO_TOP` で、かつ読み全体の学習表記が無く、1-best が学習やユーザ辞書の語を含まないとき
    (CONVNBEST の 1・2 番の候補が protected でないとき) は先頭に置く。元の 1-best は 2 番目になる
  - それ以外は 2 番目 (CONVNBEST の 1-best の直後、学習表記があればその後ろ) に置く
- 文節: 補正の最良経路を CONVNBEST の N-best と同じ規則で文節に区切る。文節の読みは打ったかなの区間
- 表記が他の候補と同じなら足さない (先勝ちで除く今の規則のまま。補正のほうが後ろなら補正の印は付かない)
- LLM の並べ替えでは位置を動かさない (protected)。並べ替えはこの候補の位置を飛ばして詰める
- `TYPO_COST`・`TYPO_SHOW`・`TYPO_TOP` の値は検証方法の計測で決める。決める基準は、打ち間違いの無い
  文で補正の候補が先頭になる件数が 0 件、2 番目に出る件数がなるべく少ないこと

### D. 対象と設定

- 対象は CONVNBEST と RERANK (候補バーの全体変換と、変換キーの候補一覧)。文節 UI (設定 `segment_ui`)
  の CONVSEG・CONVCTX と、CONVERT には入れない
- 設定 `typo_correction` (既定 1) が 0 なら作らない。予測の補正と同じ設定で切り替える。新しい設定は設けない

### E. プロトコル: 候補の種類

- CONVNBEST と RERANK の要求に、末尾の省略可能なフィールド `kinds` を足す:

```
要求:   CONVNBEST\t<文脈読み>\x1f<文脈表記>\t<かな>[\tkinds]\n
        RERANK\t<LLM 文脈>\t<文脈読み>\x1f<文脈表記>\t<かな>[\tkinds]\n
成功:   OK\t<候補1>\t<候補2>\t...\n
候補 = <読み>\x1f<表記>\x1e<読み>\x1f<表記>...[\x1d<種類>]
```

- `kinds` があるときだけ、補正の候補の末尾に `\x1d` (ASCII Group Separator) と種類 `typo` を付ける。
  ほかの候補には付けない。RERANKGET の DONE の候補は、元の RERANK の `kinds` の有無に従う
- `kinds` が無ければ補正の候補も印なしで返す
- 旧 TSF 層は `kinds` を送らないので、今の解析 (文節は読み + 表記の 2 つ組) のまま読める。旧エンジンは
  余分なフィールドを読まずに無視するので、新 TSF 層は印の無い候補として扱う

### F. 表示 (TSF 層)

- 補正の候補を、候補の種類 (`SuggestPanel::ItemKind`) の新しい種類 `Typo` にする
- 横一列 (`layout row`) の `pill` / `rounded` では、次の語の予測と同じ形で `typo` 色の縁を付ける
- 縦積み (`layout column`) の `kind_tag on` では種類のタグ「補正」を出す
- 変換キーの候補一覧は `kind_tag` を出さない仕様だが、補正の候補にだけは「補正」のタグを出す
  (縦に積むので縁では目立たず、ほかに見分ける方法が無いため)
- テーマの色のキーを 2 つ足す。既定は 2 つとも `#E58F8F` (ダーク) / `#B5484A` (ライト)
  - `typo`: 補正の候補の縁
  - `tag_typo`: 種類のタグ「補正」の文字の色

### G. 学習 (TSF 層)

- 補正の候補を採用・確定したときは、LEARN・LEARN2・LEARNSEG・LEARNWORD を送らない。打ち間違えた読みで
  学習データを汚さないため。同じ打ち間違いは次も補正の候補として出る
- 候補バーの先頭文節 (部分採用) は、補正の候補の第 1 文節からも今の規則どおり作る (`おねぎあ` → お願い)。
  補正の候補にしか無い先頭文節は補正の候補と同じく扱い、採用・確定しても学習を送らない。ほかの候補にも
  同じ第 1 文節 (読みと表記の組) があれば、ふつうの先頭文節として学習する。表示の種類は今の「文節」のまま
- 前文脈 (直前に確定した文節) と LLM の左文脈は、ほかの候補と同じく更新する
- 採用した文字列の記憶 (docs/design/adopted-reconversion.md) も、ほかの候補と同じく打ったかなを読みとして覚える

## 実装手順

各手順の後にビルドとテストが通り、既存の動作が壊れていないことを確かめる。

1. engine: typo.rs (かな ↔ ローマ字、誤りを戻した読みの生成)。`cargo test` に
   `おねぎあします` から `おねがいします` が、`ありがとう` の各誤り (`ありがtぽう` 相当など) から元の読みが
   作られるテスト、先頭のかなを変えないテスト
2. engine: 補正の語のノードと 2 状態の Viterbi。補正の語を足しても通常の 1-best・N-best が変わらないテスト
3. engine: 計測でしきい値を決める (下記「計測」)。`TYPO_COST`・`TYPO_SHOW`・`TYPO_TOP` を定数にする
4. engine: `convert_nbest` の補正の候補と位置の規則、CONVNBEST・RERANK の `kinds`。テスト
5. tsf: engine_client の `kinds` と種類の解析
6. tsf: 表示 (`ItemKind::Typo`、テーマの色、変換キーの一覧のタグ)
7. tsf: 補正の候補の採用・確定で学習を送らない
8. ドキュメントの更新

## 検証方法

### 自動テスト

- `cargo test` (engine): 手順 1・2・4 のテスト。`よろしくおねぎあします` の CONVNBEST に
  `よろしくお願いします` が種類 `typo` 付きで出る。`kinds` 無しでは印が付かない。`typo_correction 0` では出ない

### 計測

- 打ち間違いの無い文: `engine/examples/data/llm_cases.tsv` の読みと、日常の文 100 文程度を追加した
  テストセット (examples/data/ に置く。手作りまたはライセンスの明確な出典の文) で、補正の候補が出た件数・
  先頭になった件数を数える
- 打ち間違いのある文: 上の文の読みに、A の 4 種類の誤りを 1 打ずつ入れた読みを機械的に作り、補正の候補が
  出て正しい文になった割合・先頭になった割合を数える
- 両方を `engine/examples/` の計測用 example (`nbest_eval` への追加か新規) で出し、結果の表を
  本書の「計測の結果」に書く。応答時間 (中央値・最大) も補正なしと比べる

### 実機テスト

開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、メモ帳で行う。`QUICKLIME_CONFIG_FILE`・
`QUICKLIME_LEARN_FILE` を隔離し、`candidate_bar 1`・`debug_log` を設定する。エンジンを release・debug の
両方でビルドし直し、古いエンジンプロセスが残っていないことを確かめる。

## 未決事項

- 文節 UI (CONVSEG・CONVCTX) の文節ごとの補正は本書の対象外。必要になったら別の設計にする
- かな入力 (ローマ字を使わない入力) は今の QuicklIME に無いため、かな単位の誤り (清濁・大小) は戻さない
- よくある誤読 (げっきょく → 月極) の対応表は本書の対象外

### テストセット

- 打ち間違いの無い文: `llm_cases.tsv` の読み (重複を除く) と、本プロジェクトで作った日常の文 101 文
  (`examples/data/typo_cases.tsv`) の計 145 件から、3 文字未満の読み 1 件を除いた 144 件
- 打ち間違いのある文: 上の 144 件の読みのローマ字 (訓令式とヘボン式を交互) に、A の 4 種類の誤りを
  1 打ずつ、先頭のかなの打鍵より後ろの決まった擬似乱数の位置に入れてかなに直したもの 561 件
  (余分 144・抜け 144・隣のキー 144・入れ替え 129)。かなにならない・元の読みと同じになる誤りは位置を
  変えて 20 回まで試し、作れなかった 15 件は除いた。余分に入れる字は隣のキーか同じキー

### 打ち間違いの無い文の Δ

補正の最良経路は、どの経路も補正の語を 1 つだけ通るので `TYPO_COST` によらない。
`TYPO_COST` は Δ を `TYPO_COST / 文字数` だけ下げる。

| TYPO_COST | Δ の最大 | 2 番目 | 3 番目 | 最大を超える Δ で正しい文になる割合 |
|---|---|---|---|---|
| 0 | 672 | 389 | 385 | 28% |
| 1000 | 338 | 264 | 227 | 47% |
| 2000 | 139 | 116 | 64 | 53% |
| 3000 | 14 | 5 | -3 | 55% |
| 3500 | -36 | -48 | -51 | 56% |
| 4000 | -69 | -82 | -107 | 55% |
| 4500 | -103 | -111 | -162 | 54% |
| 5000 | -136 | -140 | -218 | 54% |

- `TYPO_COST = 0` で Δ が大きいのは、短い読み (`かった` → 方、`いった` → いた) と、1-best の
  コストが高い読み (`よちはむずかしい` → よりは難しい、`ふくをきる` → 封を切る)
- 打ち間違いのある文で、補正の最良経路が正しい文になるのは 325/561 件 (58%、Δ の条件なし)。
  抜け・隣のキー・入れ替えでは、別の 1 打の直し方 (`はしがる` → は4月) のほうが安くなることが多い

### 決めた値

`TYPO_COST = 4000`、`TYPO_SHOW = -50`、`TYPO_TOP = 0` (上の表の太字)。

- 打ち間違いの無い文で、補正の候補は先頭にも 2 番目にも出ない。先頭にする Δ の下限は、打ち間違いの
