# 候補バー

入力モデル v2 (docs/design/input-model-v2.md) の段階3。入力中は横一列の候補バーを常時表示し、
ライブ変換と予測サジェストをそこへ統合する。文書は採用したときにだけ書き換える (P1)。

## 背景と目的

段階2でライブ変換を削除し、run 中の文書にはかなだけが入るようになった。変換結果を見るには
変換キーで候補選択に入る必要がある。予測サジェストは縦の候補ウィンドウに出しており、
読める文書では選ぶたびに文書を書き換える (P1 に反する)。

本段階の目的は次のとおり。

- 変換キーを押さなくても変換結果が見え、1打で採用できるようにする (ライブ変換の作り直し)
- 予測サジェストを同じバーに統合し、縦の予測ウィンドウをなくす
- 長い入力を前から順に片付けられるようにする (先頭文節の部分採用)。後続の打鍵で前方の
  変換が変わる問題 (docs/archive/live-conversion-commit-notes.md) は、正しい時点で採用すれば
  以後変わらない、という形で解消する
- 選択では文書を書き換えず、採用時だけ書き換える。読める文書と追記のみの文書で挙動を揃える

## 決定事項

### バーの内容

バーの並びは [unified-suggest.md](unified-suggest.md) で置き換え。英字候補を先頭に置き、その後ろに
エンジンの SUGGEST が 1 つの点数で並べた全体変換と予測候補を、返った順に並べる。

| 種類 | 内容 |
|---|---|
| 英字候補 | モードレス入力で、今 run を終えたら英字になる形 (docs/design/modeless-commit-candidate.md)。最大1 |
| 全体変換 | run の確定済みかな (`ConfirmedKana()`) の入力全体の候補 (補正の候補を含む。SUGGEST の `whole`・`typo`) |
| 予測候補 | 打鍵と照合した予測 (SUGGEST の `predict`・`predict_typo`) |

- 合計の上限・点数・並べ方は unified-suggest.md の E。1 ページは最大9件で、ページ送りで全候補に届く
  ([suggest-paging.md](suggest-paging.md))
- 区間分割した run (英字区間の前に日本語区間が残る run) は、日本語区間を読みにし、予測候補を出さない
  (日本語区間の後ろに英単語が続くので、読みを延ばす予測は合わない)
- 先頭文節だけを採用するには、選んだ全体変換の採用範囲を Shift+← / → で縮める (unified-suggest.md の F)
- 画面の作業領域の幅に収まらない後ろの候補は次のページに送る ([suggest-paging.md](suggest-paging.md))

### 表示条件

- run の確定済みかなが `min_suggest_chars` (既定2) 文字以上のときに出す
  - TSF 層の ConfigLoader にも `min_suggest_chars` を読ませる (今は TSF 層が2を固定で持っている)
- 出さない状態: 候補選択中 (変換キーで入る。縦の候補ウィンドウを使う)、モードレスの英字モード中、
  設定 `candidate_bar` がオフ、候補が1件も無い
- run の無いときにも、確定キーで run を終えた直後などに読みなしの後続語予測を同じバーで出す。
  表示・選択・採用は docs/design/next-word-prediction.md に定める
- 打鍵ごとにエンジンへ同期で問い合わせ、バーを作り直す (問い合わせは下記の「エンジン」)。エンジンの
  自動起動や接続待ちをしない呼び出しを使い、未接続ならバーを出さない
- 予測候補だけを止める設定は、既存の `suggest` (エンジン側) のまま

### 表示位置と見た目

見た目、画面中央に出す設定 (`candidate_position`)、入力行の表示 (`panel_input`) は
docs/design/suggest-panel.md による。以下は `candidate_position caret` (既定) のときの位置。

- キャレット行のすぐ下に出す。下に入らなければ行の上に出す (縦に並ぶパネルの上下の決め方と上に出すときの
  並べ方は [panel-above-caret.md](panel-above-caret.md))
- x 座標は、run でバーを最初に出した時点の位置に固定する (打鍵ごとに左右へ動かさない)。
  部分採用で run の先頭が変わったときは、その時点の位置で取り直す
- 位置の基準は、未完成ローマ字の小窓と同じ矩形 (選択範囲の矩形、取れなければ
  システムキャレットの矩形) を使う
- 未完成ローマ字の小窓とは別のウィンドウにする
- 各候補の前にページ内の番号 (1〜9) を付け、選択中の候補を強調する。未選択のときはどれも強調しない
- 表示は `SuggestPanel` で行う。候補選択中の縦の表示は `CandidateWindow` のまま

### 選択

- 状態「サジェスト選択中」(keymap.md) を「バー選択中」の意味に読み替える。判定・設定上の
  名前 (`suggest`) は変えない
- Tab / ↓ で右へ、Shift+Tab / ↑ で左へ選択を動かす。未選択から Tab / ↓ で先頭を選び、
  先頭で Shift+Tab / ↑ を押すと末尾へ、末尾から右へは先頭へ循環する。未選択に戻すのは Esc
- 候補選択中の Tab / Shift+Tab は、変換を取り消してバーの先頭を選ぶ
- バー選択中の数字 1〜9 は、今出しているページ内のその番号の候補を選ぶ (採用はしない。既存のサジェストと同じ)
- **選択しても文書は書き換えない**。読める文書でも追記のみの文書でも、バー上の選択だけを動かす
  (読める文書で選ぶたびに置き換える今のサジェストの経路は削除する)

### 採用

採用は次の操作で行う。

| 操作 | バー未選択 | バー選択中 |
|---|---|---|
| 確定キー (`CommitRun`) | かなのまま run を終える (採用しない) | 選択中の候補を採用して run を終える |
| Enter / Ctrl+M | かなのまま run を終えて渡す (今どおり) | 選択中の候補を採用して run を終え、渡す |
| 印字キー | (採用しない。打鍵を続ける) | 選択中の候補を採用し、その打鍵から続ける |
| Space | かなのまま run を終えてスペース (今どおり) | 選択中の候補を採用して run を終え、スペース |
| 変換キー | 候補選択に入る (今どおり) | 候補選択に入る (今どおり) |

採用の結果は候補の種類で変わる。

- 全体変換・予測候補: run の確定済みかな全体を候補の表記に置き換える
- 採用範囲を縮めた全体変換 (先頭文節の候補は [unified-suggest.md](unified-suggest.md) の F で置き換え):
  run の先頭の、範囲の文節の読みにあたる部分だけを置き換える。残りのかなは run として続き、前文脈に範囲の
  最後の文節を渡してバーを作り直す。確定キーで採用したときも run は終えない (残りが無いときだけ終える)

共通の扱い:

- 採用した部分は run から外す。以後その文字列を IME が書き換えることはない
- 文書の書き換え: 読める文書は run の文字列の置換 (採用部分 + 残りのかな)。
  追記のみの文書は、擬似 Backspace で run の文字列を消してから、採用部分 + 残りのかなを追記する
  (今のサジェスト採用と同じ仕組み)
- 未完成のローマ字は全体変換の採用の対象外で、小窓に残る。run を終える採用 (確定キー・Enter・Space) では、
  未完成のローマ字を文書に残す。予測候補の採用では未完成のローマ字を捨てる (予測は未完成のローマ字も
  含めて照合しているため。unified-suggest.md の E)
- バー未選択の確定キーは採用せず、Enter と同じく見えているとおりに run を終える
  (モードレスの run 終了時の判定は適用しない)
- 学習: 採用時に送る。全体変換は候補の文節ごとの (読み, 表記) を前文脈つきで送り、2文節以上なら
  読み全体 → 候補の表記 (文脈なし) も同じ LEARN2 で送る。予測候補は候補の完全な読みと表記を、
  採用範囲を縮めた全体変換は範囲の文節ごとの (読み, 表記) を前文脈つきで送る。全体変換の補正の候補は
  学習を送らない。採用した最後の文節を次の前文脈にする
- 確定アンドゥの記憶は、run を終えた時点の確定文字列 (最後の採用部分、または run のかな) とする。
  部分採用の後に run が続いている間は、確定アンドゥは働かない (入力なしの状態でだけ働くため)
- 採用後は RomajiComposer から採用した読みの分のかなを先頭から取り除く。
  `RomajiComposer` に先頭の n 文字 (かなと対応する打鍵列) を切り離す操作を足す

### 採用せずに run が終わったとき

- かなのまま残す (今どおり)。確定キー・Space・Enter・矢印・キャレット移動・フォーカス移動などで
  run が終わったときに、全体変換を自動で採用することはしない (P1)

### 設定

- `candidate_bar` (既定 1) を新設する。0 なら次のとおり動く
  - バーを出さず、毎打鍵のエンジンへの問い合わせをしない
  - 「バー選択中」の状態に入らない。run 中の Tab・↑↓ は、他の編集キーと同じく run を終えて
    アプリへ渡す
  - 確定キーは、かなのまま run を終える (段階2の挙動)
- 設定ツールに「候補バーを表示する」チェックボックスを足す
- 縦の予測ウィンドウを出す設定は設けない (候補バーに一本化する)

### エンジン

エンジンへの問い合わせは [unified-suggest.md](unified-suggest.md) で置き換え。

- 全体変換と予測候補は、打鍵を付けた 1 回の SUGGEST で受け取る
- SUGGEST を知らない旧エンジンには、その接続では以後送らず、CONVNBEST (打鍵なし) の上位 3 件と PREDICT で
  「英字候補 → 全体変換 → 予測候補」の並びを作る (unified-suggest.md の H)

## 実装手順

各手順の後にビルドが通り、既存の動作が壊れていないことを確かめる。

1. `RomajiComposer` の先頭切り離しと、config の `candidate_bar`・`min_suggest_chars`
2. `CandidateWindow` の横一列表示
3. バーの作り直し: 打鍵ごとの CONVNBEST・PREDICT から候補を組み立てて表示する
   (採用はまだ既存のサジェスト採用の経路のまま)。縦の予測ウィンドウを置き換える
4. 選択で文書を書き換えないようにする (読める文書の置換経路の削除)
5. 採用: 全体変換・予測候補 (確定キー・Enter・印字キー・Space)
6. 採用: 先頭文節の部分採用 (run の継続、前文脈の受け渡し、位置の取り直し)
7. `candidate_bar` オフの挙動と設定ツール
8. ドキュメントの更新 (README.md、direct-input.md、keymap.md)

## 検証方法

開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、テスト用アプリで行う。
config.tsv は `QUICKLIME_CONFIG_FILE` で隔離したものを使い、`debug_log` を設定する。
