# モードレス入力の英語判定の強化と英字区間の切り出し

モードレス入力 (docs/design/modeless.md) の自動英字判定に、綴り・文脈・語リストによる判定を足し、
判定が成立したときに run 全体ではなく英単語の部分だけを英字にする (区間分割)。
検討の経緯と Meltype の調査結果は docs/archive/modeless-detection-notes.md にある。

## 背景と目的

現状の判定はローマ字の成立だけを見る3ルールで、次の問題がある。

- ローマ字として読める英単語は日本語になる。英文の途中の `pen`、`camera`、`remote` など
- 判定が成立すると run 全体を英字に作り直す。`kyouhagithub` は `きょうはぎてゅb` まで進み
  (既定テーブルに `thu` = てゅ があるため)、Space のルール3で `kyouhagithub` になる

本書の目的は次のとおり。

- 辞書なしで足せる判定 (綴り・文脈) と、小さな語リストで、英語と判定できる語を増やす
- 日本語に続けて英単語を打ったとき、日本語の部分を残して英単語だけを英字にする
- 境界の判定が外れたときは、既存の F10 (半角英字) / F6 (ひらがな) で run 全体を直せるようにする

## 決定事項

判定はすべて設定 `modeless` が有効なときだけ働く。新しい設定は設けない。

### 判定の追加

既存のルール1〜3 (modeless.md) はそのまま残し、次を足す。

#### ルール4: c 行の綴り (打鍵中に判定)

- `c` の直後に母音 (`ca` `ci` `cu` `ce` `co`) が来た綴りを含み、run の打鍵列が5文字以上になった時点で英字と判定する
  (`camera` `account`)。`ch` (ち行) は対象外
- 日本語を打つときは k や s を使うため。短い語は誤判定を避けるため対象外とする
- 英単語の始まりは、その c を含むかなの位置とする (境界が分かる判定)。打鍵列の5文字は
  英単語側の長さではなく run 全体で数える

#### ルール5: th + 母音 (打鍵中に判定)

- `tha` `thu` `the` `tho` (てゃ・てゅ・てぇ・てょ) が完成した時点で英字と判定する (`github` `the` `method`)
- `thi` (てぃ) は外来語 (パーティー) で日本語でも使うので対象外
- ローマ字テーブルの照合で `th` + 母音に一致したときに判定する (かなを足す前に判定する。ルール2と同じ)

#### ルール6: 直前の確定が英字 (run 終了時に判定)

- 直前の確定文字列 (`lastCommitText_`。run の外の Space の半角追随と同じ基準) が ASCII 英数字だけで、
  run 全体がローマ字として読めるかな列 (未完成のローマ字が無い、または `n` だけ) なら英字にする
  (`this is a pen` の `pen`)
- 助詞などと同じ形の語は対象外: `no` `to` `ga` `wo` `ni` `de` `ha` `wa` `mo` `he` `ya` `ka` `yo` `ne`
  (`GitHub no` → 「の」)
- 区間分割した run には適用しない (run 全体が対象のルール)

#### ルール7: 語リスト (run 終了時に判定)

- 「ローマ字として読めるが日本語にならない英単語」のリストを DLL に埋め込む (200語程度)
- run の打鍵列の全体、または run の末尾 (かなの境目から始まる部分) がリストの語と一致すれば英字にする。
  末尾で一致した場合は、その語の頭が英単語の始まり (境界が分かる判定)
- リストは自作する。英単語の頻度表などからローマ字として読める語を拾い、エンジン辞書に読みとして
  載っている語 (日本語として成立する語) を除いてから、人の目で選ぶ。Meltype の表は GPL-3.0 のため使わない
- 一致は大文字小文字を区別しない打鍵列の比較とする

#### run 終了時に判定するルールの適用場所

ルール3・6・7 (run 終了時の判定) は、文書の表示も英字に直せる場所でだけ適用する。
既存のルール3の適用場所 (Space、読める文書でアプリへ渡すキー、確定キー) に加え、
語の区切りになる記号キー (`.` `,` `!` `?` `:` `;`) の入力でも適用する。

- 確定キーと記号キーは IME が食べるキーなので、追記のみの文書でも擬似 Backspace の順序の問題が無い。
  確定キーでは、読める文書・追記のみの文書の両方でルール3・6・7 を適用する
- 記号キーで英字になった場合、その記号は英字モード中と同じく半角で入る (`pen.` → `pen.`)
- フォーカス移動・IME オフ・Ctrl/Alt 併用キー・追記のみの文書でアプリへ渡すキーでは今どおり適用しない

採らなかった案: ぢ・づの綴り (`di` `du`) を英語の根拠にする案。`tuduku` (続く)、`tidimu` (縮む)
のように日本語の打鍵で普通に使うため。

### 区間分割

#### run の構造

- `RomajiComposer` に英字区間の開始位置 (かなの位置) を持たせる。開始位置より前は日本語区間、
  以降は英字区間
- 開始位置が 0 なら run 全体が英字で、今の英字モードと同じ。Shift+英字で入った英字モードも、
  入った時点のかなの位置を開始位置とする (Shift+英字は打った文字から英字であることが明らかなため)
- 英字区間の後に日本語区間へは戻らない。英字区間は Space・確定キーなどで run が終わるまで続く
- 英字区間への切替は、日本語区間を残して、英字区間に入る部分の打鍵列だけを1文字ずつ置き直す
  (今の `SwitchToAscii()` を開始位置つきにしたもの)
- `Raw()` は日本語区間と英字区間を通した打鍵列を返す。F10 (半角英字) / F9 / F6〜F8 は今どおり
  run 全体を `Raw()` / かなから作る。区間分割の境界が外れたときの直し方はこれとする
- Backspace で英字区間が空になったら、英字区間を解除して日本語区間の末尾から入力を続ける
  (run 全体が空になったときの `Clear()` と同じ考え方)
- 設定 `modeless` が無効なときは、Shift+英字の英字モードも区間分割の扱い (英字区間の解除・候補バー・
  採用・確定キー) をせず、今の挙動のままにする。開始位置は持ってよいが、挙動に使わない

#### 境界の決め方

判定の種類で決め方が変わる。

| 判定 | 英単語の始まり |
|---|---|
| ルール4 (c 行)・ルール7 (語リストの末尾一致) | 判定の根拠になった語の頭 |
| Shift+英字 | その打鍵の位置 |
| ルール1・2・3・5・6 | 下の英単語辞書の問い合わせで決める |

英単語辞書の問い合わせ:

- 切替が成立した時点で1回だけエンジンに問い合わせる (打鍵ごとではない)。新しいコマンド ASCIISTART を使う
- 境界の候補は、かなのかたまり (打鍵列を持つかな。`きょ` は1かたまり) の境目。TSF 層は
  かたまりごとの打鍵列と、末尾の未変換ローマ字を送る
- エンジンは先頭の境目から順に、そこから後ろの打鍵列 (小文字にしたもの) が英単語辞書の語と
  一致するかを調べ、最初に一致した境目を返す。最も前の境目を採るのは、後ろの短い打鍵列
  (`th` など) ほど偶然に一致しやすいため
- 照合の方法は判定の種類で変える
  - 打鍵中の判定 (ルール1・2・5): 前方一致 (完全一致を含む)。英単語をまだ打っている途中のため
  - run 終了時の判定 (ルール3): 完全一致。打ち終わった語なので、前方一致を根拠にしない
- 後ろの打鍵列が2文字以下の境目は候補にしない (英字区間は3文字以上)。1〜2文字はほぼ必ず
  何かの英単語の頭になり、日本語の末尾に英字が1〜2文字だけ付く結果になるため
  (`kaisyast` が `かいしゃst` になるなど)。開始位置 0 (run 全体) はこの制限を受けない
  - `kyou|ha|gi|th` → `hagith` ✗、`gith` ✓ (github) → `きょうは` + `gith`
  - `ko|re|ha|a|っ|pl` → `appl` ✓ → `これは` + `appl` (`haappl` `aappl` は ✗)
  - `kyou|ha|the` → `the` ✓ → `きょうは` + `the`
  - `wo|rl` → `worl` ✓ (world) → run 全体が英字
  - ルール3 `kyou|ha|wa|n|t` → `want` が完全一致 → `きょうは` + `want`
  - ルール3 `wa|ta|si|ha|n|t` → 3文字以上で完全一致する境目が無い → run 全体が英字
  - ルール3 `ka|i|sya|s|t` → `st` は2文字なので候補にならない → run 全体が英字
- どの境目でも一致しなければ開始位置 0 (run 全体が英字。今の挙動)
- エンジン未接続・エラー・旧エンジン (不明なコマンド) のときも開始位置 0 とする。
  自動起動や接続待ちはしない (候補バーの `ConvertNBestLive` と同じ呼び方)

採らなかった案: CONVNBEST の1位候補の文節区切りから境界を推測する案。エンジンで実測すると、
1文字の助詞 (`を` `は`) が単独の文節になる (`world` → `をrld`)、英単語由来のかなが細かく
分かれる (`今日は|技|テュ` → `きょうはぎthub`) など、日本語の文節区切りでは英単語の始まりを
決められなかった。

#### 英単語辞書

エンジン (Rust) が起動時に読み込む。TSF の DLL は全アプリのプロセスにロードされるため、
数万語の辞書は持たせない。

- 一般語: SCOWL (米語、サイズ35、所有格と略語を除く、英字だけの語を小文字にしたもの。約4万語の見込み) から
  生成した単語リスト `data/english-words.txt` をリポジトリに置く。生成の手順と条件は
  ファイル先頭のコメントに書く
- 固有名詞・技術用語: SCOWL に無い語 (`github` `google` `python` `zoom` など) を自作のリスト
  `data/english-names.txt` に置く (数百語)
- ユーザ辞書: 表記が ASCII 英字だけの語 (表記を小文字にしたもの) も英単語として扱う。RELOADUSER で更新する
- 照合は小文字にした語の整列済み配列への二分探索 (前方一致・完全一致) で行う。語数が数万なので fst は使わない
- 配布: インストーラは `english-words.txt` と `english-names.txt` を `dict\` に置き、
  SCOWL の著作権表示と許諾文を `LICENSE-SCOWL.txt` としてインストール先に置く
  (Mozc・llama.cpp と同じ扱い)。開発時はリポジトリの `data/` から読む
- 辞書が見つからないときは ASCIISTART が常に開始位置 0 を返す (今の挙動)

#### プロトコル: ASCIISTART

```
要求:   ASCIISTART\t<照合方法>\t<打鍵列1>\x1f<打鍵列2>\x1f...\n
        (照合方法は prefix (前方一致) か exact (完全一致)。打鍵列はかなのかたまりごと。
         末尾の未変換ローマ字は独立した最後の要素にする)
成功:   OK\t<要素の位置>\n   (英字区間を始める要素の位置。0 は全体を英字にする)
失敗:   ERR\t<メッセージ>\n
```

- 返す位置は、一致した境目の要素の位置。一致しなければ 0
- 打鍵列の英大文字は小文字にして照合する

#### 文書の書き換え

- 英字区間に入る部分だけを書き換える (`きょうはぎてゅ` → `きょうはgithu`)。
  読める文書は run の文字列の置換、追記のみの文書は擬似 Backspace で英字区間の分だけ消してから追記する
- 日本語区間の文字は書き換えない

#### 候補バー

- 区間分割した run では、日本語区間が `min_suggest_chars` 文字以上ならバーを出す
  (今は英字モード中は出さない。開始位置 0 の英字モードは今どおり出さない)
- バーの候補は日本語区間だけを対象に、全体変換と先頭文節を通常の run と同じ規則で作る。
  予測候補は出さない (日本語区間の後ろに英単語が続いているので、読みを延ばす予測は合わない)
- 全体変換の表示は候補の表記の後ろに英字区間を付ける (`今日はgithub`)。先頭文節は今どおり
  `今日は…` と表示する
- 採用は、日本語区間を候補の表記に置き換える。英字区間は run として続く
  (先頭文節の部分採用と同じ扱い。採用後は英字区間だけの run になる)
- 確定キー (バー未選択) は、日本語区間の全体変換の1件目を採用し、英字区間を付けて run を終える
  (`kyouhawant` → 確定キー → `今日はwant`)。今の「ルール3で英字になるときは全体変換を採用しない」は、
  開始位置 0 のとき (run 全体が英字) だけに限る
  - 確定キーでルール3が成立して区間分割になった場合、表示中のバーは分割前のかな全体に対するもので
    使えないため、日本語区間に対して CONVNBEST をもう一度呼び、1件目を採用する。日本語区間が
    `min_suggest_chars` 未満なら採用しない (バーを出す条件と揃える)
  - このときの文書の書き換えは、「日本語区間の変換 + 英字区間」を組み立ててから1回で行う。
    追記のみの文書で擬似 Backspace の処理を2つ続けると、目印の打鍵の対応が食い違うため
- 全体英字の候補はバーに出さない (F10 で出せるため)
- Space・Enter は今どおり自動で採用しない (`きょうはwant ` のまま)

#### 学習

- 区間分割した run を採用せずに終えたときの学習は、今の英字を含む入力と同じ扱い
  (読み = 表記)。日本語区間の採用時は、その採用分の学習を通常どおり送る

## 実装手順

各手順の後にビルドが通り、既存の動作が壊れていないことを確かめる。

1. romaji: 英字区間の開始位置と開始位置つきの切替。開始位置 0 は今の英字モードと同じ動作にする。
   `Raw()`・`Commit()`・`Display()`・Backspace・`RemoveFront()` の対応
2. engine: 英単語辞書 (data/ の生成と読み込み、ユーザ辞書の英字の語) と ASCIISTART。
   隔離したエンジンにコマンドを送って境界の結果を確かめる
3. romaji / text_service: 切替を「要求」と「確定」の2段階にし、ASCIISTART で境界を決める。
   ルール1〜3 をこの経路に載せる
4. text_service_direct: 英字区間だけの文書の書き換え (読める文書・追記のみの文書)
5. text_service_direct: 区間分割した run の候補バー・採用・確定キー
6. ルール4・5 (打鍵中の判定)
7. ルール6・7 (run 終了時の判定)、語リストの作成、記号キーでの適用
8. インストーラの対応とドキュメントの更新 (README.md、protocol.md、modeless.md、roadmap.md)

## 検証方法

開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、テスト用アプリで行う。
config.tsv は `QUICKLIME_CONFIG_FILE` で隔離したものを使い、`modeless 1` と `debug_log` を設定する。
