# 入力と変換

キーボードで入力した読みは、確定や候補の採用を行うまで IME 側で保持され、文書には確定時に反映されます。日本語への変換は主に変換キーで行います。

入力中の読み（`k` や `ky` などの未完成なローマ字を含む）を表示する場所は、設定 `input_buffer` で切り替えることができます。一般的な IME と同様に文書内へ下線付きで表示する `composition`（既定値）と、パネルの入力行だけに表示する `panel` の 2 種類が用意されています（詳細は [入力中の読みの表示 (input_buffer)](#入力中の読みの表示-input_buffer) を参照してください）。どちらの表示方式を選んでも、キー操作の意味や挙動は共通です。

## キー操作

IME がオンのときの主なキー操作です。変換キー、無変換キー、ファンクションキー（F4〜F10）などは既定の割り当てであり、[キー割当](keymap.md) から自由に変更できます。

### 文字入力と削除
- **英字・記号・数字**: 入力を開始し、読みを追加します。
- **Backspace**: 入力末尾の文字（未完成のローマ字がある場合はその 1 文字）を削除します。入力中の読みが空になると入力セッションが終了し、その後の Backspace はアプリへ直接渡されます。

### 変換と候補選択
- **変換キー**:
  - 入力中は**変換を開始**します（入力がない状態で押した場合は、後述の「後置再変換」が働きます）。
  - 候補選択中は**次候補**へ進みます（`Shift + 変換キー` で前候補に戻ります）。
  - **入力全体の変換**: 既定では、入力中のかな全体を 1 単位として変換します。文節の区切り方が異なる複数の変換結果（例:「今日は医者に行った」「今日歯医者に行った」など）が候補一覧に並びます。
  - **英字・数字を含む変換**: 英字を含む入力は全体を 1 語として変換でき、ローマ字のままの大文字・小文字変換（`apple` / `Apple` / `APPLE`）も選べます。また、固有名詞や技術用語は正規の大文字小文字表記が最上位に表示されます（例: `github` や `ぎてゅb` から `GitHub` を選択可能）。数字の入力では、打ったとおりの半角/全角表記のほか、漢数字・桁区切り・万単位表記などのバリエーションが並びます（例: `1234えん` から「千二百三十四円」「1,234円」「１２３４円」などを選択可能）。
  - **打ち間違い（タイポ）の自動補正**: キーの打ちすぎ、抜け、隣接キーの誤打、文字の入れ替えなどを自動補正した候補が、最上位または 2 番目に提示されます（例: `yorosikuonegiasimasu` から「よろしくお願いします」）。その読み全体で以前に確定した表記がある場合は、その表記と通常の変換結果の後ろ（2 つが違う表記なら 3 番目、同じ表記なら 2 番目）に置かれます。補正は実際に打鍵されたキーに基づいて行われるため、`romaji.tsv` でカスタマイズした綴りも正しく認識されます。ただし、文節単位の変換（`segment_ui: 1`）と、後置再変換などで文書から読み込んだかなでは、打鍵の記録を使わず、かなを標準的なローマ字の綴りに戻して補正します（`romaji.tsv` でカスタマイズした綴りは反映されません）。候補一覧では補正候補に「補正」タグが付きます。補正候補は確定しても学習に記録されません（設定 `typo_correction` を `0` にすると無効化できます）。
  - **文節単位の変換 (`segment_ui: 1`)**: 設定で文節単位の変換を有効にしている場合は、補正された読みの区切りに合わせて文節が分割され、誤打のあった語を含む文節に「補正」タグ付きで候補が入ります。
  - **候補選択中の操作**: 候補選択中は `Space` で次候補、`Shift + Space` で前候補に進むほか、`↑` `↓` で候補を移動でき、ファンクションキー `F4`〜`F10` で文字種を一括変換することも可能です。`Ctrl + 1`〜`Ctrl + 9` を押すと、表示中のページのその番号の候補で確定します（Enter と同じ確定で、改行は入りません。文節単位の変換では、現在の文節をその候補にして全体を確定します）。数字キー `1`〜`9` は文字キーと同じく、選択中の候補で確定してから数字の入力を始めます。

### 変換範囲の伸縮
候補選択中に `→` を押すと変換範囲の先頭が 1 文字縮み、`←` を押すと縮めた文字が 1 文字ずつ元に戻ります（右端は固定）。
- 範囲を変更すると、その読みの範囲で変換がやり直されます。
- 縮めて除外されたかなは未確定文字列の先頭に下線付きで残り、確定時にはそのかなと選択した候補がまとめて文書に入力されます（除外されたかなは学習されません）。
- 入力中の文字列を超えて、それ以前の文書内の文字列へ範囲を広げることはできません。
- 英単語を含む入力時や文節単位変換 (`segment_ui: 1`) ではこの範囲伸縮は無効化され、`←` `→` は後述のとおり確定してキャレット移動、または文節移動として機能します（ただし `F6`〜`F10` での文字種変換中は伸縮可能です）。

### 文節単位の変換 (`segment_ui`)
設定 `segment_ui`（設定ツールの「文節単位で変換する」、既定値 `0`）を `1` にすると、候補選択を文節ごとに行う従来の一般的な IME と同等の操作になります。
- 候補選択中に `←` `→` で着目文節を移動し、`Shift + ←` / `Shift + →` で文節の長さを伸縮できます。
- `PageUp` / `PageDown` で先頭または末尾の文節へ素早く移動できます。

### 確定と取り消し
- **Enter**: 選択中の候補を確定した上で、アプリへ Enter キーを渡します（1 打で確定と改行・送信が同時に行えます）。
- **確定キー (無変換キー)**:
  - 入力中は、画面に見えている読みのまま（未完成のローマ字を含む）確定します（候補バーの候補は採用されません）。
  - 候補選択中は、現在選択している候補を確定します。
  - アプリへキーは渡されないため、改行は入りません。
- **Esc**:
  - 変換中は、変換を取り消して元の読みの入力状態に戻ります。
  - 通常の入力中は、入力中の読みをすべて破棄します（文書には何も入力されません）。
  - 候補バーで候補を選択しているときは、選択を解除します。
- **Backspace**: 変換中に押すと、変換前の読みの入力状態に戻ります。
- **Tab**: 変換を取り消し、候補バーの先頭候補を選択します。
- **文字入力キー**: 変換中に英字などの文字キーを押すと、現在の候補を確定した上で、その文字から新しい入力を開始します。
- **キャレット移動キー (Home / End / Delete / PageUp / PageDown など)**: 候補を確定した上で、キー入力をアプリへ渡します。`↑` `↓` は次の候補・前の候補の選択、`←` `→` は変換範囲の伸縮（文節単位の変換では文節の移動）に使われます。範囲を伸縮できない変換（英単語を含む入力など）では、`←` `→` も候補を確定してアプリへ渡します。

### 後置再変換
入力を行っていない状態で変換キーを押すと、カーソル周辺の既存の文字列を読みとして変換モードに入ります（`F6`〜`F10` も同様に利用できます）。

1. **文字列を選択している場合**: 選択範囲の文字列（127 文字まで）を変換します。
   - ひらがな・カタカナ・長音「ー」だけの選択は、その文字列を読みとして変換します。
   - 漢字を含む選択（ひらがな・カタカナ・ー・漢字・々・〇・〆・数字からなるもの）は、辞書から読みを推測して変換します。ほかの IME やアプリで入れた文字列も直せます。候補の先頭は元の文字列なので、変換キーを押しただけでは文書は変わりません。
   - 推測した読みが誤っていたときは、`Esc` で推測した読みの入力状態に戻し、読みを直して変換し直します。
   - 漢字を含む選択から変換したときは、表記を変えた文節だけを学習します（元の文字列のまま確定したときは学習しません）。
   - 英字・記号・空白・改行を含む選択や、読みを推測できない文字を含む選択では、変換キーはそのままアプリへ渡されます。エンジンの起動直後（約 1 秒）も同じです。
2. **選択がない場合（直前の確定履歴）**: キャレット直前の文字列が QuicklIME で直前に入力した文字列と一致する場合、その 1 回分の確定単位を丸ごと再変換します。漢字混じりの文字列であっても、読みを打ち直すことなく簡単に修正できます。
3. **選択がない場合（直前のかな文字列）**: キャレット直前にひらがなや長音「ー」が連続している場合（最大 127 文字）、その部分を対象に変換を開始します。確定キーでかなのまま確定してしまった場合などに便利です。

#### 後置再変換の注意点
- 選択範囲がない場合の後置再変換は、後述の「読める文書」でのみ動作します。
- 対象となった文字列は文書から一時的に削除され、未確定文字列として扱われます。取り消し（`Esc` や `Backspace`）を行うと、その読みの入力状態に戻ります。
- Space による空白挿入や、アプリ側での直接編集・改行などを挟むと、それ以前の履歴は使用できなくなります。また、フォーカス移動や IME のオフによっても履歴は破棄されます。
- 対象となる文字列が存在しない場合は、変換キーがそのままアプリへ渡されます。

### その他のキー操作
- **Space**: 設定 `space` に従ったスペースを入力します。文字入力中に押すと、読みを確定してスペースを挿入します（候補バーで候補を選択しているときは、その候補を採用してスペースを挿入します）。
- **Enter / 矢印 / Tab / Home / End / PageUp / PageDown / Delete / Insert / Ctrl 併用キー**: 入力中の読みをそのまま確定し、キー入力をアプリへ渡します（候補バーが表示されている間の `Tab` や `↑` `↓` は候補選択に使われます）。Ctrl 併用キーのうち、`Ctrl+H` は読みを 1 文字削除し、候補バーが表示されている間の `Ctrl+1`〜`Ctrl+9` は候補の採用、改行キーなど機能を割り当てた組み合わせはその機能になります。
- **Alt 併用キー (Ctrl+Alt 含む)**: 入力状態を維持したまま、キー入力を直接アプリへ渡します。
- **Ctrl+Backspace (確定アンドゥ)**: 入力確定の直後に押すと、直前に入力した文字列を文書から削除し、確定前の読みの入力状態に戻します（読める文書でのみ機能します）。
- **Ctrl+J (改行キー)**: チャットアプリ（Discord、Slack、Teams、LINE など）で、誤送信を防ぎながら改行を入力するために `Shift + Enter` をアプリへ送信します。文字入力中や候補選択中に押すと、確定した上で改行を挿入します。対象アプリは設定 `newline_apps` で変更できます（詳細は [アプリごとの設定](app-settings.md) を参照してください）。
- **IME オフ**: 現在の読みをそのまま確定して入力セッションを終了します。
- **入力パネルの外でのマウスクリック**: 入力中の読みをそのまま確定して入力を終了します。候補バーで候補を選択していても、選択した候補ではなく読みのまま確定します。変換の候補を選択中のときは、今選んでいる候補で確定します。次の語の予測は消えます。クリックはそのままアプリに届きます。入力パネル自体をクリックしたときは入力を続けます。
- **フォーカスの移動**: 入力を終了します（学習は行われません）。

## 読める文書

QuicklIME は、直前に入力・確定した文字列をキャレット直前から正しく読み戻せる文書を「読める文書」として自動認識します。

- **読める文書の例**: メモ帳、Microsoft Word、Google Chrome、一般的なテキストエディタなど。
- **読めない文書の例**: WezTerm や Windows Terminal などの一部のターミナルエミュレータ（CUAS 経由で動作するアプリなど）。

### 動作の違い
- 選択範囲がない状態での「後置再変換」および「確定アンドゥ」は、読める文書でのみ利用可能です。
- 入力を確定してアプリへキーを渡す際（Enter や矢印キーなど）、読める文書ではテキスト確定後にキーをスムーズに送信します。読めない（または未判定の）文書では、キー入力が先行して誤動作するのを防ぐため、入力中は文字の確定完了を待ってからキーを送信します。候補を選んでいる間は、確定の完了を待って送り直すのは Enter だけで、それ以外のキーは確定してからそのままアプリへ渡します。

## 入力中の読みの表示 (input_buffer)

設定 `input_buffer`（設定ツールの「入力」ページ「入力中の読み」）で、入力中の読みを表示する位置を変更できます。

設定ツールの「入力中の読み」では、次の 3 つから選びます。

| 選択肢 | 書き込まれる設定 |
|---|---|
| 文書に下線付きで出す（既定） | `input_buffer composition`、`panel_input 0` |
| 文書と入力パネルの両方に出す | `input_buffer composition`、`panel_input 1`（入力パネルの上部にも入力行を出します。詳細は [候補バー](candidate-bar.md) の「入力行の表示」を参照してください） |
| 入力パネルだけに出す | `input_buffer panel`（`panel_input` は読み込んだ値のまま書きます。このとき `panel_input` は効きません） |

### `composition`（既定値: 文書に下線付きで出す）
一般的な日本語 IME と同様に、入力中の読みを文書内に下線付きの未確定文字列としてインライン表示します。
- 候補バーは未確定文字列のキャレット位置に合わせて表示されます。
- マウスクリックやキャレット移動時、アプリ側が未確定文字列を確定した場合はその内容で入力を終了します。
- 未確定文字列の直接表示に対応していないアプリでは、自動的に `panel` 方式に切り替えて入力を継続します。

### `panel`（入力パネルだけに出す）
入力中の読みを文書内には表示せず、入力パネル内の入力行にのみ表示します。確定や候補採用のキーを押して初めて、文書内に文字が一括挿入されます。
- **メリット**: 入力中のキーストロークごとに文書の内容が書き換わらないため、文字入力のたびにインクリメンタル検索が走る検索欄や、文字数カウンターのあるフォーム、入力ごとにアンドゥ履歴が細かく積まれてしまうアプリでも快適に入力できます。
- 候補バーが無効化されている場合でも、読みを表示するための入力行パネルが表示されます。
- 変換キーを押すと、候補選択の間だけキャレット位置に未確定文字列が表示され、確定によって文書に反映されます。

## 数字・メールアドレスなどの入力欄 (input_scope_passthrough)

設定 `input_scope_passthrough`（設定ツールの「入力」ページ「数字やメールアドレスの欄では日本語入力を使わない」、既定値 `1`）が有効な場合、アプリ側が半角英数字専用と指定している入力欄（InputScope）において、IME を手動でオフにしなくてもキー入力をそのまま直接アプリへ受け渡します。

- **対象となる入力欄**:
  - 数字専用欄（Web フォームの `inputmode="numeric"` や `type="number"`）
  - 電話番号欄 (`type="tel"`)
  - メールアドレス欄 (`type="email"`)
  - パスワード欄、PIN 入力欄、半角英数専用欄など
- **対象外の入力欄**: ブラウザのアドレスバー、URL 入力欄 (`type="url"`)、検索欄 (`type="search"`) や、種類が特に指定されていない通常のテキスト欄は対象外です。アドレスバーは検索語も入力する欄のため、日本語入力を使えるようにしています。
- **利点**: 認証コードの 1 枠 1 文字の入力欄や、カード番号・メールアドレスの入力欄で、全角文字や未確定の下線が入ってしまうトラブルを防ぎます。
- **補足**: 対象の入力欄から別の入力欄へフォーカスを移動すると、自動的に元の日本語入力状態に戻ります。なお、アプリ側が入力欄の種類情報をシステムに通知していない場合は判別できないため、その際は手動で IME をオフにして入力してください。
