# ファジィ入力の段階を run ごとに変える

## 背景と目的

打ち間違いを直した候補 (全体変換の補正の候補とずれのある予測。[engine.md](../spec/engine.md)「タイプミス補正」、
[suggest.md](../spec/suggest.md)「ファジィ照合」) は、誤検出を避ける側に倒した設定で自動で出している。

- 読みの末尾 1 文字は補正しない (`tail_chars` 1)
- 許すずれは `min(3, 打鍵の数 / 4)` で、3 打以下は 0
- 全体変換の補正の候補は最良の 1 件だけで、Δ ≥ `TYPO_SHOW` のときしか出さない

このため、打ち間違いに気づいても目的の候補が出ないことがある。QuicklIME はこの機能を打ち間違いの後始末ではなく、
崩して速く打つための入力方法として積極的に使う設計にする。そのために次の 2 つを行う。

- 利用者が run ごとに補正の強さ (段階) をキーで上げ下げできるようにする。上げると末尾も補正し、補正の候補を複数件、
  先頭から出す。下げるとその run では補正しない
- 機能の名前を「ファジィ入力」に改める

## 決定事項

### A. 段階

段階は −1〜3 の 5 つ。0 が今の自動補正。

| 段階 | 全体変換の補正 | 予測の照合 |
|---|---|---|
| −1 | 作らない | ずれを許さない (完全な前方一致) |
| 0 | 今のまま (末尾 1 文字を保護、K = `min(MAX_EDITS, n / KEYS_PER_EDIT)`、最良の 1 件、Δ の足切りと位置の規則) | 今のまま |
| 1 | 末尾も補正する (`tail_chars` 0)。Δ の足切りをやめ、補正の候補を最大 3 件、先頭から出す。K は段階 0 と同じ | 末尾も照合する (`predict_tail` 0。今と同じ)。K は段階 0 と同じ |
| 2 | 1 に加え、K を 1 増やす。補正の候補は最大 4 件 | K を 1 増やす |
| 3 | 1 に加え、K を 2 増やす。補正の候補は最大 5 件 | K を 2 増やす |

- n は打鍵の数 (未完成のローマ字を含む)。K の増分は `MAX_EDITS` の上限の後に足す (段階 2 は `min(3, n / 4) + 1`)。
  3 打以下でも段階 2 以上では許すずれがある
- 先頭のかなは、どの段階でも補正しない
- 隣り合わないキーへの置き換えは、どの段階でも誤りとして扱わない
- `MIN_TYPO_CHARS` (読みが 3 文字未満なら全体変換の補正を作らない) はどの段階でも変えない
- 誤りの種類ごとのコスト (隣のキー 3000 など) はどの段階でも同じ

#### 段階 1 以上の補正の候補の並び

- 補正の候補は、補正の語を 1〜K 個通る経路を、コストの安い順に段階ごとの件数 (3・4・5) まで取る。表記が同じ経路は
  安いほうの 1 件にする
- 補正の候補を並びの先頭から置く。読み全体の学習表記・保護する 1-best よりも上にする (利用者が明示的に強めたため)。
  その後ろは段階 0 の並びから補正の候補を除いたもの
- 表記が補正なしの候補 (読み全体の学習表記・通常の N-best・数字の書き方など) と同じ補正の候補は出さない。
  補正の印が付いて学習されなくなるのを避けるため
- 補正の候補が無ければ、段階 0 で補正の候補が無いときと同じ並び
- SUGGEST では、補正の候補 (`typo`) を先頭から置き、その後ろを今の並べ方 (s の小さい順など) で並べる。ずれのある予測
  (`predict_typo`) は点数で並べるままで、許すずれの数だけが段階で変わる
- 補正の候補とずれのある予測を採用・確定したときに学習しないのは今と同じ

### B. 標準の段階の設定 `fuzzy_level`

- 新しい設定 `fuzzy_level` (−1〜3、既定 0) を run の始めの段階にする。範囲外・数値でない値は既定値
- `typo_correction` は廃止する。`fuzzy_level` が無く `typo_correction 0` があれば `fuzzy_level −1` として読む
  (エンジン・TSF 層・設定ツールで同じ)。設定ツールは保存時に `fuzzy_level` だけを書き、`typo_correction` の行は書かない
- エンジンと TSF 層の両方が読む。TSF 層は run の始めの段階に、エンジンは段階のフィールドが無い要求に使う

### C. 段階を変えるキー

- 割当機能を 2 つ足す

| 機能 | 設定キー | 働く状態 | 既定の割当 | 働き |
|---|---|---|---|---|
| `FuzzyStronger` | `key.fuzzy_stronger` | run 中・サジェスト選択中・候補選択中 | `F2` | ファジィ入力の段階を 1 上げる |
| `FuzzyWeaker` | `key.fuzzy_weaker` | run 中・サジェスト選択中・候補選択中 | `Shift+F2` | ファジィ入力の段階を 1 下げる |

- 段階は run の状態として持つ。run を始めたときと、文書に文字列を入れたとき (候補バーの採用・変換の確定。採用範囲を
  縮めた採用や区間分割した run の印字キーでの採用のように、run が続く採用も含む) に `fuzzy_level` に戻す。run の途中で
  打ち足しても保つ。変換の取消で run に戻ったときも保つ
  - 段階を変えるのは、いま出ている候補に対して強すぎる・弱すぎると感じたときの操作で、確定した後の入力には持ち越さない
- 端 (3 と −1) では止まり、一周しない。端で押しても打鍵は食べる (アプリへ渡さない)
- run 中・サジェスト選択中: 段階を変えて SUGGEST を引き直し、候補バーを作り直す。選択は未選択に戻す
  - 候補バーを出していないとき (かなが `min_suggest_chars` 未満・候補が無い・`suggest` 0 など) も段階は変え、
    入力パネルに段階の印だけでも出す (下記 D)。押した手応えが必ず見えるようにするため
- 候補選択中 (`segment_ui` 0): 段階を変えて CONVNBEST を引き直し、変換の候補一覧を作り直す。選択は先頭に戻す。
  LLM の並べ替えを使うときは RERANK も新しい段階で送り直す
- 候補選択中 (`segment_ui` 1 の文節 UI): 打鍵を食べて何もしない (下記 E)
- 段階が変わらなかった (端で押した) ときは引き直さない
- 状態別の上書き・設定ツールでの割当は、ほかの割当機能と同じ扱い

### D. 段階の印 (ドットのメーター)

入力パネルに、今の段階を点の並びで出す。段階が 0 以外のときに出し、0 のときは出さない (標準の段階を 0 以外に
していれば、run の始めから出る)。

| 段階 | 印 |
|---|---|
| 1 | ●○○ |
| 2 | ●●○ |
| 3 | ●●● |
| −1 | ⊘ (斜線を引いた丸) |

- 塗った点はテーマの `typo` 色。塗らない点は `typo` 色の線 (`line_width_px`) の丸。−1 の印は副次色
- 点の直径と間隔は `label_text_size` を基準にする
- 置く場所
  - 入力行があるとき: 入力行の右端 (`style ghost` ではゴーストの後ろ)
  - 入力行が無く、横一列 (`row`): チップの列の右端 (位置の表示があればその右)
  - 入力行が無く、縦積み (`column`): 最後の行の下、位置の表示と同じ行の右端
  - キャレット行の上に反転して出すときも同じ部品の中で右端に置く
  - 入力行も候補も無いとき: 印だけのパネルを出す
- 変換の候補一覧でも同じ規則で出す
- 印を出している間だけ、その幅をパネルの幅に足す
- 印はテーマで消せない (段階が変わっていることに気づけないと、候補の変化の理由が分からないため)

### E. 対象

- 段階が効くのは候補バー (SUGGEST) と、`segment_ui` 0 の変換の候補一覧 (CONVNBEST・RERANK)
- 文節 UI (`segment_ui` 1 の CONVSEG・CONVCTX) は run の段階を使わず、`fuzzy_level` だけを見る。−1 なら補正しない、
  0 以上なら今の文節 UI の補正のまま (段階 1〜3 の違いは出ない)
  - run の段階が −1 でも、文節 UI の変換には効かない (標準の段階に従う)
- 後続語の予測 (読みなし) は照合しないので関係しない

### F. プロトコル

段階を要求に付ける。省略したときはエンジンの `fuzzy_level`。

```
SUGGEST\t<文脈読み>\x1f<文脈表記>\t<かな>\t<打鍵>[\t<段階>]\n
CONVNBEST\t<文脈読み>\x1f<文脈表記>\t<かな>[\tkinds[\t<打鍵>[\t<段階>]]]\n
RERANK\t<LLM 文脈>\t<文脈読み>\x1f<文脈表記>\t<かな>[\tkinds[\t<打鍵>[\t<段階>]]]\n
```

- `<段階>` は `-1`〜`3` の整数。範囲外・数値でなければ ERR
- CONVNBEST・RERANK の `<打鍵>` が空のフィールドなら打鍵なし (かなを戻した近似で補正する)。打鍵の無い要求
  (後置再変換など文書から読んだかな) にも段階を付けられるようにするため
- TSF 層は、kinds を付ける CONVNBEST・RERANK と SUGGEST に、常に run の段階を付ける
- 旧エンジンは後ろのフィールドを読まないので、段階を付けても今の挙動になる (段階が効かないだけ)

### G. 名前を「ファジィ入力」に改める

- ユーザの目に入るもの (設定ツールの文言、候補の種類のタグ、README.md・docs/user/) では、この機能を「ファジィ入力」と呼ぶ。
  候補の種類のタグ「補正」は「ファジィ」にする
- 仕様書では、機能の名前 (節の見出し・概要・索引) を「ファジィ入力」にする。仕組みを表す語 (全体変換の補正、
  補正の候補、ずれ、ずれのある予測) は今のまま使う
- 段階は、ユーザ向けには「ファジィ入力の強さ」と呼ぶ。段階に名前は付けない
- 設定ツールの「変換」ページでは、ほかの設定と同じカード (左に見出しと説明、右端にコントロール) を使う。Windows の
  設定のスライダーの項目と同じ形にする
  - 見出しは「ファジィ入力の強さ」。説明には今の値の挙動を下の表の 1 行で出し、値を変えると切り替える
  - 右端に「弱い」・スライダー・「強い」を並べる。スライダーは −1〜3、1 刻みで整数に吸い付き、目盛りは付けない。
    幅は 100px 前後の短いものにする (選べる値が 5 つしかないため)

| 値 | 説明に出す 1 行 |
|---|---|
| −1 | 打ち間違いを直さず、打ったとおりに変換する |
| 0 | 標準。確かな打ち間違いだけを直す (最後の文字は直さない) |
| 1 | 最後の文字の打ち間違いも直し、直した候補を先頭に並べる |
| 2 | 1 に加えて、打ち間違いの多い入力も直す |
| 3 | 直せる打ち間違いの数をさらに増やす。候補が出るまで少し遅くなる |

- 採らなかった案: コンボボックスで段階に名前 (「強め 1」など) を付けて選ぶ。名前から各段階の違いが分からない。
  スライダーなら強さの程度は位置で分かるので、名前の代わりに挙動を説明する
- 採らなかった案: スライダーをカードの幅いっぱいに伸ばし、その下に説明を置く。選べる値が 5 つしかないのに長すぎ、
  ほかの設定のカードとも形がそろわない
- 内部の名前 (`typo.rs`・候補の種類 `typo`・`predict_typo`・`Tuning` など) は変えない
- テーマのキー `typo`・`tag_typo` は利用者がファイルに書く値なので変えない (説明の文言だけ「ファジィ入力の候補」にする)

### I. 補正の語の枠を補正した読みごとにする

補正の語 ([engine.md](../spec/engine.md)「補正の語」) は、打ったかなの区間ごとにコストの安い `MAX_TYPO_WORDS` (6) 語までに
している。同じ区間を別の補正が覆うと、コストの安い語の多い補正が枠を埋め、ほかの補正の語が入らない。

- 例: 「すきでう」(sukidesu の s 抜け) の区間「でう」には、う を余分として消す補正の「で」(品詞違いで 7 件、コスト 0) と、
  す の抜けを足す補正の「です」(コスト 40) が集まり、6 語の枠が「で」などで埋まって「です」が入らない。段階を上げても
  「好きです」が出ない。末尾でない「すきでうね」でも、段階 0 では補正の候補が出ず、段階 1 でも「好きですね」が出ずに
  「好きデスね」になる
- 枠を「打ったかなの区間 × 補正した読み」ごとにする。1 つの補正の仮説が、別の仮説の語を枠から締め出さないようにするため
- 同じ補正した読みの中で、同じ語 (表記・品詞) が複数の位置から当たったときは今と同じく安いほうの 1 つにする。
  区間に置く語のうち、別の補正した読みから来た同じ語 (表記・品詞・区間が同じ) は安いほうの 1 つにする
- 枠の数 (補正した読みごとの語の数) は fuzzy_eval で 3・4・6 を比べて決める。比べるのは段階 0〜3 の崩した入力の回復、
  崩さない入力・打ちかけの入力で補正が上位に出る件数、1 打鍵ぶんの SUGGEST の時間
- 全体変換の補正と文節 UI の補正の両方に効く (同じ関数で語を足すため)

### H. 採らなかった案

- 段階 3 で先頭のかなも補正する・隣り合わないキーへの置き換えを扱う。先頭のかなの打ち間違いも、隣り合わないキーへの
  打ち間違いもまず起きず、誤補正の元になるため
- 段階を上げたときの補正の候補を 1-best の直後から並べる。利用者が明示的に強めたので、補正を優先して先頭に置く
- 印を文字 (「補正+1」など) で出す。ひと目で段階が分かりにくい
- 印を入力行の下線の色と太さで出す。入力行を出さない設定で見えない
- 印をパネルの縁の色で出す。縁を持たない `style ghost` で使えない
- 端で一周させる。弱めるキーで戻せるので要らない
- `typo_correction` の値の範囲を広げる。今 `typo_correction 0` と書いている人の設定が「段階 0 (自動補正あり)」と読まれ、
  意味が逆になる
- 文節 UI にも段階を効かせる。CONVSEG・CONVCTX は打鍵を受け取らず、補正の語も経路に 1 つだけの別の仕組みで、作業が
  大きく増える
- 補正の語の枠を表記の数で数える (品詞違いの同じ表記を 1 つと数える)。コストの安い別の語が多い区間では、また押し出される
- 段階 1 以上で補正の語の枠を広げる。段階 0 の押し出しが直らず、原因も残る

## 実装手順

1. エンジン: 設定 `fuzzy_level`、段階から `Tuning` を作る関数、許すずれの数
2. エンジン: 段階 1 以上の補正の候補の N-best と並び (CONVNBEST・SUGGEST)。単体テスト
3. エンジン: プロトコルの段階のフィールドと空の打鍵のフィールド。単体テスト
4. fuzzy_eval に段階の指定を足し、段階ごとの計測を取る
5. TSF 層: 設定・割当機能・run の段階・引き直し
6. TSF 層: 段階の印の描画
7. 設定ツール: `fuzzy_level` の選択と割当機能
8. 名前の変更 (画面の文言・タグ)
9. 仕様書・ユーザ向けドキュメント・protocol.md の書き換え

## 検証方法

### 自動テスト

- `cargo test` (engine・engine/gui)。足すテストの例:
  - 段階 −1 の SUGGEST で `typo`・`predict_typo` が出ない
  - 段階 0 の結果が段階のフィールドを付けない要求と同じ
  - 段階 1 で、末尾の打ち間違い (すきでう → 好きです) が補正の候補の先頭に出る
  - 段階 1 で補正の候補が最大 3 件で、表記が通常の候補と重ならない
  - 段階 2 で 3 打以下の打鍵でもずれのある予測が出る
  - 段階のフィールドが範囲外なら ERR、CONVNBEST の空の打鍵のフィールドがかなを戻した近似になる
  - `fuzzy_level` が無く `typo_correction 0` だけがある設定で −1 になる
- TSF 層のビルド

### 計測 (fuzzy_eval)

- 段階 0〜3 で、崩した入力の回復 (正解が 1 ページ目に出る割合) と 1 回の時間 (中央値・最大) を取る
- 段階 3 の最大時間が候補バーの打鍵ごとの引き直しに耐えるかを見る。目安を超えたら実装者は報告し、件数・増分の
  見直しはメインで決める

### 実機確認 (隔離したエンジンとメモ帳)

| 手順 | 期待 |
|---|---|
| `sukidesu` の打ち間違い `sukideu` を打って F2 | 印 ●○○、候補バーの先頭付近に「好きです」(ファジィのタグ・縁) |
| 続けて F2 を 2 回 | ●●○ → ●●●、候補が増える。もう一度 F2 でも ●●● のまま |
| Shift+F2 を 4 回 | ●●○ → ●○○ → 印なし → ⊘。⊘ ではファジィの候補が出ない |
| 段階 2 のまま 1 字打ち足す | 印は ●●○ のまま、候補が引き直される |
| run を確定キーで終えて次の run を打つ | 印なし (段階 0) に戻る |
| かな 1 文字だけ打って F2 | 候補が無くても印だけのパネルが出る |
| 変換キーで候補一覧を出して F2 | 一覧が作り直され、先頭にファジィの候補、選択は先頭 |
| `segment_ui 1` で変換中に F2 | 何も起きない (アプリにも渡らない) |
| `fuzzy_level 1` にして打つ | run の始めから ●○○ |
| 古い設定 (`typo_correction 0` のみ) で打つ | run の始めから ⊘ |
| 入力行なし・横一列 / 縦積み / `style ghost` / 反転表示 | 印が D の場所に出て、パネルの幅が足りる |
| 設定ツール | 「ファジィ入力の強さ」のスライダーと、値ごとに切り替わる説明の 1 行、キー割当に 2 項目 (既定 F2・Shift+F2)、保存で `fuzzy_level` だけが書かれる |
