# 実験 0a: 追記型入力 (F1 / F2)

入力モデル v2 (docs/design/input-model-v2.md) の段階0a。段階2 (フォールバック改善) の
方式を決めるための試作と比較の仕様。

## 背景と目的

direct 方式は、打鍵ごとにキャレット直前の run を置換して文字を入れる
(docs/design/direct-input.md「置換 edit session」)。置換するには文書を読み戻す必要がある。
そのため、読み戻せない次の2つの場面では composition 方式にフォールバックしている。

- 空の入力欄の冒頭: 周辺テキストが無く、CUAS と区別できない
- CUAS 経由のアプリ (WezTerm など): composition の外の文字列を次の打鍵で読み戻せない

置換が要るのは、未完成のローマ字 (`k` → `か`) を文書に入れているためである。
かなを追記だけで入れれば、読み戻しは要らない。本実験では、未完成のローマ字の扱いが異なる
2つの方式を試作し、次の点を確かめる。

- 打鍵の体感
- 空の欄の冒頭・CUAS アプリで direct 方式として動くか
- 置換できない文書で、擬似 Backspace を使った変換が安全にできるか

## 決定事項

### 切替

- 隠し設定 `direct_append` (config.tsv。値は `off` / `f1` / `f2`、既定 `off`) で切り替える。
  設定ツールには出さない
- `off` のときは現状の挙動から一切変えない
- `f1` / `f2` は `input_style` が `direct` のときだけ効く
- `f1` / `f2` のときは、ライブ変換を設定によらず無効にする (段階3の候補バーで置き換える
  予定のため、実験の対象外)

### 未完成のローマ字の扱い

| | F1 | F2 |
|---|---|---|
| 未完成のローマ字 (`k`、`ky`、`n` など) | 文書に入れず、キャレット付近の小窓に表示する | 未完成のローマ字だけを composition として文書に表示する |
| かなが完成したとき | かなを文書に追記し、小窓の表示を消す (残りの未完成ローマ字があれば表示を更新する) | composition をかなに書き換えて終了 (確定) する。残りの未完成ローマ字があれば、新しい composition を始める |
| 母音などで、未完成のローマ字を経ずにかなが完成したとき | 文書に追記する | 文書に追記する (composition を張らない) |

- F1 の小窓は、候補ウィンドウ (candidate_window.cpp) と同じ描画 (フォント・配色) にし、
  キャレット位置 (選択範囲の矩形) に重ねて表示する。サジェストの候補ウィンドウとは
  別の窓とし、重ならないようにサジェストはその下に出す。キャレットの矩形が取れない
  文書では、表示しなくてよい (実験の記録対象)
- `n` の扱い (`n` の後に子音が来たら「ん」を確定する) など、ローマ字の解釈は
  RomajiComposer の現状どおりとする。変えるのは文書への出し方だけ

### 文書の分類

フォーカス中の文書 (ITfDocumentMgr) ごとに、次の3つに分類する。`OnSetFocus` で未判定に戻す。

| 分類 | 意味 | 追記時の照合 | 置換 (変換・英字切替) の方法 |
|---|---|---|---|
| 未判定 | まだ読み戻しを試していない、または周辺テキストが無かった | しない | 次の追記で判定してから行う |
| 読める (Readable) | run の文字列を別の edit session から読み戻せた | する (run の文字列と一致しなければ run を捨てる) | 現状の置換 edit session |
| 追記のみ (AppendOnly) | 周辺テキストが無いか、run の文字列を読み戻せなかった | しない | 擬似 Backspace (後述) |

- 追記は、照合できない場合 (未判定・追記のみ) でもキャレット位置に挿入して行う。
  composition 方式へのフォールバックはしない
- 未判定の文書で、2文字目以降の追記時に run の文字列を読み戻せたら「読める」にする。
  読み戻せなかったら (周辺テキストが無い、または内容が違う) 「追記のみ」にする
- 空の欄の冒頭は、1文字目を追記した後の2文字目で「読める」になる想定。
  CUAS は「追記のみ」になる想定
- 判定の詳細 (読み戻しの手段) は、現状のフォールバック判定 (`ShiftStart` / `ShiftEnd`) の
  知見を流用してよい。照合で「キャレット移動による食い違い」と「読めない文書」を
  区別できないときは、未判定の文書に限り「追記のみ」側に倒す

### Backspace

- 未完成のローマ字があれば、それを1文字削る (F1 は小窓、F2 は composition の更新)。
  キーはアプリに渡さない
- 未完成のローマ字が無ければ、キーをアプリに渡して文書の文字を消させ、run の読み・表示の
  末尾から1文字 (UTF-16 で1単位ではなく、表示上の1文字) を削る。置換は行わない
- run の表示が空になったら run を終える
- アプリに渡した Backspace の後は、その run の打鍵列 (`Raw()`) と表示が対応しなくなる。
  その run はモードレスの英字判定の対象外にしてよい

### 変換 (変換キー)

- 読める文書: 現状どおり、run を composition に昇格して候補選択に入る (PromoteRun)
- 追記のみの文書: run の表示の文字数ぶん Backspace の擬似打鍵を送って文書から消し、
  消し終わってから run の読みで composition を張り、候補選択に入る。候補選択に入った後は
  composition 方式の候補選択と同じ (CUAS でも composition は動く)
- 未判定の文書: 読み戻しを試して分類してから、上のどちらかで行う

### 擬似 Backspace

- SendInput で VK_BACK を送る。送った打鍵は IME 自身のキー処理にも届くので、
  IME が送った数を数えておき、その数だけは処理せずにアプリへ渡す
- SendInput は非同期で、送った打鍵は今のキー処理が終わった後に届く。
  Backspace を送った直後に composition を張ると、順序が逆になって張った composition の
  側が消される。「Backspace がすべてアプリに渡った後」を検出してから composition を
  張る。手段の例: Backspace の後ろに目印の打鍵 (未使用の仮想キー、例えば VK_F24) を
  続けて送り、その打鍵を受け取った時点で composition を張る (目印の打鍵はアプリに
  渡さない)
- 擬似打鍵を送っている間にユーザが打鍵した場合の扱いは、実験では考慮しなくてよい
  (記録対象)

### run の終了 (追記のみの文書)

追記のみの文書では照合ができないため、キャレット移動を見落とすと、擬似 Backspace が
run とは別の文字を消す。次の契機で run を終える。

- 既存の契機: フォーカス移動、IME オフ、IME を経由しないキー (矢印・Home/End・Tab・Enter など)
- マウスクリックなどによるキャレット移動: `ITfTextEditSink::OnEndEdit` の選択変更
  (`ITfEditRecord::GetSelectionStatus`) が CUAS の文書でも届くかを調べる。
  届くなら、IME 自身の編集でない選択変更で run を終える。届かないなら、届かないことを
  記録する (段階2で対策を検討する)

### モードレス入力・サジェスト

- モードレスの英字切替で表示を作り直すとき (`あっp` → `appl`): 読める文書では現状の置換、
  追記のみの文書では擬似 Backspace のあとに英字を追記する。F1 で未完成のローマ字だけが
  変わる場合は、小窓の更新だけで済む
- サジェスト: 読める文書では現状どおり。追記のみの文書では表示しない (実験の対象外)

### 実験用ログ

- 隠し設定 `debug_log` (config.tsv。値はログファイルのパス、未設定なら出さない) を設けて、
  次を1行ずつ追記する。プロセス ID と時刻を付ける
  - 文書の分類が決まった・変わった (理由: 読み戻し成功 / 周辺テキストなし / 内容不一致)
  - 擬似 Backspace の送信数と、目印の打鍵を受け取ったこと
  - OnEndEdit の選択変更を受け取ったこと (IME 自身の編集かどうか)
  - 追記のみの文書で run を終えた契機
- ログは実験の終了後に段階2で取り除くか残すかを決める

## 実装手順

1. 設定 `direct_append` / `debug_log` とログ出力
2. 文書の分類と、照合付き / 照合なしの追記 (F1・F2 共通部分)。ライブ変換の無効化
3. F1: 未完成ローマ字の小窓
4. F2: 未完成ローマ字の composition
5. Backspace (未完成ローマ字の削除、アプリへの受け渡しと run の追従)
6. 変換: 読める文書の昇格、追記のみの文書の擬似 Backspace + composition
7. 追記のみの文書の run 終了 (OnEndEdit の調査を含む)
8. モードレスの英字切替の対応

各手順の後に `direct_append` = `off` で既存の挙動が変わっていないことを確認する。

## 検証方法

ビルドと既存の動作確認 (`off` での回帰) は実装者が行う。以下の比較は、開発版 DLL に
切り替えたうえで (scripts\dev-deploy.ps1 -Dll)、メモ帳などのテスト用アプリで行う。

### テストケース

| # | 環境 | 操作 | 期待 (F1 / F2 共通。差は「観点」に記録する) |
|---|---|---|---|
| 1 | メモ帳 (中身あり) | `kyouha` | 「きょうは」が入る。F1 は `k` `ky` が小窓に、F2 は下線付きで出る |
| 2 | メモ帳 (空) | 空の状態から `kyouha` | 1文字目から direct 方式で入り、ログで2文字目以降に「読める」になる |
| 3 | Chrome の空の検索欄・テキストエリア | `kyouha` → 変換キー → 確定 | 冒頭から direct 方式で入り、変換・確定できる |
| 4 | Chrome の文字数固定・自動で次欄へ移る欄 (郵便番号・電話番号など) | 数字とかなの入力 | 欄の移動が誤動作しない (特に F2 の1文字 composition) |
| 5 | WezTerm | `kyouha` | 「きょうは」が入り、ログで「追記のみ」になる。1文字目が二重に残らない |
| 6 | WezTerm | `kyouha` → 変換キー → 確定 | 擬似 Backspace で「きょうは」が消え、composition の候補選択を経て変換結果が入る |
| 7 | WezTerm | `kyou` → マウスで別位置をクリック → `ha` → 変換キー | run が終わっていて、別の文字が消されない。終わらない場合はその旨とログを記録する |
| 8 | 各環境 | `kyous` → Backspace ×2 | 未完成の `s` が消え、次の Backspace で「う」が消える |
| 9 | Word | `kyouha` → 変換キー → 確定 | 「読める」で動く |
| 10 | 各環境 (モードレス ON) | `apple` | 英字に切り替わる。WezTerm では擬似 Backspace 経由で切り替わる |
| 11 | `direct_append` = `off` | 既存の direct 方式のテスト (direct-input.md のテストケース) | 現状と同じ |

### 記録する観点

- 打鍵の体感 (F1 で未完成のローマ字が文書の外に出る違和感、小窓の位置)
- 空の欄の冒頭・CUAS で direct 方式になったか
- F2 の1文字 composition が不安定なフォームで問題を起こさないか
- 擬似 Backspace が誤った文字を消さないか、打鍵中の割り込みで乱れないか
- OnEndEdit の選択変更が CUAS で届くか

## 判断基準

- 体感はユーザが判断する
- F2 が不安定なフォームで問題を起こすなら F1 を採る
- 擬似 Backspace が安全に使えない (キャレット移動を検知できない、順序が乱れる) なら、
  段階2で CUAS 向けの代案 (CUAS では composition 方式を残す、など) を検討する
