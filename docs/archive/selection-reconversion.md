# 漢字を含む選択範囲の再変換 (逆変換)

## 背景と目的

run が無いときの選択範囲の再変換 (後置再変換) は、ひらがな・カタカナ・ー だけの選択に限られている
(docs/archive/conversion-range.md)。漢字を含む部分を直せるのは、IME が入れた文字列の記憶と一致する
ときだけで (docs/archive/adopted-reconversion.md)、ほかのアプリで入れた文字列・記憶を捨てた後の文字列・
別の IME で入れた文字列は、読みを打ち直すしかない。

表記から読みを推測する逆変換をエンジンに足し、漢字を含む任意の選択範囲を変換キー・F6〜F10 で
再変換できるようにする。

## 決定事項

### A. 対象

[docs/spec/conversion.md](../spec/conversion.md)「漢字を含む選択の再変換」の「対象」へ移した

### B. 逆変換 (エンジン)

表記を、文節ごとの (読み, 表記) の列にする。結果は 1-best の 1 通りだけを返す。

- 表記の文字の格子に、表記で引いた語を並べ、今の変換と同じ語のコストと連接コストで Viterbi を
  かけて最小コストの経路を選ぶ
- 語の引き方:
  - 漢字・々 を含む表記: 表記をキーにした逆引きの索引 (下記) で、表記の前方一致の語を引く
  - かなだけの表記: 読みは表記そのもの (カタカナはひらがなに直す) に決まるので、今の読みの辞書を
    その読みで引き、表記が一致する語を使う。逆引きの索引には入れない
  - 数字の並び: 読みは数字そのもの (半角・全角は元のまま) の 1 語にする。今の変換の
    `merge_digit_runs` でまとめた数字の語と同じ扱い。表記に数字を含む辞書の語 (3日 → みっか など) は
    使わない。読みから数字が消え、再変換の候補が打った数字から作られなくなるため
  - 数字の直後の助数詞の読み: 辞書には助数詞の読みが複数あり、数字の後では使わない読みの方が安いことが
  ある (日 は ひ 1734・にち 1826、人乗り は ひとのり・にんのり。品詞が同じで連接コストも同じため
  語のコストで決まる)。数字の後の読みの表 (`reverse.rs` の定数) を持ち、次をすべて満たす語を格子から外す
  - 数字の並びの直後から始まる
  - 品詞が `名詞,接尾,助数詞` (id.def の 2 列目が 接尾・3 列目が 助数詞)
  - 表記が表の見出しで始まる (複数の見出しが当たるときは最長のもの)
  - 読みが表の読みのどれでも始まらない。比べるときは濁点・半濁点を外す (ぷん・ぶん は ふん で受ける)
  - 学習にある (読み, 表記) の組でない
  - 表 (見出し → 数字の後の読み):
    日 → にち、人 → にん、時・次・字 → じ、年 → ねん、歳 → さい、名 → めい、問 → もん、巻 → かん、
    戦・銭 → せん、話 → わ、種 → しゅ、色・食 → しょく、軒 → けん、店 → てん、戸・個 → こ、
    床・勝・章 → しょう、球 → きゅう、泊 → はく、畳 → じょう、元 → げん、円 → えん、合 → ごう、
    世 → せい、体 → たい、位 → い、通 → つう、連 → れん、重 → じゅう、品 → ひん、棟 → とう、
    行 → ぎょう・こう、分 → ふん、か月・カ月・ヶ月・ヵ月・ケ月 → かげつ
  - 表に入れないもの: 数字の後でどちらの読みも使う助数詞 (羽・把・割・枠・夜・石・文) と、
    今の辞書で正しく読める助数詞 (月 など)
  - 見出しは語の先頭だけを見るので、単位の後ろの部分の読み (キロ位 → きろい) は直らない
    (docs/roadmap.md の既知の問題)
- どの語にも当たらないかな 1 文字: 読みはその文字 (ひらがなに直す) の語を置く。コストは高くする
  - 辞書の語に当たらない漢字 1 文字: 単漢字辞書 (single_kanji.tsv) を逆に引いた読みの語を置く。
    コストは辞書の語より高くする
- 逆引きの索引: システム辞書 (Mozc + UT) とユーザ辞書のうち、表記に漢字・々 を含む語だけを、
  表記の前方一致で引けるようにする
  - 持ち方: 対象の語の辞書内の位置を表記の順に並べた配列にし、二分探索で範囲を絞って引く。
    語の読みは、読みの run の開始位置の配列から run を求め、読みの fst を値から逆に引いて得る
    (UT 込みで約 161 万語・約 13.5MB)
  - 構築: システム辞書の分は、エンジンが待ち受けを始めた後に別スレッドで作る (約 1 秒)。
    できるまでの REVERSE は ERR を返す (変換キーは今どおりアプリへ渡る)。ユーザ辞書の分は
    読み込み時と RELOADUSER で作る (インポート辞書は同じ索引、手動登録の語は件数が少ないので線形に見る)
- 学習: 学習にある (読み, 表記) の組は、同じ表記の別の読みより優先する
  (その人がその表記をその読みで打ったことがあるため)。学習にある組の語があれば、同じ位置・同じ表記で
  読みの違う語を格子から外す。変換と同じ学習の割引だけでは、辞書のコストの差
  (きょう/今日 と こんにち/今日 など) を覆せないため
- どの経路でも格子が繋がらない (読めない文字がある) ときは失敗を返す
- 文節: 結果の単位は Viterbi の語にする。文節にまとめない (記憶の文節と同じく、前文脈と
  学習の判定 (E) にしか使わないため)

### C. プロトコル

新しいコマンド REVERSE を足す。

```
REVERSE\t<表記>
→ OK\t<読み>\x1f<表記>\t<読み>\x1f<表記>...
→ ERR (読めない文字がある・対象外の文字がある)
```

### F. 採らなかった案

ITfFnReconversion・逆変換の読みを複数返す案・範囲全体を学習する案は [docs/spec/conversion.md](../spec/conversion.md)「漢字を含む選択の再変換」の「採らなかった案」へ移した

- 逆引きの索引にすべての語 (かなだけの表記を含む) を入れる案。かなの表記は読みが決まっているので
  読みの辞書で引けば足り、索引のメモリが増えるだけのため
- 逆引きの索引を「表記 + 読み」をキーにした fst にする案。表記が先頭のキーは圧縮が効かず
  (約 70MB)、起動時の構築に約 4 秒かかったため
- 語の読みを索引の中の文字列の表に持つ案。検索は約 4 倍速いが (1 回約 1.5µs と約 6µs)、
  メモリが約 3 倍 (約 44MB) になり、選択 1 回の逆変換では速さの差が問題にならないため
