# 予測を語の単位にする (頭の語・付属語の後続語予測・前文脈の連結)

## 背景と目的

候補バーの予測は、句の学習 (確定した文節) を打鍵と前方一致で照合して出す。文節は「東京の」「東京が」のように
自立語に付属語が付いた形で覚えるので、学習が溜まると次の問題が起きる。

- 「とうき」の時点で「東京の」「東京が」…が上位を埋め、助詞の付かない「東京」が沈む。別の助詞を続けたいときや
  文の終わりで、欲しい候補が出ない
- 句の学習の点数 (`PHRASE_BASE` − 割引) は辞書の語の予測 (`PREDICT_BIAS` 2000 を足す) より強く、語の学習の割引だけでは
  逆転しない
- 「東京の」を選んで「の」を消すほうが速いので、学習には「東京の」が残り、使い続けても直らない

語を打ち切るまでは語だけを予測し、語を打ち切ったときにだけ語 + 付属語の句を出す。確定後の後続語の予測も、
「名詞 → 付属語 → 次の語」と語の単位で続くようにする。

## 決定事項

### 頭の語

句 (読み, 表記) の頭の語を次のように決める。

1. 句を `split_path` で辞書の語に分ける。分けられない句 (辞書の語に分けられない句) は頭の語を持たない
2. 句の最初の文節 (付属語の後に自立語が来る手前まで。文節のまとめ方は変換と同じ) を取る
3. 最初の文節の末尾が、名詞系の語 (品詞名が `名詞` で始まる語。`名詞,接尾` を含む) の後ろに助詞・助動詞の語が 1 つ以上
   続く形なら、その名詞系の語までが頭の語 (読み・表記はその範囲の連結)。それ以外の形の句は頭の語を持たない

| 句 | 頭の語 |
|---|---|
| 東京の・東京です・雨が | 東京・東京・雨 |
| 田中さんが | 田中さん (「さん」は `名詞,接尾`) |
| 静かな | 静か (形容動詞語幹は `名詞,形容動詞語幹`) |
| 今日はいい天気 (種類 `whole`) | 今日 (最初の文節「今日は」に当てる) |
| 食べました・よろしくお願いします・東京 | なし |
| マイグラフィは (分けられない句) | なし |

- 句ごとの頭の語はメモリ上に覚えておき、句ごとに 1 回だけ求める。ファイルには書かない。ユーザ辞書を読み直したとき
  (RELOADUSER・ADDWORD など、分け方が変わりうるとき) は覚えた結果を捨てる
- 採らなかった案
  - 自立語すべて (動詞・形容詞を含む) を頭の語にする。「食べました」の頭の語が「食べ」のような語幹になり、候補にならない
  - 分けられない句の末尾の助詞を推定して外す。手間に見合わず、分けられない句は少ない

### 打ち始めた後の予測 (SUGGEST)

句の学習と文脈の句の学習の照合 (engine/src/predict.rs `scored`) を次のようにする。

- 頭の語を持たない句は今のまま
- 頭の語を持つ句は、打鍵が頭の語の読みを打ち切っているかで分ける
  - 打ち切った (読みの頭の語の長さ以上の位置で打鍵を使い切る照合がある): 今のまま句を出す (「とうきょう」「とうきょうn」で
    「東京の」「東京が」)
  - 打ち切っていない (照合できるが、使い切る位置がすべて頭の語の途中): 句の代わりに頭の語を候補に出す。点数は句の点数
    (句の学習の割引・前文脈の文脈の句の学習の割引・ずれのコスト) をそのまま使う。読みは頭の語の読み
- 同じ頭の語を持つ句は、今の表記の重複の規則 (点数の小さいほうの 1 件) で 1 件にまとまる
- 句の学習の件数の打ち切り (`max_predictions` 件) は、頭の語に置き換えたあとの候補で数える (置き換え前に切ると、
  同じ頭の語の句で枠を使い切るため)
- 頭の語の候補の種類は `predict` (ずれを使えば `predict_typo`)。人名の印は付けない
- 頭の語を採用したときの学習は、今の予測候補の採用と同じ (頭の語の読みと表記を前文脈の表記を付けて送る)。「東京」が
  句の学習に入るので、使うほど頭の語が強くなる
- 頭の語の長さ以上の位置での照合には、`typo::Matcher` に読みの途中から先の位置だけで使い切りを見る照合を足す
- PREDICT (旧エンジンとの互換の経路) は変えない

### 後続語の予測 (NEXTWORD)

前文脈 (下記「前文脈の連結」で連結したもの) を `split_path` で辞書の語に分け、最後の語が名詞系で後ろに付属語が無い
(助詞の付かない名詞で終わる) かで分ける。

**名詞で終わるとき** (「東京」): 付属語を出す。次の順に並べ、表記の重複は先勝ちで除く。

1. 文脈の句の学習 (前文脈の表記で引く。割引の大きい順。今と同じ)
2. 句の学習のうち、頭の語の (読み, 表記) が前文脈と同じ句の残りの部分 (「東京の」の「の」)。割引の大きい順
3. 統計の付属語の表 (下記「付属語の表」) を、前文脈の最後の名詞系の語の表記で引いた件。回数の多い順

- 文節の表とバックオフの表は引かない (助詞の付かない名詞の後に次の文節を出すと、「東京」の後に「大学」のような
  句の後ろの語が出るため)

**それ以外** (「東京に」「食べました」): 今と同じ 3 つ (文脈の句の学習・文節の表・バックオフの表) を引き、各候補を頭の語に
置き換えてから表記の重複を除く (「雨が」「雨の」→「雨」)。付属語だけの候補 (「には」) はそのまま。

- 頭の語の候補を採用すると、次は名詞で終わる前文脈になり、付属語を出す。「名詞 → 付属語 → 次の語」と続く
- 採らなかった案: 固定の頻出助詞の一覧を付属語の候補にする。前の名詞によらず同じ並びになる

### 付属語の表

next_word.tsv に 3 つ目の表を足す。

- 付属語の表 (`s`): 名詞系の語の表記 → その後ろに続いた付属語 (助詞・助動詞の語の連続) の (読み, 表記) と回数
- 数え方: 文節の末尾が「名詞系の語 + 助詞・助動詞の語の連続」の形のとき、その名詞系の語の表記をキーに、付属語の連続を
  1 回数える。名詞系の語が `名詞,接尾` (さん・都) なら、そのまま「さん」をキーにする
- 除くもの・最小回数 (15)・上位 36 件・行の書式・ファイル名は、今の 2 つの表と同じ。行の表の区別が `s` になる
- 生成ツールの終わりの出力に、付属語の表の文脈の数と件数を足す
- 表を作り直すまで (`s` の行が無い表) は、名詞で終わるときの候補は学習だけになる

### 前文脈の連結

助詞の付かない名詞を確定し、続けて付属語だけを確定すると (「東京」→「に」)、前文脈が「に」になり、後続語の予測にも
文脈の句の学習にも役立たない。この組のときは前文脈を連結する (「東京に」)。

- TSF 層は、前文脈 (直前に確定した文節) に加えて、その 1 つ前の文節 (読み, 表記) を持つ。1 つ前の文節は、同じ確定の
  中の前の文節でも、前の確定の最後の文節でもよい。前文脈を捨てるときは 1 つ前の文節も捨てる。前文脈を run 全体のかな
  (読み = 表記) にするときなど、前文脈を置き換えるときは、置き換える前の前文脈を 1 つ前の文節にする
- 前文脈を送るコマンド (CONVCTX・CONVNBEST・SUGGEST・PREDICT・NEXTWORD) の文脈のフィールドを
  `<文脈読み>\x1f<文脈表記>[\x1f<前の読み>\x1f<前の表記>]` にする。LEARN2 の各組は
  `<読み>\x1f<表記>\x1f<文脈表記>[\x1f<文脈読み>\x1f<前の読み>\x1f<前の表記>]` にする (TSF 層は先頭の組にだけ付ける。
  2 つ目以降の組の文脈は同じ確定の中の文節で、今のまま)
- エンジンは文脈を読むところで連結を判定する (engine/src/main.rs `parse_context` と LEARN2 の受付)。前の文節が名詞で
  終わり (上記「後続語の予測」と同じ判定)、前文脈が助詞・助動詞の語だけに分けられるとき、前の文節 + 前文脈を前文脈にする。
  それ以外は今の前文脈のまま
- 連結は 1 段だけ (「東京」→「に」→「は」の「は」は「に」とつながず、前文脈は「は」)
- 付け足したフィールドが無い要求は今と同じに扱う
- 採らなかった案
  - 確定のたびに、次の前文脈をエンジンに問い合わせる新しいコマンド。往復が 1 回増え、学習しないアプリでも送ることになる
  - 連結しない。助詞の後の後続語の予測がほぼ出なくなる

### 範囲外

- Space・Enter で run を終えたときに後続語の予測を出さないことの見直し ([roadmap.md](../roadmap.md)) は、この変更とは別に扱う

## 実装手順

1. pos.rs・convert.rs: 品詞の判定と、句の頭の語・名詞で終わるかの判定。テストで上の表の例を確かめる
2. typo.rs: 途中から先の位置で使い切りを見る照合
3. learn.rs・predict.rs: SUGGEST の頭の語。頭の語の記憶とユーザ辞書の読み直しでの破棄
4. build_next_word.rs・predict.rs: 付属語の表の生成と読み込み、`next_words` の変更
5. main.rs: 文脈のフィールドの拡張と連結
6. TSF 層: 1 つ前の文節の保持と送信
7. learning_eval.rs: 判定の変更
8. 仕様書・文書の書き換え

## 検証方法

単体テスト (例)

- 頭の語: 上の表の各句
- SUGGEST: 「東京の」「東京が」を学習して
  - `touki` で「東京」が 1 件だけ出て、「東京の」「東京が」が出ない。点数は「東京の」の句の点数
  - `toukyou` で「東京の」「東京が」が出る。`toukyoun` で「東京の」が出て「東京が」が出ない
  - 「食べました」を学習して `tabe` で「食べました」が出る (頭の語なし)
  - 「今日はいい天気」(whole) を学習して `kyo` で「今日」、`kyou` で「今日はいい天気」
  - ずれのある打鍵 (`tpukyo`) でも頭の語が出る
- NEXTWORD
  - 前文脈「東京」で、「東京に」の学習から「に」、付属語の表から「の」「は」が出て、文節の表の「大学」が出ない
  - 前文脈「今日は」で、文節の表の「雨が」「雨の」が「雨」の 1 件になる
  - 付属語の表が無い表でも、学習から付属語が出る
- 前文脈の連結
  - `NEXTWORD\tに\x1fに\x1fとうきょう\x1f東京` が前文脈「東京に」で引く
  - 前の文節が「東京の」(名詞で終わらない) や、前文脈が「行く」(付属語だけでない) ではつながない
  - LEARN2 の先頭の組に前の文節を付けると、文脈の句の学習の文脈が「東京に」になる
  - フィールドを付けない要求は今と同じ結果
- 付属語の表の生成: 小さい入力の本文で `s` の行が数えた回数で書かれる

評価

- `learning_eval` の予測の判定 (`p`・`q` の行。読みの先頭 50% の打鍵で SUGGEST を引く) は、打鍵が正解の句の頭の語を
  打ち切っていなければ頭の語を正解とする。変更前の判定の割合も並べて出し、変更前後で比べる
- `learning_eval --next-word` で、名詞で終わる前文脈の行と、それ以外の行に分けた割合を変更前後で比べる
- 付属語の表は、4 分割の本文から作り直した表で測る (生成は数時間かかるので、利用者が実行する)

実機 (隔離したエンジンとメモ帳で)

- 学習を空にして「東京の」「東京が」を何度か確定し、`touki` で「東京」だけが出る。選んで確定キーで確定すると後続語の予測に
  「に」「の」などの付属語が並ぶ。「に」を採用すると、続く後続語の予測が「東京に」の後の語になる
- 「とうきょう」まで打つと「東京の」「東京が」が出る
