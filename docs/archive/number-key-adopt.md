# 数字キーと Ctrl+数字キーによる候補の採用

## 背景と目的

候補バー (run のサジェスト・後続語の予測) と変換の候補一覧では、数字 1〜9 がページ内の番号の候補を
選ぶだけで、採用・確定は別のキーで行う。数字の打鍵が状態によって「入力」と「選択」に分かれ、
選んだ候補を入れるのに 2 打鍵かかる。

- 数字キー (修飾なし) は、どの状態でも文字キーと同じ扱いにそろえる
- 番号での採用・確定は Ctrl+数字キーで行い、候補を出しているパネル全般で働かせる

## 決定事項

### 数字キー (修飾なし)

上段の数字 1〜9 を、ほかの印字キー (英字・記号・0・テンキー) と同じに扱う。候補番号の選択はしない。

| 状態 | 動作 |
|---|---|
| run 中 (バー未選択) | 読みに追加する (今どおり) |
| バー選択中 (run あり) | 選択中の候補を採用し、その数字から打ち続ける (`BarAdopt::Continue`) |
| 後続語の予測の選択中 (run なし) | 選択中の候補を入れ、その数字で新しい run を始める |
| 候補選択中 | 選択中の候補で確定し、その数字で新しい run を始める |

- 後続語の予測の選択中は、`digits half` でも数字をアプリへ素通しせず run を始める
  (ほかの印字キーと同じ経路。予測の採用と数字の入力を 1 打鍵で順序どおりに行うため)

### Ctrl+数字キー

上段の数字 1〜9 に Ctrl を足した打鍵 (Shift・Alt なし) は、候補を出しているパネルがあるとき、
今出しているページ内のその番号の候補を採用・確定する。

| 状態 | 動作 |
|---|---|
| run 中でバーが出ている (未選択・選択中とも) | その番号の候補を、確定キーと同じく採用する (`BarAdopt::CommitKey`) |
| 後続語の予測が出ている (未選択・選択中とも) | その番号の候補を、確定キーと同じく入れる (続けて次の語の予測を出す) |
| 候補選択中 | 現在の文節 (入力全体の候補選択では入力全体) でその番号の候補を選び、変換全体を確定する (Enter と同じ確定。アプリへ Enter は渡さない) |
| 上記以外 (パネルが無い) | 今どおり (run 中は run を終えてアプリへ渡す。入力なしはアプリへ渡す) |

- パネルが出ている間は、ページ内に無い番号でも打鍵を食べて何もしない。アプリのショートカット
  (ブラウザの Ctrl+1〜9 のタブ切り替えなど) より、パネルの操作を優先する。後続語の予測は確定の直後に
  自動で出るため、出ている間はアプリの Ctrl+数字が効かない
- 採用範囲を縮めた全体変換 (unified-suggest.md の F) は、番号で選び直すと採用範囲が元に戻る
  (今の選択の移動と同じ)。選択中の候補と同じ番号でも全体を採用する
- Ctrl+0・テンキーの Ctrl+数字は対象外 (今どおり)
- キー割当 (keymap.md) の機能にはせず、数字キーと同じく固定にする。Ctrl+1〜9 (Shift なし) は割当の
  対象外にする (設定ファイルに書かれても無視し、設定ツールでは受け付けない)。割当を許すと、割り当てた
  番号の候補だけが Ctrl+数字で採用できなくなるため。Ctrl+Shift+数字・Ctrl+0 は今どおり割り当てられる
- 追記のみの文書での run の採用は、今の Ctrl+M (Enter) での採用と同じく擬似 Backspace と追記で行う。
  擬似 Backspace は Ctrl を離した状態で送られる (`SendKeyWithModifiers`)。run 中の Ctrl 併用を
  「run を終えて送り直す」扱い (`PanelKeyNeedsResend`) からは、パネルが出ているときの Ctrl+1〜9 を外す

### 採らなかった案

- 数字キー (修飾なし) をバー選択中だけ「選んで採用」にする案: 数字の打鍵が状態で入力と採用に分かれたままで、
  未選択のときは番号で採用できない
- 後続語の予測では選択中のときだけ Ctrl+数字を食べる案: 衝突は避けられるが、パネルが出ている間は IME が
  食べる、という規則のほうが分かりやすいため採らない
- 設定での切り替え: 選ぶだけの操作は Tab / ↑↓ で残るので設けない

## 実装手順

1. TSF 層・設定ツールで Ctrl+1〜9 を割当の対象外にする (`cargo test` が通ること)
2. 修飾なしの数字の候補番号の選択を外し、印字キーの経路に流す (バー・後続語の予測・候補選択中)
3. Ctrl+1〜9 の判定 (食べるか) と処理 (採用・確定) を、run のバー・後続語の予測・候補選択中に足す。
   `DismissNextWordForKey`・`PanelKeyNeedsResend` を合わせる
4. ドキュメント

## 検証方法

TSF 層は開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、`QUICKLIME_PIPE_NAME`・`QUICKLIME_CONFIG_FILE`・
`QUICKLIME_LEARN_FILE`・`QUICKLIME_USER_DICT_FILE` で隔離したメモ帳で行う。テスト前に
`taskkill /IM Notepad.exe /F` と旧エンジンプロセスの終了を行う。追記のみの文書は WezTerm で確かめる。
