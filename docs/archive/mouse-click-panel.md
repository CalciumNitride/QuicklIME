# 入力パネルの外のマウス操作で入力を終える・後続語の予測を時間で消す

## 背景と目的

同じアプリの中で入力欄以外 (余白・ボタン・メニューなど) を押しても、TSF の文書のフォーカスが変わらず
(`ITfThreadMgrEventSink::OnSetFocus` が来ない)、キャレットも動かないことがある。そのとき入力パネル
(run の候補バー・入力行・変換の候補一覧・後続語の予測) が出たまま残る。

- WezTerm・マビノギで起きる
- マビノギはチャット欄の外ではキーを TSF に通さない (診断ログで、チャット欄の外の打鍵が `OnTestKeyDown` に
  1 件も届かず、フォーカスの通知も無いことを確かめた)。そのため、外での Esc などのキーでは消せず、
  パネルが残り続ける

入力パネルを出している間に、パネルの外でマウスのボタンが押されたら、入力を終えてパネルを消す。
あわせて、マウスもキーも IME に届かない場面 (マビノギでキーボードだけでチャット欄を抜けたときなど) で後続語の予測が
残らないよう、選んでいない後続語の予測を一定時間で消す。

## 決定事項

### マウスの押下の契機

- 入力パネルを出している間だけ、文書のスレッドに限ったマウスフック (`SetWindowsHookEx(WH_MOUSE, proc, nullptr,
  GetCurrentThreadId())`) を付け、パネルを消したら外す。パネルを出していないときはフックを付けない
- 次のメッセージで働く: `WM_LBUTTONDOWN`・`WM_RBUTTONDOWN`・`WM_MBUTTONDOWN`・`WM_XBUTTONDOWN` と、その非クライアント
  領域版 (`WM_NC*BUTTONDOWN`)。ダブルクリック (`*BUTTONDBLCLK`) も同じに扱う。ホイール・移動・ボタンを離す操作では働かない
- 押した先 (`MOUSEHOOKSTRUCT::hwnd`) が入力パネルのウィンドウなら働かない
- マウスの操作は食べずに、そのままアプリへ渡す (フックは `CallNextHookEx` の結果を返す)
- 入力欄の中を押したときも働く (キャレットを同じ位置に置いたときも含めて、パネルの外の押下はすべて同じに扱う)

### 押されたときの処理

IME オフになったとき (docs/spec/input.md「IME のオン/オフ」) と同じ後始末をする。IME はオンのまま。

| 状態 | 処理 |
|---|---|
| run 中 (候補バーで選んでいるときを含む) | 見えているとおりの読み (未完成のローマ字もそのまま) を文書に入れて run を終える (`CommitRunText(context, composer_.Display())`)。候補バーの選択は採用しない |
| 候補選択中 (composition がある) | 今の選択で確定する (`CommitComposition`) |
| 後続語の予測 | 消す (`ClearBar`) |

- いずれも、続けて後続語の予測を出さない
- 前文脈・LLM の左文脈の履歴 (`ClearContext`)・採用した文字列の記憶を捨てる。押した操作でキャレットが動かされうるため
- 文書は、そのとき TSF のフォーカスにある文書の最上位の context (`threadMgr_->GetFocus` → `GetTop`) を使う
  (IME オフの処理と同じ)
- 書き込みはフックの中で、アプリが押下を処理する前に行う。フックの中で edit session が同期で走らず書き込めなかったときは、
  `CommitRunText` の既存の失敗時の処理 (run を捨てる) に任せる

### 後続語の予測を時間で消す

- 後続語の予測を出してから、選ばないまま設定 `next_word_timeout` の秒数がたったら予測を消す (`ClearBar`)。前文脈などの
  状態は、選んでいないときの打鍵で予測を消すときと同じく捨てない
- 選んでいないときは、選択の機能と Ctrl+1〜9 以外のキーで予測がもともと消えるので、測るのは出してからの時間でよい
  - `NextWordNext` / `NextWordPrev` で選んだら止める (選んでいる間は時間で消さない)
  - Ctrl+1〜9 で採用して次の語の予測を出したら、出し直した時点から測り直す
  - 予測を消したとき (どの契機でも) は止める
- 実装はスレッドのタイマー (`SetTimer(nullptr, 0, ms, proc)`)。手続きは static 関数で、マウスフックと同じ thread_local の
  ポインタで `TextService` を引く。発火時に、予測を出していて選んでいないことを確かめてから消す
- run (入力中のパネル)・変換の候補一覧は時間で消さない。消すには読みを確定するか捨てるかが要り、確定は利用者の操作なしに
  文書を書き換え (docs/spec/input.md「文書を自動で書き換えない」に反する)、捨てると入力を失い、パネルだけ隠すと見えない
  読みが残るため

### 設定 `next_word_timeout`

| 項目 | 内容 |
|---|---|
| 読む側 | TSF 層 |
| 値 | 秒数。選択肢は `0` (時間で消さない)・`3`・`5`・`10`・`30`・`60` |
| 既定 | `5` |
| 選択肢に無い値 | 次に大きい選択肢へ切り上げ、`60` を超える値は `60` にする (`max_predictions` と同じく、TSF 層と設定ツールで同じ規則)。数でない値は無視して既定のまま |
| 設定ツール | 「候補バー」のページ、「確定の後に次の語を予測する」の次に「次の語の予測を消すまでの時間」のコンボボックス。選択肢の表示は「消さない」「3 秒」「5 秒」「10 秒」「30 秒」「60 秒」 |

### 採らなかった案

- 入力中のパネル (run) も時間で消す: 上記「後続語の予測を時間で消す」の最後の項目の理由
- 後続語の予測だけを消し、入力中のパネルは残す: マビノギではチャット欄の外でキーが IME に届かず、パネルが残り続けるため
- 押したときに読みを捨てる (フォーカス移動と同じ): うっかり押すと入力を失うため
- 入力欄の外での Esc でパネルを消す: マビノギではチャット欄の外の打鍵が TSF に届かない。スレッドに限ったキーボードフックも
  届かない見込みが高く、低レベルのキーボードフック (`WH_KEYBOARD_LL`) はゲームのプロセスから全アプリのキーを見ることになり、
  チート対策のソフトに疑われる恐れがある
- `ITfThreadFocusSink::OnKillThreadFocus` で消す: ウィンドウの切替では今も消えており、同じアプリの中の押下は捉えられない

## 変更対象ファイル

- `tsf/src/text_service.h` / `tsf/src/text_service.cpp` (必要なら `tsf/src/text_service_direct.cpp`)
  - フックの付け外し: 入力パネルが見えている (`suggestPanel_.Visible()`) 間だけ付ける。パネルを出す所・消す所で状態を
    合わせる関数を 1 つ用意して呼ぶ。`Deactivate` でも外す
  - フックの手続きは static 関数。スレッドの `TextService` は thread_local のポインタで引く
  - 押下の処理 (上記「押されたときの処理」)。IME オフの処理 (`OnChange`) と共通にできる部分は共通にする
  - 診断ログ: 押下で入力を終えたこと (状態と押した先のメッセージ)
  - 後続語の予測のタイマー: 予測を出す所 (`ShowNextWordBar` など) で始め、選んだとき・予測を消すとき・`Deactivate` で止める。
    発火で予測を消し、診断ログに「時間で後続語の予測を消す」を出す
- `tsf/src/config.h` / `tsf/src/config.cpp`: `next_word_timeout` を読む (上記「設定 `next_word_timeout`」の丸め)
- 設定ツール
  - `engine/gui/src/config.rs`: `next_word_timeout` の読み書き・選択肢の定数・丸めの関数とそのテスト
  - `engine/gui/src/bin/quicklime-config.rs`: 画面との受け渡し
  - `engine/gui/ui/settings.slint`・`engine/gui/ui/pages/candidate-bar-page.slint`: コンボボックス
- `tsf/src/suggest_panel.h` (必要なら `.cpp`): 押した先が入力パネルのウィンドウかを判定する手段 (ウィンドウハンドルを
  返す・比較する関数)
- 仕様書
  - `docs/spec/input.md`「run の終わり方」の表に「入力パネルの外でマウスのボタンを押した」の行を足し、本書の契機・
    処理・採らなかった案の要点 (WHY) を書く
  - `docs/spec/suggest.md`「後続語の予測」「出すとき・消すとき」の「消すとき」に、入力パネルの外でのマウスの押下と、
    選ばないまま `next_word_timeout` の秒数がたったことを足す (時間で消すのを後続語の予測に限る理由も)。「設定」の表に
    `next_word_timeout` の行を足す
  - `docs/spec/tools.md`: 設定キーの表に `next_word_timeout` の行、画面の構成の表の「候補バー」に項目を足す
- 利用者向け
  - `docs/user/settings.md` の設定の一覧に `next_word_timeout` の行を足す
  - `docs/user/candidate-bar.md`「次の語の予測」の「予測候補が消える条件」に、選ばないまま設定の秒数 (既定 5 秒) が
    たったときを足す
  - `docs/user/input.md`「その他のキー操作」に、入力パネルの外をマウスで押したときの働き (読みをそのまま確定する) を足す
  - `docs/user/candidate-bar.md` の後続語の予測の「予測候補が消える条件」の「マウスクリック」を、入力パネルの外での
    クリックだとわかる書き方にする
- `docs/roadmap.md` の既知の問題: マビノギではチャット欄の外の打鍵が IME に届かないため、チャット欄の外での Esc などの
  キーでは入力パネルを消せない (マウスの押下では消える)

## 実装手順

1. `SuggestPanel` に、押した先が入力パネルのウィンドウかを判定する手段を足す
2. `TextService` にマウスフックの付け外しと、押下の処理を足す。パネルの表示・非表示の箇所でフックの状態を合わせる
3. TSF 層の設定に `next_word_timeout` を足し、`TextService` に後続語の予測のタイマーを足す
4. 設定ツールに `next_word_timeout` を足す (`cargo test`・`cargo clippy` を通す)
5. 仕様書・利用者向けの文書・roadmap を書き換える
6. TSF 層を Debug でビルドする

## 検証方法

テストはメモ帳・WezTerm・マビノギで行う (常用環境を壊さないよう docs/development.md の手順で開発版 DLL に切り替える)。

| # | アプリ | 手順 | 期待 |
|---|---|---|---|
| 1 | メモ帳 | 語を確定して後続語の予測を出し、メニューバーを押す | 予測が消える。メニューは普通に開く |
| 2 | メモ帳 | 後続語の予測を出し、本文の別の位置を押す | 予測が消え、キャレットが押した位置へ動く |
| 3 | メモ帳 | 読みを打っている途中 (composition) で本文の別の位置を押す | 読みがそのまま確定し、パネルが消える。キャレットは押した位置へ動く |
| 4 | メモ帳 | 変換の候補一覧を出し、本文を押す | 今の候補で確定し、候補一覧が消える |
| 5 | メモ帳 | 候補バーの候補を選んだまま本文を押す | 選んだ候補ではなく読みのまま確定する |
| 6 | メモ帳 | 入力パネル自体を押す | 何も起きない (入力が続く) |
| 7 | メモ帳 | 入力中にホイールでスクロールする | 入力が続く |
| 8 | WezTerm | 入力中・後続語の予測の表示中に、ターミナルの画面を左クリック・右クリックする | 読みが確定し (予測は消え)、その後でアプリがクリックを処理する (右クリックの貼り付けは確定した文字の後ろに入る) |
| 9 | マビノギ | チャット欄で後続語の予測を出し、チャット欄の外を押す | 予測が消える |
| 10 | マビノギ | チャット欄で読みを打っている途中 (パネル保持入力) にチャット欄の外を押す | 読みがチャット欄に入り、パネルが消える (書き込めなかった場合は読みが捨てられてパネルが消える。どちらになったかを診断ログで確かめる) |
| 11 | 各アプリ | 入力パネルを出していないときにクリックする | 何も起きない (診断ログに押下の処理が出ない) |
| 12 | メモ帳 | 後続語の予測を出して 5 秒待つ (既定) | 約 5 秒で予測が消える |
| 13 | メモ帳 | 後続語の予測を出し、すぐ Ctrl+↓ で選んで 5 秒以上待つ | 消えない |
| 14 | メモ帳 | 後続語の予測を出して 3 秒後に Ctrl+1 で採用する | 次の語の予測が出て、そこから約 5 秒で消える (最初の表示から 5 秒では消えない) |
| 15 | メモ帳 | 読みを打ったまま (run 中) 5 秒以上待つ | パネルは消えない |
| 16 | メモ帳 | 設定ツールで「消さない」にして保存し、予測を出して待つ | 消えない |
| 17 | 設定ツール | config.tsv に `next_word_timeout 7` と書いて開く・保存する | 「10 秒」が選ばれ、保存すると `10` になる |
| 18 | マビノギ | チャット欄で後続語の予測を出し、キーボードだけでチャット欄を抜けて待つ | 約 5 秒で予測が消える |
