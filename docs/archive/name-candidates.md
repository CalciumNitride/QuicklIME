# 人名の候補を抑える・人名変換 (F3)

## 背景と目的

短い読みの同音異義語では、システム辞書の人名 (名・姓) が候補の上位を埋め、一般名詞が辞書の候補の枠
(`MAX_DICT_CANDIDATES` 24 件) から押し出される。

- 「せいこう」: 「正孔」は Mozc 辞書にある (コスト 6806) が、重複と読みと同じ表記を除いた順位は 32 番目で、変換の候補に
  出ない。それより上の 31 語のうち約 18 語が名の人名 (静香・正孝・正幸・正康・成晃など)
- 候補バーの予測でも、「せいこう」の 1 ページ目 9 件のうち 3 件が人名 (静香・正孝・正幸)

一般名詞を候補に出すため、辞書の候補の枠を広げ、システム辞書の人名の数を抑える。抑えた人名を探せるよう、
記号・日付変換 (F4)・ユーザ語変換 (F5) と同じ形で、人名だけを出す人名変換を足す。

## 決定事項

### 人名の判定

- 品詞 ID 表 (id.def) の品詞名が `名詞,固有名詞,人名,` で始まる ID を人名とする (Mozc では 1921 人名一般・1922 名・
  1923 姓)。ID の数値は固定せず、id.def を読んだときに求める (テストの id.def は ID が違うため)
- 判定は語の左文脈 ID で行う
- 抑える対象はシステム辞書 (Mozc 辞書と UT 辞書) の人名だけ。ユーザ辞書・インポート辞書の人名の品詞の語は、利用者が
  入れた語なので抑えない
- id.def が無いか読めないときは人名を判定できないので、抑えない

### 通常の変換の候補

- `MAX_DICT_CANDIDATES` を 24 から 40 にする。CONVERT の「候補が 25 件になるまで」も同じ定数に従う
- 読み全体に完全一致する辞書の語 (`exact_candidates`) を、コストの順のまま次のように並べ直す
  - システム辞書の人名は、コストの小さい `MAX_NAME_CANDIDATES` (3) 件だけを元の位置に残す
  - 残りの人名は、人名以外の語 (ユーザ辞書・インポート辞書の語を含む) のすべての後ろへ、コストの順で回す
- `exact_candidates` を使う所すべてに効く: 文節の候補 (CONVSEG・CONVCTX) の 4〜6 (先頭の語・数字に続く部分の
  入れ替えを含む)、全文一括の候補 (CONVERT)、N-best (CONVNBEST) の候補の並びの 5
- 経路上の表記・句の学習の表記・短縮よみには手を入れない。学習した人名は今までどおり上に出る
- 「せいこう」では、人名は静香・正孝・正幸が残り、「正孔」は 14 番目前後になる

### 予測

- 候補バーの予測 (SUGGEST の「予測」の 4) のうち、システム辞書の人名の予測は、点数の小さい `MAX_NAME_CANDIDATES` (3) 件
  だけを点数の位置に残し、残りを並びの最後 (`max_predictions` 件で切る前) に回す
- 全体変換・句の学習・ユーザ辞書の語・短縮よみ・インポート辞書の語の予測には手を入れない
- 「せいこう」では、今の 1 ページ目の人名は 3 件なので並びは変わらない。人名が 4 件以上入る読みで効く (利用者と合意済み)

### 人名変換

| 項目 | 内容 |
|---|---|
| 機能 | `ConvertName` |
| 設定キー | `key.convert_name` |
| 既定の割当 | `F3` |
| 働く状態 | 入力なし以外 (`ConvertSymbol`・`ConvertUser` と同じ)。入力なしではアプリへ渡す (ブラウザの検索などの F3 を妨げない) |
| 表の位置 | keys.md「機能」の表・`KeyFunc`・設定ツールの `KEY_ITEMS` で、`CommitRun` の次、`ConvertSymbol` の前 |
| 設定ツールの表示名 | 「人名変換」 |

- 対象・連打・範囲の伸縮は F4・F5 と同じ: run 中なら読み全体、候補選択中なら現在の文節。同じ候補を出している間の F3 は
  次候補。候補が無い読み (エンジン不調を含む) では何もしない。候補が出た後に範囲を伸縮すると通常の変換をやり直す
- エンジンに要求 `CONVNAME` を足す。形式は CONVSYM・CONVUSER と同じ (`CONVNAME\t<かな>\n` → `OK\t<候補1>\t...\n`、
  該当なしは候補ゼロの OK、読みが空なら ERR)
- `CONVNAME` は読みに完全一致する人名を次の順で返す。表記が先に入ったものと同じなら入れない
  1. ユーザ辞書の人名・姓・名の語 (記載順)
  2. インポート辞書の人名の品詞の語 (記載順)
  3. システム辞書の人名 (コスト順。抑えた人名も含めすべて)
- 旧エンジン (CONVNAME 未対応) は「不明なコマンド」を返す。TSF 層は候補が無いときと同じく何もしない

### 採らなかった案

- 枠を広げるだけ: 「正孔」は 32 番目のままで、人名の多い読みでは一般名詞まで遠い
- 人名を候補から除く: 人名を変換キーの候補一覧から選べなくなる。人名変換があっても、候補一覧の後ろに残しておく
- 予測の人名を点数に上乗せして下げる: 上乗せの値を評価セットで決める手間がかかる。件数で抑える
- ユーザ辞書・インポート辞書の人名も抑える: 利用者が自分で入れた語なので抑えない

## 変更対象ファイル

- エンジン
  - `engine/src/pos.rs` (または品詞 ID 表を持つ所): 人名の左文脈 ID の判定
  - `engine/src/convert.rs`: `MAX_DICT_CANDIDATES` を 40 に、`MAX_NAME_CANDIDATES` (3) を足し、`exact_candidates` で
    システム辞書の人名を並べ直す。ユーザ辞書・インポート辞書の語と区別できるよう、システム辞書の語かどうかを持たせる
  - `engine/src/suggest.rs` (予測を集める所。必要なら `engine/src/predict.rs`): システム辞書の人名の予測を 3 件に抑える
  - `engine/src/main.rs`: `CONVNAME` の受付とテスト
  - `engine/src/dict.rs`・`engine/src/userdict.rs`: 必要なら人名の語を引く関数
- TSF 層
  - `tsf/src/config.h` / `tsf/src/config.cpp`: `KeyFunc::ConvertName`、設定キー `key.convert_name`、既定 F3
  - `tsf/src/engine_client.h` / `tsf/src/engine_client.cpp`: `ConvertNames` (CONVNAME)
  - `tsf/src/text_service.h` / `tsf/src/text_service.cpp`: `ApplyFunctionKey` に `ConvertName` を足し、`ConvertToSymbols`
    と同じ流れの `ConvertToNames` を足す (共通にできる部分は共通にする)。キーの照合で `ConvertSymbol`・`ConvertUser` を
    扱っている所 (働く状態の判定など) に `ConvertName` を足す
- 設定ツール: `engine/gui/src/keys.rs` の `KEY_ITEMS` に `("key.convert_name", "人名変換", IN_INPUT, "F3")` を足す
  (件数の型も直す)。キー割当のページが `KEY_ITEMS` から作られていなければ、そのページも
- 仕様書
  - `docs/spec/engine.md`「文節の候補 (CONVSEG・CONVCTX)」の 4 と枠の説明 (24 → 40、人名の並べ直しと WHY、採らなかった案)、
    「全文一括の候補 (CONVERT)」の件数、「候補の並び」(N-best) の 5 の件数
  - `docs/spec/suggest.md`「予測」: システム辞書の人名の予測を 3 件に抑えること
  - `docs/spec/conversion.md`「ファンクションキー変換 (F4〜F10)」: 見出しを「(F3〜F10)」にし、F3 (人名変換) を足す。
    見出しへのリンク (`F4〜F10` を含む文書・コードコメント。archive を除く) も合わせて直す
  - `docs/spec/keys.md`「機能」の表に `ConvertName` の行、「run の無い状態のキー」の「F4・F5」の行を「F3〜F5」に
  - `docs/spec/dictionary.md`: 冒頭の CONVSYM などを並べた箇所に CONVNAME を足し、人名の判定 (品詞 ID 表) を
    「連接行列と品詞 ID 表」に書く
  - `docs/spec/runtime.md` 118 行目の表 (エンジンを起動して待つ要求) に CONVNAME を足す
  - `docs/protocol.md`: `CONVNAME` の節を CONVUSER の後に足す
- 利用者向け
  - `docs/user/keymap.md` の表に「人名変換」`key.convert_name` `F3` の行
  - `docs/user/input.md`: ファンクションキーの説明 (F4〜F10) に F3 の人名変換を足す
  - `docs/user/dictionary.md`: 変換の候補で人名を数件に抑え、残りは候補の後ろに回ること、F3 で人名だけを出せること

## 実装手順

1. エンジン: 人名の判定、`exact_candidates` の並べ直しと枠の拡大、予測の抑制、`CONVNAME`。単体テストを足し、
   `cargo test`・`cargo clippy` を通す
2. TSF 層: `ConvertName` の設定・エンジンへの要求・F3 の処理。Debug でビルドする
3. 設定ツール: `KEY_ITEMS` に足し、`cargo test`・`cargo clippy` を通す
4. 仕様書・protocol・利用者向けの文書を書き換える
5. release のエンジンもビルドし直す (TSF の exe 探索は release を優先するため)

## 検証方法

### エンジンの単体テスト

| # | 内容 | 期待 |
|---|---|---|
| 1 | テスト用の辞書で、同じ読みに人名 5 件 (低コスト) と一般名詞 2 件 (高コスト) を置き、CONVSEG | 人名の上位 3 件はコストの位置、残り 2 件の人名は一般名詞の後ろ |
| 2 | 同じ辞書で CONVNBEST | 読み全体の完全一致の部分が #1 と同じ並び |
| 3 | ユーザ辞書に人名の品詞の語を同じ読みで登録 | ユーザ辞書の語は抑えられず、コストの位置に出る |

| 5 | CONVNAME | ユーザ辞書の人名 → インポート辞書の人名 → システム辞書の人名 (コスト順、抑えた人名も含む)。一般名詞は出ない |

| 7 | id.def の無い構成で CONVSEG | 人名を抑えない (今までどおりコスト順) |
