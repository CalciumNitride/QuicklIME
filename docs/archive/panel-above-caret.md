# キャレット行の上に出す入力パネル

## 背景と目的

縦に並ぶ入力パネル (縦積みのテーマのサジェスト・後続語の予測と、変換の候補一覧) を `candidate_position caret`
で出すとき、上下のどちらに出すかを今出している高さで決めており、上に出すときはパネルの下端をキャレット行の
上に揃えている。そのため画面の下端に近い入力欄では次のことが起きる。

- 入力行だけのときや候補が少ないときは行の下に出て、候補が増えると行の上へ飛ぶ。パネル保持入力では
  入力した文字の表示位置が大きく上へずれる
- 上に出ている間は、候補の数が変わるたびに入力行と候補がまとめて上下に動く

キャレットの近くに出す縦の入力パネルで、同じ行で入力している間は入力行と各候補の位置を動かさないようにする。

## 決定事項

### 対象

- 縦に並ぶ入力パネルを `candidate_position caret` で出すとき
  - サジェスト (run のサジェスト・後続語の予測) は `layout column` のテーマのとき (`SuggestPanel::LayoutPage`)
  - 変換の候補一覧はテーマの `layout` によらず縦積みなので、すべてのテーマ (`SuggestPanel::ShowConversion`)
- 入力方式 (`input_buffer`) は composition 入力・パネル保持入力の両方。入力行の有無だけが違う
- 横一列 (`layout row`) のサジェストと `candidate_position center` は今のまま (高さが候補の数によらないか、
  すでに上端を固定しているため)

### 上下の判定: 出しうる最大の高さで決める

- 下に出したときに最大の高さが作業領域に収まれば下、収まらなければ上に出す。今出している候補の数では決めない
  - 最大の高さは「作業領域の高さに収まる行数 (最大 9 = `kMaxItems`) の行と、位置の表示の行」を出すときの
    パネルの高さ。入力行の有無はそのときの入力方式に従う (`ColumnHeight` を使う)
  - 位置の表示の行は、ページ送りが起きるかどうかによらず常に含める (候補の数で判定を変えないため)
  - サジェストと変換の候補一覧で同じ式にし、パネル保持入力でサジェストから変換に移っても出る側が変わらないようにする
- 下にも上にも最大の高さが収まらないときは、キャレット行の下と上で空きの大きい方に出し、1 ページの行数を
  その空きに収まる行数 (最大 9) にする。1 行も収まらないときは今の扱い (作業領域の下端に寄せる) のまま
  - 空きは、下は「キャレット行の下端 (カプセルの下端を含む) + 下側の間 から作業領域の下端まで」、上は
    「作業領域の上端から キャレット行の上端 − 上側の間 まで」
  - 1 ページの行数は、出す側が決まった後に、その側の空きで数える (今は作業領域全体の高さで数えている)
- 判定は表示のたびに行う。キャレット行が同じなら結果は同じになるので、前回の判定を覚えておく仕組みは足さない
- 採らなかった案:
  - 上に出すときに上端を最大の高さで固定し、下へ伸ばす。候補が少ないときにパネルとキャレット行の間が
    最大で 9 行分空き、入力した文字が挿入先から遠くに出るため
  - 上下の判定だけを直す。上に出したときに候補の数で上下に動くのが残るため

### 上に出すときの並べ方: キャレット側から積む

- パネルの下端をキャレット行の上に揃える (上側の間は今と同じ。`pointer` では尻尾の高さ)
- 中の並びを上下で反転する。キャレット側 (下) から順に:
  1. 入力行 (入力行を出すとき)
  2. 区切り線 (今と同じ条件)
  3. 候補の 1 番目、2 番目、…。1 番目が入力行 (入力行が無ければパネルの下端) のすぐ上に来る
  4. 位置の表示 (`12/24`。複数ページのとき)。最後の候補の上に出す
- これにより、入力行と各候補の位置はキャレット行からの距離で決まり、候補の数が変わっても動かない。
  伸び縮みするのはパネルの上端だけになる
- 番号 (1〜9) は今と同じく候補の順に振る (1 番目がキャレット側)
- 下に出すときの並べ方は今のまま
- 尻尾 (`caret_marker pointer`) は今と同じく下辺から下向きにキャレットを指す。`triangle` も今のまま

### 矢印キー: 見た目の方向で動かす

上に出して反転しているパネルでは、↑ / ↓ を見た目の方向に合わせる。

- ↑ は上の候補 (順番では次)、↓ は下の候補 (順番では前) を選ぶ
  - サジェストの選択 (`MoveBarSelection` を呼ぶ ↑ / ↓)
  - 変換の候補一覧の選択 (`CycleCandidate` を呼ぶ ↑ / ↓)
  - キー割り当て `NextWordNext` / `NextWordPrev` (後続語の予測の選択。既定 Ctrl+↓ / Ctrl+↑) も、割り当てた
    キーが ↑ / ↓ なら見た目の方向に従う。つまり反転中は既定の Ctrl+↑ で次の候補になる
- 未選択からの最初の一打の扱いは、反転を入れ替えた後の向きで今と同じにする。たとえば、今の
  「未選択から次へで 1 番目」は反転中は ↑ で 1 番目を選ぶ。後続語の予測の「未選択から前へで最後の候補」は
  反転中は Ctrl+↓ で最後の候補を選ぶ。run のサジェストの「未選択から前へは何もしない」は反転中は ↓ で何もしない
- 端での循環 (末尾から次へで先頭、先頭から前へで末尾) とページの切り替えは、順番での次 / 前に対して今のまま
- Tab / Shift+Tab、Space / Shift+Space (`NextCandidate` / `PrevCandidate`)、変換キーなど、方向を持たないキーは
  順番での次 / 前のまま
- 横並びのテーマでの ← / → (docs/design/basics.md) は対象外 (横一列は反転しない)
- 反転しているかどうかは `SuggestPanel` が持ち、TextService が ↑ / ↓ を順番での次 / 前に直すときに問い合わせる。
  パネルが出ていないときは反転していないとみなす

### 責務の分け方

- `SuggestPanel` に、縦の入力パネルを上に出しているか (反転しているか) を返す口を足す
- 上下の判定と 1 ページの行数は、ページの区切りを決める時点 (`Show` と `ShowConversion`) で決めて保持する。
  `LayoutPage` (ページの切り替え・選択の変更) はその判定を使い、選択の変更では出す側を変えない
- 反転時の行の位置は、`itemBoxes_`・`inputTop_`・`pageTop_`・区切り線の位置を反転した並びで設定する。描画は
  これらの値を使うので、描画側は区切り線の位置を受け取れるようにする以外は変えない
  (今は区切り線を入力行の直下に引いている前提があれば、その前提を外す)
- TextService は ↑ / ↓ から順番での向き (+1 / −1) を得る共通の関数を使い、上の各キー処理をそこへ寄せる

## 実装手順

1. `SuggestPanel` の `Show` / `ShowConversion` で、最大の高さによる上下の判定と、出す側の空きでの 1 ページの
   行数を決めて保持する。`LayoutPage` と `ShowConversion` の位置の計算をその判定に従わせる
2. 上に出すときの反転した並び (入力行・区切り線・候補・位置の表示) を入れる
3. 反転しているかを返す口を足し、TextService の ↑ / ↓ の処理を共通の関数に寄せる
4. ドキュメント

## 検証方法

TSF 層は開発版 DLL に切り替え (scripts\dev-deploy.ps1 -Dll)、メモ帳で行う。`QUICKLIME_PIPE_NAME`・
`QUICKLIME_CONFIG_FILE`・`QUICKLIME_LEARN_FILE`・`QUICKLIME_USER_DICT_FILE`・`QUICKLIME_THEME_DIR` で隔離する。
テスト前に `taskkill /IM Notepad.exe /F` と旧エンジンプロセスの終了を行う。画面の下端付近の入力は、メモ帳の
ウィンドウを作業領域の下端まで広げて最終行に打つ。
