# 補正で読みの末尾を変えない

## 背景と目的

タイプミス補正 ([engine.md](../spec/engine.md)「タイプミス補正」) と、ずれのある予測 ([suggest.md](../spec/suggest.md)
「ずれのモデル」) のしきい値は、打ち終えた入力で決めた。候補バーは 1 打ごとに SUGGEST を引くので、打ちかけの読みでも
補正が働く。

fuzzy_eval で、打ち間違いの無い文 (llm_cases.tsv と typo_cases.tsv) を 1 打ずつ打った途中の状態 (確定済みのかなが
3 文字以上の 1984 件) を SUGGEST にかけると、補正の候補かずれのある予測が 3 位以内に 269 件 (14%)、先頭に 196 件 (10%)
出た。打ち終えた入力では先頭に出る件数は 0 件。先頭に出た例の多くは、打っている末尾のかなを直したもの。

| 打鍵 | かな | 先頭 | 種類 |
|---|---|---|---|
| haisyanii | はいしゃにい | 歯医者に | 全体変換の補正 (末尾の い を余分として消す) |
| kouseiwoo | こうせいをお | 構成を | 全体変換の補正 |
| shiryouwookurima | しりょうをおくりま | 資料をおクルマ | 全体変換の補正 (末尾から 2 文字目が変わる) |
| kakuninnsiteokima | かくにんしておきま | 確認してお聞か | 全体変換の補正 |
| tomodachitoa | ともだちとあ | 友達と一緒 | ずれのある予測 |

先頭のかなを変えない保護はすでにある。本書の目的は、その対として読みの末尾も補正で変えないようにし、打ちかけの読みで
補正が先頭に出るのを減らすことである。打ち終えた入力の末尾の打ち間違い (すきでう → 好きです) は直らなくなるので、
その損を計測で確かめてから既定値を決める。

## 決定事項

### A. 2 段階で進める

1. 計測: 末尾の保護の文字数を調整値 (`typo::Tuning`) に足し、既定値は 0 (今と同じ挙動) にする。fuzzy_eval で値を振って比べる
2. 既定値を決める: 計測の結果をユーザと見て既定値を決め、仕様書を書き換える

本書の実装の範囲は 1 段目。2 段目は結果を見てから本書に追記する。

### B. 全体変換の補正の末尾の保護 (`Tuning` の `tail_chars`)

- 補正した読みは、打ったかなの末尾 `tail_chars` 文字を変えない。`CorrectionSet::push` で、補正後の読みと打ったかなの
  共通の末尾 (`suffix`) が `tail_chars` 文字未満なら足さない。先頭のかなの判定と同じ所で行う
  - 「変わった所が末尾 `tail_chars` 文字より前で終わる」と同じ条件。末尾に 1 打を足して かな を増やす補正
    (`すこしお` の後ろに足す) もこれで除く
  - 対象は読みの末尾の文字 (かなに限らない)。英字区間で終わる読みでは英字の後ろが末尾になり、その前のかなは保護しない
    (英字を打っている最中は日本語の末尾を打っていないため)
- 打鍵による補正 (`key_corrections`) とかなを戻した近似 (`corrections`) の両方に効く。全体変換の補正を使うすべての要求
  (SUGGEST・CONVNBEST・RERANK・文節 UI の CONVSEG・CONVCTX) に同じ値で効く
  - 文節 UI は今 `typo::TUNING` を使うので、既定値を変えればそのまま効く
- `MIN_TYPO_CHARS` (3) の判定は今のまま (保護で補正できる所が無くなる読みは、結果として補正が出ない)

### C. ずれのある予測の末尾の保護 (`Tuning` の `predict_tail`)

- 予測の照合 (`Matcher`) で、末尾の `predict_tail` 個のかなのかたまりの打鍵と、未完成のローマ字には誤りを認めない。
  先頭のかなのかたまりの打鍵 (`l0`) と同じ扱いを末尾に足す
- 0 なら今と同じ

### D. 要求ごとに保護を変えない

保護は全体変換の補正を使うすべての要求に同じく当てる (B)。変換キーの候補一覧と候補バーで同じ補正の候補になるという今の
仕様 ([suggest.md](../spec/suggest.md)「打鍵の受け渡し」) を保つため。

- 採らなかった案: 候補バー (SUGGEST) だけに保護を当て、変換キーを押したら打ち終えたとみなして末尾も直す。候補バーと
  変換キーの候補一覧で補正の候補が食い違う

### E. 採らなかった案

- 通常の最良経路の 1 文字あたりのコストで補正の判定を足切りする。打ち間違いの無い文を途中で切った読みのコストが
  打ち間違いのある文と重なる (中央値 1851 と 2094。typo_eval。[roman-ime-notes.md](../roman-ime-notes.md))

## 実装手順

1. typo.rs に `tail_chars`・`predict_tail` を足し、`CorrectionSet::push` と `Matcher` で判定する。既定値 0 で今の
   単体テストが通ることを確かめる
2. 単体テストを足す (`tail_chars` 1 で、末尾のかなを消す・変える・末尾に足す補正が出ないこと、末尾より前の補正は出ること。
   `predict_tail` 1 で、末尾のかなの打鍵の誤りを照合しないこと)
3. fuzzy_eval の `--config` に `tail`・`ptail` を足す
4. 計測を回す (下記「検証方法」)

## 検証方法

- `cargo build --release --examples` が警告なしで通る。`cargo test --release` が通る
- 既定値 0 で、fuzzy_eval の既定の行が今の値と同じ (時間の列を除く)。`先頭変化 0`・`誤補正 1/0`・
  `途中誤補正 3位内 269 (14%) / 先頭 196 (10%)`・`崩し 1 26%` など
- 計測: 次の 6 組を fuzzy_eval にかけ、表と `--detail` の打ちかけの例を見る
  - `tail` 0 / 1 / 2 と `ptail` 0 / 1 の組み合わせ
  - 見る列: 途中誤補正 (減らしたい)、崩し 1/3/9・崩し 3 (誤り 1/2/3)・補正=正解 (損を確かめる)、文・語の崩さない/崩した
    (予測の回復の損を確かめる)、誤補正・先頭変化 (増えないこと)

### F. 既定値 (2 段目)

`tail_chars` 1・`predict_tail` 0 にする。fuzzy_eval の結果 (同じテストセット):

| 調整値 | 途中誤補正 (3 位以内 / 先頭) | 崩し 1 | 補正=正解 (誤り 1) | 語 崩した (50%/75%) | 誤補正 (3 位以内 / 先頭) |
|---|---|---|---|---|---|
| 保護なし | 269 (14%) / 196 (10%) | 26% | 46% | 25%/66% | 1/0 |
| `tail_chars` 1 | 104 (5%) / 44 (2%) | 23% | 41% | 26%/66% | 1/1 |
| `tail_chars` 2 | 80 (4%) / 24 (1%) | 20% | 38% | 26%/66% | 1/0 |
| `predict_tail` 1 | 255 (13%) / 196 (10%) | 26% | 46% | 18%/49% | 1/0 |

- `tail_chars` 1: 打ちかけで先頭に出る件数が 10% から 2% に減り、打ち終えた入力の末尾の打ち間違いが直らない損は崩し 1 で
  3 ポイント。末尾の打ち間違いは打った直後に入力パネルで見え、自分で直しやすい
- `tail_chars` 2 は先頭に出る件数をさらに 20 件減らすが、損が倍になる
- `predict_tail` 1 は打ちかけで先頭に出る件数を減らさず、途中まで打った崩した語の回復を落とす。値は計測用に残す
- `tail_chars` 1 で、打ち終えた打ち間違いの無い入力の 1 件 (ともだちとあう) で補正の候補 (友達等) が先頭になる。
  保護なしでは同じ入力でずれのある予測 (友だち登録) が 3 位に出ていた。145 件中 1 件で、打ちかけの読みの減りに比べて小さいので許容する
